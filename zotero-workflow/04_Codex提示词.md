# Codex 提示词

这些提示词用于把 Zotero 证据库转成可复查产物。每次运行前先明确输入文件和 Zotero 集合。

## 1. 批次筛选

```text
请基于以下 Zotero 导出文件和项目主题，做标题/摘要级筛选。

项目主题：异常检测，重点是多模态开放集加密恶意流量检测、DA-FDIDS、网络入侵检测、可信解释。
输入文件：
- zotero-workflow/exports/异常检测.bib
- 文献.md

输出：
1. 生成 screening/YYYYMMDD_screening_batchNN.csv。
2. 每篇给 keep/maybe/reject。
3. 每个 reject 必须写一句排除理由。
4. 给出应回写 Zotero 的标签。
不要编造文献；引用键必须来自输入文件。
```

## 2. 主题简报

```text
请基于已筛选为 keep/maybe 的文献生成一页研究简报。

输出文件：briefs/YYYYMMDD_research-brief_主题.md
必须包含：
- 关键论文表
- 研究脉络
- 核心争议
- 建议阅读顺序
- Zotero 回写标签
每个关键判断都要列 citation key。
```

## 3. 选题脑暴

```text
请基于研究简报和证据卡，生成 3-5 个候选选题。

每个选题必须包含：
- 研究问题
- 可用证据
- 创新点
- 数据/实验可行性
- 最大风险
- 需要补充检索的问题
不要直接写论文正文。
```

## 4. 审稿人视角检查

```text
请以安全/网络测量/机器学习审稿人的视角检查该研究问题。

重点检查：
- 问题是否真实存在
- 与已有工作差异是否清楚
- 数据集和实验是否能支撑结论
- 是否存在数据泄漏、弱基线、不可复现风险
- 章节结构是否服务于主张
输出必须包含“必须补的证据”和“可以删掉的论点”。
```

## 5. 综述草稿

```text
请只基于已完成证据卡的论文写综述草稿。

要求：
- 每段至少有 citation key。
- 不允许出现没有证据卡支撑的泛泛判断。
- 先写证据地图，再写正文。
- 最后列出 Zotero 中需要补笔记或补标签的条目。
```
