# [604] Alert2Vec: Eliminating Alert Fatigue by Embedding Security Alerts Through Subgraph Learning

## 2. 中文翻译与核心摘要

这篇论文提出 Alert2Vec，目标不是再做一个特定 IDS、EDR 或在线服务场景下的告警过滤器，而是构造一个能同时处理网络侧与主机侧安全设备告警的通用威胁等级识别框架。

论文的核心思想是：每条告警都可抽象为由 `subject`、`action`、`object` 三类元素组成的异构告警子图；大量告警子图再合并为 Alert Intelligence Graph，简称 AIG。不同告警之间如果共享 IP、进程、文件、用户、攻击动作等元素，或者在短时间窗口内具有上下文关系，就会在 AIG 中形成连接。随后，论文为每个告警子图学习一个向量表示，向量由六类属性拼接而成：全局邻域、全局结构、位置、局部邻域、局部结构、异构性。最后用 DBSCAN 支持半自动标注启动，用 Random Forest 支持全自动威胁等级分类。

论文要解决的实际痛点很明确：大型组织每天产生海量告警，低中危告警占绝大多数，分析员真正需要优先处理的是少量高危、上下文上更可疑的告警。Alert2Vec 试图把“单条告警是否触发规则”提升为“这条告警在组织整体告警关系图中处于什么位置、和哪些告警聚集、其内部元素组成是否支持高危判断”。

## 3. 论文解决的具体问题

论文瞄准的是安全运营中的告警疲劳问题，即安全设备每天生成大量告警，而安全分析员无法逐条深度研判。

具体问题可以拆成三层：

1. 异构告警难统一  
   网络侧设备如 Firewall、WAF、NIDS 产出的告警通常围绕源 IP、目的 IP、攻击类型；主机侧设备如 EDR、HIDS、杀软则围绕用户、进程、文件、操作行为。过去方法常针对某一类设备或某一业务系统设计特征，难以迁移。

2. 单条告警信息不足  
   很多低危或误报告警在表面上和高危告警相似，仅看告警名称、规则 ID 或单个事件字段无法可靠判断。论文强调高危攻击往往体现在“多个告警之间的相似、聚集、时序上下文和共享实体”上。

3. 序列式关联表达能力有限  
   DeepCase、Context2Vector 这类方法把告警按时间排成序列，能捕获一定上下文，但难表达多攻击源、多受害者、多动作之间的非线性关系。例如僵尸网络 C&C 长时间分散通信，在序列中可能被切碎，但在图中可通过共同目标或共同动作聚成结构。

## 4. 创新点深度提炼

第一，论文提出了面向异构安全告警的 AIG 表达。  
它没有依赖某个设备的专有字段，而是提炼出 `subject-action-object` 三元元素。网络侧可映射为源 IP、攻击类型、目的 IP；主机侧可映射为用户/进程、操作、文件/进程等对象。这使它比只服务 NIDS 或 EDR 的方法更通用。

第二，把“告警”作为子图而不是节点。  
每条告警不是简单变成一个事件节点，而是变成一个内部有元素和边的 alert subgraph。这样既保留告警内部组成，又能让不同告警通过共享元素在大图中关联起来。

第三，设计了六属性子图表示。  
论文没有直接套用 Sub2Vec、SubGNN，而是根据告警威胁研判的特点拆成局部和全局两组信息：局部邻域、局部结构、异构性描述告警自身；全局邻域、全局结构、位置描述告警在 AIG 中的关系环境。

第四，引入半自动到全自动的落地路径。  
初始阶段用 DBSCAN 聚类，让分析员只标注每簇 1-2 条代表告警，再传播标签；积累足够标签后用 Random Forest 自动分类。这一点比单纯追求端到端模型更贴近 SOC 的数据冷启动现实。

第五，实验覆盖网络侧、主机侧和公开 NIDS 数据。  
论文在清华校园网网络告警、ADB 主机告警和公开 NAD 数据上验证，试图证明它不是只对某一类日志成立。

## 5. 科学问题与研究假设

核心科学问题是：能否通过告警子图在异构信息网络中的局部组成和全局关联，可靠推断告警威胁等级？

论文隐含了几个关键假设：

- 告警可被充分归约为 `subject`、`action`、`object` 三类元素，且这些元素包含威胁等级判别所需的主要信息。
- 同一威胁等级的告警更容易在 AIG 中聚集，因为攻击者常复用目标、漏洞、动作或基础设施。
- 误报或低危告警也会形成可识别模式，例如管理员周期性巡检导致的敏感操作聚集。
- 高危告警不仅由内部字段决定，也由其靠近哪些告警簇、是否连接高危上下文决定。
- 子图级表示比节点级表示、序列级表示更适合表达多源告警之间的复杂关系。

这些假设总体合理，但也意味着 Alert2Vec 依赖长期、连续、字段较完整的告警数据；如果组织的告警字段贫乏或设备间实体命名不一致，图结构质量会直接下降。

## 6. 科学方法与技术路线

技术路线分三步。

第一步，构建告警子图与 AIG。  
网络告警中，`subject -> action -> object`，方向体现网络流从源到目的；主机告警中，subject、action、object 之间多为无向关系，因为论文认为主机行为元素间没有网络流那样明确的信息方向。若两条告警在短时间内发生，并共享 subject 或 object，则在 action 节点之间加上下文边。

第二步，生成告警向量。  
每个告警子图的向量由六部分拼接：

- 局部邻域：用 node2vec 预训练节点嵌入，再对告警子图内部节点取平均。
- 局部结构：用 Anonymous Walk Embedding 表达子图内部路径结构。
- 异构性：通过节点类型监督分类得到能表达 subject/action/object 类型的节点表示，再按类型累计拼接。
- 全局邻域：找告警子图边界节点的 n-hop 邻居，对这些邻居节点嵌入取平均。
- 全局结构：对邻域补图使用 AWE，表达周边连接结构。
- 位置：随机生成 anchor subgraphs，以到锚子图的最短路径距离加权聚合，表达该告警在 AIG 中相对位置。

第三步，威胁等级识别。  
冷启动时用 DBSCAN 聚类并少量人工标注；标签积累后用 Random Forest 做多分类。论文选择 RF 的理由是稳定、抗噪、调参成本低，适合安全告警这种字段噪声较高的任务。

## 7. 实验设计与实验步骤

可复核流程如下：

1. 数据  
   使用三个真实数据集：ADB 两个月主机侧告警 HD，共 230 条；清华校园网一周网络侧告警 ND，超过 1 万条；公开 NAD 网络入侵告警数据，超过 130 万条，二分类为 important / irrelevant。

2. 预处理  
   对每条告警抽取 subject、action、object。网络侧通常映射为源 IP、攻击类型、目的 IP；主机侧映射为用户/进程、操作、文件/进程。缺失字段可设为 None，多值字段可形成多个节点。

3. 图构建  
   每条告警转成 alert subgraph；所有子图合并成 AIG。共享元素自然合并；短时间窗口内共享 subject/object 的告警在 action 节点间增加上下文边。

4. 表示学习  
   用 node2vec 生成节点嵌入；用 AWE 生成结构嵌入；计算六类属性并拼接成告警向量。最终较优维度设置为：全局邻域 128、局部邻域 128、全局结构 52、局部结构 52、位置 96、异构性 128。

5. 模型与基线  
   告警分类基线包括 Rule-based、AlertRank、Context2Vector、DeepCase、StreamCluster、ActiveLearning。子图表示基线包括 Structure2Vec、Metapath2Vec、Sub2Vec-N/S/NS、SubGNN。

6. 训练  
   监督模式下 70% 数据训练，30% 测试。Random Forest 使用 1000 棵树，Gini，`max_features=sqrt`。半自动模式使用 DBSCAN，`eps=0.30`、`min_samples=9`。

7. 指标  
   主要看 accuracy、recall、F1-score。每个结果重复三次，报告平均值和标准差。

8. 消融与敏感性  
   逐一只使用某个属性做分类，检验六属性贡献；再调整六类属性维度比例，观察表示向量中不同属性权重对准确率的影响。

9. 结果核查  
   需要重点复核表 II、表 III、图 9、图 10。表 II 支持 Alert2Vec 对分类基线的优势，图 9 支持其对子图学习基线的优势，表 III 说明邻域属性贡献最大，图 10 说明维度分配不能过度偏向单一属性。

## 8. 关键结果、结论与证据

Alert2Vec 在三个数据集上都超过基线。论文报告其在 ND 上准确率 94.7%，HD 上 95.6%，NAD 上 99.1%。这说明其设计至少在论文实验条件下同时适用于网络级和主机级告警。

与规则方法相比，Alert2Vec 的优势来自关联信息，而不是只看静态字段。与 AlertRank 相比，优势来自不依赖在线服务 KPI 等场景专有特征。与 DeepCase、Context2Vector 相比，优势来自图结构能表达非线性、多实体、多关系关联。

消融实验中，全局邻域和局部邻域单独使用时效果最好，说明“告警包含哪些节点”以及“告警周围连接着哪些节点”比纯结构模式更有判别力。结构属性单独表现较弱，但完整模型最好，说明结构信息不是主导特征，却能补充边和路径关系。

案例研究也有说服力：同样的 SOCKS 代理或 HTTP flood 行为，在不同上下文中威胁等级不同。Alert2Vec 能通过攻击者关联节点、受害者历史高危告警等上下文，把表面相似的告警区分开。

## 9. 局限性与待解决问题

论文自己承认两个主要局限。

第一，依赖历史告警数据质量。  
AIG 需要连续、完整、覆盖足够周期的数据。短期、碎片化、字段缺失严重的数据会造成图结构偏差。论文建议至少一个月连续告警数据，但实验中的 ND 只有一周，这里存在一定张力：一周数据能证明可行性，但未充分证明长期部署稳定性。

第二，不适合时间序列指标异常告警。  
CPU、内存、延迟等时间序列异常通常只有时间戳和指标偏离值，缺少 subject、action、object。Alert2Vec 的核心图构建无法自然适配这类告警，因此对 AIOps 指标告警或业务监控告警覆盖有限。

还存在一些论文未充分展开的问题：

- 三元元素抽取依赖字段规范化，跨厂商设备的字段对齐、实体归一、IP/主机/账号别名合并会很麻烦。
- AIG 规模随告警量增长，论文未深入讨论在线增量更新、滑动窗口维护和大规模图计算成本。
- 标签来自检测系统和分析员，可能包含历史偏见；RF 会继承这些标签偏差。
- DBSCAN 参数对数据分布敏感，换组织后是否稳定需要更多验证。
- 高准确率在类别极不均衡场景下可能掩盖高危小类召回问题，应更关注 per-class recall、误报压降率和分析员节省工时。

这篇论文与“异常检测”项目中基于图学习、知识图谱、威胁情报的方向中等相关，相关性评分 7 是合理的。

## 11. 代码对照分析

本地未发现该论文对应开源代码包，因此无法做逐文件复现级对照。但根据论文方法，若实现 Alert2Vec，代码目录大概率应拆成以下模块：

- 数据预处理：负责读取 NIDS/EDR/HIDS 告警，抽取 subject、action、object，处理 None、多值字段、时间戳和标签。
- 图构建：实现 HAS、NAS、AIG；网络侧应支持有向边，主机侧支持无向边；还要实现短时间窗口内 action-action 上下文边。
- 表示学习：调用或实现 node2vec、AWE，计算六类属性，生成最终 alert vector。
- 锚子图生成：对应论文 Algorithm 1，随机选择不重叠节点邻域作为 anchor subgraphs。
- 训练分类：实现 DBSCAN 半自动模式、Random Forest 全自动模式、训练测试划分。
- 评估实验：输出 accuracy、recall、F1，做三次重复实验、消融实验和维度比例敏感性实验。
- 可视化/案例：绘制 AIG 局部图，展示高危簇、低危簇和上下文升级案例。

如果后续复现，优先寻找或实现的关键文件应类似：`preprocess_alerts.py`、`build_aig.py`、`subgraph_embedding.py`、`anchor_subgraphs.py`、`train_rf.py`、`cluster_dbscan.py`、`evaluate.py`。论文给出的实现环境是 Python 3.6、Sklearn、Networkx。

## 12. 本篇精华

1. Alert2Vec 的关键不是“又训练了一个分类器”，而是把告警分级问题转化为异构告警子图表示学习问题。

2. `subject-action-object` 是全文最重要的抽象，它使网络侧和主机侧告警可以进入同一个建模框架。

3. AIG 的价值在于把共享实体、共享动作和短时间上下文显式连接起来，弥补序列模型只能表达线性上下文的不足。

4. 六属性表示中，邻域信息贡献最大；这说明安全告警研判更依赖“和谁相连、周围是什么”，而不仅是单条告警字段。

5. 局部属性判断告警自身是否可疑，全局属性判断告警处在何种攻击上下文中；两者结合才是论文性能提升的主要来源。

6. 半自动 DBSCAN 加全自动 RF 的设计很工程化，适合标签稀缺到标签逐渐积累的 SOC 落地过程。

7. 该方法对时间序列指标类告警支持较弱，因为缺少构图所需的主体、动作、客体元素。

8. 复现难点不在 RF，而在多源告警字段归一、实体对齐、AIG 增量维护和六属性向量稳定生成。
