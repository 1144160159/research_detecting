# [440] FedIn-NID: A Federated Learning Framework for Network Intrusion Detection in Large-Scale Heterogeneous Industrial IoT

- 题名：FedIn-NID: A Federated Learning Framework for Network Intrusion Detection in Large-Scale Heterogeneous Industrial IoT

## 2. 中文翻译与核心摘要

这篇论文关注的是下一代工业物联网中的网络入侵检测问题。工业 4.0 场景下，不同企业、工厂、边缘设备和生产系统之间需要协同制造，网络边界变得模糊，攻击面扩大；但各参与方又不能把原始流量数据集中到一个地方训练模型，因为涉及工业数据隐私、合规和跨主体信任问题。

论文提出 FedIn-NID，一个面向大规模异构 IIoT 的联邦学习入侵检测框架。它试图同时解决两个更贴近真实部署的难点：第一，IIoT 中设备数量巨大，但每轮只有少量设备可参与训练；第二，不同设备遭遇的正常流量和攻击类型分布差异很大，局部数据严重 Non-IID。

核心做法有两部分：一是多维客户端选择策略，同时考虑设备可用性、局部数据规模和类别分布均衡性；二是 FedEMA 聚合策略，用指数移动平均思想在旧的全局知识和新的本地模型更新之间动态折中。实验在 NF-ToN-IoT-v2 数据集上进行，构造 50 到 500 个客户端、10% 参与率、不同 Dirichlet 非独立同分布强度的场景。结果显示 FedIn-NID 在 macro-F1 和 accuracy 上整体优于 FedAvg、FedProx、SCAFFOLD，尤其在稀有攻击类别上更稳。

## 3. 论文解决的具体问题

论文不是泛泛讨论“用联邦学习做入侵检测”，而是把问题压到了更现实、更困难的 IIoT 条件下：

1. **跨工业主体不能集中数据**  
   IIoT 中 NetFlow 流量包含设备运行、业务流程和攻击暴露信息，集中训练会触碰隐私、商业敏感和合规问题。联邦学习允许数据留在本地，只共享模型更新。

2. **客户端数量大，但参与不稳定**  
   论文设定的客户端数达到 50、100、200、500，而每轮参与率仅 10%。这更接近工业边缘设备：有的设备电量不足，有的通信链路差，有的计算资源紧张，不能假定所有客户端稳定在线。

3. **局部攻击分布高度异构**  
   不同设备可能承担不同工业功能，正常流量模式不同；同时不同设备暴露给不同攻击，例如某些节点主要遇到扫描，另一些节点可能只出现少量注入或后门流量。单个客户端的数据不能代表全局分布。

4. **稀有攻击类别难以被联邦模型学习**  
   NF-ToN-IoT-v2 中类别极不平衡，少数攻击如 Ransomware、MITM、Backdoor 等样本稀少。普通 FedAvg 在低参与率和 Non-IID 条件下容易被主流类别牵引，导致稀有类别 F1 很低甚至为 0。

5. **现有 FL-NID 工作规模不足或异构性处理不足**  
   论文认为已有工作要么没有显式处理数据异构和可用性问题，要么只在 5 到 10 个客户端的小规模场景中评估，难以支撑“大规模异构工业物联网”这一目标。

## 4. 创新点深度提炼

1. **把 FL-NID 的挑战从“小规模隐私训练”推进到“大规模异构低参与率”**  
   论文的价值不只在提出一个算法，而是强调真实 IIoT 中客户端数量多、在线不稳定、攻击分布偏斜这三个问题会同时出现。FedIn-NID 的设计目标正是处理这三个因素叠加后的模型漂移和收敛困难。

2. **多维客户端选择不是只看设备在线，而是把“谁的数据更有用”纳入选择**  
   客户端选择权重由三类因素相乘：设备可用性、数据量、类别分布均衡性。这样做的直觉是：一个客户端即使在线，如果数据极少或只集中在一两个类别，也不一定适合作为本轮代表；反过来，一个数据量大、类别覆盖更均衡、可用性高的客户端更应被选中。

3. **用熵和 Gini impurity 描述本地类别分布均衡性**  
   论文用熵衡量分布不确定性，用 `1 - sum(p_k^2)` 形式的 Gini impurity 衡量类别混杂程度，二者相乘作为平衡因子。需要注意的是，文中文字称其为 Gini coefficient 并说数值越高越集中，这与公式含义不完全一致；按公式看，它更接近 Gini impurity，数值越高通常表示类别越分散、越均衡。

4. **FedEMA 聚合在训练后期更重视旧全局模型，抑制局部偏移**  
   FedEMA 的聚合形式是：
   `theta_g^{t+1} = alpha theta_g^t + (1-alpha) weighted_local_models`。  
   其中 `alpha = lambda exp(-beta(1-(t+1)/T)^2)`。在论文默认 `lambda=0.5, beta=4.0` 下，训练早期 alpha 很小，更接近 FedAvg；训练后期 alpha 增大，保留更多全局历史知识。这有助于在低参与率、大规模 Non-IID 客户端下减少局部更新造成的全局模型震荡。

5. **模型结构保持轻量，方法重点放在联邦机制而非复杂检测模型**  
   本地 NID 模型是 1D-CNN：4 个一维卷积层，通道数 32、64、128、256，配合 ReLU、max pooling、adaptive max pooling 和最终线性分类头。它面向 43 维 NetFlow 特征做 10 类分类。论文的主要贡献不在网络结构，而在客户端选择和聚合策略。

6. **实验专门考察客户端规模和异构强度两个维度**  
   论文使用 Dirichlet 参数 `gamma=0.5, 0.2, 0.1` 控制 Non-IID 强度，并改变客户端数量。这个设计能观察方法在更强异构、更大规模、更少每客户端数据情况下是否崩溃。

## 5. 科学问题与研究假设

**科学问题 1：在大规模 IIoT 中，少量、非稳定客户端参与是否会导致联邦入侵检测模型明显漂移？**  
论文假设：会。因为每轮只有 10% 客户端参与，且客户端数据分布不同，局部模型更新方向差异大，FedAvg 简单平均会把全局模型拉向当前参与子集，造成收敛慢和稀有类别识别差。

**科学问题 2：客户端选择是否应同时考虑系统因素和数据因素？**  
论文假设：应当。只按可用性选客户端，可能选到数据分布极偏、类别覆盖很少的客户端；只按数据质量选，又可能选到通信或计算条件差的设备。三者结合能提高本轮训练更新的代表性和稳定性。

**科学问题 3：动态保留历史全局知识能否缓解 Non-IID 联邦聚合偏差？**  
论文假设：可以。旧的全局模型虽然不是最新，但包含此前多轮、多客户端累积的整体知识；新本地模型虽然新，但只来自少量客户端。FedEMA 通过时间变化的 alpha 在两者之间折中，特别在后期降低局部异常更新对全局模型的扰动。

**科学问题 4：FedIn-NID 对稀有攻击类别是否更友好？**  
论文假设：是。多维选择提高类别覆盖，FedEMA 降低局部偏置，因此模型对 Injection、Backdoor、Ransomware、MITM 等少数类应比基线更稳。

## 6. 科学方法与技术路线

论文技术路线可以拆成五步：

1. **建立 IIoT 联邦客户端模型**  
   设共有 `M` 个客户端，每个客户端 `C_i` 有本地数据集 `D_i={(x_i,j, y_i,j)}`。输入 `x` 是 NetFlow 特征，标签 `y` 属于 benign 加 9 种攻击类型，共 10 类。训练数据通过 Dirichlet 分布切分到客户端，用 `gamma` 控制异构程度。

2. **建模客户端可用性**  
   可用性由能量状态、通信成本、计算成本构成。能量越充足、传输速率越高、计算能力越强，设备可用性越高。最终用 `A_i = 1 / (1 + O_i)` 表示。

3. **计算本地数据贡献价值**  
   对每个客户端统计类别计数和类别概率，计算熵 `H_i`、Gini impurity `G_i`，得到分布平衡因子 `B_i=H_i*G_i`。再根据本地样本数得到数据量因子 `N_i`。

4. **多维客户端选择**  
   选择权重为：
   `R_i = A_i^{wA} * N_i^{wN} * B_i^{wB}`。  
   按 `R_i` 排序，选取前 `m=max(1, floor(M*F))` 个客户端参与当前轮。论文实验中 `wA=wN=wB=1`，参与率 `F=0.1`。

5. **本地训练与 FedEMA 聚合**  
   被选客户端用交叉熵训练本地 1D-CNN。服务器用 FedEMA 聚合本地模型，早期更依赖新本地更新，后期更多保留全局历史模型，以提升收敛稳定性。

## 7. 实验设计与实验步骤

**1. 数据**

- 数据集：NF-ToN-IoT-v2。
- 总流量数：16,940,496 条 NetFlow。
- 攻击流量：10,841,027 条，占 63.99%。
- 正常流量：6,099,469 条，占 36.01%。
- 类别：benign 加 9 类攻击，包括 Scanning、XSS、DDoS、Password、DoS、Injection、Backdoor、MITM、Ransomware。
- 特征：每条流量 43 个 NetFlow 特征。

**2. 预处理**

可复核流程如下：

1. 读取 NF-ToN-IoT-v2 原始 NetFlow 数据。
2. 删除 `IPV4_SRC_ADDR` 和 `IPV4_DST_ADDR` 两个 IP 地址特征，避免模型直接记忆地址。
3. 对剩余特征做 label encoding。
4. 删除冗余数据流。
5. 随机划分 60% 为训练集、40% 为测试集。
6. 对数据做归一化。
7. 对训练集按 Dirichlet 分布切分到各客户端，构造 Non-IID 本地数据。

**3. Non-IID 设置**

- Dirichlet 参数：`Dir(0.5)`、`Dir(0.2)`、`Dir(0.1)`。
- `gamma` 越小，客户端间类别分布越极端。
- 客户端数：论文实验覆盖 50 到 500 个客户端。
- 每轮参与率：10%。

**4. 模型与基线**

- FedIn-NID：多维客户端选择 + 1D-CNN + FedEMA。
- FedAvg：标准联邦平均。
- FedProx：在本地损失中加入 proximal term，缓解 Non-IID 下局部漂移。
- SCAFFOLD：使用控制变量校正客户端漂移。
- 为了更贴近 IIoT 可用性问题，论文给基线使用了基于设备可用性的客户端选择，而 FedIn-NID 进一步加入数据量和类别分布因素。

**5. 训练设置**

- 框架：PyTorch。
- 优化器：Adam。
- 初始学习率：`1e-3`。
- batch size：1024。
- 通信轮数：50。
- 本地 epoch：1。
- 客户端参与率：0.1。
- AMP：所有方法都使用自动混合精度。
- 评估间隔：每 5 个通信轮评估一次。
- FedEMA 参数：`lambda=0.5`，`beta=4.0`。
- 多维选择权重：`wA=wN=wB=1`。
- 实验重复：结果报告 5 次试验的均值和标准差。

**6. 指标**

- Accuracy：整体多分类准确率。
- macro-F1：每个类别 F1 的非加权平均。  
  由于数据类别严重不平衡，macro-F1 比 accuracy 更能反映稀有攻击类别识别能力。

**7. 消融 / 敏感性**

论文没有给出严格的“只去掉客户端选择”或“只去掉 FedEMA”的模块级消融，这是一个不足。但它做了两类重要敏感性实验：

- 数据异构敏感性：比较 `Dir(0.5)`、`Dir(0.2)`、`Dir(0.1)`。
- 客户端规模敏感性：比较不同总客户端数量，最高到 500。

**8. 结果核查**

复核时应重点看三类证据：

1. macro-F1 是否在低 `gamma` 下仍领先。
2. 稀有类别如 Backdoor、Ransomware、MITM 的 F1 是否不再大量为 0。
3. 收敛曲线中 FedIn-NID 是否在 50 轮内更快达到较高 macro-F1，且标准差是否较小。

## 8. 关键结果、结论与证据

1. **FedIn-NID 在 macro-F1 上明显优于基线**  
   论文报告在不同异构设置下，FedIn-NID 相比 FedAvg 有约 8% 到 30% 的 macro-F1 提升。摘要中概括为相对基线提升约 10% 到 30%。

2. **异构越强，FedIn-NID 的优势越有意义**  
   当 Dirichlet 参数从 0.5 降到 0.2、0.1，所有方法性能都会下降，但 FedIn-NID 下降更缓。说明客户端选择和 FedEMA 对严重 Non-IID 有一定缓冲作用。

3. **稀有攻击类别是 FedIn-NID 的主要收益来源**  
   论文明确指出，FedAvg 等方法在某些小样本攻击类别上 F1 可能为 0。FedIn-NID 对 Injection、Backdoor、Ransomware 等类别更稳，这拉高了 macro-F1。这个结果比单纯 accuracy 提升更重要，因为入侵检测真正关心的往往正是稀有但高危攻击。

4. **客户端数量增加会让所有方法退化**  
   当总客户端数变多，每个客户端平均训练样本减少，局部模型更容易过拟合，本地更新方向差异更大，全局聚合更难。FedIn-NID 在 500 客户端场景下仍能保持优势，说明它更适合大规模边缘设备条件。

5. **accuracy 提升存在，但不如 macro-F1 明显**  
   论文报告 FedIn-NID 在 accuracy 上平均提升约 5% 到 20%。由于 benign 和大类攻击占比高，accuracy 容易被多数类支配，因此 macro-F1 更能证明方法对类别不平衡的改善。

6. **收敛曲线支持方法有效性**  
   Fig. 7 显示 FedIn-NID 在多数设置中更快达到较高 macro-F1，并最终收敛到更好性能。作者用 Gaussian filter 平滑曲线，阴影表示 5 次试验标准差。

## 9. 局限性与待解决问题

1. **缺少模块级消融实验**  
   论文同时提出多维客户端选择和 FedEMA，但没有充分展示只使用客户端选择、只使用 FedEMA、二者组合三种情况的对比。因此还不能精确判断性能提升主要来自哪一部分。

2. **客户端可用性在实验中被随机采样，未真实模拟工业网络状态**  
   虽然系统模型中定义了能量、通信、计算三类成本，但实现细节中说明为了降低复杂度，每轮客户端可用性从随机分布采样。这会削弱“工业设备真实可用性建模”的说服力。

3. **数据预处理描述略粗**  
   文中说对剩余特征进行 label encoding，但 NetFlow 特征中通常有数值型、类别型、计数型、时间型等混合特征。若对所有特征统一 label encoding，可能引入不合理的序关系或破坏连续数值含义。需要回到数据处理代码或复现实验进一步确认。

4. **安全性不是本文重点**  
   论文解决的是联邦学习可用性和异构性问题，没有深入处理模型投毒、梯度泄露、恶意客户端、后门攻击等联邦安全威胁。对于安全论文而言，这一点需要在综述中区分清楚：它是“用 FL 做 NID”，不是“保护 FL 本身”。

5. **通信约束和系统开销评估不足**  
   论文未来工作也承认当前是在较理想通信环境下研究算法，没有充分评估通信延迟、带宽限制、掉线、异步更新、边缘服务器层级结构等生产部署问题。

6. **1D-CNN 模型较简单，未与更强检测模型充分比较**  
   论文选择轻量 1D-CNN 是合理的，但没有与 Transformer、TabNet、DeepFM、时序模型或专门的表格模型进行系统对比。因此结论主要支持联邦策略有效，不代表该检测器本身最优。

   本次正文包标注为未截断，因此上述理解基于完整提供文本；但若用于正式引用或复现实验，仍建议回到 PDF 核查表格数值、图中曲线和公式排版细节。

## 10. 与本项目的关系

这篇论文与“异常检测 / 网络异常检测”项目高度相关，尤其适合作为以下几个方向的核心参考：

1. **分布式异常检测框架参考**  
   如果项目关注多站点、多边缘节点或多工业系统协同检测，FedIn-NID 提供了一个清晰范式：数据不出域，模型协同更新。

2. **Non-IID 异常数据建模参考**  
   异常检测中常见问题是不同节点异常类型不同、异常比例不同、正常模式不同。论文用 Dirichlet 切分模拟这种异构性，可作为项目实验构造方法。

3. **客户端选择机制可迁移**  
   论文的 `可用性 + 数据量 + 类别均衡性` 选择思想可迁移到其他异常检测任务。例如工业传感器异常、车联网攻击检测、边缘日志异常检测等。

4. **稀有异常类别评估提醒**  
   论文强调 macro-F1，而不是只看 accuracy。这对异常检测尤其重要，因为少数类异常往往才是最关键目标。

5. **可作为综述中的“现实化 FL-NID”代表工作**  
   相比只在少量客户端上做 FedAvg 的论文，这篇文章更强调大规模、低参与率和异构攻击分布，适合放在“面向真实工业物联网部署的联邦入侵检测”小节。

| 客户端可用性建模 | `federated/availability.py` | 能量、通信、计算成本，计算 `A_i`；实验中可能用随机采样替代 |
| 多维客户端选择 | `federated/client_selection.py` | 统计本地类别分布，计算 entropy、Gini impurity、数据量因子和 `R_i`，排序选前 10% |
| 本地训练 | `train/local_trainer.py` | Adam、交叉熵、本地 epoch=1、batch size=1024、AMP |
| 聚合策略 | `federated/aggregation.py` | FedAvg、FedProx、SCAFFOLD、FedEMA；FedEMA 动态计算 alpha |
| 评估 | `eval/metrics.py` | accuracy、per-class F1、macro-F1、5 次重复实验均值和标准差 |
| 实验入口 | `main.py`、`run_fedin_nid.py` | 参数包括 `M`、`gamma`、`F=0.1`、`T=50`、`lambda=0.5`、`beta=4.0` |

如果后续拿到代码包，应优先核查三点：第一，Gini 部分是否按公式实现为 `1-sum(p^2)`；第二，FedEMA 的 alpha 是否随轮次按论文公式递增；第三，基线是否使用与论文一致的 availability-only 客户端选择，否则实验对比会发生变化。

## 12. 本篇精华

1. FedIn-NID 的核心定位是：在大规模、低参与率、Non-IID 的工业物联网中做隐私保护型网络入侵检测。

2. 论文真正抓住了 FL-NID 的现实痛点：不是“能不能联邦训练”，而是“只有少量异构客户端在线时，模型还能不能稳定学到稀有攻击”。

3. 多维客户端选择把系统可用性、数据规模和类别分布均衡性合成一个选择权重，避免每轮训练被极端偏置客户端主导。

4. FedEMA 通过指数移动平均保留历史全局知识，训练后期更抑制局部模型漂移，适合低参与率 Non-IID 场景。

5. 论文的实验强项是同时改变 Dirichlet 异构强度和客户端数量，证明方法在更难设置下仍有优势。

6. macro-F1 是本文最关键指标，因为 NF-ToN-IoT-v2 类别极不平衡，accuracy 容易掩盖稀有攻击检测失败。

7. 本文仍缺少组件消融和真实通信约束评估，不能直接等同于生产级 IIoT 联邦入侵检测系统。

8. 对综述写作而言，这篇可归类为“面向大规模异构工业物联网的联邦入侵检测框架”，重点引用其客户端选择和动态聚合思想。
