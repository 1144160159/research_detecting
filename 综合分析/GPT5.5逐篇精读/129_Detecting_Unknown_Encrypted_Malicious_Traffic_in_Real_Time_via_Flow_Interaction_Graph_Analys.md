# [129] Detecting Unknown Encrypted Malicious Traffic in Real Time via Flow Interaction Graph Analysis

## 1. 基本信息

论文发表于 NDSS 2023，题为 *Detecting Unknown Encrypted Malicious Traffic in Real Time via Flow Interaction Graph Analysis*，DOI 为 `10.14722/ndss.2023.23080`。作者来自清华大学和中关村实验室。系统名为 HyperVision，公开代码仓库本地路径为 [source/HyperVision](F:/泉城实验室/二期/论文/异常检测/source/HyperVision)。

本文归类到“恶意流量、暗网与攻击检测”非常合适，二级上与图学习、知识图谱、威胁情报有关，但它更准确地说是“流交互图上的无监督异常检测”，不是传统语义知识图谱方法。

## 2. 中文翻译与核心摘要

这篇论文的核心主张是：加密之后，单条流的载荷和应用层语义不可见，甚至单流统计特征也会与正常 HTTPS/SSH/TLS 流量高度相似；但攻击往往不是孤立单流，而是由攻击者、受害者、诱饵服务器、C&C、扫描目标、下载节点之间的大量交互组成。因此，与其识别“某条流像不像已知攻击”，不如识别“这批流的交互结构是否异常”。

HyperVision 将网络流构造成紧凑的内存图。顶点是地址或地址集合，边代表短流聚合或长流分布摘要。系统用连通性、稀疏性、结构统计和流统计特征进行无监督图学习，目标是在没有已知攻击标签、不能看明文载荷的情况下检测未知加密恶意流量。实验覆盖 92 个数据集，其中包含 48 类加密恶意流量，论文报告整体至少达到 0.92 AUC、0.86 F1，并在平均检测延迟约 0.83 秒下达到 80.6 Gb/s 以上检测吞吐。

## 3. 论文解决的具体问题

论文解决的不是一般“加密流量分类”问题，而是更困难的实时、无监督、未知攻击检测问题。已有方法通常依赖 TLS header、HTTPS header、握手、单流时间序列、NetFlow 统计或有标签训练集，这些方法可以识别已知模式，却难以处理未知加密攻击。

具体痛点有三类：第一，DPI 在加密载荷下失效；第二，监督学习依赖已知攻击标签，遇到新型攻击会失效；第三，单流特征太局部，低速、分布式、阶段化攻击可以让每条流都“像正常流”，但整体交互关系仍然异常。

## 4. 创新点深度提炼

第一，论文把检测对象从“单条流”提升到“多流交互模式”。这是全文最关键的视角转移：攻击流量的恶意性不一定体现在每条流内部，而体现在谁和谁反复通信、以什么方向、规模、持续时间、稀疏结构相互连接。

第二，图构造不是简单 IP-as-vertex、flow-as-edge。作者观察到互联网流量中短流数量多、长流承载包多，因此短流做相似聚合，长流做特征分布拟合，避免图密度爆炸。

第三，无监督检测由多阶段轻量图学习组成：连通分量筛选、DBSCAN 预聚类、顶点覆盖选择关键顶点、K-Means 聚类边并用损失函数打分。这套流程比直接上 GNN 更适合实时高吞吐场景。

第四，论文补了信息论分析，用流记录熵模型比较理想记录、采样记录、事件记录和 HyperVision 图记录，论证其图表示在信息保留量和单位存储信息密度上接近理想上界。

## 5. 科学问题与研究假设

科学问题可以概括为：在无法读取载荷、无法依赖已知攻击标签的条件下，是否能仅凭流间交互结构实时识别未知加密恶意流量？

核心假设有三条：加密隐藏的是载荷和部分应用语义，但不会完全隐藏通信对象、方向、频度、时序和规模；攻击行为虽然可以伪装单条流，却难以长期伪装多主体交互结构；正常业务的交互图在连通分量、度分布、聚类中心、时间跨度上具有稳定统计规律，异常攻击会成为结构或统计上的离群模式。

## 6. 科学方法与技术路线

技术路线从包到告警依次为：解析包头字段，提取源/目的地址、端口、协议、长度和到达时间；按五元组和超时构造流；按包数阈值区分短流与长流；短流根据源/目的地址、端口和协议做聚合，长流用长度、协议、到达间隔直方图表示；由短边和长边共同构造流交互图。

检测阶段先用 DFS 找连通分量，再对分量级统计做 DBSCAN，筛掉大部分正常分量。对剩余异常候选分量，边先按局部结构特征预聚类。随后用顶点覆盖思想选择关键顶点，使每条边至少被一个关键顶点覆盖。最后在每个关键顶点邻接边集合中聚类，依据“离聚类中心距离、预聚类簇时间跨度、簇/聚合规模”组合成异常损失分数。

## 7. 实验设计与实验步骤

可复核流程如下：

1. 数据：使用 MAWI 2020 年 1 至 6 月骨干网流量作为背景流量，叠加自建 VPC 与公开数据集中的攻击流量；攻击覆盖传统暴力攻击、加密洪泛、加密 Web 攻击、加密恶意软件通信。
2. 预处理：去除背景中明显攻击流量；按原始速率重放背景与攻击；每个数据集约 1200 万至 1500 万包，前 75% 时间不含恶意流量，用于收集正常交互和基线训练。
3. 模型/基线：比较 Jaqen、FlowLens、Whisper、Kitsune、DeepLog；HyperVision 不用攻击标签训练。
4. 训练/检测：HyperVision 通过图构造、连通分量筛选、DBSCAN 预聚类、Z3 顶点覆盖、K-Means 边聚类产生包级异常分数。
5. 指标：主要报告 AUC 与 F1，同时使用 Precision、Recall、F2、Accuracy、FPR、EER。
6. 消融/敏感性：论文考察超参数影响、长时间运行、混淆/逃逸流量注入；阈值变化造成的准确率损失最多约 5.2%。
7. 结果核查：重点检查不同攻击组平均指标、44 个基线均失败的数据集、实时吞吐与延迟、内存/存储开销是否与系统目标一致。

## 8. 关键结果、结论与证据

总体结果是 HyperVision 在 80 个新构造数据集上平均 F1 为 0.927 至 0.978，AUC 为 0.974 至 0.993，相比最佳基线平均提升约 35% F1 和 13% AUC。更重要的是，44 个数据集中所有基线 F1 都无法超过 0.80，而 HyperVision 仍能检测。

传统攻击上，HyperVision 对扫描、反射放大、SYN/RST/UDP/ICMP 等也有接近饱和的 AUC/F1，说明方法不是只针对加密流量。加密洪泛、Crossfire、SSH 注入、密码爆破等场景中，论文认为胜出的原因是图保留了攻击者与多个目标之间的重复交互。加密 Web 攻击中，单流看起来像正常访问，但攻击者与 Web 服务之间的异常长流/频繁交互能在图中显现。恶意软件流量中，C&C、P2P botnet、矿池、广告/下载服务器会成为异常关键顶点。

性能方面，论文报告图构造平均约 28.2 Gb/s，图检测平均约 121 Gb/s，稳定检测吞吐 80.6 至 148.9 Gb/s；平均检测延迟 0.83 秒，99 分位 4.48 秒；图表示比原始包头、Zeek/Suricata 记录更省存储。

## 9. 局限性与待解决问题

第一，检测逻辑依赖“攻击具有异常交互结构”。如果攻击者能长期模仿正常 CDN、企业 SaaS、浏览器同步、移动 App 后台通信的多主体交互结构，图异常会被削弱。

第二，论文虽然宣称无监督，但仍有较多经验阈值和权重，例如 DBSCAN 半径/最小点数、连通分量选择比例、K-Means 的 K、损失函数权重和最终阈值。这些参数跨网络、跨时间迁移的稳定性仍需进一步验证。

第三，公开仓库更像 demo/offline 复现实验代码，没有完整呈现论文中 DPDK 实时数据面和高吞吐部署细节。因此工程复现论文 80Gb/s 级结果需要额外系统实现工作。

第四，正文包未截断；但本地缓存中少量作者符号、公式、图表字符存在编码噪声，信息论推导和附录算法细节如需引用到论文正文，仍建议回 PDF 复核公式排版。

## 10. 与本项目的关系

对异常检测项目而言，这篇论文的价值在于提供了一条“加密流量下绕开载荷语义”的路线：把流量表示为交互图，再做结构异常检测。它适合用作恶意流量检测、未知攻击发现、暗网/加密通道行为分析的核心参考。

如果本项目涉及威胁情报或知识图谱，HyperVision 可以作为前端行为图生成器：把异常边、关键顶点、组件簇、攻击阶段候选输出给上层威胁画像系统。它本身不是情报知识图谱，但能提供高质量的“谁与谁异常交互”的证据。

## 11. 代码对照分析

本地代码是公开 demo，主入口在 [main.cpp](F:/泉城实验室/二期/论文/异常检测/source/HyperVision/main.cpp)，读取 JSON 后启动 `hypervision_detector`。整体流水线在 [graph_analyze/detector_main.hpp](F:/泉城实验室/二期/论文/异常检测/source/HyperVision/graph_analyze/detector_main.hpp)：包解析、数据集构造、流构造、边构造、图构造、图检测、保存包级分数。

数据预处理与标签：`dataset_construct/basic_dataset.cpp` 负责按配置导入 `.data/.label` 或根据攻击地址和攻击开始时间生成标签。包解析在 `packet_parse/pcap_parser.cpp`，提取 IPv4/IPv6、TCP flags、UDP、ICMP、端口、长度和时间戳。

流与边：`flow_construct/explicit_constructor.cpp` 实现五元组流构造和超时合并；`graph_analyze/edge_constructor.cpp` 对应论文的短/长流分流、短流聚合、长流长度/协议/时间间隔直方图。配置里的 `edge_long_line=15`、`edge_agg_line=20` 对应论文附录阈值。

图分析与检测：`graph_component.cpp` 实现连通分量和分量筛选；`graph_analysis_basic.cpp` 提取短边/长边结构特征并做 DBSCAN 预聚类；`graph_analysis_short.cpp` 和 `graph_analysis_long.cpp` 分别实现短边与长边的 K-Means 聚类和损失计算；长边代码中引入 Z3 顶点覆盖约束。结果映射在 `graph_define.cpp`，将边分数回填到包级分数。

运行线索：README 给出的路径是 `sudo ./env/install_all.sh`、下载数据集、`./script/rebuild.sh`、`./script/expand.sh`、进入 `build` 后运行 `../script/run_all_brute.sh` 等。各实验组脚本位于 `script/run_all_*.sh`，阈值与指标分析在 `result_analyze/basic_analyzer.py`、`batch_analyzer.py` 和 `result_analyze/configure.json`。

## 12. 本篇精华

1. 加密恶意流量检测的关键不是破解加密，而是寻找加密无法隐藏的多流交互结构。
2. HyperVision 的核心贡献是“紧凑流交互图”：短流聚合降低边数，长流直方图保留高信息量。
3. 方法避免了监督学习对已知攻击标签的依赖，更适合未知攻击、零日攻击和低速加密攻击。
4. 实时性来自轻量图学习流程，而不是重型 GNN：连通分量筛选、DBSCAN 预聚类、关键顶点、K-Means 异常分数。
5. 信息论分析用于支撑图表示的必要性：采样/事件记录会丢失交互信息，图记录在信息密度上更优。
6. 实验中最有说服力的是 44 个基线失败案例，说明单流统计、日志事件和监督模型确实难以覆盖未知加密攻击。
7. 公开代码能帮助理解算法链条，但不是完整高性能实时系统复现包。

先读 Introduction 和 Threat Model，明确论文为什么不用载荷、为什么不用标签。第二步读 Section IV，重点理解短流聚合和长流分布拟合，这是整篇方法成立的基础。第三步读 Section V 和 VI，把连通分量、边预聚类、关键顶点、损失函数串成检测流水线。第四步读 Section VIII，按攻击类别看哪些基线失败、HyperVision 为什么成功。最后读 Appendix A 和代码中的 `edge_constructor.cpp`、`graph_analysis_*.cpp`，把公式、特征表、参数和实现逐项对齐。
