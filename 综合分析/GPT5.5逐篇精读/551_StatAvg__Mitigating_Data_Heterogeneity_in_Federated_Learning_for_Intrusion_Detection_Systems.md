# [551] StatAvg: Mitigating Data Heterogeneity in Federated Learning for Intrusion Detection Systems

## 1. 基本信息

- 题名：StatAvg: Mitigating Data Heterogeneity in Federated Learning for Intrusion Detection Systems
- 中文可译：StatAvg：缓解联邦学习入侵检测系统中的数据异质性
- 年份：2025
- 来源：IEEE Transactions on Network and Service Management, Vol. 22, No. 4, August 2025
- DOI：10.1109/TNSM.2025.3564387
- 主题：联邦学习入侵检测、非 IID 特征、统一归一化、数据异质性缓解
- 数据集：TON-IoT、CIC-IoT-2023
- 代码状态：本地未发现该论文对应代码包；论文脚注提到 Flower Baselines 中提供 StatAvg 复现实验入口。

## 2. 中文翻译与核心摘要

这篇论文研究的是联邦学习式入侵检测系统中的一个具体但常被忽视的问题：不同客户端不仅类别分布可能不同，特征本身的统计分布也可能不同。传统 FL-IDS 研究更多处理类别不平衡、标签分布差异或客户端样本量差异，而本文关注的是输入特征的非 IID，即不同客户端的同一特征均值、方差、条件分布不一致。

作者提出 StatAvg。它的核心思想非常直接：在正式联邦训练开始前，每个客户端计算本地每个特征的均值和方差，把这些统计量发给服务器；服务器按客户端样本占比聚合出全局均值和全局方差，再把全局统计量发回客户端；之后所有客户端都用同一套全局 scaler 对输入特征做 z-score 标准化。这样，客户端本地模型虽然仍在各自数据上训练，但输入空间的缩放标准被统一了，减少了由于本地归一化不一致造成的模型更新漂移。

论文的关键结论是：在 TON-IoT 和 CIC-IoT-2023 两个入侵检测数据集上，StatAvg 相比 FedAvg、FedLN、FedBN 更稳定，准确率收益约 4% 到 17%。特别是在 TON-IoT 上收益更明显，说明主机级日志特征的客户端统计差异对联邦收敛影响较大。

## 3. 论文解决的具体问题

论文解决的不是泛泛的“联邦学习非 IID”问题，而是 FL-IDS 中的非 IID 特征归一化问题。

传统联邦学习中，每个客户端往往用自己的本地训练集计算 scaler，例如本地均值和标准差。这个做法在集中式训练中问题不大，但在联邦场景下会引入一个隐蔽冲突：不同客户端对同一物理含义的特征使用不同尺度进行归一化。结果是，各客户端模型看到的输入空间并不一致，服务器再把这些模型参数平均，容易得到一个不稳定甚至偏置的全局模型。

作者认为，现有 FL-IDS 工作主要处理：

- 标签分布不一致；
- 类别不平衡；
- 客户端样本数量不均；
- 不同网络环境导致的数据源差异；
- 个性化联邦模型。

但这些方法没有充分回答：当客户端拥有相同标签空间、近似相同标签比例，但特征统计分布不同的时候，应该怎样训练一个可分发的统一全局 IDS 模型？

FedBN、FedLN 虽然也面向 non-IID features，但它们把问题放在模型内部的归一化层上。尤其 FedBN 保留本地 BN 参数，不参与服务器聚合，这对训练参与方有效，却不利于生成一个外部实体也能直接使用的统一全局模型。StatAvg 则把归一化问题前置到输入数据层面。

## 4. 创新点深度提炼

第一，论文把 FL-IDS 中的异质性焦点从“标签不平衡”转向“特征分布不一致”。这是一个更贴近工程部署的问题。真实 IDS 节点可能监控不同主机、网段、IoT 设备或攻击流量环境，即便标签集合一致，特征均值、方差、条件分布也会明显不同。

第二，StatAvg 的创新不在复杂模型，而在统一输入空间。它不修改联邦优化目标，也不强依赖某种神经网络结构，而是先构造一个全局标准化器。这个设计使方法可以嵌入 FedAvg、FedProx、SCAFFOLD 等不同聚合策略前面。

第三，论文给出了全局均值与全局方差的数学证明。服务器按样本占比聚合客户端均值，并用局部方差加均值偏移项计算全局方差。这个方差公式不是简单平均局部方差，而是包含客户端均值到全局均值的偏移，因此等价于把所有客户端数据拼接后计算总体方差。

第四，StatAvg 解决了模型发布时常被忽略的问题：一个训练好的模型必须绑定输入归一化方式。FedBN 类方法依赖参与训练客户端的本地 BN 状态，而 StatAvg 能输出一套全局 scaler，使未参与训练的第三方也能按同一标准处理输入后调用全局 IDS 模型。

第五，方法通信代价很低。每个客户端只在训练前发送每个特征的均值和方差，通信规模约为 `2S`，远小于模型参数量 `K`。对网络流量或主机日志 IDS 这类特征维度有限的任务，这个代价基本可以忽略。

第六，论文还讨论了差分隐私扩展。虽然作者认为均值、方差属于高层统计摘要，不直接暴露原始样本，但仍给出对均值和方差添加高斯噪声以满足 DP 的思路，说明方法可以向隐私增强版本扩展。

## 5. 科学问题与研究假设

核心科学问题可以表述为：

在联邦入侵检测中，如果客户端之间存在特征分布偏移，仅依靠模型参数聚合是否足够？是否可以通过统一输入归一化来提升全局 IDS 模型的稳定性和泛化能力？

论文隐含了几个研究假设：

- 假设一：FL-IDS 中的客户端特征分布差异会显著影响模型收敛和检测精度。
- 假设二：本地归一化会放大这种差异，因为每个客户端把本地数据映射到不同的标准化空间。
- 假设三：用全局均值和全局方差统一归一化，可以让各客户端模型更新更一致，从而提升聚合后的全局模型性能。
- 假设四：客户端共享均值、方差这类统计量，在隐私风险和检测性能之间是可接受的折中；若安全要求更高，可叠加差分隐私噪声。
- 假设五：方法的有效性不依赖特定聚合算法，因此可以作为联邦训练前的通用预处理步骤。

## 6. 科学方法与技术路线

论文方法路线很清晰：

1. 建模联邦学习系统  
   设有 `N` 个客户端，每个客户端拥有本地数据集 `Di`，全局目标是最小化所有客户端按样本量加权后的损失函数。

2. 界定 non-IID features  
   作者使用两个角度描述特征异质性：一是边缘特征分布不同，即 `Pi(x)` 不同；二是同一标签下特征分布不同，即 `Pi(x|y)` 不同。

3. 计算本地统计量  
   每个客户端对每个输入特征计算本地均值 `μi` 和方差 `σi²`。

4. 聚合全局统计量  
   服务器按样本比例 `ni = Di / D` 聚合：
   - 全局均值是客户端均值的加权平均；
   - 全局方差等于局部方差与客户端均值偏移项的加权和。

5. 统一客户端归一化  
   所有客户端使用同一个 `μG` 和 `σG` 对本地训练、测试和推理输入做 z-score 标准化。

6. 进入常规 FL 训练  
   StatAvg 只发生在正式训练前；之后可以使用 FedAvg 或其他聚合策略训练全局模型。

7. 与归一化类基线比较  
   实验比较 FedAvg、FedLN、FedBN，重点观察准确率、F1 和收敛曲线稳定性。

## 7. 实验设计与实验步骤

可复核流程如下。

数据：

- TON-IoT：使用 Ubuntu 14/18 操作系统审计追踪数据，偏向主机型 IDS。标签包括 DDoS、DoS、Injection、Password、Mitm、Normal。
- CIC-IoT-2023：使用 IoT 网络攻击流量数据，偏向网络型 IDS。标签包括 Brute force、DDoS、DoS、Mirai、Recon、Spoofing、Web-based、Normal。

预处理：

- 将原始数据划分给 `N=5` 或 `N=10` 个客户端。
- 每个客户端获得相同样本比例。
- 按标签分层划分，使客户端标签分布尽量一致，目的是突出特征分布非 IID，而不是标签非 IID。
- 每个客户端本地再按 4:1 划分训练集和测试集。
- 由于数据类别不平衡，在每个客户端训练集上独立使用 SMOTE 对少数类过采样。
- FedAvg、FedLN、FedBN 使用本地统计量做本地标准化；StatAvg 使用服务器聚合出的全局统计量做统一标准化。

模型与基线：

- 主模型为 3 个全连接隐藏层，每层 128 个神经元，ReLU 激活，输出层使用 softmax。
- FedAvg：标准联邦平均。
- FedLN：在本地模型中加入 Layer Normalization。
- FedBN：在本地模型中加入 Batch Normalization，BN 参数不在服务器端聚合。
- StatAvg：训练前执行全局统计归一化，随后默认使用 FedAvg 聚合模型参数。

训练：

- 客户端数为 5 时，联邦轮次为 50。
- 客户端数为 10 时，联邦轮次为 80。
- 所有客户端参与每一轮训练。
- 本地优化器为 Adam。
- 服务器每轮按客户端样本占比聚合模型参数。

指标：

- 使用混淆矩阵、Accuracy、F1 score。
- 因为是多分类任务，指标按类别平均。
- 结果再跨客户端测试集平均。

消融与敏感性：

- 客户端数量敏感性：比较 `N=5` 和 `N=10`。
- 数据集敏感性：比较主机 IDS 数据 TON-IoT 与网络 IDS 数据 CIC-IoT-2023。
- 归一化机制对比：本地 scaler、LN、BN 与 StatAvg 全局 scaler。
- 特征异质性观察：论文用 CIC-IoT-2023 中 Web-based 类别的 Flow Duration 分布，以及 TON-IoT 中 VSIZE、MINFLT 等特征统计差异，解释 non-IID features 的存在。

结果核查：

- 观察训练轮次中的测试准确率曲线，StatAvg 应表现为更高且更平稳。
- 对比表格中最优模型的 Accuracy 与 F1。
- 检查混淆矩阵中哪些类别仍易混淆，例如 CIC-IoT-2023 中 Brute Force、Recon、Spoofing。
- 确认性能提升不是由标签分布差异造成，因为实验已通过分层划分尽量控制 `Pi(y)` 一致。

## 8. 关键结果、结论与证据

第一，StatAvg 在两个数据集和两种客户端规模下均优于 FedAvg、FedLN、FedBN。论文报告的总体准确率提升范围约为 4% 到 17%。

第二，在 TON-IoT 上提升更大。相对第二优 FedLN，StatAvg 在准确率和 F1 上分别有超过 17% 和 16% 的改善。这说明 TON-IoT 的主机审计特征在客户端之间可能存在较强统计差异，本地归一化会明显破坏全局聚合效果。

第三，在 CIC-IoT-2023 上，StatAvg 仍有优势，但幅度较小，准确率提升超过 4%，F1 提升超过 2%。这说明网络流量数据中也存在特征异质性，但可能部分攻击类别特征更稳定，或者基线方法已经能处理一部分偏移。

第四，StatAvg 的收敛曲线更稳定。论文强调 FedAvg、FedLN、FedBN 曲线波动更大，而 StatAvg 更平滑，说明统一输入尺度不仅提升最终指标，也改善训练过程。

第五，混淆矩阵显示，DDoS、DoS、Mirai、Normal 等类别更容易分类，而 Brute Force、Recon、Spoofing 等类别更容易混淆。作者将其归因于类别样本量和流量模式相似性。

第六，论文通过特征分布可视化说明，即便标签分布被人为控制得相近，同一标签下的特征分布仍可能不同。这一点支撑了本文的核心设定：FL-IDS 的异质性不能只看标签比例，还要看特征统计和条件分布。

## 9. 局限性与待解决问题

第一，StatAvg 目前只使用均值和方差，默认 z-score 标准化足以缓解特征异质性。但网络安全数据常有长尾分布、离群点和离散计数特征，均值方差对异常值敏感。对 heavy-tail 流量特征，鲁棒统计量如中位数、分位数、MAD 可能更合适。

第二，实验主要验证了全客户端参与的同步 FL。真实部署中，客户端可能掉线、异步参与或周期性新增。论文提到动态数据可每轮重新计算统计量，但没有系统实验验证频繁更新 scaler 对稳定性和通信的影响。

第三，隐私分析还不充分。均值和方差确实不是原始样本，但在客户端数量少、特征稀疏或某些攻击样本极少时，统计量仍可能泄露环境特征。论文给出 DP 扩展公式，但没有实验展示隐私预算、噪声强度和检测性能之间的权衡。

第四，基线选择仍偏窄。论文比较了 FedAvg、FedLN、FedBN，但没有系统结合 FedProx、FedNova、SCAFFOLD 或个性化 FL 方法。由于作者声称 StatAvg 可与任意聚合策略组合，后续应验证“StatAvg + FedProx”等组合是否进一步提升。

第五，实验中的客户端划分是人为分层的。这样有利于隔离特征非 IID 问题，但真实 IDS 场景下标签分布、样本量、设备类型、攻击阶段往往同时异质。StatAvg 在混合异质性场景下的表现仍需更多验证。

第六，论文没有充分讨论特征语义一致性。StatAvg 假设各客户端拥有同一套特征空间。如果不同组织的 IDS 特征字段缺失、采集粒度不同或协议解析器不同，单纯聚合均值方差并不能解决 schema 异构。

## 10. 与本项目的关系

这篇论文与“入侵检测与网络异常检测”方向的关系较强，尤其适合放在“联邦学习、隐私保护与分布式协同”子方向中。

对本项目有三点直接启发：

第一，如果项目中存在多站点、多设备、多租户或多网段协同训练 IDS，不能只检查类别比例是否一致，还要检查每个特征在不同客户端上的均值、方差和条件分布。论文中的 TON-IoT 特征统计表和 CIC-IoT 特征分布图可以作为诊断模板。

第二，模型复现时必须把 scaler 当作模型的一部分保存。集中式异常检测常犯的错误是只保存模型权重，不保存训练时的标准化参数；联邦场景下这个问题更严重。StatAvg 提醒我们：全局模型发布时应同时发布全局标准化器。

第三，StatAvg 可作为本项目中 FL-IDS 的低成本 baseline 或增强模块。即使主算法是 FedProx、个性化 FL、蒸馏式 FL 或隐私增强 FL，也可以在训练前加一层全局统计归一化，再评估是否提升稳定性。

  - `global_mean = sum(n_i * local_mean_i)`

- 最终报告应跨客户端测试集平均。
- 应保存每轮测试准确率曲线，用于复现 Fig. 2 至 Fig. 5。

运行复核重点：

- 检查 StatAvg 是否只在训练开始前执行一次。
- 检查测试集是否使用同一套全局 scaler，而不是测试时重新拟合 scaler。
- 检查 FedBN 的 BN 参数是否真的没有参与服务器聚合。
- 检查客户端划分是否按标签分层，否则实验可能混入标签分布非 IID 的影响。

## 12. 本篇精华

1. 本文的关键贡献是把 FL-IDS 的非 IID 问题从标签不平衡推进到特征分布不一致，指出本地归一化本身可能破坏全局模型聚合。

2. StatAvg 的核心是“训练前统一 scaler”：客户端共享均值和方差，服务器生成全局标准化参数，所有客户端按同一标准缩放输入。

3. 全局方差不是局部方差的简单平均，而是包含客户端均值偏移项，因此等价于在全体数据拼接后计算总体方差。

4. 该方法几乎不增加通信负担，只传输每个特征的均值和方差，且不绑定特定聚合算法。

5. 对 IDS 工程部署很重要的一点是：全局模型必须连同全局归一化器一起发布，否则外部实体即使拿到模型权重也可能无法正确推理。

6. 实验表明 StatAvg 在 TON-IoT 和 CIC-IoT-2023 上均优于 FedAvg、FedLN、FedBN，准确率提升约 4% 到 17%。

7. 论文的证据链较完整：先数学证明统计量聚合正确，再用两个 IDS 数据集验证性能，最后用特征分布例子解释 non-IID features 的真实存在。

8. 后续值得扩展的是鲁棒统计量、差分隐私实测、动态客户端场景，以及与 FedProx、SCAFFOLD、个性化 FL 的组合。

## 13. 建议精读路线

建议第一遍先读 Introduction 的 Motivation 和 Contribution，抓住作者为什么认为现有 FL-IDS 没有充分处理 non-IID features。

第二遍精读 Section II-B，明确 feature distribution skew 和 same label, different features 的区别。这个部分决定了论文问题设定，不要把它简单理解成类别不平衡。

第三遍重点读 Algorithm 1 和 Proposition 1。尤其要确认全局方差公式的含义，这是 StatAvg 相比简单统计平均的关键。

第四遍读实验设置，特别关注客户端划分、SMOTE 使用位置、本地归一化和全局归一化的差别。复现时最容易出错的地方就在这里。

第五遍看结果表和混淆矩阵，不只看总体准确率，还要看哪些攻击类别仍然混淆。对异常检测项目而言，这比平均指标更能指导下一步改进。

最后回到局限性思考：如果自己的数据存在离群点、字段缺失、客户端动态加入或隐私约束更强，StatAvg 需要怎样改造成更鲁棒、更安全的版本。
