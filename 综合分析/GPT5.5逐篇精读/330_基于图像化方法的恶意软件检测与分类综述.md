# [330] 基于图像化方法的恶意软件检测与分类综述

## 2. 中文翻译与核心摘要

这篇论文系统综述了“把恶意软件转成图像，再用图像学习模型做检测或家族分类”的研究路线。它关心的不是单个新模型，而是这一技术路线为什么出现、解决了传统静态/动态/机器学习检测中的哪些痛点、在 Windows、Android、IoT、Linux 等平台上如何落地，以及当前仍有哪些瓶颈。

论文的核心判断是：传统恶意软件检测依赖代码结构、API、运行行为或人工特征，在遇到加壳、变形、虚拟机规避、动态代码加载等技术时容易失效；图像化方法把二进制字节、PE 结构、`.dex`、API 序列、ELF 或内存转储映射成灰度图、RGB 图、熵图、马尔科夫图等，使模型能够从纹理、局部结构、全局模式和多通道特征中学习恶意家族相似性。

但论文并没有把图像化方法神化。它指出该路线仍存在特征表示不足、动态行为捕获不充分、数据集老化和类别不平衡、对抗样本攻击、可解释性不足、实时检测成本高等问题。作者认为未来更有价值的方向是多模态融合、对抗防御、可解释检测、大规模实时处理和概念漂移适应。

## 3. 论文解决的具体问题

论文试图回答三个层次的问题。

第一，为什么传统恶意软件检测在新变种面前不够用。静态分析速度快，但容易被加壳、加密、代码变形、API 混淆干扰；动态分析能观察运行行为，但依赖沙箱环境，成本高，且会被虚拟机检测、延迟触发、沙箱规避绕过；机器学习方法能自动学习特征，但仍依赖特征工程和训练数据质量，遇到分布漂移、少样本家族和高级混淆时鲁棒性不足。

第二，图像化方法到底“图像化”的是什么。论文将输入对象分成 PE 文件、API 调用序列、Android `.dex` 与 Manifest、IoT 二进制、Linux ELF/内存转储等，再讨论它们如何被映射为灰度图、RGB 图、频谱图、马尔科夫图、熵图、空间填充曲线图或类二维码表示。

第三，图像化方法是否真的适合实际安全检测。论文通过大量表格比较现有研究的数据集、样本规模、平台、检测任务、准确率、抗混淆能力和模型结构，得出较审慎的结论：图像化方法在家族分类和混淆变体识别上很有潜力，但实际部署仍受数据质量、实时性、解释性和对抗鲁棒性制约。

## 4. 创新点深度提炼

这篇论文的创新不在于提出一个新模型，而在于把图像化恶意软件检测这条分散的研究线整理成了较完整的知识框架。

第一，它把图像化方法放回恶意软件攻防背景中理解。论文不是简单罗列 CNN、VGG、ResNet，而是先解释恶意软件的类型、传播方式、混淆技术，再说明为什么图像纹理和结构模式可能保留传统特征无法捕获的信息。

第二，它按平台和文件结构组织综述。Windows 下重点讨论 PE、反汇编字节、API 序列；Android 下重点讨论 `.dex`、Dalvik 字节码、Manifest 权限；IoT 下讨论资源受限环境中的二进制图像化；Linux 下讨论 ELF 和内存转储。这比单纯按模型分类更贴近安全实践。

第三，它把图像化流程拆成“表示、增强、学习、数据、解释”几个环节。论文不仅看最终准确率，还讨论图像生成方式是否丢失信息、尺寸调整是否破坏结构、RGB 多通道是否引入更多特征、GAN/SMOTE 是否缓解不平衡、Grad-CAM/LIME/SHAP 是否能解释模型关注区域。

第四，它强调数据集问题。论文指出 Malimg、MMCC、Drebin、Ember、AndroZoo、CICAndMal、VirusShare 等数据集在规模、更新年份、类别分布和平台覆盖上差异明显，模型结果很可能受数据老化、样本偏置和类别不平衡影响。

第五，它明确把未来挑战收束到特征表示、对抗攻击、数据不平衡、可解释性、实时检测和大规模处理。这对后续研究选题比单纯追求更高准确率更有指导意义。

## 5. 科学问题与研究假设

论文背后的科学问题可以概括为：恶意软件的二进制或行为结构在视觉空间中是否存在稳定、可学习、可泛化的模式，并且这些模式是否比传统人工特征更能抵抗混淆和变体演化。

主要研究假设包括：

- 同一家族恶意软件即使经过一定混淆，仍会在字节分布、局部纹理、节区结构、API 调用形态或熵分布上保留相似性。
- 将恶意软件映射为图像后，CNN、注意力网络、迁移学习模型等视觉模型能够自动学习这些相似性。
- 多通道表示比单通道灰度图能保留更多异质特征，例如局部字节、指令序列、字符串、熵值或节区信息。
- 图像化方法可降低人工特征工程依赖，但并不能天然解决数据偏置、概念漂移、对抗扰动和可解释性问题。
- 仅用静态图像表示不足以覆盖恶意行为全貌，未来更可靠的方向应融合动态行为、流量、日志和图像特征。

## 6. 科学方法与技术路线

论文归纳出的典型技术路线如下：

1. 样本采集：收集恶意软件与良性软件，来源包括 Malimg、MMCC、Drebin、Ember、AndroZoo、CICAndMal、VirusShare、阿里云天池数据集或研究者自建数据集。
2. 文件解析：根据平台选择 PE、`.bytes`、`.asm`、API 序列、`.dex`、Manifest、ELF、IoT 二进制或内存转储。
3. 图像化映射：将字节序列映射为灰度像素，将多个特征维度映射为 RGB 通道，或构建熵图、频谱图、马尔科夫转移图、空间填充曲线图。
4. 图像预处理与增强：统一尺寸、裁剪或填充、直方图均衡、颜色增强、旋转/翻转/亮度扰动、GAN 生成扩充、SMOTE/欠采样平衡类别。
5. 模型训练：使用传统机器学习、CNN、VGG、ResNet、EfficientNet、Transformer、BiLSTM、BiTCN、SNN、原型网络、集成模型等完成检测或家族分类。
6. 结果评估：关注准确率、召回率、F1、误报率、家族分类准确率、抗混淆能力、推理效率和资源开销。
7. 解释与鲁棒性分析：使用 Grad-CAM、LIME、SHAP、层相关传播等解释模型关注区域，并讨论对抗样本、混淆技术和概念漂移下的可靠性。

## 7. 实验设计与实验步骤

虽然本文是综述论文，没有提出一套单独的新实验，但它给出了可复核图像化恶意软件检测实验应遵循的完整流程。

- 数据：选择至少一个公开数据集作为主实验集，例如 Windows PE 任务可用 Malimg、MMCC、Ember；Android 任务可用 Drebin、AndroZoo、CICAndMal；IoT 任务可用 IoT_malware 或 VirusShare 子集。需要记录样本总数、家族数量、良恶性比例、最后更新时间。
- 预处理：按平台解析输入。Windows 可读取 PE 字节、`.bytes/.asm` 或 API 序列；Android 可解包 APK 并提取 `.dex`、Manifest 权限或 Dalvik 字节码；IoT/Linux 可读取二进制、ELF 或内存转储。随后映射为灰度图、RGB 图、熵图或马尔科夫图，并统一尺寸或使用保比例填充。
- 模型/基线：至少设置传统基线和深度基线。传统基线可包括 SVM、RF、KNN、朴素贝叶斯；深度基线可包括 CNN、VGG16、ResNet50、EfficientNet；若研究少样本，应加入 SNN、原型网络；若研究序列融合，应加入 LSTM/BiTCN。
- 训练：划分训练/验证/测试集，避免同一家族或同源变体泄漏到不同集合。类别不平衡时要对比原始训练、过采样、欠采样、SMOTE、GAN 增强等策略。迁移学习模型需说明预训练来源和微调层数。
- 指标：二分类任务报告准确率、召回率、精确率、F1、误报率；家族分类报告 macro-F1、weighted-F1、混淆矩阵；实际部署还应报告图像生成耗时、训练耗时、推理延迟和显存/内存占用。
- 消融/敏感性：比较灰度图与 RGB 图、单通道与多通道、固定尺寸与保比例缩放、是否使用熵特征、是否使用 API 序列、是否使用增强、不同图像尺寸、不同模型深度、不同类别不平衡比例。
- 结果核查：检查高准确率是否来自数据泄漏、重复样本、家族偏置或训练/测试分布过近；对加壳、混淆、重打包、动态加载样本单独评估；用 Grad-CAM/LIME/SHAP 查看模型是否关注有效区域，而不是学习到数据集噪声。

## 8. 关键结果、结论与证据

论文的关键结论是：图像化方法在恶意软件检测与家族分类中已经形成较成熟的研究谱系，尤其适合处理 PE 字节图、Android `.dex` 图和 IoT 二进制图，但它距离可靠工程部署仍有明显差距。

证据主要来自文中多张对比表。传统静态/动态方法在部分任务上可达到 95% 以上准确率，但多用于恶意检测而非细粒度家族分类，且抗高级混淆能力有限。机器学习方法在特征充足时表现较好，但依赖人工特征和数据质量。

图像化方法的结果普遍更高，许多基于 CNN、VGG、ResNet、EfficientNet、多通道图像、马尔科夫图和序列融合的方法在 Malimg、MMCC、DataCon、IoT_malware 等数据集上报告了 97% 到 99% 以上的分类准确率。尤其是多通道 RGB、马尔科夫转移图、API 调用可视化、序列与空间特征融合等方法，被认为比单纯灰度图能捕获更丰富的结构信息。

但论文也强调：这些高分数不应被直接等同于真实环境能力。很多数据集长期未更新，样本分布不平衡，家族差异可能明显，训练集与测试集可能共享相似变体。真正困难的问题是未知家族、少样本新变种、对抗扰动、实时检测和跨平台泛化。

## 9. 局限性与待解决问题

本文自身作为综述，局限在于它主要整合已有研究结论，并未统一复现实验，也没有在同一数据划分、同一硬件和同一评价指标下重新比较各方法。因此表中准确率只能说明各论文报告的结果，不能直接作为公平排名。

图像化方法本身的局限更加关键：

- 特征表示不足：二进制图像主要保留静态分布，难以完整表达运行时行为、触发条件、网络通信和环境依赖。
- 动态行为缺失：API 序列图像化能补充行为信息，但序列重组可能破坏调用语义。
- 数据集老化：Malimg、Drebin、MMCC 等常用数据集虽方便复现，但与当前恶意软件生态存在时间差。
- 类别不平衡：少数家族样本不足会使模型偏向多数类，单纯数据增强可能只是复制视觉变体，并不增加真实恶意行为多样性。
- 对抗攻击风险：攻击者可以通过填充字节、插入无效代码、重排节区或生成对抗扰动改变图像纹理。
- 可解释性不足：Grad-CAM、LIME、SHAP 能给出可视化解释，但解释质量依赖模型本身，且未必能对应可验证的恶意语义。
- 实时部署困难：图像转换、特征构造、多通道融合和深模型推理都会带来计算成本，资源受限 IoT 场景尤其明显。

## 10. 与本项目的关系

本项目粗分类为“其他AI安全与跨域异常检测”，与本文的关系属于弱相关但有借鉴价值。

弱相关之处在于，本文关注对象是恶意软件文件级检测与家族分类，而不是典型网络流量异常检测、日志异常检测或工业时序异常检测。它的输入形式、标签体系和攻击语义与一般异常检测任务不同。

有价值之处在于，本文提供了一种跨域异常检测思路：把非图像安全对象转换成视觉结构，再利用视觉模型学习模式差异。这种思想可以迁移到网络安全其他任务中，例如把流量序列、系统调用、日志事件、二进制协议载荷、进程行为图转换为图像或多通道矩阵，再做异常检测。

更重要的是，本文对数据集偏置、类别不平衡、概念漂移、可解释性和实时检测的讨论，与异常检测项目高度共通。如果本项目研究的是安全场景下的 AI 异常检测，这篇综述可作为“安全对象表征方式”和“视觉化异常检测路线”的参考文献，而不是核心算法来源。

## 12. 本篇精华

- 图像化恶意软件检测的核心不是“把文件画成图片”本身，而是利用视觉模型捕获字节分布、纹理、节区结构、熵分布和调用模式中的家族相似性。
- 传统静态分析快但怕混淆，动态分析语义强但成本高且怕沙箱规避，机器学习自动化程度高但依赖特征质量；图像化方法试图在自动特征学习和抗混淆之间取得平衡。
- Windows 研究重点在 PE、反汇编字节和 API 序列；Android 重点在 `.dex`、Dalvik 字节码和 Manifest；IoT/Linux 重点在二进制、ELF 和内存转储。
- 单通道灰度图是基础路线，多通道 RGB、马尔科夫图、熵图、频谱图和序列-空间融合是提升表达能力的主要方向。
- 高准确率结果需要谨慎解读，很多实验依赖老数据集、类别分布偏斜或相似变体，未必能代表真实新变种检测能力。
- 少样本和类别不平衡是恶意软件家族分类的核心障碍，SNN、原型网络、GAN、SMOTE 等方法能缓解但不能根治数据偏置。
- 未来真正关键的问题是多模态融合、对抗鲁棒、概念漂移、可解释性和实时部署，而不是继续在同一老数据集上刷新小幅准确率。
