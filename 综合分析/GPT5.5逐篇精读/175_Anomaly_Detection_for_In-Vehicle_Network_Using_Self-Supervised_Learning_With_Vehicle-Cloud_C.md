# [175] Anomaly Detection for In-Vehicle Network Using Self-Supervised Learning With Vehicle-Cloud Collaboration Update

## 1. 基本信息

- 论文：Anomaly Detection for In-Vehicle Network Using Self-Supervised Learning With Vehicle-Cloud Collaboration Update
- 作者：Jinhui Cao, Xiaoqiang Di, Xu Liu, Jinqing Li, Zhi Li, Liang Zhao, Ammar Hawbani, Mohsen Guizani
- 年份与来源：2024，IEEE Transactions on Intelligent Transportation Systems，Vol.25 No.7
- DOI：10.1109/TITS.2024.3351438
- 研究对象：车载网络 IVN 中 CAN 总线消息级异常检测
- 方法名称：IVNSL；核心模型为 MPMHit
- 数据集：Car Hacking Dataset
- 代码状态：本地未发现该论文对应开源代码包

## 2. 中文翻译与核心摘要

这篇论文关注智能网联汽车中车内 CAN 总线的异常检测问题。CAN 协议本身缺乏认证、加密和访问控制，外部联网能力增强后，攻击者一旦进入车载网络，就可以注入、篡改或伪造 CAN 报文。作者认为现有方法主要有三类不足：监督方法依赖大量标注数据，传统无监督方法往往只能判断窗口级异常，已有深度模型还会随时间发生概念漂移。

论文提出 IVNSL，把异常检测转化为“被遮蔽 CAN 消息预测”任务：如果模型能根据上下文正确预测某条消息，则认为它符合正常车载消息分布；如果预测失败，则视为异常。为提高预测能力，作者设计了 MPMHit，即层次化 Transformer 消息预测模型：第一层处理 CAN 消息内部的 ID 与 payload 物理信号结构，第二层处理消息序列之间的依赖关系。

另一个重要设计是车云协同更新。车辆端部署检测模型并监控输出概率分布的信息熵；当平均熵超过阈值时，认为模型可能发生概念漂移，请求云端使用新数据重训练模型，再下发新模型到车辆端替换旧模型。

实验在 Car Hacking Dataset 上进行，覆盖 DoS、Fuzzy、Gear spoofing、RPM spoofing 四类攻击。论文报告 IVNSL 在 F1-score、FNR、AUC 和推理延迟上优于多数基线，长度为 40 的消息序列下，整段检测耗时约 4.3 ms，单条消息平均约 0.1075 ms。

## 3. 论文解决的具体问题

论文解决的是 CAN 总线入侵检测中一个很具体的问题：在缺少标注攻击数据的情况下，如何做到消息级异常检测，并且让模型能适应正常通信分布随时间变化的问题。

这个问题比“窗口级异常检测”更难。窗口级方法只判断一段流量是否异常，但在车载安全场景中，系统更关心哪一条 CAN 报文异常，因为响应、隔离、溯源和 ECU 级联影响分析都需要消息粒度。论文明确批评已有无监督方法常常只看 CAN ID 序列，或者只看数据域片段，不能同时建模消息内部结构与消息间上下文。

它还针对概念漂移提出工程化补救：车载 ECU/边缘设备算力有限，不适合频繁本地训练，所以检测部署在车端，重训练放在云端，由熵触发更新。

## 4. 创新点深度提炼

第一，论文把 CAN 异常检测重新表述为自监督消息预测任务。它借鉴 BERT 式 masked language modeling，但预测对象不是自然语言 token，而是 CAN 消息类型。这个表述使模型可以用正常或近似正常消息序列生成训练监督信号，不需要人工标注攻击标签。

第二，MPMHit 的“层次化”不是简单堆 Transformer，而是分两级建模：先在消息内部提取 ID 与 payload 的空间结构，再在消息序列层面学习上下文依赖。这个设计对应 CAN 报文的实际结构：ID 决定消息类别和优先级，payload 携带车辆物理信号，序列上下文反映 ECU 周期通信规律。

第三，payload 没有被直接当作 64 bit 原始串暴力编码，而是引入 bit-flip rate 来切分物理信号边界。作者利用相同 CAN ID 连续消息中各 bit 翻转频率的数量级变化推断信号边界，试图降低 payload 编码维度，并保留物理信号粒度。

第四，异常判定采用 top-ε 预测排名，而不是固定概率阈值。若真实被遮蔽消息位于预测分布前 ε 个候选中，就判为正常，否则判为异常。这让检测标准更接近“上下文能否解释该消息”。

第五，论文把概念漂移纳入整体方案，而不只是离线实验。车辆端用 MPMHit 输出分布的信息熵作为漂移信号，熵过高意味着模型对正常消息不确定性升高，于是触发云端更新。

## 5. 科学问题与研究假设

核心科学问题是：CAN 报文序列中的正常通信是否具有足够稳定的上下文规律，使得一个自监督预测模型可以学到正常分布，并通过预测失败识别异常消息。

论文隐含了几条研究假设：

- 正常 CAN 消息不是独立出现的，而是强依赖上下文、周期、功能状态和 ECU 交互关系。
- 注入攻击、伪造攻击或模糊攻击会破坏这种上下文可预测性。
- CAN ID 与 payload 共同决定消息语义，只建模 ID 或只建模时间间隔都不足以识别复杂篡改。
- payload 中物理信号边界可通过 bit-flip rate 近似恢复，且这种恢复有助于深度模型学习。
- 当模型发生概念漂移时，输出概率分布会变得更不确定，信息熵会上升，因此熵可作为更新触发指标。

这些假设整体合理，但也存在强前提：训练数据必须主要代表正常分布；攻击消息必须足够扰动上下文或内容；信息熵升高必须能区分“正常工况变化”和“攻击扰动”。

## 6. 科学方法与技术路线

IVNSL 的技术路线可以概括为“遮蔽构造、自监督预测、排名判别、熵触发更新”。

首先，用滑动窗口构造长度为 n 的 CAN 消息序列。对序列中每个位置依次遮蔽，把被遮蔽消息替换为特殊 MASK 消息，ID 与数据域都设为 0。训练时，遮蔽序列作为输入，原始消息作为监督目标。

其次，MPMHit 对每条消息做内容编码。ID 通过前馈网络映射到 d 维向量；payload 先基于 bit-flip rate 切分为物理信号序列，再通过 Transformer 编码物理信号间关系，得到 payload 表征。ID 表征与 payload 表征相加后经线性层融合，得到消息内容向量。

再次，模型加入消息相对位置编码，将消息内容向量与位置向量相加，送入第二级 Transformer，学习窗口中消息之间的依赖关系。最终平均池化后接线性层和 softmax，输出所有消息类型的概率分布。

在线检测时，对窗口内每条消息逐个遮蔽并预测。如果真实消息不在 top-ε 预测集合中，则判为异常。车端继续计算多个遮蔽序列输出分布的平均信息熵，若超过阈值 δ，则请求云端更新模型。

## 7. 实验设计与实验步骤

1. 数据  
   使用 Car Hacking Dataset。数据包含一个正常 CAN 流量文件和四个攻击流量文件：DoS、Fuzzy、Gear spoofing、RPM spoofing。训练集由正常流量文件中的消息，以及四个攻击文件中的正常消息组成；测试集从四个攻击通信文件中各抽取 10000 条连续 CAN 消息。

2. 预处理  
   先按时间顺序形成 CAN 消息序列，再用滑动窗口构造固定长度序列。对每个窗口逐个位置生成 MASK 序列。对 payload，按相同 CAN ID 的连续消息计算各 bit 翻转率，再通过翻转率数量级变化推断物理信号边界，形成物理信号序列。

3. 模型与基线  
   主模型是 IVNSL/MPMHit。基线包括传统方法 OTIDS、SAIDuCANT，监督深度方法 Amato 等的 Supervision，非监督或自监督深度方法 MT-LSTM、Song and Kim 的 Self-Supervision。比较维度包括检测精度、误报/漏报、阈值敏感性和效率。

4. 训练  
   训练阶段不使用攻击标签。遮蔽后的消息序列作为输入，原始消息作为预测目标，通过交叉熵式分类目标训练消息预测模型。模型实现环境为 PyTorch，硬件为 Xeon W-2123、TITAN Xp、64GB RAM，Ubuntu 18.04.5。

5. 指标  
   使用 Precision、Recall、F1-score、FNR、FPR/ROC-AUC。论文尤其强调 FNR，因为车载安全中漏检攻击消息风险更高。效率部分统计序列级检测时间和单消息平均检测时间。

6. 消融/敏感性  
   论文没有给出严格模块消融，如去掉 payload 编码、去掉 ID 编码、去掉层次 Transformer 的对照。它主要用 AUC 展示 top-ε 阈值不敏感性，并用不同序列长度测试效率变化。严格来说，结构贡献的因果证据不足。

7. 结果核查  
   需要重点核查四类攻击上 Precision、Recall、F1-score、FNR 与 AUC 是否一致。文中报告 DoS 与 Fuzzy 的 F1-score 达 100%，Gear spoofing 与 RPM spoofing 也接近满分。AUC 分别为 0.9923、0.9999、0.9961、0.9999。效率上，窗口长度 40 时整段约 4.3 ms，单消息约 0.1075 ms。

## 8. 关键结果、结论与证据

论文最重要的结果是 IVNSL 能在无人工标签前提下实现消息级检测，并在四类攻击上取得高 F1-score 和低 FNR。

在 DoS 攻击上，IVNSL Precision、Recall、F1-score 都达到 100%。这符合 DoS 注入高频 ID 0x00 消息会显著破坏正常序列上下文的直觉。

在 Fuzzy 攻击上，IVNSL 也报告 100% F1-score。随机 CAN ID 和 payload 与正常消息分布差异大，因此基于 ID、payload 和上下文联合建模的方法天然占优。

在 Gear spoofing 和 RPM spoofing 上，攻击消息使用与车辆功能相关的 CAN ID，更接近正常通信，因此更考验模型对 payload 与上下文的联合理解。论文报告 IVNSL 的 Recall 分别约 99.34% 和 100%，说明模型对伪造功能消息仍有较强识别能力。

效率方面，论文认为车载 CAN 约每秒 2000 条消息，而 IVNSL 在序列长度 40 时可推理约 9302 条消息/秒，因此满足实时检测需求。这个结论建立在 TITAN Xp GPU 实验环境上，迁移到真实车载硬件时仍需重新验证。

## 9. 局限性与待解决问题

第一，论文没有提供充分消融实验。MPMHit 同时包含 bit-flip 物理信号切分、ID 编码、payload Transformer、消息级 Transformer、top-ε 判别。没有逐项拆除对比，很难判断性能提升主要来自哪一部分。

第二，概念漂移更新机制更多是方案设计和可行性讨论，缺少真实长期车载数据上的漂移实验。熵阈值 δ 如何设定、误触发频率、云端更新周期、新旧模型切换风险，都没有被充分实证。

第三，实验数据集较单一。Car Hacking Dataset 是经典基准，但攻击类型和车辆场景有限。真实 IVN 中不同车型、不同驾驶状态、诊断模式、OTA 更新、ECU 老化都可能改变正常分布。

第四，论文的“云端实时上传与训练”假设偏乐观。虽然单条 CAN 消息很小，但实际车云链路还涉及认证、加密、丢包、隐私、成本和监管要求，不能只按 5G 理论上传速率估算。

第五，文中结果表述存在小不一致：摘要称平均 F1-score 比最佳基线高 2.282%，正文又写 2.82%；摘要提到 false positive rates 降低 1.595%，正文 Fig.9 附近讨论的是 FNR 降低 1.595%。复核 PDF 图表和原始数值时应特别注意。

第六，本次正文包标注为未截断，因此理解不受截断影响；但由于未提供配套代码，无法从实现层面验证模型细节、超参数、训练划分和评估脚本。

## 10. 与本项目的关系

这篇论文与“入侵检测与网络异常检测、IoT、车联网、工业互联网与边缘安全”高度相关。它的价值不只在车载 CAN 场景，也在于提供了一种通用范式：把工业/边缘网络异常检测转化为自监督上下文预测。

对本项目有三点直接启发：

- 如果目标系统缺少标签，可以优先考虑 masked prediction、next-event prediction 或 denoising prediction，而不是强行构造攻击标签。
- 对协议数据建模时，应同时处理字段内部结构和序列上下文，不能只依赖时间间隔或统计频率。
- 对长期部署的异常检测模型，需要把概念漂移检测和模型更新机制纳入系统设计，而不是只报告离线测试精度。

如果本项目涉及车联网或工业控制网络，可以借鉴其“边缘检测、云端重训练、熵触发更新”的架构，但需要补充安全通信、模型签名、回滚机制和更新验证。

## 11. 代码对照分析

本地未发现该论文对应的开源代码包，因此不能给出真实文件级对应关系，也不能确认作者实现是否与论文公式完全一致。

若复现该论文，合理的代码目录应至少包含以下模块：

- 数据预处理：读取 Car Hacking Dataset，解析 timestamp、CAN ID、DLC、payload、label；构造固定长度滑动窗口；区分训练正常消息与测试攻击消息。
- MASK 构造：对窗口中每个位置生成遮蔽序列，MASK 的 ID 与 payload 置 0，保存原始消息类别作为预测目标。
- bit-flip 物理信号切分：按 CAN ID 聚合同类消息，计算 payload 每一 bit 的翻转率和数量级数组，根据相邻 bit 翻转率变化确定信号边界。
- 模型文件：实现 MPMHit，包括 ID feed-forward encoder、physical signal Transformer encoder、message Transformer predictor、position encoding、pooling 与 softmax 分类头。
- 训练脚本：自监督训练循环、loss、optimizer、窗口长度、embedding 维度、Transformer 层数、head 数、batch size 等超参数。
- 评估脚本：实现 top-ε 异常判定，输出 Precision、Recall、F1-score、FNR、FPR、AUC，并按四类攻击分别统计。
- 在线更新模拟：计算输出分布平均信息熵 q̄，与阈值 δ 比较，模拟触发云端重训练和模型替换。

需要注意，论文中的“消息类型 |T|”实现细节很关键：到底是仅以 CAN ID 作为类别，还是 ID 与 payload/信号组合后的类别，正文表述并不完全清晰。复现时必须回到公式、数据标签和预测目标定义仔细确认。

## 12. 本篇精华

- IVNSL 的核心思想是：正常 CAN 消息应能被上下文预测，预测失败即异常。
- 论文把无标签 CAN 入侵检测推进到消息级，而不是只判断窗口级异常。
- MPMHit 用层次 Transformer 分别建模消息内部结构和消息间依赖，契合 CAN 数据的协议特点。
- payload 处理引入 bit-flip rate 推断物理信号边界，试图避免直接编码 64 bit 原始数据带来的高维问题。
- top-ε 预测排名判别比单一概率阈值更贴近“该消息是否符合上下文”的检测逻辑。
- 车云协同更新是论文区别于普通离线 IDS 的系统亮点，但实验验证仍偏弱。
- 实验在 DoS、Fuzzy、Gear/RPM spoofing 上取得接近满分的结果，但数据集单一和消融不足限制了说服力。
- 对综述而言，这篇可归入“自监督序列预测式车载 IDS + 概念漂移适应”代表工作。
