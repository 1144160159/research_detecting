# [622] CAN Bus Intrusion Detection Based on Deep Learning With Data Augmentation for Connected Autonomous Vehicles

## 1. 基本信息

- 论文题名：CAN Bus Intrusion Detection Based on Deep Learning With Data Augmentation for Connected Autonomous Vehicles
- 作者：Xiang Wang, Jian Zhao, Pengbo Liu, Nianmin Yao, Zheng Xu
- 来源：IEEE Transactions on Vehicular Technology
- DOI：10.1109/TVT.2025.3603056
- 发表时间：2025 年在线发表，卷期版本为 2026 年 2 月
- 主题归类：车载 CAN 总线入侵检测、异常检测、数据增强、深度学习、车联网安全
- 核心任务：在攻击样本极少、车辆 CAN 协议私有、车端资源受限的条件下，检测 CAN 总线中的注入、DoS、重放、丢弃、篡改攻击。

## 2. 中文翻译与核心摘要

这篇论文提出了一个面向车载 CAN 总线的预测式入侵检测框架。作者认为，CAN 总线缺少认证和加密机制，攻击者一旦通过 OBD-II、无线入口或被攻陷网关接入车内网络，就可能注入、重放、阻塞或篡改关键控制报文。深度学习 IDS 虽然能学习复杂模式，但车载场景里攻击样本稀缺，训练集严重不平衡，导致模型容易偏向正常类，对少见攻击尤其是篡改攻击识别不足。

论文的方案由两个部分组成：一是基于 WGAN-GP 的数据增强模块，用 CAN ID 和 payload 的位级/one-hot 图像表示生成攻击样本，以平衡训练集；二是 LSTM-CNN 预测模块，其中 CNN 学习连续 CAN ID 序列之间的空间/关联关系，LSTM 针对每个 CAN ID 的 payload 时间序列学习时序变化规律。作者进一步制作了一个 CAN 总线入侵检测设备，可连接真实车辆 OBD-II，并在 PC、APEX AD10、GEACX2 两类域控制器平台上测试。

论文报告的总体效果很高：平均 Accuracy 为 99.78%，平均 F1-score 为 99.74%；相对参考工作，F1-score 提升 15.25%，检测时间降低 29.11%。更重要的是，论文把“攻击样本少”和“车端实时约束”两个现实问题放在同一个框架里处理，而不是只追求离线分类精度。

## 3. 论文解决的具体问题

论文要解决的不是泛泛的 CAN 入侵检测，而是一个更具体的工程-学习耦合问题：

1. CAN 报文本身缺少安全机制  
   CAN 是广播总线，报文没有内建认证、加密和发送者身份验证。攻击者只要接入总线，就可能伪造合法 ID 报文，利用仲裁机制发起 DoS，或重放历史报文。

2. 车载攻击数据难以获得  
   真实车辆上进行攻击采集存在安全风险；不同厂商、车型的 CAN ID 和 payload 编码私有；即使同一车型，驾驶习惯、道路状态、工况也会影响报文分布。因此训练集中正常样本远多于攻击样本。

3. 不平衡数据导致深度模型偏置  
   如果直接用深度模型训练，模型容易学到“多数正常类”的决策边界，对少数攻击尤其是低频、隐蔽、接近正常语义的攻击识别能力不足。

4. 传统统计方法对低强度攻击不够敏感  
   基于周期、频率、熵、滑动窗口统计的方法对 DoS 等高流量扰动有效，但对重放、丢弃、篡改这类不一定显著改变流量统计特征的攻击，存在天然弱点。

5. 车端部署要求低延迟和小资源占用  
   IDS 不能只在离线 GPU 上好看，还需要在车载网关、域控制器或嵌入式设备上实时运行。论文将平均检测时间作为关键指标，并进行了真实车辆和域控制器测试。

## 4. 创新点深度提炼

1. 用 WGAN-GP 缓解 CAN 攻击样本稀缺  
   论文没有采用简单过采样，而是用 WGAN-GP 学习 CAN 报文图像表示的分布，生成用于训练的攻击样本。相比 SMOTE、ADASYN，WGAN-GP更适合捕捉非线性、高维、结构化的报文分布。

2. 把 CAN ID 关联性和 payload 时序性拆成两个检测分支  
   CNN 分支处理连续 CAN ID 构成的图像，关注不同 ECU 报文之间的协同关系；LSTM 分支处理同一 CAN ID 下 payload 的时间序列，关注具体物理信号的周期、范围和变化趋势。这个拆分符合 CAN 网络的实际结构。

3. 直接处理 CAN ID 与 payload 的位级表示  
   方法不依赖厂商私有 DBC 文件，也不要求先逆向解析每个 payload 字节对应的真实物理含义。这一点提高了跨车型迁移的可操作性，但也带来语义解释不足的问题。

4. 同时覆盖离线仿真、公开数据和真实车辆在线检测  
   论文不仅在公开数据和 CANOE 仿真数据上评估，还设计了实际检测设备，并在 RAV4、Volkswagen、Dongfeng 相关平台上做了测试，增强了工程可信度。

5. 将数据增强效果单独剥离验证  
   作者比较了不同攻击样本比例下的检测效果，也比较了 WGAN-GP、普通 GAN、SMOTE、ADASYN，说明性能提升不只是模型结构带来的，也来自训练分布改善。

## 5. 科学问题与研究假设

论文背后的科学问题可以概括为：

1. 在攻击样本极少的 CAN 总线场景中，生成式数据增强能否有效提升 IDS 对攻击类的识别能力？
2. CAN 报文是否同时存在跨 ID 的空间关联和同 ID payload 的时间关联，并且这些关联能否用于异常检测？
3. 不解析厂商私有信号语义，仅使用 CAN ID 与 payload 的位级表示，是否足以建立高性能入侵检测模型？
4. 深度学习 IDS 是否能在车端资源受限环境中达到可接受的实时性？

对应研究假设包括：

- 假设 1：WGAN-GP 生成的攻击样本能逼近真实攻击样本的统计分布，从而缓解训练集类别不平衡。
- 假设 2：正常 CAN 流量中，不同 ECU 报文之间存在稳定协作关系，攻击会破坏这种跨 ID 关联。
- 假设 3：同一 CAN ID 的 payload 是具有周期性和连续性的时间序列，篡改、重放、丢弃等攻击会破坏该时序规律。
- 假设 4：轻量 CNN 与 LSTM 的组合可以在精度和实时性之间取得较好平衡。

## 6. 科学方法与技术路线

论文技术路线可以分成四层。

第一层是特征表示。作者从 CAN 报文中抽取 timestamp、CAN ID 和 8 字节 payload。11-bit CAN ID 被转成 one-hot/位级图像表示，payload 的 64-bit 内容也被转成图像表示。连续 64 个 CAN ID 拼接成 CAN ID image；同一 ID 的连续 256 个 payload 拼接成 CAN payload image。

第二层是数据增强。作者训练两个 WGAN-GP：一个面向 CAN ID 图像，学习不同 ECU/ID 的报文关联；另一个面向 payload 图像，学习同一 ID 下时序 payload 的变化结构。WGAN-GP 用 Wasserstein 距离和梯度惩罚改善普通 GAN 的训练不稳定问题。

第三层是检测模型。CNN 分支输入 CAN ID 图像，用多层卷积和全连接层判断跨 ID 报文序列是否异常；LSTM 分支输入按 ID 分类的 payload 时间序列，判断当前报文内容是否符合该 ID 的历史变化规律。任一分支检测到异常，即可触发告警。

第四层是工程验证。作者在 CANOE 仿真环境、公开数据集和真实车辆环境中测试模型，并制作了一个包含 CAN 接收模块、攻击发送模块和板载计算模块的检测设备。真实车辆实验中还将模型移植到 APEX AD10 与 GEACX2 域控制器上。

## 7. 实验设计与实验步骤

可复核流程如下：

1. 数据  
   使用两类数据：公开车载 CAN 入侵数据，包括 Renault Clio 和 Opel Astra 两辆车的真实数据，覆盖 injection、DoS、replay、drop、tampering 五类攻击；另一路是 CANOE 仿真数据，仿真 engine、gateway、NM_Tester_PT 等 ECU，以 500 kbps 生成 CAN 流量。

2. 预处理  
   按时间顺序整理 CAN 报文，抽取 CAN ID 和 8 字节 payload。CAN ID 转成宽度为 48 的图像表示，payload 转成宽度为 256 的图像表示。CAN ID 使用连续 64 帧拼接，payload 使用同一 ID 的连续 256 条消息拼接。测试时使用滑动窗口，初始化完成后每来一条新报文更新窗口并输出检测结果。

3. 模型与基线  
   提出模型为 WGAN-GP + LSTM-CNN。基线包括 OCSVM、iForest、LSTM-AE，并与 GPIDS、X-CANIDS、CanNet 等已有方法比较。数据增强方法对比包括普通 GAN、SMOTE、ADASYN。

4. 训练  
   先训练 WGAN-GP 生成攻击样本，再将公开数据、仿真数据、生成数据组合成增强训练集。预测模块用增强后的数据训练 CNN 和 LSTM。超参数通过 Tree-structured Parzen Estimator 搜索，训练中使用 early stopping 减少过拟合。

5. 指标  
   主要指标包括 Accuracy、Precision、Recall、F1-score、模型内存占用、平均每帧检测时间。真实车辆实验还统计窗口初始化时间、消息采集时间和不同硬件平台上的检测延迟。

6. 消融/敏感性  
   论文做了三类关键分析：图像尺寸敏感性，最终选择 CAN ID image 为 48×64、payload image 为 256×256；攻击样本平衡比例敏感性，从 0% 增加到 50%；数据增强方法对比，验证 WGAN-GP 优于 GAN、SMOTE、ADASYN。

7. 结果核查  
   对生成样本，论文用特征分布图和字节统计范围验证其与攻击数据相似但不完全等同。对检测模型，核查五类攻击下的分类指标。对工程部署，核查 PC、APEX AD10、GEACX2 上的延迟与准确率是否接近离线结果。

## 8. 关键结果、结论与证据

论文最核心结果是：所提方法平均 Accuracy 达到 99.78%，平均 F1-score 达到 99.74%。相较参考方法，F1-score 提升 15.25%，检测时间降低 29.11%。

数据增强带来的收益非常明显。LSTM-CNN 在未使用生成数据时准确率为 63.74%，使用增强数据后提升到 99.78%；LSTM-AE 从 60.48% 提升到 90.82%。这说明论文的关键贡献不是单纯换了一个分类器，而是训练数据分布被显著修正。

不同攻击中，DoS 最容易检测，因为高优先级 0x000 报文高频注入会明显扰动总线流量。篡改攻击最难，因为攻击报文可能使用合法 ID，payload 也可能落在合理范围附近，只是在时序、上下文或物理语义上异常。即便如此，论文报告篡改攻击检测准确率仍超过 99%。

效率方面，离线平均检测时间为 0.56 ms；真实车辆/嵌入式平台上，PC 为 0.82 ms，APEX AD10 为 1.12 ms，GEACX2 为 1.14 ms。平均窗口初始化时间为 26.05 ms，平均消息采集时间为 0.42 ms。作者据此认为该方法适合车载实时检测。

## 9. 局限性与待解决问题

1. 生成样本是否真正代表未知攻击仍需更强验证  
   论文用分布图和字节统计说明生成数据接近攻击数据，但这还不足以证明生成样本覆盖真实攻击空间。尤其是篡改攻击涉及物理语义，位级相似不等于行为语义合理。

2. “用正常数据训练 WGAN-GP 生成攻击数据”的逻辑表述存在疑问  
   文中有一处说 WGAN-GP 可用正常数据训练来生成攻击数据，这在机制上需要更清楚解释：如果没有攻击分布，生成器如何学习攻击特征？更合理的理解可能是利用已有少量攻击样本和正常边界信息进行增强，但论文表述不够严谨。

3. 对跨车型泛化的证明仍有限  
   虽然论文强调不依赖 DBC 和私有规范，且测试了多辆车/平台，但不同车型 CAN ID 集合、周期、payload 编码差异很大。模型是否能不重新训练或少量微调就迁移到新车型，仍未充分回答。

4. 真实车辆实验处于 standby 状态  
   真实车辆测试主要在静止/待机状态下进行，信号种类包括门锁、车灯、雨刷等。高速行驶、复杂驾驶工况、驾驶员操作扰动下的实时检测表现仍需验证。

5. 对误报成本讨论不足  
   车载 IDS 的误报可能影响驾驶体验甚至触发错误防护策略。论文报告了高精度指标，但对误报场景、误报告警处理、与车控安全策略的联动讨论不够。

6. 检测后响应机制缺失  
   论文主要解决“发现异常”，没有深入讨论检测到攻击后如何隔离 ECU、过滤报文、降级控制或进行安全恢复。

7. UART 通信瓶颈限制设备适用性  
   作者也承认，随着 CAN-FD 超过 1 Mbps 的应用增加，当前检测设备中 UART 转发 CAN 消息可能成为瓶颈。

## 10. 与本项目的关系

这篇论文与“入侵检测与网络异常检测”高度相关，尤其适合支撑车联网、IoT、工业互联网和边缘安全方向的综述或方法设计。

对本项目最有价值的启发有三点。第一，它把异常检测中的类别不平衡问题放到了车载安全真实约束下处理，可作为“小样本攻击检测/不平衡异常检测”的代表案例。第二，它展示了如何将原始协议字段转成深度模型可处理的结构化表示，而不依赖私有语义解析。第三，它将检测精度、检测延迟、模型占用和真实硬件部署同时评估，适合作为边缘 IDS 工程化验证的参考。

如果本项目关注跨域异常检测，这篇论文可归入“协议原始字段 + 时序关联 + 生成式增强”的路线。若进一步扩展，可比较 CAN、工业 Modbus、车联网 V2X、IoT MQTT 等协议在字段语义私有、攻击样本稀缺、时序强相关方面的共性。

## 12. 本篇精华

1. 论文的中心问题是车载 CAN IDS 中“攻击样本稀缺 + 数据不平衡 + 实时部署”的组合难题，而非单纯离线分类。
2. 方法核心是 WGAN-GP 数据增强加 LSTM-CNN 检测：前者补足攻击样本，后者分别学习跨 ID 关联和同 ID payload 时序规律。
3. 直接使用 CAN ID 与 payload 位级表示，绕开厂商 DBC 私有语义，增强了跨车型适配潜力。
4. 数据增强贡献非常大：LSTM-CNN 准确率从 63.74% 提升到 99.78%，说明少数类攻击分布补全是性能关键。
5. DoS 最容易检测，篡改最难检测，这符合 CAN 攻击的物理直觉：篡改可能保留合法 ID 和近似合法 payload。
6. 论文不仅做离线实验，还设计了真实 CAN 检测设备，并在域控制器平台上验证延迟，工程完整度较高。
7. 最大疑点是生成攻击样本的真实性和跨车型泛化能力，尤其是生成样本是否覆盖真实语义攻击空间。
8. 对综述写作而言，这篇论文可作为“生成式数据增强用于车载 IDS”的强相关代表工作。

## 13. 建议精读路线

建议先读 Introduction 和 Method，抓住作者为什么把数据不平衡视为 CAN IDS 的核心瓶颈，以及为什么将 CNN 与 LSTM 分工处理。然后重点看 Feature Extraction，确认 CAN ID 和 payload 如何被图像化，这是理解后续 WGAN-GP 与 CNN 的关键。

第二步精读 Data Augmentation Analysis 和 Comparison to Other Algorithms。这里能看出 WGAN-GP 相比 GAN、SMOTE、ADASYN 的实际收益，也能判断论文性能提升到底来自模型结构还是数据增强。

第三步读 Efficiency Evaluation 和 Intrusion Detection Equipment。重点关注 0.56 ms、0.82 ms、1.12 ms、1.14 ms 这些延迟指标，以及窗口初始化时间是否会影响真实部署。

最后回到局限性思考：生成攻击数据是否可信、standby 状态实验是否足够、跨车型是否真的容易、检测之后如何响应。这些问题很适合写入后续综述的批判性分析部分。
