# [528] RT-APT: A real-time APT anomaly detection method for large-scale provenance graph

## 2. 中文翻译与核心摘要

这篇论文提出 RT-APT，一个面向大规模溯源图的实时 APT 异常检测方法。它的基本思路不是写攻击规则，也不是依赖已知攻击样本训练分类器，而是从内核日志构造系统溯源图，学习“正常系统执行状态”的长期行为模式；部署时，只要当前系统状态无法落入正常状态簇，或状态转移不符合训练阶段学到的正常演化过程，就判为异常。

方法链条可以概括为：

1. 使用 SPADE 采集 Linux 内核级日志。
2. 将日志转成节点和边，构造进程、文件、网络连接等实体之间的溯源图。
3. 用 WL subtree graph kernel 聚合节点多跳邻域上下文，把溯源图转为直方图式表示。
4. 用 FlexSketch 将持续增长的流式直方图压缩成定长 graph sketch。
5. 用 K-means 对良性 graph sketch 序列聚类，每个簇代表一种正常系统状态。
6. 测试时根据 sketch 到簇中心的距离和状态转移合法性检测异常。

论文的核心观点是：APT 的难点在于长期、隐蔽、低频和攻击样本稀缺，因此检测系统应建模长期正常行为，而不是只识别短片段攻击特征或手工规则。

## 3. 论文解决的具体问题

论文瞄准的是主机侧 APT 检测中的三个实际痛点。

第一，规则方法泛化性不足。SLEUTH、HOLMES、Poirot、APTSHIELD 等方法依赖专家规则、威胁情报或图模式匹配，对已知攻击解释性强，但面对 0-day、攻击变体或环境变化时维护成本高。

第二，短序列模型难以覆盖 APT 的长期行为。APT 攻击链可能跨越数小时甚至数天，攻击事件之间夹杂大量正常活动。只看局部系统调用或短窗口行为，容易漏掉长期因果关系，也容易被模仿攻击规避。

第三，大规模溯源图的实时处理压力大。完整保存和比较图结构成本很高；持续更新节点嵌入又会遭遇内存、CPU 和概念漂移问题。RT-APT希望在“保留长期上下文”和“实时低开销”之间取得平衡。

## 4. 创新点深度提炼

第一，论文把 APT 检测明确转化为“正常系统状态序列建模”问题。它不要求攻击样本完备，也不把攻击检测做成已知类别分类，而是通过正常行为簇与状态转移来识别未知异常。

第二，WL subtree kernel 被用于溯源图上下文聚合。它通过多轮邻域标签传播，把进程、文件、网络节点及其因果邻域压缩进节点标签和图直方图中。相比只看边类型或节点频率，它能表达“某个行为发生在什么因果上下文里”。

第三，FlexSketch 负责把不断增长的直方图转成定长流式表示。这个设计针对的是大规模流式溯源图：直方图维度未知且持续增长，直接比较稀疏高维直方图不可行，sketch 则提供了低维、可增量更新、近似保持相似性的表达。

第四，论文强调概念漂移下的“忘旧保因果”。衰减参数 α 使旧数据影响逐渐降低，但只要历史事件与当前操作仍存在因果联系，其邻域信息仍会影响当前图特征。这一点对 APT 很关键，因为攻击链早期事件可能很久之后才与数据窃取动作形成可见关联。

第五，实验不仅看准确率，也比较运行速度、内存和 CPU。RT-APT 的定位不是离线取证工具，而是主机运行时检测系统，因此开销指标是论文论证的重要部分。

## 5. 科学问题与研究假设

论文背后的科学问题可以表述为：

- 如何在没有充分攻击样本的条件下，利用系统溯源图检测未知 APT 行为？
- 如何从长时间、噪声很大的系统日志中提取足以区分正常与异常的因果上下文？
- 如何让溯源图检测在大规模、流式场景下保持实时性？
- 正常系统行为是否可以被表示为有限个稳定状态及其转移模式？

核心研究假设包括：

- APT 行为虽然隐蔽，但最终会引入正常场景中罕见的因果结构，例如敏感文件读取、提权脚本修改、异常网络传输等。
- WL 多跳邻域聚合能够把这些罕见因果结构反映到图特征分布中。
- 正常系统执行不是完全随机的，而是可以被若干系统状态簇近似表示。
- 攻击行为会表现为远离正常簇中心，或造成正常状态机中不存在的状态转移。
- 使用 FlexSketch 后，压缩表示仍能保留足够的相似性信息，同时满足实时处理需求。

## 6. 科学方法与技术路线

RT-APT 的技术路线是“日志采集 -> 溯源图 -> 图上下文直方图 -> 流式 sketch -> 正常状态聚类 -> 异常检测”。

日志采集阶段，SPADE 记录 Linux 主机内核级活动，节点包括进程、文件、网络连接等，边表示读、写、执行、连接等交互。论文选择 SPADE 的理由是内核级日志更接近完整信息流，适合捕捉 APT 长链条中的因果依赖。

图特征阶段，WL subtree kernel 对每个节点进行多轮邻域标签扩展。第 r 轮标签包含 r-hop 邻域信息，标签频率形成图直方图。论文最终选择 k-hop=3，认为此时上下文信息足够，超过后可能引入无关上下文并稀释攻击信号。

流式处理阶段，FlexSketch 用局部敏感哈希和一致加权采样思想，把高维动态直方图压缩成固定长度向量。相似图在 sketch 空间中仍应接近。论文还引入衰减率 α，让模型更关注当前系统状态和与当前状态存在因果关系的历史信息。

异常检测阶段，K-means 在训练集良性 sketch 序列上聚类。每个簇被解释为系统执行状态，例如启动、初始化、稳定运行等。测试时，如果当前 sketch 到所有正常簇的距离超过阈值，或状态转移不合法，则判为异常。

## 7. 实验设计与实验步骤

可复核流程如下。

数据：

- Laboratory dataset：作者自建，Ubuntu 16.04 + SPADE。包括 3 类攻击 T-1/T-2/T-3 和 5 类良性 B-1 到 B-5。
- T-1：Apache Webshell 攻击。
- T-2：钓鱼网站诱导下载远控木马。
- T-3：利用脆弱服务触发溢出的 fileless attack。
- StreamSpot dataset：5 类良性活动和 1 类 drive-by download 攻击，每类 100 个图。
- Unicorn dataset：两个供应链攻击场景 SC-1、SC-2，每个场景包含良性和攻击图。

预处理：

- 用 SPADE 或已有预处理数据获得节点、边。
- 构造异构溯源图，节点表示进程、文件、网络等实体，边表示系统事件。
- 按流式边/节点到达顺序持续更新图。
- 用 WL subtree kernel 生成多跳标签直方图。

模型与基线：

- RT-APT：WL subtree kernel + FlexSketch + K-means。
- 基线：StreamSpot、Unicorn。
- 论文也讨论了 DBSCAN、层次聚类、GMM，但主实验采用 K-means。

训练：

- 在 Laboratory 和 StreamSpot 上，使用 80% 良性图训练，剩余 20% 良性图与攻击图测试。
- 在 Unicorn 上，对 125 个良性图做 5 折交叉验证，每次 100 个良性图训练，25 个良性图测误报，再用 25 个攻击图测漏报。
- 用轮廓系数选择聚类数，最终 K=6。
- 用 PR 曲线选择测试阈值。

指标：

- Precision、Recall、Accuracy、F-score。
- 性能指标包括平均边处理速度、内存开销、CPU 使用率。

消融与敏感性：

- k-hop：最佳为 3。
- sketch-size：最佳为 2000。
- Interval：按边触发时最佳为 3000，按节点触发时最佳为 500。
- decay rate α：最佳为 0.03。

结果核查：

- 检查 RT-APT 是否在三类数据集上均优于或接近 SOTA。
- 检查最优参数下处理速度是否接近 SPADE 采集速度。
- 检查内存和 CPU 是否低于 StreamSpot、Unicorn。
- 特别关注 Laboratory 表 6 中 accuracy：RT-APT 为 0.94，而 Unicorn 为 0.97；这说明 RT-APT 并非所有指标都绝对领先，论文更强的证据在 precision、recall、F-score 及运行开销上。

## 8. 关键结果、结论与证据

参数实验显示，k-hop=3 时 precision、recall、accuracy 最好。论文给出的解释是 3-hop 能捕获足够因果上下文，继续扩大邻域会混入无关行为，降低攻击信号辨识度。

在 Laboratory 数据集上，RT-APT 的 precision=0.98、recall=0.96、F-score=0.97，高于 StreamSpot 和 Unicorn；但 accuracy=0.94，低于 Unicorn 的 0.97。这一点需要如实看待：RT-APT 在攻击识别相关指标上更强，但总体准确率并非该表最高。

在 StreamSpot 数据集上，RT-APT 的 precision=0.96、recall=0.94、accuracy=0.95、F-score=0.95，整体接近或优于 Unicorn，明显优于 StreamSpot baseline。论文认为原因是 RT-APT 的多跳图上下文和流式 sketch 更适合提取长期行为差异。

在 Unicorn 数据集上，RT-APT 在 SC-1 和 SC-2 两个场景均优于 StreamSpot 和 Unicorn。尤其 SC-2 中 RT-APT 的 precision=0.84、recall=0.88、accuracy=0.86、F-score=0.85，高于 Unicorn 的 0.75/0.80/0.77/0.78。

运行开销方面，RT-APT 在最优参数下处理速度与 inline baseline 差距约 1% 左右；平均内存约 588-609 MB，低于 StreamSpot 和 Unicorn；CPU 使用率约 16.9%-18.6%，总体较稳定。

论文的结论是：RT-APT 能在不依赖攻击规则和攻击样本完备性的前提下，对长周期 APT 行为进行实时异常检测，并在准确性和开销之间取得较好平衡。

## 9. 局限性与待解决问题

第一，RT-APT 依赖“训练阶段是干净良性环境”的假设。如果训练数据已经被潜伏攻击污染，正常模型会被毒化。论文提到部署时不动态建模，就是为了避免长期 APT 注入后污染模型，但这也意味着模型更新机制仍不充分。

第二，异常检测天然存在误报问题。企业真实环境中的新软件安装、系统升级、运维脚本、批处理任务可能与训练期不同，被误判为异常。论文虽然强调应收集尽可能多的良性场景，但没有给出跨组织迁移时的系统化处理方案。

第三，参数敏感性仍然存在。k-hop、sketch-size、Interval、α 都需要调参；论文在实验环境中找到最优值，但不同主机负载、业务类型、日志粒度下是否稳定，仍需更多验证。

第四，FlexSketch 的近似压缩可能丢失细粒度攻击证据。它适合检测“是否异常”，但未必能直接定位恶意节点、恶意边或攻击路径。对安全运营而言，告警后的解释和溯源仍是关键问题。

第五，论文对 K-means 状态转移建模的细节交代略粗。它说可检测“不属于已有簇”和“非法状态转移”，但状态转移图如何构造、阈值如何确定、并发多任务系统中状态混杂如何处理，仍需要复核实现或补充材料。

第六，自建 Laboratory dataset 虽然贴近 APT kill chain，但攻击类型仍有限。Webshell、钓鱼木马、fileless 攻击覆盖了一部分典型路径，但不能代表全部 APT 技术组合。

## 10. 与本项目的关系

这篇论文与“异常检测”项目的关系是中等偏高，尤其适合放在“溯源图 + 流式异常检测 + APT”方向中。

它对本项目有三点直接参考价值：

- 如果项目关注主机侧异常检测，RT-APT 提供了从内核日志到溯源图再到状态异常检测的完整路线。
- 如果项目关注大规模图学习，它展示了一种非 GNN 路线：WL graph kernel + sketch + 聚类，计算成本更低，可解释性也比端到端嵌入更强。
- 如果项目关注未知攻击检测，它的正常行为建模思路比监督分类更适合攻击样本稀缺场景。

不过，若本项目目标是精确攻击溯源、攻击路径还原或告警解释，RT-APT 还不够完整，需要与路径回溯、节点风险评分、ATT&CK 技术映射等模块结合。

## 11. 代码对照分析

本次材料明确说明未发现该论文对应的本地开源代码，因此不能逐文件对应真实实现。

如果按论文方法拆解，复现代码至少应包含以下模块：

- 数据采集：SPADE 配置脚本，负责采集 Linux kernel provenance logs。
- 数据预处理：将 SPADE 输出解析为 node table、edge table、时间有序事件流。
- 图构建：维护 process/file/network 等节点类型和事件边，支持按边或节点 interval 增量更新。
- WL 特征：实现 k-hop 标签传播、邻域标签排序、标签压缩、直方图统计。
- FlexSketch：实现直方图归一化、LSH/一致加权采样、固定长度 sketch、衰减率 α 和概念漂移处理。
- 训练模块：对良性 sketch 序列运行 K-means，选择 K 和阈值，保存簇中心与状态转移关系。
- 检测模块：在线生成 sketch，计算到正常簇的距离，检查状态转移合法性。
- 评估模块：计算 precision、recall、accuracy、F-score，并统计运行速度、内存、CPU。

若在代码包中查找，优先关注可能命名为 `preprocess`、`graph_builder`、`wl_kernel`、`flexsketch`、`kmeans`、`train`、`detect`、`evaluate` 的文件或目录。论文提到实现使用 C++ 和 Python，并使用 GraphChi 做高效图计算，因此真实工程很可能是 C++ 负责图/流式特征计算，Python 负责聚类、指标和实验脚本。

## 12. 本篇精华

- RT-APT 的核心不是识别攻击签名，而是学习正常系统状态序列；未知攻击通过偏离正常簇或非法状态转移被发现。
- WL subtree kernel 负责把溯源图中的多跳因果上下文编码进直方图，解决单点事件特征太弱的问题。
- FlexSketch 是论文处理大规模流式溯源图的关键，使持续增长的高维直方图变成定长、可增量更新的 sketch。
- 最优参数组合为 k-hop=3、sketch-size=2000、按边 Interval=3000、α=0.03、K=6。
- 实验覆盖 Laboratory、StreamSpot、Unicorn 三类数据，RT-APT 在 F-score 和资源开销上整体优于 StreamSpot 与 Unicorn。
- 论文最重要的工程价值在于低开销实时检测：约 600 MB 内存、约 17%-18% CPU，处理速度接近采集速度。
- 主要短板是解释性和部署适配：能报异常，但如何定位攻击路径、如何防训练污染、如何跨业务调参仍未完全解决。
- 表格结果需细读：Laboratory 上 RT-APT 的 accuracy 并非最高，但 precision、recall、F-score 更好。

## 13. 建议精读路线

第一遍先读 Introduction 和 Systematic design，抓住论文真正要平衡的两个词：generality 和 reliability。理解为什么作者不采用规则匹配或监督分类。

第二遍精读 3.2 和 3.3。重点看 WL 标签传播如何形成直方图，FlexSketch 如何把流式直方图变成定长 sketch，以及 K-means 状态簇如何用于异常检测。

第三遍读 3.4 的 Webshell 案例。这个案例最能帮助理解“长期因果链”为什么比短窗口事件更适合 APT 检测。

第四遍读实验部分。重点核查参数敏感性、三类数据集划分、基线对比和运行开销，不要只看最终 F-score。

第五遍带着复现问题回读论文：SPADE 输出格式是什么、WL relabeling 如何实现、FlexSketch 具体哈希函数和阈值怎么选、状态转移合法性如何定义。这些是从论文走向可运行系统的关键缺口。
