# [369] Augmentation and Fusion: Multi-Feature Fusion-Based Self-Supervised Learning Approach for Traffic Tables

## 2. 中文翻译与核心摘要

这篇论文的核心问题是：加密流量容易采集、难以标注，而现有自监督加密流量分类方法多把流量转成图像或文本，未充分利用流量天然的“包-流”和“字段-包”结构。作者认为，将一个 flow 中连续若干个包的协议头字段组织成二维 traffic table，更贴近原始网络流量结构：行表示包序列，列表示协议头字段。

论文提出一种面向 traffic table 的多特征融合自监督方法。它把输入表切分为多个子表，通过随机子集选择 RSS 构造两种不同视角：一部分子表保持原样，一部分子表加噪后作为扰动视角。模型同时做重构任务和对比任务，借助 attention pooling 学习不同字段子表的重要性。随后，作者又从重构表中用均值池化提取简单时间特征，并与表格潜表示拼接，形成融合表征。

核心结论是：在强类别不均衡的加密流量数据集上，该方法用少量标注样本也能训练出较好的分类器；相较 SubTab 这类通用表格自监督方法，分类性能整体更优，且处理速度从 1.83 tables/s 提升到 3.76 tables/s，接近两倍。

## 3. 论文解决的具体问题

论文针对的不是一般异常检测，而是加密流量分类中的少标注学习问题。它的现实背景是：流量数据大规模采集较容易，但为每条 flow 或每个应用服务打标签成本很高，因此需要利用大量无标签流量学习可迁移表征。

作者指出已有方法有三类不足。

第一，图像化和文本化流量表示会损失或扭曲流量结构。图像方法通常把字节序列裁剪、填充为固定二维矩阵；文本方法把报文或 payload token 化，再套用 BERT 类模型。这些方法有效，但未必自然表达“多包构成一个流、多个协议字段构成一个包”的结构。

第二，traffic table 虽然结构合适，但表格数据的数据增强手段贫乏。对比学习依赖多视角增强，图像领域有裁剪、颜色扰动、旋转等，文本领域有 mask、替换等；表格领域常见方法主要是特征扰动、swap noise，增强多样性不足。

第三，已有 traffic table 方法多聚焦单一表征，没有显式利用时间特征。traffic table 的行天然保留包到达顺序，理论上包含时序信息，但如果只把整张表当普通 tabular input，容易忽略包序列模式。

## 4. 创新点深度提炼

第一项创新是 RSS，即 Random Subsets Selection。作者不是简单对整张表加噪，而是先把 traffic table 切成 7 个子表，再随机选择部分子表构成一个视角，剩余子表中再随机选择部分，加噪后构成另一个视角。这样做的意义在于：模型被迫从不同字段组合中学习稳定判别信息，而不是依赖某个固定字段片段。

第二项创新是把重构和对比学习合在同一个 pretext task 中。重构任务要求潜表示保留足够信息以还原输入表；对比任务要求同一张表的不同增强视角在表征空间接近，不同样本远离；距离损失进一步拉近正样本投影。这比单纯重构更适合少标注分类，因为它不仅保留输入信息，还塑造了类别可分的表示空间。

第三项创新是 attention pooling 式子表加权。作者的隐含判断是：协议头不同字段对分类贡献不等，例如长度、标志位、协议类型、时间序列相关字段可能比某些稳定或填充字段更有用。通过对子表表示加权聚合，模型可以学习“哪些字段片段更像分类线索”。

第四项创新是低成本时间特征融合。作者没有引入 LSTM、Transformer 或 TCN，而是对重构表按包维度做均值压缩，得到 14 维时间特征，再与潜表示拼接。这一设计很轻量，实验中确实带来增益，但也说明论文更强调工程性和效率，而非复杂时序建模。

第五项创新是速度优化。与 SubTab 对每个子表多次重构、成对子表计算对比/距离损失不同，本文只对两个聚合视角计算损失，显著减少计算次数。这也是论文区别于“只追指标”的地方：它把自监督预训练的吞吐速度作为重要贡献。

## 5. 科学问题与研究假设

这篇论文背后的科学问题可以概括为：在加密流量 payload 不可用或不可靠、标签稀缺、类别不均衡的条件下，如何从协议头构成的 traffic table 中学习稳定且可迁移的流量表征？

论文至少包含四个研究假设。

第一，traffic table 比图像或文本更适合表达 flow-packet-field 三层结构。行保留包序列，列保留协议头字段，既能避免 payload 隐私问题，也能保留与服务或应用相关的行为模式。

第二，字段子表之间的重要性不同。若把所有字段等权处理，模型会被无关字段、填充字段或噪声字段干扰；通过子表切分和 attention pooling，可以学习更有效的字段组合权重。

第三，随机子集选择能作为表格对比学习的数据增强。对同一张 traffic table 的不同子表视角进行一致性约束，能够提升表征鲁棒性，并减少对少数固定字段模式的过拟合。

第四，traffic table 中存在可利用的时间特征。即便只是对每个包的字段均值做简单池化，也能捕捉包序列层面的差异，从而改善分类。

## 6. 科学方法与技术路线

论文技术路线从原始流量到分类输出大致如下。

首先，原始 pcap/flow 数据被转换为 traffic table。作者过滤 DNS、ARP、SNMP 等无关包；提取 IP、TCP/UDP 头；删除源/目的 IP 和源/目的端口，避免隐私泄露与过拟合；UDP 头补零对齐 TCP 头长度；每 14 个连续包组成一张表，每个包保留 28 字节头部字段，因此单表形状为 14×28。

其次，在自监督预训练阶段，每张表被切分为 7 个子表。结合论文关于“字段重要性”的描述，子表应主要沿字段列维度切分。每个子表输入共享或相同结构的 encoder，得到子表潜表示，再经 attention pooling 聚合。

然后，RSS 构造两个增强视角。一个视角由随机选择的原始子表聚合得到，另一个视角从剩余子表中随机选择并加噪后聚合得到。两个视角分别经过 decoder 重构原始表，并经过 projection network 得到对比学习投影。

损失函数由三部分组成：重构损失、SimCLR 式对比损失、投影距离损失。重构损失又分为原始子集重构与扰动子集重构，权重由 α 控制；对比损失权重为 β；距离损失权重为 γ。

最后，在下游分类阶段，保留预训练好的 encoder 和 attention pooling，并冻结参数。所有子表都用于聚合潜表示，再训练一个逻辑回归分类器完成流量类别预测。作者通过改变标注训练样本比例，检验模型在少标注条件下的表现。

## 7. 实验设计与实验步骤

1. 数据准备  
   使用三个数据集：ISCX VPN-nonVPN、ISCX Tor-nonTor、SHU-ET。前两个是公开基准，均包含 12 类服务或 Tor/VPN 变体；SHU-ET 是作者自采移动流量，覆盖 Facebook、Telegram、Twitter、YouTube 与 ExpressVPN、SSRVPN、V2Ray 等组合。

2. 数据预处理  
   过滤无关协议包；只保留 IP 与 TCP/UDP 头；删除 IP 地址和端口字段；UDP 头补零；连续选取 14 个包构成一张 14×28 traffic table；保持包顺序不变。作者单独做了 row count 敏感性实验，比较不同包数，最终选择 14 行。

3. 数据划分  
   训练集与测试集按 4:1 划分，并保持各类样本比例。训练集在预训练阶段去掉标签作为无标签数据；下游分类阶段只使用训练集中的 10%、30%、50%、70%、100% 标注样本。测试集大小固定为总数据的 20%。

4. 预训练模型  
   输入 traffic table 切分为 7 个子表；RSS 随机构造原始子表视角与加噪子表视角；encoder 编码子表；attention pooling 聚合表示；decoder 重构输入；projection network 输出对比学习向量；训练目标为重构损失、对比损失、距离损失加权和。

5. 下游分类  
   冻结预训练 encoder 与 attention pooling；使用全部子表聚合表征；训练逻辑回归分类网络；在固定测试集上评价。

6. 对比基线  
   包括 1DCNN、ET-BERT、MT-FlowFormer、NetMamba、SubTab。前四类代表图像化、文本化、半监督/预训练流量分类方法；SubTab 是通用表格自监督基线，与本文方法在 traffic table 输入上最直接可比。

7. 指标  
   使用 Accuracy、Recall、Precision、F1-score。论文特别强调类别不均衡会抬高 Accuracy，因此更关注加权 F1、Recall、Precision。

8. 消融与敏感性  
   包括 row count 敏感性、损失权重 α/β/γ 敏感性、RSS 策略对比、是否加入 temporal feature。RSS 对比包含 DC、MC、FC、NC 等不同确定性程度，结果显示随机性最高且融合时间特征的 NC+TF 效果最好。

9. 结果核查  
   作者用 PCA 与 t-SNE 观察预训练前后表征聚类变化，用混淆矩阵检查各类别表现，用样本分布表解释类别不均衡对结果的影响，并报告 SubTab 与本文方法在参数量、计算次数、处理速度上的差异。

## 8. 关键结果、结论与证据

最重要的结果是：本文方法在 ISCX VPN-nonVPN 和 ISCX Tor-nonTor 上整体最佳，在 SHU-ET 上仅次于 NetMamba。特别是在只使用 10% 标注数据时，ISCX VPN-nonVPN 上 Accuracy 达 99.30%、F1 达 95.27%；ISCX Tor-nonTor 上 Accuracy 达 99.47%、F1 达 96.81%。这说明预训练表征已经把多数类别拉到较可分的空间中。

第二个关键证据来自 PCA/t-SNE。原始数据分布较混乱，预训练后的 t-SNE 显示同类样本更集中、异类样本更分离。虽然 t-SNE 不能作为严格性能证明，但与少标注分类结果相互印证。

第三个结论是 traffic table 的确适合加密流量分类。SubTab 和本文方法都使用表格输入，并整体显著超过若干图像/文本基线，说明协议头表格化表达不是简单替代格式，而是更贴近任务结构的表示方式。

第四个结论是类别不均衡是 ETC 评估中的关键变量。ISCX VPN-nonVPN 中 VoIP、File-Transfer、VPN-P2P、VPN-VoIP 占据绝大部分样本；ISCX Tor-nonTor 中 Tor-P2P 接近一半。论文意识到 Accuracy 会被多数类放大，因此分析了混淆矩阵和加权指标。

第五个结果是速度提升明显。SubTab 对 7 个子表需要多次重构并计算大量子表对之间的对比/距离损失；本文只在两个聚合视角上计算，处理速度从 1.83 tables/s 提升到 3.76 tables/s。这一提升比分类指标增益更显著。

## 9. 局限性与待解决问题

第一，时间特征提取过于简单。作者用每个包所有字段的均值作为时间特征，这种做法便宜有效，但会丢失字段间结构、方向性、包间间隔、长度序列变化等更丰富的时序信息。

第二，方法仍依赖固定表长。论文选择 14 个包构成一张表，但真实 flow 长度差异很大。短流、长流、突发流和持续流可能需要不同粒度表达。固定 14 包虽然实验上较优，但泛化到其他网络环境仍需验证。

第三，SHU-ET 上未取得最优。NetMamba 在 SHU-ET 上更强，论文解释为 NetMamba 使用更多样本切片和更大参数量。这也暴露出本文方法在小规模、应用级分类场景下可能受限于样本构造方式。

第四，类别不均衡处理还不充分。论文分析了不均衡，却没有系统引入重采样、代价敏感损失、长尾校准、macro-F1 或 per-class recall 优化。对于安全场景，少数类可能更重要，仅依赖 weighted metrics 仍可能掩盖弱类问题。

第五，预训练与下游分类之间的冻结策略可能限制性能。作者冻结 encoder 和 attention pooling，仅训练逻辑回归分类器。这有利于验证表征质量，但实际部署中，少量微调可能进一步提升少数类表现。

第六，正文包未截断，本次理解不受正文截断影响。但若用于正式复现，仍建议回到 PDF 核查图表、公式排版和参考文献编号，因为正文中与 SimCLR、port-based 方法相关的引用编号存在疑似错配或抽取错位。

## 10. 与本项目的关系

该论文与“异常检测”项目的关系是中等相关，更准确地说，它是加密流量分类和应用识别方向的方法论文，而非典型异常检测论文。它解决的是已知类别流量识别，不是未知攻击发现、开放集检测或异常分数建模。

对本项目有价值的部分主要有三点。

第一，traffic table 表示可以迁移到异常检测。只使用协议头、不依赖 payload 的设计适合隐私敏感环境，也适合加密流量场景。异常检测中可以把 flow 表格化后做自监督预训练，再用于异常/正常二分类或未知类检测。

第二，RSS 可作为表格流量增强策略。异常检测常面临标注稀缺，随机字段子集增强能提升表示鲁棒性，尤其适合协议字段多、部分字段不稳定的场景。

第三，重构加对比的联合 pretext task 对异常检测有启发。重构损失可学习正常结构，对比损失可塑造聚类空间；若进一步引入正常样本预训练、异常分数、开放集阈值，可能形成面向加密流量异常检测的模型。

但需要注意，本文默认训练和测试类别已知，且最终用分类器输出 12 类标签。若本项目关注未知攻击、零日异常或跨域泛化，需要在本文基础上补充开放集评估和异常评分机制。

## 12. 本篇精华

1. 论文的核心贡献不是“又做了一个分类器”，而是把加密流量重新组织为 traffic table，并围绕这种结构设计自监督增强、重构、对比和特征融合。

2. 14×28 traffic table 是关键表示：14 个连续包保留流内时序，28 个协议头字节保留字段结构，同时删除 IP、端口和 payload 以降低隐私风险与过拟合。

3. RSS 是本文最有辨识度的机制：随机选择字段子表形成不同视角，让模型学习跨字段组合稳定存在的流量特征。

4. 重构任务负责信息保真，对比任务负责类间可分，距离损失负责正样本拉近；三者共同构成 traffic table 的自监督 pretext task。

5. 时间特征融合很轻量，只用均值池化即可带来增益，说明 traffic table 行顺序中确实包含分类信息。

6. 在 ISCX 两个强不均衡数据集上，本文方法少标注表现突出，10% 标注数据即可接近全量标注性能。

7. 与 SubTab 相比，本文性能提升不算夸张，但速度提升非常明确，说明聚合视角比逐子表成对计算更适合大规模流量表预训练。

8. 该方法适合为异常检测项目提供表征学习模块，但还不能直接等同于异常检测，需要扩展开放集、未知类和异常评分设计。

建议第一遍重点读 Introduction、Problem Formulation 和 Traffic Tables Generation，先弄清作者为什么放弃图像/文本表示，以及 14×28 表是如何从 flow 中构造出来的。

第三遍读 Evaluation 中的数据分布、混淆矩阵和 Table VII。不要只看 Accuracy，应重点看 F1、Recall、Precision，以及 Chat、Email、e-Telegram 等弱类表现。

第四遍读 Ablation Study。这里是判断论文创新是否真实有效的关键：RSS 的 NC+TF 最优、MC 明显下降、β 和 α 的敏感性，都能帮助理解模型为什么有效。
