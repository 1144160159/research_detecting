# [380] CELEST: Federated Learning for Globally Coordinated Threat Detection

## 1. 基本信息
- 题名：CELEST: Federated Learning for Globally Coordinated Threat Detection
- 中文题名：CELEST：面向全球协同威胁检测的联邦学习框架
- 年份：2025
- 来源：IEEE Transactions on Information Forensics and Security, Vol. 20
- DOI：10.1109/TIFS.2025.3614442
- 研究对象：HTTP 日志中的恶意通信检测，重点包括恶意流量、C2 通信、数据外传、IoT 恶意软件行为。
- 技术主线：跨组织联邦学习、主动学习、HTTP URL/域名/Referer 嵌入表示、投毒检测与缓解。
- 代码状态：本地未发现该论文对应开源代码包。

## 2. 中文翻译与核心摘要
这篇论文提出 CELEST，即“CollaborativE LEarning for Scalable Threat detection”，目标是在多个组织之间不共享原始 HTTP 日志的前提下，协同训练一个全局恶意 HTTP 通信检测模型。

论文的核心判断是：单个组织看到的攻击行为往往稀疏、不完整，局部模型很难识别“本地第一次出现”的攻击；而多个组织通过联邦学习共享模型知识，可以让某个组织从其他组织已观察到的攻击模式中受益。

CELEST 的方法不只是简单套用 FedAvg。它包含三层关键设计：第一，面向 URL、Domain、Referer 的联邦嵌入表示，优先使用 FastText 以处理未见过的 URL token；第二，在联邦学习过程中加入主动学习，通过全局分类器排序和本地异常检测共同挑选少量可疑样本给分析员标注，从而发现没有任何客户端预先标注的新恶意家族；第三，设计 DTrust 防御联邦学习中的数据投毒和模型投毒，让客户端使用本地可信验证集监控全局模型是否退化，并协助服务器定位恶意客户端。

论文在两个大学网络、三类公开/复现实验恶意流量、三次攻击复现演练中验证系统。一个重要结果是，在数据外传恶意软件场景中，全局模型相较本地模型 PR-AUC 可达到约 3 倍提升。部署中，CELEST 还发现了 42 个此前未知恶意 URL 和 20 个恶意域名，并经 VirusTotal 确认。

## 3. 论文解决的具体问题
论文解决的不是一般“恶意 URL 分类”问题，而是更贴近企业边界网络的 HTTP 单条日志级检测问题：

1. 单组织视角不足：攻击活动具有全球协同特征，但一个组织看到的样本有限，本地训练模型容易漏掉本地未出现过的恶意家族。
2. IoC 分享滞后：传统跨组织协作主要共享 IP、域名、URL pattern 等 IoC，但攻击者可以快速更换基础设施，使 IoC 失效。
3. HTTP 恶意通信伪装性强：HTTP 是常见合法协议，恶意 C2、漏洞利用、数据外传可以混入大量正常 HTTP 流量。
4. 标签稀缺：真实网络里绝大多数日志没有可靠标签，单纯监督学习难以持续适应新攻击。
5. 联邦学习易被投毒：协同训练虽然保护日志隐私，但恶意或失陷客户端可通过标签翻转、权重放大等方式破坏全局模型。

所以 CELEST 的实际问题是：如何在不集中共享敏感 HTTP 日志的情况下，让多个组织形成一个能发现本地未知攻击、可持续学习新攻击、并能抵抗投毒的全局检测模型。

## 4. 创新点深度提炼
1. 将跨组织 HTTP 威胁检测明确建模为 cross-silo 联邦学习问题。论文不是面向大量移动设备的 cross-device FL，而是面向少量组织级客户端，每轮所有客户端参与，符合 SOC、大学网络、企业边界网关这类部署条件。

2. URL 表示不是传统词法特征，而是结构化 token 嵌入。作者将 URL 按 domain、path、query 等结构拆为 token，把 URL 当作“句子”，用 Word2Vec/FastText 思路学习语义相似性。FastText 的子词 n-gram 机制使模型能处理训练时没见过的新 token，这对攻击者频繁变换 URL 参数、路径、子域尤其重要。

3. 嵌入模型也考虑联邦训练。论文讨论了集中训练、FedAvg 训练 Word2Vec/FastText 的代价，并采用顺序客户端更新的分布式嵌入训练方式；同时指出 FastText 可用公共语料构造 n-gram 词表，减少共享本地词表的隐私风险。

4. 主动学习与联邦学习结合，用于发现“所有客户端训练集中都没有标签”的新攻击。它不是只做不确定性采样，而是把全局分类器的可疑排序和本地 Isolation Forest 异常分数结合：前者更容易抓住已知恶意模式的变体，后者更可能发现未知行为。

5. DTrust 的防御视角有针对性。多数 FL 防御依赖服务器检测异常更新或服务器持有可信数据，而 DTrust 假设参与方是有安全能力的组织，让客户端用自己的可信数据集监控全局模型退化，再触发服务器回溯各客户端更新。这很适合安全协作联盟，但不一定适合普通移动端 FL。

6. 论文把“检测能力提升”和“部署可用性”放在一起验证。除了 PR-AUC，还强调 FPR；在网络安全告警场景中，低误报率比单纯高 AUC 更接近可上线要求。

## 5. 科学问题与研究假设
核心科学问题可以概括为三组：

1. 协同知识迁移问题：多个组织在恶意样本分布非 IID、攻击家族不完全重叠时，联邦全局模型是否能把某个组织见过的恶意模式迁移给其他组织？

2. 未知攻击发现问题：当某类恶意软件在所有客户端训练集中都没有标签时，联邦系统能否通过少量人工标注和异常检测逐步发现并学习它？

3. 对抗鲁棒性问题：当部分客户端被攻击者控制并向模型注入错误标签或恶意权重更新时，协作检测系统能否恢复全局模型性能，并定位恶意客户端？

论文隐含的研究假设包括：
- HTTP 恶意通信在 URL、域名、Referer、User-Agent、状态码、内容类型、请求/响应大小等字段上存在可学习的行为模式。
- 不同组织的恶意流量存在可迁移结构，全局模型能从数据多样性中受益。
- 新攻击相对于本地正常 HTTP 背景流量往往表现为异常，因此异常检测可辅助主动学习。
- 多数参与组织是善意的，且有动机验证模型质量；这是 DTrust 成立的关键社会技术假设。

## 6. 科学方法与技术路线
CELEST 的技术路线是“日志特征化 → 联邦表征学习 → 联邦分类训练 → 主动学习扩充标签 → 投毒检测与恢复”。

输入是边界网络 HTTP 日志。作者排除 source IP 和 source port，因为它们要么涉及主机身份隐私，要么对恶意通信判别贡献有限。最终特征共有 5862 维，分为三类：

- 嵌入特征：URL、Domain、Referer。
- 类别特征：外部 IP 子网、端口、User-Agent、HTTP method、status code、content type。
- 数值特征：request size、response size、transaction depth、browser version。

模型层面，分类器是 FFNN，使用 FedAvg 聚合各客户端本地更新。每个训练轮对应 30 分钟日志窗口。客户端本地训练后上传模型更新，服务器按数据量加权平均得到全局模型。

主动学习层面，每轮客户端对未标注样本做两种排序：一半预算来自全局分类器认为最可疑的样本，另一半来自本地 Isolation Forest 认为最异常的样本。经安全分析员或威胁情报确认后，只把恶意样本加入下一轮训练集。这个设计体现出安全场景的谨慎性：看起来正常的行为未必真正常，因此作者重点扩充恶意标签。

DTrust 层面，每个参与防御的客户端维护一个小型 trust dataset，包含本地验证过的良性与恶意样本。客户端发现全局模型在该集合上的 loss 相对历史最优显著恶化，就向服务器报告。服务器验证 trust dataset 的可信性，回到历史模型，逐个排除客户端更新，计算排除前后的 loss impact，从而识别可能投毒的客户端并移除其更新。

## 7. 实验设计与实验步骤
可复核流程如下：

1. 数据准备  
   使用两个大学网络 HTTP 日志作为主要良性背景流量，规模分别约为每天 2000 万和 900 万 HTTP 事件。恶意数据包括：NIDS 告警提取的恶意域名/IP、Mirai、Gafgyt IoT 恶意软件沙箱 HTTP 日志，以及 Bortolameotti 等人的 DEM 数据外传恶意软件数据集。

2. 数据过滤与预处理  
   去除 Tranco Top 10,000 热门域名，并去除大学网络中访问超过 10,000 次的外部域名，以降低海量常见良性流量对训练和评估的干扰。大学网络日志中的内部 IP 和 URL 参数值做一致匿名化。恶意家族按样本划分 80% 训练、20% 测试。

3. 特征构造  
   解析 URL 为结构 token，分别为 URL、Domain、Referer 训练嵌入表示；同时抽取类别特征和数值特征，组成 5862 维 HTTP 单日志特征。比较联邦 FastText、集中式嵌入和传统 lexical features。

4. 模型与基线  
   主模型是 FedAvg 下的 FFNN，全局模型与本地模型比较；另设集中式模型作为上界参考。FFNN 使用单隐藏层 128、dropout 0.1、learning rate 0.01。实现环境为 Python 3.8、Keras、TensorFlow Federated、Gensim。

5. 联邦训练设置  
   每轮使用 30 分钟日志数据；两个大学网络作为主要客户端。在知识迁移实验中，故意让 UNI-1 和 UNI-2 训练阶段看到不同恶意家族，测试它们对本地未见家族的检测能力。

6. 主动学习实验  
   构造更难场景：Mirai、Gafgyt、DEM 的恶意标签在初始训练中不可用，只作为未标注流量混入客户端。Isolation Forest 使用前 k 个时间窗口训练，当前窗口检测，实验选择 k=3。人工调查预算从 0 到 500 变化，观察 PR-AUC 随预算变化。

7. 投毒实验  
   设置 30 个客户端，包含 poisoning clients、helper clients 和普通良性客户端。投毒从第 20 轮开始，总训练 48 轮。攻击包括标签翻转和权重 boosting；场景包括 CosmicDuke 数据外传、Mirai ThinkPHP exploit、Gafgyt 家用路由器攻击。

8. 指标与结果核查  
   主要指标为 Precision、Recall、PR-AUC、FPR，并报告最大 F1。部署可用性重点看高召回下 FPR 是否足够低。投毒防御中检查 DTrust 是否能在少数轮内发现恶意客户端，并使 PR-AUC 恢复到接近无投毒基线。

## 8. 关键结果、结论与证据
最重要的结果是联邦模型显著优于本地模型，尤其在“本地第一次见到该恶意家族”的场景中。例如 UNI-1 训练见 Mirai、UNI-2 训练见 DEM 时，UNI-1 检测 DEM 的本地模型 PR-AUC 只有 0.26，而联邦全局模型达到 0.75。另一侧 UNI-2 检测 Mirai 时，本地模型 PR-AUC 0.54，全局模型 0.87。

对更相似的 IoT 家族 Mirai 与 Gafgyt，本地模型已有一定泛化能力，PR-AUC 可到 0.87-0.90，但全局模型仍提升到约 0.93-0.95。这说明联邦协作不只在完全不同家族间有价值，在相近变体间也能提供增益。

联邦模型接近集中式模型。一个场景中，集中式 PR-AUC 为 0.97，联邦模型为 0.95。考虑到联邦模型不集中原始日志，这个差距是可以接受的隐私-性能折中。

主动学习对未知攻击尤其关键。当预算为 0，即没有主动标注时，模型几乎无法识别完全新家族；例如 UNI-1 检测 Mirai 的 PR-AUC 只有 0.19。随着预算增加到 500，PR-AUC 可提升到 0.87。论文还发现只用异常检测选样不如“异常检测 + 分类器可疑排序”，检测 DEM 时后者 PR-AUC 约高 11%。

DTrust 对强投毒有效。在数据外传场景中，无防御时模型 boosting 可将 PR-AUC 从 0.93 打到 0.11；DTrust 识别并移除恶意客户端后可恢复到 0.93 左右。三个投毒场景中，DTrust 都能在 4 轮以内检测到投毒活动。

真实部署结果也支撑论文结论。CELEST 在两个大学网络和三次攻击复现实验中表现出高精度、极低误报率；论文报告两个网络上的 FPR 低于 3.3×10^-5，并发现 42 个未知恶意 URL 与 20 个恶意域名。

## 9. 局限性与待解决问题
1. 主要聚焦 HTTP，HTTPS 只在讨论中分析。作者认为企业代理解密或使用部分可见字段可以扩展到 HTTPS，但没有系统实验验证完整 HTTPS 场景。

2. DTrust 依赖客户端 trust dataset 覆盖相关恶意行为。如果后门触发模式没有出现在任何客户端可信验证集中，DTrust 可能检测不到，这是论文明确承认的未来工作。

3. 服务器被假设正确执行聚合协议。论文防御重点是恶意客户端，不处理恶意服务器、服务器被攻陷或聚合方滥用更新的问题。

4. 真实通信开销没有被充分建模。TensorFlow Federated 实验主要是模拟联邦学习，不包含真实跨组织网络延迟、断连、带宽限制、密钥管理等工程问题。

5. 主动学习假设人工分析员标注正确，并且只加入恶意样本。现实 SOC 中误标、延迟标注、威胁情报滞后会影响闭环质量。

6. 大学网络作为部署环境有代表性，但与企业、ISP、云租户、多租户代理环境仍有差异；不同组织的日志字段完整性和代理策略可能影响特征可用性。

## 10. 与本项目的关系
这篇论文与“异常检测、恶意流量、暗网与攻击检测、联邦学习、隐私保护与分布式协同”高度相关，尤其适合作为项目中“跨域协同异常检测”的代表性工作。

对本项目最有价值的不是单个 FFNN 分类器，而是完整问题框架：在隐私约束下，不同组织各自保留原始日志，通过联邦训练共享检测知识；再用异常检测解决新威胁标签不足问题；最后补上联邦投毒防御。这个组合比单纯“用 FL 做 IDS”更完整。

如果本项目关注网络安全运营落地，CELEST 给出的经验很重要：告警系统必须关心 FPR，必须考虑标签获取机制，必须把攻击者对训练过程的操控纳入威胁模型。它也提示我们，异常检测不是监督模型的替代品，而可以作为主动学习的样本发现器，为监督联邦模型持续供血。

## 11. 代码对照分析
本地未发现该论文对应的开源代码包，因此不能把论文方法映射到真实源码文件或目录。论文只给出实现线索：Python 3.8、Keras、TensorFlow Federated、Gensim。

如果复现 CELEST，代码结构大概率应拆成以下模块：

- 数据预处理：读取 HTTP proxy logs、匿名化字段、过滤 Tranco Top 10,000、过滤高频外部域名、按 30 分钟窗口切片。
- 特征工程：URL/Domain/Referer 解析与 token 化、FastText 训练、类别特征编码、数值特征归一化、拼接 5862 维特征。
- 联邦嵌入训练：客户端顺序更新 FastText/Word2Vec 嵌入模型，维护统一 n-gram 或 token vocabulary。
- 联邦分类模型：Keras FFNN，本地 SGD 训练，TFF FedAvg 聚合。
- 主动学习：全局模型可疑分数排序、Isolation Forest 异常分数排序、预算 b 分配、恶意样本回灌训练集。
- 投毒实验：标签翻转、权重 boosting、helper client 设置、PR-AUC 随轮次记录。
- DTrust：客户端 trust dataset 评估、loss impact 阈值检测、服务器历史模型和客户端更新回溯、leave-one-client-out 定位恶意更新。
- 评估脚本：PR-AUC、Precision、Recall、FPR、最大 F1、表格和曲线复现。

需要注意，论文中的真实部署还涉及大学网络内服务器、SOC 告警、VirusTotal 确认和攻击复现实验，这些不是普通开源代码可完全复现的部分。

## 12. 本篇精华
1. CELEST 的核心贡献是把跨组织威胁检测从 IoC 共享推进到模型知识共享，解决 IoC 易过期和单组织视野不足的问题。

2. 联邦模型在本地未见恶意家族检测上收益最大；数据外传场景中 PR-AUC 可从本地模型 0.26 提升到全局模型 0.75。

3. URL 嵌入表示是关键工程点。FastText 的子词机制适合攻击者频繁变换 URL token 的现实场景，比传统 lexical features 更具泛化性。

4. 主动学习使 CELEST 能处理“没有任何客户端预先标注该攻击”的场景，异常检测负责发现新行为，分类器排序负责扩展已知恶意变体。

5. DTrust 的新意在于让客户端参与信任引导，而不是完全依赖服务器检测异常更新；这与组织级安全协作的实际条件匹配。

6. 论文重视部署指标，尤其是 FPR。低至 3.3×10^-5 以下的误报率是其声称可用于真实网络的重要证据。

7. CELEST 仍未充分解决 HTTPS、隐蔽后门、恶意服务器、真实通信开销和跨行业泛化问题，这些是后续研究可以继续推进的方向。

## 13. 建议精读路线
1. 先读 Introduction 和 Problem Statement，抓住论文真正反对的是“单组织检测 + IoC 共享”的传统协作范式。

2. 再精读 Section III-A 的特征表示，尤其是 URL 结构化 token、FastText、联邦嵌入训练三者的关系。这部分决定模型是否能泛化到变形 URL。

3. 接着读 Section III-B 主动联邦学习，重点理解为什么分类器排序和异常检测排序要同时使用，以及为什么只回灌恶意标签。
