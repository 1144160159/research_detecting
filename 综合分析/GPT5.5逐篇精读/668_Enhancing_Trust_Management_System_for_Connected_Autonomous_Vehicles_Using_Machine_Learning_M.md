# [668] Enhancing Trust Management System for Connected Autonomous Vehicles Using Machine Learning Methods: A Survey

## 1. 基本信息

题名可译为《使用机器学习方法增强联网自动驾驶汽车信任管理系统：综述》。论文发表于 IEEE Transactions on Intelligent Transportation Systems，DOI 为 `10.1109/TITS.2025.3647284`。文稿接收时间是 2025-12-01，在线发表时间是 2026-01-05，正式卷期为 2026 年 4 月第 27 卷第 4 期；所以元数据标为 2025 可以理解为 DOI/接收年度，引用时建议核对最终 IEEE 格式。

论文类型是探索性综述，不是提出单一算法的实验论文。其对象是 CAV/IoV 场景中的 trust value-based TMS，重点讨论 ML 如何增强信任数据、信任计算、信任激励与攻击防御。

## 2. 中文翻译与核心摘要

论文核心意思是：CAV 运行在动态、开放、多域的车-路-云协同网络中，仅靠证书、规则 IDS 或固定阈值难以识别“身份合法但行为恶意”的节点。TMS 用信任值组织数据收集、计算、更新、传播、激励和防御，使车辆在数据共享、路由、边缘卸载、众包感知、编队等任务中做出更可靠的协同决策。

作者提出一个三层 ML-based TMS-CAV 框架：信任数据层、信任计算层、信任激励层；再提出六维评价目标：有效性、灵活性、可靠性、效率、安全性、隐私保护。文章不是简单罗列 ML 模型，而是把监督学习、半监督学习、GNN、RL/DRL、FL、Transformer 等方法放回 CAV 的高动态、间歇连接、机会交互、资源受限和实时安全约束中讨论。

## 3. 论文解决的具体问题

论文针对三个具体断层：第一，传统 CAV 安全综述多把 trust 当成安全子项，TMS-CAV 综述又常把 ML 放在附属位置；第二，传统 TMS 分类按贝叶斯、模糊逻辑、D-S 证据、图模型等方法展开，不适合解释 ML 在数据、计算、激励全流程中的作用；第三，已有 ML-based TMS 多停留在“信任值预测/恶意节点分类”，没有充分进入 CAV 的实际服务场景。

安全问题上，作者关心的不只是外部入侵，而是内部合法节点、虚假消息、Sybil/串谋、白洗、自我提升、推荐操纵、边缘卸载欺骗、众包低质数据等会污染协同决策的行为。

## 4. 创新点深度提炼

最主要创新是把 ML-based TMS 从“一个信任计算模型”扩展成三层系统：数据层处理 BSM、MAP、SPAT、RSM、PSM、轨迹、传感器、图像/雷达/LiDAR 等异构数据；计算层负责聚合、计算、更新和权重调节；激励层负责鼓励诚实参与并抵御信任相关攻击。

第二个创新是六维目标框架。它把 ML 常用的 Accuracy、Precision、Recall、F1、MSE 等指标，与 CAV 需要的实时性、可扩展性、计算/通信/存储开销、隐私预算、解释性、服务级收益结合起来。

第三个创新是按 CAV 应用场景组织文献：数据分发、路由、车载边缘计算、车辆众包感知、CAV 编队，以及机制层进展。这比单纯按 SVM/CNN/RL 分类更接近工程落地。

## 5. 科学问题与研究假设

核心科学问题是：在高速移动、拓扑频繁变化、交互对象临时出现、通信间歇且安全实时要求很高的 CAV 网络中，能否用 ML 形成比手工权重和固定规则更准确、更动态、更可扩展的信任管理系统？

隐含假设包括：异构交通与网络数据中存在可学习的信任模式；ML 能从历史行为、上下文、邻居关系和服务反馈中学习节点/数据可信度；GNN 适合动态图信任传播，RL 适合信任更新、路径/卸载/激励决策，FL 适合跨车辆/跨域隐私训练；但这些优势只有在实时性、鲁棒性、隐私和解释性同时满足时才有 CAV 价值。

## 6. 科学方法与技术路线

方法上，论文采用简化 PRISMA 流程：提出 5 个研究问题，围绕 trust/TMS、ML、CAV、安全等关键词检索，筛选 2018 年以来英文核心文献，强调 ML-based TMS-CAV、ML-based TMS-IoT、ML for ITS、传统 TMS-CAV 基线等优先级，最终形成 172 篇左右的核心文献集合。

技术路线是先界定 CAV 中 trust 的对象和形式，包括数据中心、节点中心、混合信任，连续值/二分类/多等级信任；再回顾传统 TMS；然后建立三层框架和六维目标；最后在典型 CAV 场景中评价已有方法，归纳开放问题。

## 7. 实验设计与实验步骤

这篇是综述，作者没有做统一复现实验；可复核流程应理解为“文献筛选与方法评估流程”。

1. 数据：以 2018 年至当前的 WoS/高质量期刊会议论文为主体，覆盖 TMS-IoT、TMS-CAV、ML-based TMS、ITS 安全、FL/GNN/RL 等。
2. 预处理：按关键词组检索，剔除非英文、非同行评议、仅加密认证而无信任值、ML/TMS/CAV 关系不清、方法细节不足或质量较低的文献。
3. 模型/基线：传统基线包括统计加权、贝叶斯/D-S/模糊/主观逻辑、熵、图、博弈；ML 类包括分类、回归、聚类、GNN、RL/DRL、FL、Transformer、半监督和端到端方法。
4. 训练：综述本身不训练模型；被综述论文通常使用自建仿真、SUMO/IoV 仿真、BSM/轨迹/交互记录，标签多为可信/恶意或连续信任值。
5. 指标：分类用 Accuracy、Precision、Recall、F1、MCC、ROC；回归用 MSE、RMSE、MAE、R2；系统层检查延迟、吞吐、PDR、通信/存储开销、MTTR/MTBF、隐私预算和解释性。
6. 消融/敏感性：应比较攻击比例、节点密度、车辆速度、拓扑变化、信任阈值、AV 渗透率、模型压缩、隐私机制和不同 ML 范式。
7. 结果核查：不仅看信任计算准确率，还要核查服务是否改善，如消息分发可靠性、路由稳定性、卸载成功率、众包数据质量、编队安全，以及是否抵御白洗、串谋、Sybil、投毒和隐私推断。

## 8. 关键结果、结论与证据

论文给出的关键结论是：ML 的价值不应局限于“预测一个信任值”。在数据层，ML 处理异构、多源、多模态数据；在计算层，深度模型/GNN/RL 可学习复杂时空关系和动态更新；在激励层，RL/博弈/合约/拍卖结合可促进诚实参与并约束投机行为。

场景证据较清晰：数据分发中已有聚类、朴素贝叶斯、RL、FL；路由中已有 DQN、Transformer、SVM、GMM-HMM-LSTM 的借鉴；边缘计算中有 BPNN、S-ADMM、A3C、FedQ-Trust；众包感知中出现 GNN、GAN、DRL 激励；编队中目前传统/区块链/隐私保护方案更多，ML 仍不足。总体判断是：研究增长快，但真正满足 CAV 实时、安全、隐私、解释和真实道路泛化要求的工作仍少。

论文自身局限也明显：作为综述没有统一实验平台；大量被综述方法依赖自建仿真，公共 CAV trust 数据集缺失；多数 ML-based TMS 仍偏监督学习，面对未知攻击和少标签数据不足；GNN/Transformer 等模型的实时部署成本高；FL 可缓解隐私但不能自动解决跨厂商数据孤岛；信任相关攻击、对抗样本、数据投毒、后门攻击之间的耦合还没有系统建模。

## 10. 与本项目的关系

与异常检测项目的关系是弱到中等相关。它不提供直接可用的异常检测数据集或模型代码，但提供了一个很有价值的安全建模视角：异常不只是流量偏离，也可以是“协同实体的可信度下降”。在 IoT、车联网、工业互联网和边缘安全中，trust score 可以作为 IDS 的补充特征，也可以作为告警后的决策层信号。

如果本项目关注跨域异常检测，这篇的价值在于把异常行为、数据可信度、节点信誉、隐私训练和激励机制放进一个统一系统框架；如果项目只需要可复现实验基准，它的直接贡献较弱。

## 12. 本篇精华

- 这篇论文的核心不是“ML 做信任分类”，而是把 TMS 拆成信任数据、信任计算、信任激励三层系统。
- CAV 的 trust 问题比静态 IoT 更难，关键差异是高速移动、机会交互、间歇连接、道路约束、实时安全和资源受限。
- 六维评价框架很适合写综述：有效性、灵活性、可靠性、效率、安全性、隐私保护。
- GNN 适合动态图信任传播，RL 适合动态更新和决策，FL 适合隐私协同，但都受实时性和鲁棒性约束。
- 当前研究最强的是信任计算，最弱的是真实部署、公共数据集、混合交通、信任激励和信任攻击防御。
- 对异常检测研究而言，TMS 可以作为 IDS 之后的决策层，也可以把信任值作为跨节点、跨服务的异常证据。
- 未来关键问题是少标签/半监督、对抗鲁棒、模型轻量化、可解释、跨厂商协同和 SUMO-实车混合验证。
