# [520] Respond to Change With Constancy: Instruction-Tuning With LLM for Non-I.I.D. Network Traffic Classification

## 1. 基本信息

论文发表于 IEEE TIFS 2025，DOI 为 `10.1109/TIFS.2025.3574971`。主题是加密流量分类在 Non-I.I.D./O.O.D. 场景下的泛化问题。作者提出 ETooL，将流量交互图、图结构对齐、自监督指令微调和任务指令微调结合，用大语言模型提升加密流量在时间漂移、版本漂移、恶意类型漂移和动态分布偏移下的分类能力。

## 2. 中文翻译与核心摘要

题名可译为：**以不变应万变：面向非独立同分布网络流量分类的 LLM 指令微调方法**。

论文的核心观点是：加密流量虽然缺少明文语义，但并不等于没有可迁移结构。单条流的包长、载荷字节、统计特征容易随应用版本、时间窗口、网络环境变化而漂移；而多条流之间的并发、相邻、BURST 结构更可能保留应用交互逻辑。ETooL 通过把流量转换成 Traffic Relation Graph，再让 LLM 通过图结构指令理解这些流间关系，从而在新分布测试集上保持更稳定的分类能力。

## 3. 论文解决的具体问题

论文瞄准的不是普通加密流量分类，而是**训练分布和测试分布不一致时的加密流量分类**。典型变化包括：同一 App 在不同时间采集、同一 App 不同版本、训练集中只见过部分 botnet 类型、服务类别内部组成比例变化等。

传统方法的问题在于：统计特征依赖人工经验，深度模型依赖大量标注样本，预训练模型如 ET-BERT 虽有迁移能力，但仍主要围绕单流表示，难以显式利用多流交互。论文希望解决“旧分布训练出的模型，面对新分布还能否保持标签映射稳定”的问题。

## 4. 创新点深度提炼

第一，论文把 O.O.D. 加密流量分类问题明确建模为流量边缘分布变化下的标签映射保持问题，强调现实网络中 I.I.D. 假设不可长期成立。

第二，ETooL 不再只看单流，而是构造 Traffic Relation Graph。节点是网络流，节点特征包含 raw datagram 和 directed packet length sequence；边包括同一 BURST 内的 burst edge，以及不同 BURST 之间的 adjacency edge。

第三，论文设计了 BURST Graph Matching 自监督指令任务。它让模型根据图拓扑关系，把被打乱的 BURST 流量特征与图节点重新匹配，本质上是在训练 LLM 理解“流与流为什么属于同一个交互上下文”。

第四，论文提出两阶段指令微调：先做图结构指令微调，注入流量结构知识；再做流量任务指令微调，适配具体分类任务。训练时冻结 LLM 和图编码器，只更新投影层与轻量分类头，降低训练成本。

第五，论文构造 NETD，用 ISCX-VPN 的服务组成变化模拟可控 Non-I.I.D. 偏移，并引入比例偏移和组成偏移，使 O.O.D. 程度可调。

## 5. 科学问题与研究假设

科学问题可以概括为：**在加密负载不可见、流量分布持续变化的条件下，是否存在比单流特征更稳定的可迁移结构表示？LLM 的指令微调能力能否把这种结构知识转化为 O.O.D. 分类泛化能力？**

核心研究假设有三点：多流交互结构比单流局部特征更稳定；BURST 反映应用层资源请求、并发连接和服务协作逻辑，因此跨时间或版本仍有保留；LLM 虽不是为流量设计，但通过图结构对齐和指令微调，可以学习非文本结构数据中的上下文关系。

## 6. 科学方法与技术路线

技术路线是 `Traffic2Graph -> Graph Structural Instruction Tuning -> Traffic-Task Instruction Tuning`。

Traffic2Graph 先从每条流提取两类主要特征：前 128 字节 datagram 的双字节 token 序列，以及带方向符号的包长序列。随后按流起始时间排序，以阈值 `γ=1s` 划分 flow-level BURST，构造节点和两类边。

图结构指令微调阶段使用图编码器和流特征编码器做对比学习对齐，再通过 BURST Graph Matching 任务把 `<graph>` token 替换为对齐后的图节点表示。任务指令微调阶段继续冻结 LLM 主体和图编码器，只微调结构感知 projector 与分类头。

## 7. 实验设计与实验步骤

数据：使用 APP53、ISCX-Botnet、ISCX-VPN，并构造 NETD。APP53 用于同时间/同版本 I.I.D. 分类，以及跨时间、跨版本 O.O.D. 分类；ISCX-Botnet 用于未知 botnet 类型下的二分类和多分类；NETD 用于可控动态分布偏移。

预处理：从 pcap/flow 中切分双向五元组流；提取 raw datagram 前 128 字节并双字节编码；提取带方向包长序列；按时间阈值构造 BURST；生成流量关系图。

模型/基线：ETooL 基座为 Vicuna-7B-v1.5；对比 AppScanner、CUMUL、DF、FS-Net、GraphDApp、PERT、ET-BERT。

训练：两阶段微调。第一阶段做图结构自监督指令微调；第二阶段做流量分类任务指令微调。论文设置学习率 `2e-3`，warmup ratio `3e-2`，epoch 为 3，batch size 为 2，最大输入长度 2048。

指标：Accuracy、Macro-Precision、Macro-Recall、Macro-F1。多类任务使用 Macro 平均以减少类别不平衡影响。

消融/敏感性：消融 raw datagram、packet length、图结构指令微调、LLM；敏感性分析 BURST 时间阈值和学习率。

结果核查：重点比较 I.I.D. 与 O.O.D. 下 F1 降幅、跨版本/跨时间零样本测试表现、NETD 不同偏移强度下的稳定性，以及冻结式指令微调的训练显存和时间收益。

## 8. 关键结果、结论与证据

在 APP53 I.I.D. 场景，ETooL 相比 ET-BERT 的 F1 提升分别达到 6.62% 和 4.19%，说明它不是只在漂移场景有效，在常规监督分类中也能利用多流关系提升识别。

在 APP53 O.O.D. 场景，跨时间和跨版本任务中，传统方法性能明显下降。ETooL 在 APP53 O.O.D. 上相对最优基线提升 18.17% 和 15.15%，说明流间交互结构确实比单流特征更抗漂移。

在 ISCX-Botnet O.O.D. 场景，ETooL 在二分类和多分类任务上分别提升 9.16% 和 12.08%。这说明方法不仅适用于 App 指纹，也能迁移到恶意服务识别。

消融结果最有说服力：去掉图结构和图指令微调后，平均 F1 下降 22.13%；去掉 LLM 后平均下降 12.84%。这说明论文性能并非单纯来自“大模型参数量”，而是来自“流量图结构 + LLM 指令适配”的组合。

## 9. 局限性与待解决问题

本文没有解决实时在线检测问题。作者自己也承认 ETooL 的推理时延尚不能满足实时检测，更适合辅助决策或高价值流量分析场景。

方法依赖 BURST 阈值、图构造策略和流采集窗口。如果实际网络中连接复用、HTTP/3/QUIC 行为、NAT 聚合或代理转发导致流间关系被扰乱，TRG 的稳定性可能下降。

NETD 虽然提供可控分布偏移，但它本质上是在 ISCX-VPN 上通过服务组成和比例变化模拟 O.O.D.，仍不能完全替代真实长期采集、多地区、多设备、多协议栈的漂移数据。

本次正文包未被截断，因此理解不受正文缺页影响；但若要复现实验，仍需回到 PDF 和作者实现细节核对表格数值、数据划分脚本、标签清洗规则和 NETD 构造细节。

## 10. 与本项目的关系

这篇论文与“加密流量分类与应用识别”“跨域异常检测”强相关。它对本项目最有价值的启发是：异常检测或流量分类不应只依赖单流特征，而应考虑会话簇、BURST、上下文连接关系和跨流交互结构。

如果本项目面对的是跨时间、跨网络环境、跨设备或跨版本的异常检测，ETooL 的思想可以转化为：把单条告警/流量事件扩展为局部交互图，再用自监督任务学习稳定结构表示，最后做少样本或零样本适配。

## 12. 本篇精华

1. 加密流量 O.O.D. 问题的关键不是“缺少明文”，而是“单流特征随分布变化不稳定”。

2. ETooL 的核心贡献是把多流交互结构转化为 LLM 可理解的图指令表示。

3. BURST Graph Matching 是全文最关键的自监督任务，它迫使模型学习流量图拓扑与流特征之间的对应关系。

4. 论文证明图结构比单纯 raw datagram 或 packet length 更关键，去掉图结构后性能下降最大。

5. LLM 在这里不是用来生成文本答案，而是作为具备上下文推理能力的结构表示适配器。

6. NETD 的价值在于让分布偏移强度可控，为 O.O.D. 加密流量分类提供了更系统的评估方式。

7. 方法性能强，但实时性和真实大规模部署仍是短板。
