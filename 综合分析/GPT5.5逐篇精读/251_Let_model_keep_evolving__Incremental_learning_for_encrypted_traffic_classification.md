# [251] Let model keep evolving: Incremental learning for encrypted traffic classification

## 1. 基本信息
- 论文：Let model keep evolving: Incremental learning for encrypted traffic classification
- 作者：Xiang Li, Jiang Xie, Qige Song, Yafei Sang, Yongzheng Zhang, Shuhao Li, Tianning Zang
- 来源：Computers & Security 137, 103624；在线发表时间为 2023-12-04，期刊卷期对应 2024
- DOI：10.1016/j.cose.2023.103624
- 主题：加密流量分类、应用识别、类增量学习、多视图序列融合、样本记忆选择
- 本地材料：正文包完整，未截断；未发现该论文对应的本地开源代码包

## 2. 中文翻译与核心摘要
这篇论文的核心问题是：加密流量分类模型不能只在固定应用集合上训练一次，因为真实网络中应用会不断新增，旧模型会逐渐失效。传统做法是把旧应用和新应用数据重新汇总后从头训练，但这会消耗大量算力和存储。

作者提出 MISS，一个面向加密流量分类的增量学习框架。MISS 不是简单把计算机视觉里的类增量学习方法搬到流量分类上，而是利用流量本身的多视图序列特征、通信目的地模式和 TLS 证书等先验信息，解决“如何保留旧知识、如何学习新应用、如何减少样本存储”三个问题。

方法上，MISS 先用多视图序列构建较强的初始模型；随后在每个增量阶段只保存少量代表性旧样本，并用 plastic/stable 双分支结构兼顾新知识学习和旧知识保持。实验表明，MISS 在 PURE-TLS、Cross-Platform、USTC-TFC-2016 等数据集上优于已有 ETC 增量方法和迁移了 iCarl 框架的强 ETC 模型。

## 3. 论文解决的具体问题
论文解决的是开放网络环境中的“应用类增量加密流量分类”问题。模型在第 0 阶段只见过一批应用，例如 TikTok、Amap、Twitter；部署后又出现 Alipay、Taobao、Pinduoduo 等新应用。此时模型既要识别新应用，又不能遗忘旧应用。

这个问题比普通加密流量分类更难：一是训练数据按阶段到达，不能一次性获得所有类别；二是存储空间有限，不能保留所有历史流量；三是深度模型更新参数时会覆盖旧知识，产生灾难性遗忘；四是加密流量的特征受网络环境、应用家族、业务类型和 TLS 行为影响，单一特征视角不稳定。

## 4. 创新点深度提炼
1. **把 ETC 问题重新定义为应用类增量学习问题**：论文不再假设应用集合固定，而是让模型随新应用持续演化，这是比封闭集分类更贴近实际部署的设定。

2. **多视图序列融合不是简单拼接**：MISS 同时使用到达时间、载荷字节、包长、TLS content type 等序列视图，并通过跨视图相关矩阵生成 cross-view information，让模型学习不同流量侧信道之间的稳定关联。

3. **代表样本选择利用了流量通信模式**：不同于 iCarl 只依赖特征空间 herding，MISS 先按目的 IP、目的端口、TLS 证书做类内通信模式聚类，再在每个簇内选代表样本。这更符合应用流量由多个服务模块、CDN、后端接口共同组成的事实。

4. **plastic/stable 双分支面向遗忘问题**：plastic branch 保持可学习性，用于适应新应用；stable branch 冻结大部分参数，用于保存最近阶段的旧知识。两者输出再通过可学习权重融合。

5. **把增量学习评估做得比较系统**：不仅比较平均准确率和 F1，还考察样本保留率、初始类别数量、同质应用增量、未知应用发现与聚类等场景，使论文更接近真实部署问题。

## 5. 科学问题与研究假设
核心科学问题是：在加密流量明文不可见、应用类别持续增加、历史数据不可完全保存的条件下，能否设计一种模型演化机制，使 ETC 模型在学习新应用时尽量保持旧应用识别能力？

论文隐含了几条研究假设：

- 多视图序列比单一序列更能表达应用行为，因此强初始模型能提升后续演化能力。
- 应用通信模式具有一定稳定性，目的地址、端口、TLS 证书可以辅助选出更有代表性的旧样本。
- 灾难性遗忘不可完全避免，但通过旧样本回放、知识蒸馏和稳定分支可以显著缓解。
- 初始阶段类别越充分，模型形成的特征空间越稳定，后续增量阶段的性能下降越小。
- 同质应用会压缩类别边界，是 ETC 增量学习中的特殊困难。

## 6. 科学方法与技术路线
MISS 的技术路线分为两个阶段。

第 0 阶段训练初始模型。每条 flow 被表示为多视图序列：`x1` 为包间到达时间，`x2` 为 payload byte 序列，`x3` 为带方向的包长序列，`x4` 为 TLS content type 序列。每个视图有独立特征提取网络，可以是 Text-CNN 或 Transformer。随后计算不同视图之间的 cross-correlation，得到跨视图信息，再用 MLP 类结构做自适应融合，最后用交叉熵训练分类器。

第 i 个增量阶段，MISS 读取新应用数据和旧应用代表样本。旧样本不是随机保存，而是先按通信目的地和 TLS 证书进行类内聚类，再用 herding 选择每个簇中最能代表均值特征的样本。模型结构上，新模型继承上一阶段 plastic branch；同时冻结上一阶段模型形成 stable branch。最终用 plastic/stable 输出加权融合，再结合交叉熵和蒸馏损失训练。

## 7. 实验设计与实验步骤
可复核流程如下：

1. **数据**：使用 Cross-Platform iOS、Cross-Platform Android、USTC-TFC-2016，以及作者构建的 PURE-TLS。PURE-TLS 包含 100 个应用、166,939 条 TLS flow。
2. **预处理**：去除以太网头；分类特征不使用 IP 头和端口，避免强标识偏差；IP、端口和 TLS 证书只用于代表样本聚类。公共数据集提取 payload byte、arrival time、packet length；PURE-TLS 额外提取 TLS content type。
3. **类别划分**：约一半应用用于第 0 阶段初始训练，其余应用平均分配到 `N=1/10/25` 等增量阶段。每次实验随机打乱类别顺序，重复 3 次报告均值和标准差。
4. **样本划分**：训练、验证、测试按 `6:1.5:2.5` 划分；公共数据集每类最多 500 条 flow，PURE-TLS 每类最多 1000 条 flow。
5. **模型与基线**：比较 Omt-CNN、CNN-iCarl+、EBSNN(IL)、ET-BERT(IL)、MISS-CNN、MISS-TF，并测试 MIMETIC 多视图迁移和 iCarl 框架迁移。
6. **训练**：Text-CNN 版本使用 SGD；Transformer 版本第 0 阶段使用 BertAdam；增量阶段训练分支参数，同时用平衡样本小批量更新 plastic/stable 融合权重。
7. **指标**：使用宏平均 Accuracy 和宏平均 F1，强调长尾类别下每个应用的平均表现。
8. **消融与敏感性**：比较不同代表样本选择策略、不同样本保留率、不同初始类别数、同质应用增量、未知应用增量，以及不同视图特征。
9. **结果核查**：重点看 UB 与增量阶段性能差距、旧类准确率下降、低样本保留率下 F1 是否崩溃、同质应用 t-SNE 可分性和未知应用 open-set 性能。

## 8. 关键结果、结论与证据
论文最重要的结论是：面向流量特性设计的增量学习框架明显优于直接迁移视觉领域 IL 框架。

在 Cross-Platform iOS 上，MISS-TF 的增量性能非常接近 UB，`N=1` 时 avg.ACC 为 97.18%，avg.F1 为 97.03%；相对 ET-BERT(IL) 有更强演化能力，即便 ET-BERT 有预训练优势。PURE-TLS 上，MISS 也保持较好表现，并在多阶段增量下优于 Omt-CNN、CNN-iCarl+ 等方法。

代表样本选择的证据也很明确：当样本保留率降到 2% 时，MISS-ES 的 avg.F1 仍显著高于 iCarl-ES 和 Random-ES。这说明通信模式聚类加 herding 的组合确实比纯特征均值或随机保存更适合 ETC。

同质应用实验揭示了一个重要现象：来自同一公司家族或同一业务类型的应用会降低增量收益，但 MISS 的多视图特征能缓解这种影响。未知应用实验则说明，开放集发现和聚类错误会向后传播，新增未知类别越多，演化效果越受非增量组件拖累。

## 9. 局限性与待解决问题
论文的主要局限有四点。

第一，PURE-TLS 虽然强调纯 TLS，但删除非 TLS 流量可能丢失应用行为的一部分，尤其是混合协议应用。因此它更适合研究 TLS 场景，不一定覆盖完整移动应用网络行为。

第二，实验中每类最多抽取 500 或 1000 条 flow，可能削弱真实长尾差异。作者也承认后续应考虑按比例欠采样，更好保留类别间分布差异。

第三，同质应用仍是困难场景。相同云服务、相同 SDK、相同业务 API 会让不同应用在加密侧信道上高度相似，MISS 虽然缓解但不能根治。

第四，未知应用演化仍依赖开放集识别和聚类质量。OpenMax 与 constrained clustering 的错误会进入增量训练，导致误差传播。论文还没有形成完整的“发现-验证-标注-演化”闭环。

## 10. 与本项目的关系
这篇论文与“加密流量分类与应用识别”强相关，也可迁移到异常检测项目中的持续学习场景。异常检测系统部署后会不断遇到新应用、新服务、新攻击家族、新业务流量，如果每次都全量重训，成本和响应速度都不可接受。

对本项目最有价值的不是某个具体网络结构，而是三点思想：用多视图流量序列提高初始表征质量；用通信模式选择少量历史代表样本；用稳定/可塑双机制控制模型更新。若项目涉及跨域异常检测，可把“旧域正常/异常模式保持”和“新域样本适配”对应到 MISS 的 stable/plastic 思路。

## 11. 代码对照分析
本地未发现该论文对应的代码包，因此无法做真实源码逐文件对应，也不能确认作者实现中的具体目录结构。

如果复现 MISS，代码通常应拆成以下模块：

- `preprocess/`：PCAP 解析、flow 切分、TLS flow 过滤、以太网头移除、序列截断到前 32 个包、payload 前 128 字节提取。
- `features/`：arrival time 二元编码、payload 2-byte chunk 字典编码、带方向 packet length 编码、TLS content type 编码。
- `datasets/`：Cross-Platform、USTC-TFC-2016、PURE-TLS 的类别阶段划分、训练/验证/测试拆分、增量阶段采样。
- `models/`：Text-CNN/Transformer 视图编码器、cross-view correlation、压缩网络 `phi`、MLP adaptive fusion、分类头。
- `incremental/`：exemplar selection，包括按 `{dst_ip, dst_port}` 和 TLS certificate 的类内聚类，以及 intra-cluster herding。
- `train.py`：第 0 阶段交叉熵训练、增量阶段双分支初始化/冻结、交叉熵加蒸馏损失训练。
- `eval.py`：宏平均 ACC/F1、phase-wise 曲线、UB/LB 对比、不同 `T%` 保留率测试。
- `open_set/`：OpenMax、未知应用拒识、Modified PCKMeans 聚类，若复现实验 5.4.5 需要实现。

## 12. 本篇精华
- 加密流量分类不应只做封闭集分类；真实部署更接近类增量学习。
- MISS 的关键不是“用了 Transformer”，而是把多视图流量序列、代表样本选择和双分支抗遗忘组合起来。
- 初始模型的 UB 很关键；第 0 阶段学得越充分，后续演化越稳。
- 旧样本保存不能只随机抽样，应用通信模式是 ETC 任务中非常有价值的先验。
- 样本保留率是性能与资源的折中参数；低保留率下代表样本选择算法的作用会被放大。
- 同质应用是加密流量分类的天然难点，尤其是同公司、同业务类型、同云服务生态。
- 未知应用增量的瓶颈不只在分类器，还在开放集发现和聚类，错误会进入后续训练。
- 对异常检测项目而言，MISS 提供了一种“少量记忆样本 + 可塑/稳定模型”的持续演化范式。

建议先读 Introduction 和 Preliminaries，抓住论文的问题设定：为什么 ETC 需要增量学习，以及 `D_i`、`lambda_i`、阶段模型 `M_i` 的定义。
