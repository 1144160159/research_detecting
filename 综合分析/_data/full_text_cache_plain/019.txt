Flow Level and Circuit Level Classification
Khalid Shahbar

A. Nur Zincir-Heywood

Faculty of Computer Science
Dalhousie University

Abstract— Recently,
many internet users, who seek
anonymity, use Tor, which is one of the most popular anonymity
software solutions. Tor provides this anonymity by hiding the
identity of the user from the destination that the user aims to
reach. It also hides the user activities into encrypted cells. In this
work, we investigate up to what level we can define what the user
in Tor is doing. To this end, we extended on the previous work to
classify the user activities using information extracted from Tor
circuits and cells. Moreover, we developed a classification system
to identify user activities based on traffic flow features. Our
results show that flow based classification can reach up to the
accuracy of the cell level classification as well as being more
flexible.
Keywords—Tor traffic classification; Traffic Flow; Tor
Circuits

I.

INTRODUCTION

Tor provides its users with anonymity by hiding their
browsing activities and locations. This level of anonymity
achieved by relaying the users activities through three Tor
nodes. When the user connects to the first relay, the first relay
knows the IP address of this user. The user activities stay
encrypted while moving from the first relay to the second one,
and from the second one to the third one. The third relay sends
the user activities on behalf of the user without any information
regarding the identity of the user.
In this work, we aim to analyze the amount of information
that can be extracted from the encrypted Tor traffic without
decrypting the traffic. To explore this, we propose to employ
machine learning (ML) algorithms. To this end, we employ
two different approaches for the classification of user activities.
The first approach is the Flow level classification. It depends
on analyzing the TCP communication between the user and the
relay to predict the type of user activities in the encrypted
traffic. The second approach is the Circuit level classification.
The encrypted circuits have characteristics that can be
extracted and calculated to classify the type of traffic in the
circuits. The main difference between the Flow level
classification and the Circuit level classification is the level of
access to Tor network. The Circuit level classification requires
having access to the relay node, itself [1]. That means only the
one who runs the relay can gather the required statistics about
the circuit. On the other hand, the Flow level classification
requires access to anywhere between the user and the relay.

This means the collection of the encrypted TCP
communication between the user and the relay can be in the
user machine, the relay machine, or the ISP.
Our work provides a benchmarking study for the
classification of Tor user activities. Furthermore, we extend the
prior work [1] for classifying Tor circuits to achieve high
classification accuracy, and aim to classify Tor flows with high
accuracy even without having access to the relay.
The reminder of this paper is structured as follows. Section
II presents the related work. Tor background is reviewed in
section III. Features used in both the Flow and the Circuit level
classification are explained in section IV. Experiments
performed and the results obtained are presented in sections V
and VI, respectively. Finally, conclusions are drawn and the
future work is discussed in section VII.

II.

RELATED WORK

In [1], Alsabah et al. used ML algorithms to classify the
application used by Tor’s users. The applications are
Browsing, Streaming and BitTorrent. Because Tor traffic is
encrypted, they used the circuit level and the cell level
information to do the classification. The circuit level
information includes the circuit lifetime and the amount of data
transferred by the circuit. The cell level information includes
the inter arrival time of the cells and their statistics. The
classification includes online and offline classification. The
online classification uses the cell level information to classify
the circuit while it is in use. The offline classification uses both
the cell and the circuit level information to classify the circuit.
In terms of accuracy, the best result they achieved in the offline
classification is 91%, whereas the best results achieved in the
online classification is 97.8%.
In [2], a simulated Tor network is used to differentiate
between encrypted traffic and Tor traffic. The simulated
network contains three directory servers and fifteen relays.
Salenium browser (a Firefox add-on) is used to gather a sample
of thirty website browsing traces. To do the comparison
between the two types of encrypted traffic, HTTPS traffic is
gathered alone for a period of two weeks then followed by
HTTP traffic over the simulated Tor network for two weeks.
Lastly, an HTTPS over the simulated network is gathered also
for two weeks. In total, around 25 GB of data collected for the

check the size of the requested site; (iv) Rounded transmitted
bytes: the number of all transmitted packets in both directions
(rounded in increments of 10,000); (v) Number of markers:
grouping the packet size for all packets of a flow in one
direction; (vi) Occurring packet size: the number of each site’s
packets in both directions; (vii) Percentage of Incoming
Packets; and (viii) Number of packets. Using these features
improves the results of detecting closed world websites from
3% to 55% in Tor network and from 20% to 80% in JAP
compared to other related works. In the open world data set,
the detection is 73% with 0.05% false positive rate.
In [4], authors use traffic analysis to discover the identity of
the user using the Tor network. The analysis depends on the
size of the packet transmitted on the network from the web
server through the router to the user. Tor has a fixed cell size
but the packet size can vary. So they used padding with one bit
to mark the packets so that they could be traced back at the
receiver side. The authors report that ten packets are enough to
get a reasonable detection with low false positive. The length
of the padding will force the Tor router to use the known
number of cells. The Tor cell size is 512 bytes, which means if
the data size is more than 512 bytes then it needs to be
fragmented to fit into the cell size. This enables the authors to
mark the client who receives these cells as the client has access
to the server. During the path from the server to the client,
packets may face congestion, retransmission or any normal
traffic behavior that affects the receiver to detect the encoded
bit. To solve such problems, delay is used between buffered
packets before sending them. By setting the delay interval to
400 ms, the authors achieved a detection rate of 90% with 4%
false positive rate.

III.

TOR BACKGROUND

Tor is a publicly available software that is built to provide
users with anonymization when using the Internet. Tor
Network depends on the volunteers who run their machines as
relay nodes to forward other users’ traffic through Tor. The
user starts by establishing a virtual circuit. This circuit consists
of three relays. A directory server is used to get the addresses
of available routers and their keys to encrypt the data. User
data is encrypted with three layers of encryption. First, data are
encrypted with the last relay (exit router) key then the middle
relay and finally, by the first relay (entry router). This way, the
entry router only knows the source of the data. The middle
router(s) only knows where to get the encrypted data and
where to send them, but nothing about the source of the data or
the destination of them. Finally, the exit router knows the
destination of the data, but knows nothing about the source.
This ensures that the whole path is not known by any of the
three nodes (routers) on the Tor network.
The user and the relay use encrypted TLS connections to
communicate. Circuits and cells are the components for Tor
communication. The circuit is a virtual path from the user
machine to the last relay (the exit relay). Inside the circuit the
data are packed into cells. Each cell contains the identifier of
the circuit it belongs. The circuit ID is unique in the connection
between the user and the relay. Through the path, the circuit ID
is not the same.
Figure 1 shows the sequence for establishing the circuit.
When the user wants to send data through Tor, he/she starts by
establishing a circuit. The circuit establishment starts from the
user to the first relay in a CREATE cell. When the circuit is
established, the relay sends back the CREATED cell to the
user. The user then extends the circuit to the second relay by
using the RELAY_EXTEND cell. The first relay sends the
CREATE cell to the second relay. The second relay responds
back with the CREATED cell when the circuit is established
between the first and the second relay. The first relay replies
back to the user with the RELAY_EXTENDED cell to inform
the user that the circuit path is now up to the second relay.

type of traffic and the number of cells that flow in the circuit.
The higher the amount of data the higher the number of cells.

how the application acts to send data requests.

IV.

CLASSIFICATION FOR TOR

A. Circuit Level Classification
This approach depends on using statistics extracted from
the Circuits and their Cells to classify the user activities in the
Tor traffic without decrypting the traffic. It is similar to the
work done in [1] but we extended it with the following
attributes:
1) Cells per circuit life time: The amount of data delivered
by a circuit is a good indication about the type of traffic carried
by the circuit. But without considering the time the circuit is
alive, this indication might be misleading. For example, two
circuits might deliver the same amount of data in two different
durations. As shown in Figure 5, the number of streaming
circuits and BitTorrent circuits are both high compared to the
number of browsing circuits. The circuit life time is what
distinguishes between them.

2) Uplink Cells: Relays’ cells are transferred in both
directions; uplink and downlink. BitTorrent seems to transmit
higher amount of uplink cells than the browsing or streaming
applications. In other words, number of cells required to send a
request might be a good indicator of the type of traffic running
on the Tor network.
3) The Rate of the Downlink Cells to the Uplink Cells:
Even though the uplink data is a good indication about the type
of traffic the circuit has, the rate of the uplink to the downlink
is also important. If the circuit life time is long enough, it could
transmit considerable amount of uplink cells even if it is used
for browsing. However, most of the time, the rate will vary
based on the type of traffic no matter how long the life of the
circuit is. Figure 6 shows the rate of the downlink cells to the
uplink cells with the circuit life time.

Intuitively, we think that EWMA is a good indicator because it
can differentiate between two circuits when both have the same

1) Tranalyzer2: This is an open source tool that generates
flows from a captured traffic file or directly by working on the

Selecting which attributes to include in the classification of Tor
is very important.

only ground truth known to us. We differentiate our own traffic
using the IP address.
The flow between the client and the node contains many
other information that are used by the flow exporters to
generate the attributes. For example, the IP address, the port
number, the MAC address, time when the flow starts or ends,
the sequence number and any information related to the
physical client but not the data between the client and the node.

V.

EXPERIMENTS

A. Setup
In our experiments, we set up a testbed with three clients.
These three clients are used to automatically generate the three
traffic types: Browsing, Streaming and BitTorrent. All the
clients are configured to use our node as the only entry node.
We used iMacro [11] to automate the Browsing and the
Streaming activities. Both of them start by searching for
random words generated using the English alphabets. They
pick randomly one of the sites returned for the search made. In
case of Browsing, the iMacro script picks one of the search
results, it navigates through the site by clicking a random
hyperlink existing on the web site. It keeps moving from one
link to another. For each link, the client will stay for a random
period of time on that page then move again to another link.
The setting is similar in the streaming activities. The script
will move from one video to another. The time spent for
watching a video or moving from a link to another is set
randomly. The difference between the time set in the browsing
and the streaming is that the streaming random time is little
longer than the browsing time setting. Deluge [12] is used as
the BitTorrent software. We used a proxy to be an interface
between the clients’ traffic and the Tor node. The socket port in
Tor is enabled to listen for the proxy requests.
Tor source code is edited to log only incoming circuit
creation requests from our clients. The IP address of each client
is used to enable the logging and also to label the circuit as one
of the three traffic types. This keeps the privacy of the users
who use our node on the Tor network.
B. Data Collection
1) Circuit Level Classification Data
The circuit level classification is based on the cells statistics
per circuit to distinguish between each traffic type. Tor source
code is edited to relate each circuit to its source IP. Even for
the relay cells where Tor will switch the circuit ID, we make
Tor logging this ID in its previous circuit ID not the new
switched ID. This way we keep track of the uplink and the
downlink cells related to each class. The log for each circuit
contains the circuit ID, the class, the time when the circuit is
created, and the time when the circuit is destroyed. Cells’ log
contains the class and the circuit ID each cell belongs to, the
cell arrival time, and the direction of the cell. The attributes we
need in the circuit level classification are then extracted from

the circuits log and the cells log. To maintain the privacy of
other users, circuits related to the other users using our node
have not been logged.
2) Flow Level Classification Data
PCAP network traces are collected in the entry node
machine for the duration of the experiment (10 hours). The
required connection information are the traffic between our
entry node and each client. To keep the privacy of other users
who use our node, a filter is applied to the capturing so only
connections from our clients are logged. For the duration of the
experiment, we captured 4.2 GB of data.

D. Classification Algorithms
We used four supervised ML algorithms: Naïve Bayes,
Bayes Net, C4.5 and Random Forest. Naïve Bayes is a simple
algorithm based on Bayes theorem. Naïve Bayes [16] does not
take into consideration relations between variables while Bayes
Net [17] is more general form that makes connections between
the related variables. C4.5 [18] is a pruned decision tree based
on the information gain of the attributes. Random Forest [19]
depends on building multiple decision trees to enhance the
decision making. A more detailed information about each one
of these well-known classifiers can be found in [20]. We have
used Weka [21] to implement each of the classifiers with its
default parameters.

RESULTS AND DISCUSSION

A. Circuit Level Classification Results
We used the circuit level classification with the use of the
cell attributes in this approach. The data set consists of 60%
browsing, 20% streaming and 20% BitTorrent activities. Table
II shows the results for the circuit level classification. In this
case, accuracy reaches to 100% when using C4.5 classifier
with 70% of the instances as a training set. When 10-Fold
cross-validation is used, the best accuracy was ~95% using the
random forest classifier. Figure 7 shows the results for the
circuit level classification for all the classifiers using the 70-30
training/testing split and the 10-fold cross validation.
B. Flow Level Classification Results
In this case, data set consists of the uniform distribution of
the three classes. The number of flows is approximately the
same for each class. Even though the amount of data
transferred by the Streaming and BitTorrent circuits are larger
than the browsing circuits. Table III shows the results when
using the uniform distribution of the three classes. The results
are 88% to 100% when using 70% of the instances as the
training set. When using the 10-Fold cross-validation, results
are 86% to 99%.
It should be noted here that the data set employed in [1]
consisted of 60% browsing instances, 20% streaming instances
and 20% BitTorrent instances. Those authors generated such a
data set to mimic the traffic distributions of Tor users. To make
our results comparable to theirs, we downsampled our data to
generate a data set with the same distributions. Table IV shows
the results when our data set consists of the same distributions
as [1]. In this case, our results still show high accuracy in both
the split and the 10-Fold cross-validation evaluations. Bayes
Net classifier achieved 100% in both the split and the 10-Fold
cross-validation evaluations. Figure 8 shows the accuracy for
all the three classifiers when using the 10-Fold cross-validation
evaluations.

10-Fold Cross-Validation. The classification level used was at

make the BitTorrent’s circuit behavior look similar to the
browsing’s circuit behavior. Therefore, adding the number of
cells transferred during the circuit lifetime as an attribute to the
attribute set in our work enables the circuits to be more

user privacy. To the best of our knowledge there is no publicly
available Tor data set. This is because for such studies, one
needs to capture (collect) the data on the wire. For this reason,
we generated and captured the traffic as explained above.
The circuit level classification requires access to the
traffic generated by the connections between the user machine
and the Tor relay. In the circuit level classification, the access
to the relay itself is required. That means classification at the
circuit level has its limitations in terms of who can employ it.
However, flow level classification does not have these
limitations. From the availability prospective, the flow level
classification is easier to apply compared to the circuit level
classification. The tools used in the flow level classification
are available online. These tools include traffic capturing
(such as Tcpdump or Wireshark) and flow exporters to
generate the flow statistics (such as Tcptrace or Tranalyzer2).

The challenge in the flow level classification is in dealing
with the similarities in the traffic at the flow level. Therefore,
the selection of the attribute set makes a difference in the
performance of the classification. Capturing similar data in
circuit level classification (the way we did) that are ready to be
classified by the ML algorithms requires additional efforts
compared to the flow level classification data. The circuits and
cells information in the Tor code maintain a certain level of
privacy for the Tor's users. For instance, Cells statistics
attribute (CELL_STAT) that are introduced in Tor version
0.2.5.2-alpha are only available when Tor is working in the test
mode. This mode works only when TestingTorNetwork value
is set in Tor configuration file as described in Tor control
protocol [13].

That means using this feature will work only in private
networks not the live Tor network. STEM [14] also can
provide the user with information about Tor. It provides a
library for the user to communicate with Tor using Tor control
protocol. It can generate useful information about the circuit
and bandwidth usage and so on, but for the same previous
example, STEM cannot retrieve the cells statistics by using
CELL_STAT event unless Tor is working in the test mode.
In terms of the size of the data used by the two approaches,
the flow level classification data is larger than the circuit level
classification data. The information in the circuit level is
gathered in the form of a text file where each line represents
information about a circuit or a cell. Although the number of
records is large because of the large number of cells in each
circuit, still in a text file this will come to a small size
compared to PCAP files. However, for both approaches, when
the data are converted to a form that the classier understands
then the size becomes very small.

VII. CONCLUSION AND FUTURE WORK
In this research, we used machine learning algorithms to
classify Tor traffic by using two different approaches: circuit
level classification and flow level classification. The results
show that a high accuracy can be achieved using both
approaches. The circuit level classification uses the data
captured (collected) at Tor’s relay machine. In contrast, the
flow level classification uses the data that are captured
(collected) anywhere between the user and the Tor’s relay
machine. Access to the relay machine is not essential in the
flow level classification. This enables a very flexible approach
to analyze the traffic.
For future work, we aim to use these approaches to classify
the user activities online. For both approaches, this will require
changes to the attribute set. Therefore, further investigation
will be necessary.
