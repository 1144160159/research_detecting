ABSTRACT The lack of standardization across publicly available network intrusion detection datasets

presents a significant challenge in developing generalizable machine learning-based models. These existing
datasets often exhibit inconsistencies in feature sets and typically focus only on flow-level data, overlooking
critical elements such as payload information and time-window-based contextual features. Such limitations
make it difficult to detect sophisticated, time-sensitive attacks that rely heavily on both payload analysis and
temporal patterns in network behavior. To address these challenges, we propose a unified multimodal dataset
that integrates flow, payload, and contextual features from several renowned datasets. Our methodology
implements a three-stage pipeline that processes raw packet capture (PCAP) files, extracts detailed
metadata, and synchronizes the flow and payload data with time-based contextual features to ensure a
comprehensive and enriched dataset. This approach allows for extensive cross-dataset validation, enabling
the development of more robust and adaptable machine learning models for network intrusion detection.
By providing a unified feature space and incorporating payload and contextual data, the dataset enhances
the ability to detect a wider range of network threats with greater precision.

BACKGROUND

Network intrusion detection systems (NIDSs) are critical
tools in identifying and mitigating malicious activities within
network traffic, ensuring the protection of critical systems
from unauthorized access and disruptions [1]. Unlike traditional rule-based systems, modern NIDSs leverage machine
learning to detect a broader spectrum of threats by learning
from complex patterns in large datasets. These machine
learning models are trained to recognize various types of
attacks based on network data, which can be categorized
into two primary forms: packet payloads and flow-level

information [2]. This shift from static, rule-based detection
to dynamic, data-driven approaches allows NIDSs to more
effectively detect both known and emerging threats in real
time [3].
Packet payloads contain the actual data transmitted between network entities, while flow-level information provides aggregated statistics about the communication between
endpoints, such as data transfer volumes, connection durations, and interaction frequencies. Flow-based approaches
are particularly effective for detecting large-scale anomalies,
such as denial of service (DoS) attacks, which generate

the other hand, packet-based NIDSs focus on examining

query language (SQL) injection and buffer overflow attacks,
where the malicious behavior lies within the content itself

increasing recognition that combining both flow and packetbased analysis can enhance detection accuracy across a
broader range of network intrusions [6].
To train machine learning models for NIDS, researchers
have developed benchmark datasets that simulate network
behavior under both normal and attack conditions. These
datasets, often captured in packet capture (PCAP) format,
provide labeled examples of benign and malicious network
flows [7]. The datasets are generated in controlled environments, using network testbeds to simulate traffic between
multiple nodes while introducing various attack scenarios.
This data are then processed into flow-level information
for use in machine learning models. While these publicly
available datasets have been instrumental in advancing NIDS
research, they also exhibit several limitations that hinder
the generalization and scalability of machine learning-based
detection models [8], [9].
First, there is a lack of consistency in the feature sets
across datasets, as different institutions use varying tools and
parameter settings to generate flow-level data. This results
in feature spaces that differ significantly between datasets,
preventing effective cross-dataset validation and limiting the
ability to train machine learning models on a comprehensive
set of attack classes. While some efforts have been made to
standardize the feature space, they have typically provided
labeled flow-based features, restricting studies that require
corresponding payload data [8]. Additionally, these efforts
do not provide any tool to extend the dataset further, limiting
research to the predefined datasets. Therefore, a unified
feature space that includes both payload and flow modalities
is essential for enabling cross-dataset learning and improving
the generalization capabilities of NIDS models.
Second, most publicly available datasets provide only
flow-level features, neglecting the payload information that
is critical for detecting attacks where the malicious activity
is embedded in the data content rather than the flow itself.
To address this gap, we previously developed a tool, Payload
Byte [10], which labels individual packet payloads as either
benign or malicious. However, practical NIDSs require both
flow and payload data to overcome the limitations of each.
This requires linking packet payloads with their corresponding flows to enable more comprehensive intrusion detection.
Last, current datasets lack time-window-based features
that are crucial for detecting attacks that evolve over time,
such as distributed denial of service (DDoS) attacks. These
attacks may change their behavior gradually, and without
contextual or historical information about the targeted net-

work’s state over a given time period, it becomes challenging
to accurately detect such threats. For example, analyzing how
many internet control message protocol (ICMP) requests
were received by a server within a specific time frame can
significantly reduce false positives and improve the detection
of ICMP-based DDoS attacks.
To address these limitations, we have developed a tool
and a multimodal, unified intrusion detection dataset that
standardizes data from multiple widely used sources. This
approach enables the integration of different network data
modalities, including both flow-level and payload-based features, creating a comprehensive dataset for more effective
intrusion detection. Our tool not only standardizes feature
extraction across datasets but also introduces additional
contextual features, such as time-window-based information, providing a historical perspective on network activity.
The dataset currently incorporates four major datasets—
CIC-IDS 2017 [11], CIC-DDoS 2019 [12], UNSW-NB15
[13], and CIC-IoT 2023 [14]—and can be further extended
through our GitHub tool, which allows the processing of
any raw PCAP files into this standardized feature space. This
unified dataset offers a comprehensive view of network intrusions, enabling cross-dataset validation and the development
of more robust NIDS models.
PROPOSED METHODOLOGY

To create a unified multimodal intrusion detection system
(UM-IDS) dataset that includes network flow data, associated packet payloads, and additional contextual features, we
developed a comprehensive three-stage processing pipeline.
Each stage is designed to systematically transform raw PCAP
files into a labeled, structured dataset ready for analysis and
model training. The pipeline consists of the following stages.
Stage I: PCAP Processing

As shown in Fig. 1, the first stage involves the parallel
processing of raw PCAP files, which are collected from
multiple datasets. To efficiently handle the large volume of
data, each PCAP file is assigned to a worker for independent
processing, significantly enhancing the speed and scalability
of the system.
During this stage, special consideration is given to handling large files. If a PCAP file exceeds 2 GB, it is automatically split into smaller comma-separated values (CSV) files.
This mechanism ensures efficient memory usage and facilitates the smooth processing of large-scale network traces
without overloading the system, supporting the scalability
of the pipeline when dealing with massive datasets.
This efficient file management is complemented by the use
of NFStream [15], a versatile network traffic analysis tool
that serves as the core component of the PCAP processing
stage. To enhance its functionality, a customized plugin
was developed to extract detailed flow and packet-level
features. The plugin captures standard flow metrics such
as bidirectional packet counts, source-to-destination packet

Contextual Feature Impact

In the first experiment, we assessed the performance of a
random forest classifier on several datasets, both with and
without the inclusion of contextual features. The process
began with data cleaning, where we removed features that
could bias the classifier, such as source and destination IP
addresses, port numbers, and starting timestamps. We also
excluded any rows containing erroneous data. Afterward, the
dataset was split into a 70:30 ratio for training and testing.
Once the dataset was prepared, we trained the classifier using the training set having contextual features and evaluated
its performance on the test set. To compare, we then removed
the contextual features from the training set and repeated
the evaluation on the same test set. This direct comparison
allowed us to clearly demonstrate the improvements in
performance gained from including contextual features.
As shown in Table II, the results demonstrate a substantial improvement in classifier performance when contextual
features are included. For instance, on the CIC-IDS 2017
dataset, the F1-score increased from 0.80 without contextual
information to 0.93 with it. Similar trends were observed
in the CIC-IoT 2023 dataset, where the F1-score rose from
0.83 to 0.96. Even in the more challenging CIC-DDoS 2019
dataset, contextual features helped the classifier achieve an
F1-score of 0.74, compared to just 0.43 without them. These
results underscore the importance of contextual information
in improving the accuracy and reliability of machine learning
models in detecting network intrusions.

CONCLUSION

In this article, we developed a comprehensive three-stage
processing pipeline for creating a UM-NIDS dataset. This
dataset integrates network flow data, associated packet payloads, and additional contextual features to address significant limitations in current publicly available datasets.
These limitations include inconsistencies in feature sets, the
absence of payload-level data, and the lack of time-windowbased contextual information. By standardizing the feature
space across different datasets and incorporating both flow
and payload data, our approach significantly enhances the
ability to detect sophisticated attacks, such as those relying
on payload characteristics and time-sensitive behaviors.
Our experimental analysis highlights the value of these
contextual features and payload data in improving the performance of machine learning-based NIDS. Specifically, our
results demonstrate that models trained with the unified
dataset and enriched features outperform those relying solely
on flow-level data. Furthermore, the flexibility of the tool we
developed enables users to customize the dataset according
to their specific research needs, including adjusting the
sampling strategy and contextual feature settings, making it
adaptable for a wide range of scenarios.
The final labeled UM-NIDS dataset provides a robust
foundation for cross-dataset validation and the development
of more generalized models, addressing a critical gap in
the field of network intrusion detection. This contribution
significantly advances the ability of researchers to develop
and evaluate NIDS models using a comprehensive, multimodal dataset that supports more accurate and versatile threat
detection.

REFERENCES

The UM-NIDS Tool is designed to facilitate the generation of
the unified multimodal NIDS dataset. This tool enables users
to standardize datasets, ensuring consistent feature space,
payload content, and contextual attributes across multiple
NIDS datasets. Additionally, it allows for the extension of
the dataset by processing additional raw PCAP files into the
same unified format. To extend the dataset or standardize
another dataset, the basic requirements include the PCAP
files and their corresponding pre-labeled CSV files. These
two elements are essential for converting the data into this
unified format.
An additional feature in the repository provides flexibility
in the labeling process. If the labeled CSV files are not
available, the tool can also label the PCAP files using the
MAC addresses of attackers, if such metadata are available. This provision allows users to perform labeling and
conversion into the unified dataset format without needing
pr-labeled CSVs. Examples demonstrating both approaches,
using prelabeled CSVs and MAC addresses for labeling,
are included in our GitHub repository. The source code and
scripts for this tool are also available on GitHub, allowing
users to easily extend and modify the dataset.
https://github.com/SyedWaliAbbas/UM-NIDS-Tool
