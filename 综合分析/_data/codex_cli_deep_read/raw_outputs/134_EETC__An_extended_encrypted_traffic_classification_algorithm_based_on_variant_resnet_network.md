# [134] EETC: An extended encrypted traffic classification algorithm based on variant resnet network

## 1. 基本信息

- 论文：EETC: An extended encrypted traffic classification algorithm based on variant resnet network
- 作者：Xiuli Ma, Wenbin Zhu, Jieling Wei, Yanliang Jin, Dongsheng Gu, Rui Wang
- 年份与来源：2023，Computers & Security
- DOI：10.1016/j.cose.2023.103175
- 主题定位：加密流量分类、VPN/应用联合识别、类增量学习、灾难性遗忘缓解
- 数据集：ISCXVPN2016、自采 VPN 应用流量、TLS 四类流量
- 代码状态：本地未发现该论文对应开源代码包

## 2. 中文翻译与核心摘要

这篇论文的核心目标不是单纯再做一个“把流量转图片再分类”的模型，而是解决加密流量分类在真实部署中会遇到的持续扩展问题：新 VPN 隧道、新 App、新业务类型不断出现，传统离线模型一旦遇到新类，通常要全量重训。

EETC 的方案由三部分组成：首先，把原始加密流量按五元组聚合，删除 MAC 和 IP，按上下行方向插入不同 padding 字节，再把连续 3072 字节重塑为 `32×32×3` RGB 图像；其次，用改造版 ResNet18 进行分类，目标是同时保留 payload 内容特征和包方向、频率等统计特征；最后，引入增量学习，在有限记忆空间下保存代表性旧样本，通过蒸馏损失、偏置向量和经验回放缓解灾难性遗忘。

实验显示，EETC 在 ISCXVPN2016 上达到 98.1% 准确率，在自采数据集上达到 96.0%，在 TLS 数据集上达到 97.3%。更重要的是，在逐步加入新类别时，模型不需要从头训练，并能在有限 memory buffer 下维持较高分类性能。

## 3. 论文解决的具体问题

论文针对的是“加密流量细粒度识别 + 类别持续扩展”的组合问题。加密流量内容不可直接解析，端口和 DPI 方法失效，而网络管理、安全审计、QoS 调度仍需要知道流量属于哪个应用、是否经过 VPN、属于哪类业务。

已有深度学习方法通常有两个缺陷：一是输入表示存在信息损失，例如截断前 784 字节、只取 payload、只取统计字段，容易丢掉长包或包间结构；二是训练模式静态化，模型只能在固定类别集合上工作，新类型出现时要重新训练，代价高且不适合快速变化的加密流量环境。

因此，EETC 解决的具体问题可以概括为：如何在不解密、不依赖端口和人工规则的条件下，把加密流量转换为适合 CNN 学习的表示；如何在新流量类别持续出现时，让分类器增量扩展而不严重遗忘旧类别；如何在 VPN 隧道与应用类型交织的场景中实现较稳定的多标签意义上的识别。

## 4. 创新点深度提炼

第一，论文提出了一种面向加密流量的 RGB 图像构造方式。它不是简单把固定长度 payload 灰度化，而是将连续包拼接，并用不同 padding 值区分上下行包。上行 padding 为 0，下行 padding 为 240，这让图像纹理同时携带内容字节、方向边界和交互节奏。

第二，论文强调保留包头信息，但删除 MAC 与 IP。实验中“Header + Payload”相比仅 payload 准确率从 83.7% 提升到 98.1%，说明包长、协议类型、TTL、版本号等头部字段对加密流量分类有显著价值；删除地址字段则是为了避免模型记住采集环境中的固定主机特征。

第三，论文把类增量学习引入加密流量分类。相比只报告离线准确率，EETC 关注新类别加入后的模型更新周期、记忆容量、旧类遗忘等部署问题，这是它区别于大多数流量图像分类论文的关键。

第四，论文提出 bias vector 与 balance factor 来修正 Softmax 对新类的偏置。增量学习中，新类样本通常更充分参与当前训练，分类头也会新增权重，模型容易偏向新类别；作者用预测标签与真实标签统计形成偏置向量，再归一化得到平衡因子，参与交叉蒸馏损失。

第五，论文同时比较了类增量场景下的 BV 策略和更接近数据流的 GIL 策略。BV 偏向代表性样本选择和偏置校正；GIL 使用 reservoir sampling 和正则化回放，更适合未知长度数据流，体现了从静态数据集向流式部署过渡的思路。

## 5. 科学问题与研究假设

核心科学问题是：加密流量虽然 payload 被加密，但其字节分布、包头字段、上下行方向、包间拼接模式是否仍保留足够稳定的类别判别信息？论文的实验假设是，这些信息可以通过图像纹理被卷积网络捕获。

第二个科学问题是：用于自然图像的残差网络是否适合小尺寸流量图像？作者假设小尺寸 `32×32×3` 输入中存在局部纹理与跨包结构，因此使用去掉 max pooling、调整卷积核的 variant ResNet18 可以比原始 ResNet18 更有效。

第三个科学问题是：加密流量分类模型能否在类别不断增加时持续学习？作者假设代表性旧样本回放、知识蒸馏和偏置校正能够共同缓解灾难性遗忘，使模型在有限内存下保留旧类能力。

第四个假设是：VPN 通道和应用类型并非完全不可分。即使 App 流量被 SSR、Psiphon、OpenVPN 等隧道封装，包长、方向、频率和部分头部模式仍然能支持“应用 + VPN”层面的联合区分。

## 6. 科学方法与技术路线

技术路线可以拆成“表示学习、分类网络、持续学习”三层。

表示学习层面，原始 pcap 先按五元组聚合，剔除非目标流量；然后删除 MAC/IP，防止地址泄漏；再按包方向插入不同 padding，使图像中出现可学习的方向边界；最后每 3072 字节归一化并重塑为 `32×32×3` RGB 图像，转为 TFRecords。

分类网络层面，论文以 ResNet18 为基础，但针对小尺寸流量图像做改造：去掉 max pooling 以减少细粒度信息损失，调整卷积核设计，用残差连接缓解深层训练困难，最后通过全局平均池化和全连接 Softmax 输出类别概率。

持续学习层面，论文给出两条路线。BV 路线使用代表性记忆，按类别均值的欧氏距离选择样本，并用 bias vector 修正新旧类不平衡。GIL 路线面向流式数据，不依赖明确任务边界，用 reservoir sampling 更新 memory buffer，并把当前样本交叉熵、旧样本 logit 约束、旧样本分类损失组合起来训练。

## 7. 实验设计与实验步骤

1. 数据：使用 ISCXVPN2016，包含 Chat、Email、File、P2P、Streaming、VoIP 及其 VPN 版本共 12 类；自采数据包含 YouTube、Zalo、Weibo、WeChat 在 SSR 与 Psiphon 两种 VPN 下的 8 类；另有 HTTPS、SMTPS、POP3S、FTPS 四类 TLS 数据。

2. 预处理：按五元组聚合流量，删除 MAC 和 IP；保留 header 与 payload 中其他字段；按上下行方向分别填充 0 和 240；每 3072 字节生成一个 `32×32×3` 图像；归一化后写入 TFRecords；训练集与测试集按 9:1 划分。

3. 模型/基线：主模型为 variant ResNet18；对比模型包括 1DCNN、SAE、CNN+LSTM；另比较原始 ResNet18 与 variant ResNet18，验证网络结构改造价值。

4. 训练：TensorFlow 1.15，Ubuntu 16.04，GTX 1080Ti；batch size 为 64；每个增量阶段 50 epochs；momentum 0.9，weight decay 0.00005，temperature 2，memory budget 2000；初始学习率 2.0，并在指定 epoch 衰减。

5. 指标：使用 accuracy、precision、recall、F1；多分类评价时将每个类别与其余类别视作二分类计算 TP、TN、FP、FN。

6. 消融/敏感性：比较 padding 长度 0、24、48；比较图像尺寸 `32×32×3`、`64×64×3`、`128×128×3`；比较 payload-only 与 header+payload；比较原始 ResNet18 与 variant ResNet18；在增量学习中比较不同 memory size、不同 incremental step、BV 与 GIL，以及 GIL 的 λ、μ 参数。

7. 结果核查：通过混淆矩阵确认各类别误分布；重点检查 Email 类因样本少导致性能低的问题；检查增量最后阶段是否偏向新类；用训练时间和测试时间验证“无需全量重训”的效率收益。

## 8. 关键结果、结论与证据

离线分类方面，EETC 在 ISCXVPN2016 上达到 98.1% accuracy、96.7% precision、95.8% recall、96.1% F1；自采数据集准确率为 96.0%；TLS 数据集准确率为 97.3%。这说明该表示方法不仅适用于公开 VPN 数据，也能迁移到作者自采的真实 App+VPN 场景。

消融实验很有说服力。padding 长度为 24 时效果最好，说明方向边界编码确实有帮助，但 padding 过长会引入冗余。`32×32×3` 优于更大图像，说明盲目增加输入长度不一定更好，过多字节可能稀释有效局部结构。header+payload 比 payload-only 提升 14.4 个百分点，证明非地址类包头字段对分类很关键。

网络结构方面，variant ResNet18 相比原始 ResNet18 准确率从 90.0% 提升到 98.1%。这支持作者的判断：流量图像不是自然图像，小尺寸输入中 max pooling 可能过早丢掉细节。

增量学习方面，BV 在小 memory buffer 下表现更好，最后阶段大多仍能保持 85% 以上准确率；GIL 在中大 memory 下遗忘更少。训练时间上，BV 单阶段约 26 分钟，GIL 约 34 分钟，低于需要反复重训的 1DCNN、SAE、CNN+LSTM，体现扩展分类的实际价值。

## 9. 局限性与待解决问题

第一，论文虽然称支持多标签预测 VPN 与应用，但实验呈现更接近“组合类别分类”，例如 `VPN-Chat`、`SSR-YouTube`、`Psiphon-WeChat`。真正的多标签建模通常需要分别输出 VPN 标签和 App 标签，并报告两个标签空间的指标，论文在这点上还不够充分。

第二，数据规模与场景覆盖有限。ISCXVPN2016 已较老，自采数据只有 4 个 App 和 2 个 VPN 通道，TLS 数据也只有 4 类协议。面对 QUIC、HTTP/3、移动 App 高频版本更新、CDN 混淆、企业代理等场景，泛化性仍需验证。

第三，保留 header 带来性能提升，但也可能引入数据集特异性偏差。虽然删除 MAC/IP 降低了地址泄漏风险，但 TTL、端口、长度分布、采集脚本行为仍可能与采集环境强绑定。

第四，增量实验主要是类增量，不等价于真实开放世界流量检测。真实环境会同时出现未知类、概念漂移、类别长尾、背景噪声和攻击流量混杂，论文没有系统讨论未知类拒识与漂移检测。

第五，模型解释性有限。论文用图像纹理可视化说明类别差异，但没有进一步分析模型到底依赖哪些字节区域、包头字段或方向模式，这会影响安全场景下的可信部署。

## 10. 与本项目的关系

对“异常检测”项目而言，这篇论文的价值不在于直接检测异常，而在于提供了一个可迁移的加密流量表征与持续学习框架。异常检测经常遇到新业务、新攻击、新协议形态不断进入系统的问题，EETC 的增量学习思路可以借鉴。

具体可借鉴三点：一是把流量转换为包含内容、方向、频率的紧凑图像表示，作为下游分类或异常检测模型输入；二是用 memory buffer 保存代表性历史样本，避免模型上线后只适应新流量而遗忘历史正常模式；三是将 VPN/应用识别作为异常检测前置任务，先识别业务上下文，再在同类上下文中判断行为是否异常。

但如果本项目目标是攻击检测或未知异常发现，需要补充开放集识别、无监督/半监督异常评分、时序漂移监测，而不能只沿用 EETC 的闭集分类设定。

## 11. 代码对照分析

本地未发现该论文对应开源代码包，因此无法做逐文件源码核验。根据论文方法，若要复现，代码结构大概率应对应以下模块：

- 数据预处理：读取 pcap，五元组聚合，删除 MAC/IP，按方向 padding，拼接 3072 字节，生成 `32×32×3` 图像与 TFRecords。关键依赖可能包括 Scapy、dpkt、tshark/Wireshark 导出脚本。
- 模型定义：variant ResNet18，包含残差块、去除 max pooling、小尺寸输入适配、global average pooling、分类头扩展。
- 训练逻辑：离线训练使用交叉熵和 AdaGrad；增量训练需要旧模型 teacher、当前模型 student、temperature、γ、bias vector、balance factor。
- 记忆更新：BV 应包含按类别均值距离排序的 exemplar selection；GIL 应包含 reservoir sampling、memory buffer 采样、λ 和 μ 正则项。
- 评估脚本：生成 accuracy、precision、recall、F1、混淆矩阵；增量实验还需按 step=2/3/4/6 类别划分任务，并记录不同 memory size 下的最终准确率和性能下降率。

运行线索方面，论文环境是 TensorFlow 1.15 + CUDA 9.0 + cuDNN 7.4，属于较旧栈；如果在当前环境复现，优先考虑用 PyTorch 重写模型与增量训练逻辑，或用容器固定旧版 TensorFlow 环境。

## 12. 本篇精华

- EETC 的核心不是“流量转图片”本身，而是把方向 padding、包拼接、header+payload 结合起来，让 CNN 同时看到内容特征和统计交互特征。
- 删除 MAC/IP 是必要防过拟合步骤，但保留其他 header 字段显著提升性能，说明加密流量分类并非只依赖 payload。
- `32×32×3` 比更大输入更优，提示加密流量图像任务中“更多字节”不必然等于“更多有效信息”。
- variant ResNet18 去掉 max pooling 后明显优于原始 ResNet18，说明小尺寸流量纹理需要保留早期细粒度结构。
- 将增量学习引入加密流量分类是本文最有研究价值的部分，贴近真实网络中新应用和新隧道不断出现的部署压力。
- BV 适合小记忆空间，GIL 在较大 memory buffer 下遗忘更少，两者体现了代表性样本选择与流式随机采样的取舍。
- 论文实验仍属于闭集分类和组合类识别，距离真实异常检测、开放集识别和持续漂移适应还有明显距离。
