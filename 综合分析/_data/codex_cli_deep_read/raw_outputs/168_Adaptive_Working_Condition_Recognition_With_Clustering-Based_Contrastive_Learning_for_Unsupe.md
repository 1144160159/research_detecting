# [168] Adaptive Working Condition Recognition With Clustering-Based Contrastive Learning for Unsupervised Anomaly Detection

- 论文题名：Adaptive Working Condition Recognition With Clustering-Based Contrastive Learning for Unsupervised Anomaly Detection
- 中文题名：面向无监督异常检测的基于聚类对比学习的自适应工况识别

- 应用场景：工业设备，尤其是泵和引风机在变工况下的状态监测
- 方法名称：CBCL-AE，即 Clustering-Based Contrastive Learning Autoencoder

## 2. 中文翻译与核心摘要

这篇论文关注一个很实际的工业异常检测问题：设备并不总是在单一稳定工况下运行。泵、风机等旋转机械会因为负载、转速、环境、工艺流程变化而呈现多个正常运行模式。如果把所有正常数据混在一起训练一个普通自编码器，模型可能把“正常工况切换”误判为异常，也可能因为学到过宽的正常分布而重构真实异常，导致异常残差不明显。

作者提出 CBCL-AE：以 GRU 自编码器作为重构主体，在编码器隐空间中加入基于聚类的对比学习。核心做法是：训练时随机采样一对时间序列窗口，经过编码器得到特征；在 batch 内对特征做 k-means 聚类，用聚类结果生成“同工况/异工况”的伪标签；再用对比损失拉近同工况特征、推远异工况特征，同时增加一个聚类中心间距约束，避免不同工况中心过近。最终模型既保持自编码器对正常模式的重构能力，又能在隐空间中自适应区分不同工况。

实验上，CBCL-AE 在 SMD、SMAP、MSL 三个公开数据集上表现不是最优，但达到可接受水平；真正体现优势的是两个私有变工况数据集 MSPD 和 MSFD，F1-score 分别达到 0.9407 和 0.8671，显著优于 Anomaly Transformer、OmniAnomaly、LSTM-VAE、EncDec-AD、USAD 以及不含 CBCL 的 GRU-AE。

## 3. 论文解决的具体问题

论文解决的不是泛泛的“时间序列异常检测”，而是更具体的工业变工况无监督异常检测问题。

普通重构式异常检测通常默认训练数据中的正常模式相对稳定。模型学习正常数据分布，测试时用重构误差作为异常分数。但在真实工业场景中，正常数据本身可能存在多个分布簇。例如同一台泵在不同负载、流量或转速附近运行时，传感器均值和方差都会突变。这样的突变并不一定是异常，而是工况变化。

这会带来两个相反但都严重的问题：

- 如果模型把所有工况当作一个整体分布，正常工况切换处可能产生较大残差，被误报为异常。
- 如果模型容量较强，并且训练数据覆盖了大量差异很大的正常工况，模型可能学到过泛化的重构能力，把真实异常也重构得较好，导致漏报。
- 如果只使用统一阈值，不同工况下残差分布不同，阈值很难同时兼顾高召回和低误报。
- 实际工况标签往往不可用，不能依赖监督式工况分类器。

因此，作者试图回答的问题是：在没有工况标签、只有正常训练数据的前提下，能否让异常检测模型自动识别隐含工况，并基于工况差异提高重构式异常检测效果？

## 4. 创新点深度提炼

第一，论文把“变工况识别”嵌入到异常检测模型训练过程，而不是作为外部预处理步骤。CBCL-AE 不是先聚类、再训练多个模型，而是在 GRU 自编码器训练过程中动态地在隐空间聚类，并用聚类结果反向约束特征学习。

第二，作者设计了一种无监督伪标签对比学习机制。传统对比学习需要知道样本对是否同类，而这里没有真实工况标签。论文用 batch 内 k-means 聚类结果判断两个样本是否属于同一工况，再构造对比损失。这使得模型在无标签条件下获得类似“同工况拉近、异工况推远”的训练信号。

第三，论文没有只使用普通对比损失，而是额外加入聚类中心距离约束。这个约束的目的很明确：仅仅拉近同簇样本不够，还要保证不同工况中心之间有足够距离，否则隐空间可能出现聚类收敛但类别边界不清的问题。论文的消融图显示，去掉该约束后聚类中心虽然能收敛，但中心间距不足。

第四，论文把工况识别结果用于阈值选择。CBCL-AE 的异常判断不是只依赖全局阈值，而是针对不同工况选择不同阈值。这一点很关键，因为变工况下残差分布天然不同，统一阈值往往是不稳定的。

第五，论文尝试为聚类过程收敛提供理论支撑。其论证思路是：聚类中心依赖模型提取的特征，如果模型训练损失收敛，则特征趋于稳定，进而聚类中心迭代趋于稳定。虽然证明依赖较强假设，但它至少把 CBCL 模块的有效性问题明确地转化为“特征稳定性与聚类稳定性”的问题。

## 5. 科学问题与研究假设

论文背后的科学问题可以概括为：在多变量时间序列正常数据存在多个隐含运行模式时，异常检测模型如何同时学习“正常行为重构”和“工况结构分离”？

主要研究假设包括：

- 正常工业设备数据在隐空间中存在可聚类的工况结构。
- 不同工况之间的差异会干扰普通自编码器的异常检测能力。
- 通过聚类生成的伪工况标签虽然不完美，但足以为对比学习提供有效训练信号。
- 对比学习能提升同工况特征紧凑性和异工况特征可分性。
- 聚类中心间距约束可以减少工况簇混叠，使后续分工况阈值更可靠。
- 保留重构损失是必要的；如果只优化对比学习相关目标，模型会丧失异常检测所需的重构能力。
- 当模型优化趋于稳定时，隐空间特征和聚类中心也会趋于稳定。

这些假设中，最重要的是前两个：如果数据并不存在明确工况结构，CBCL-AE 的优势会减弱；论文在三个非变工况公开数据集上的结果也印证了这一点。

## 6. 科学方法与技术路线

CBCL-AE 的主体是 GRU 自编码器。输入是多变量时间序列窗口，编码器由两层 GRU 构成，解码器也由两层 GRU 构成。模型输出重构序列，通过输入与重构之间的残差进行异常检测。

技术路线可以拆成四个环节：

1. 特征提取  
   输入一对随机采样的时间序列窗口，分别经过同一个 GRU 编码器，得到编码隐状态。论文将第二层编码器的隐状态视为特征空间表示。

2. batch 内工况聚类  
   对当前 batch 中的隐空间特征执行 k-means。若两个样本被分到同一簇，则伪标签为同工况；否则为异工况。私有数据中作者已知有三种工况，因此设置聚类中心数 K=3。

3. 聚类对比学习  
   同工况样本对通过对比损失被拉近；异工况样本对被要求保持至少 λ 的距离。除此之外，论文还加入聚类中心平均距离约束，用 γ 控制不同中心之间的最小平均间隔。

4. 重构式异常检测  
   总损失由重构 MSE 和 CBCL 相关损失加权组成。训练完成后，使用重构残差作为异常分数，并针对不同工况选择阈值。

总损失可以理解为三种力量的平衡：

- MSE：保证模型学会重构正常时间序列。
- 对比损失：让隐空间具备工况可分性。
- 聚类中心距离约束：防止不同工况簇靠得太近。

其中 α 是关键平衡参数。论文实验显示 α=0 时退化为普通 GRU-AE，不能自适应工况识别；α=1 时重构损失被移除，异常检测能力下降。最佳区域在 α≈0.2，说明这篇论文的主任务仍是重构式异常检测，对比学习是辅助结构化约束。

## 7. 实验设计与实验步骤

可复核流程如下。

数据：

- 公开数据集：SMD、SMAP、MSL，用于验证 CBCL-AE 在一般多变量时间序列异常检测上的表现。
- 私有数据集：MSPD 和 MSFD，用于验证变工况工业设备场景。
- MSPD 来自 40 台泵的正常训练数据和 35 台泵的测试数据，测试集中有 1251 个异常。
- MSFD 来自 10 台引风机的正常训练数据和 7 台引风机的测试数据，测试集中有 420 个异常。
- 私有数据每个时间点包含 3 个特征：速度均方根、基频能量、二倍频能量，采样间隔为 2 小时。

预处理：

- 论文正文没有详细展开标准化、窗口长度、滑窗步长等细节，这是复现实验时需要回 PDF、补充材料或代码进一步确认的部分。
- 训练集使用正常数据。
- 测试集包含正常与异常样本。
- 对私有数据，作者根据先验知识设定工况数 K=3。

模型与基线：

- 主模型：CBCL-AE。
- 消融模型：不含 CBCL 的 GRU-AE。
- 对比基线：Anomaly Transformer、OmniAnomaly、LSTM-VAE、EncDec-AD、USAD。
- CBCL-AE 编码器和解码器均基于 GRU，总共四层 GRU。

训练：

- 每次训练随机采样一对时间序列窗口。
- 两个窗口经过共享的 GRU-AE。
- 在 batch 隐空间特征上执行 k-means。
- 根据聚类结果生成样本对伪标签。
- 联合优化重构损失、对比损失和聚类中心距离约束。
- 使用 SGD 优化，训练中采用梯度裁剪、Xavier 初始化和 batch normalization 来支撑梯度有界假设。

指标：

- Precision
- Recall
- F1-score
- 由于异常样本远少于正常样本，论文不使用 accuracy 作为主要指标。
- 重点比较 F1-score。

阈值选择：

- 对所有模型使用相同阈值选择策略。
- 在残差范围内生成多个候选阈值，选择使检测结果最优的阈值。
- 对 CBCL-AE，针对不同工况分别选择阈值。
- 判定规则是残差大于阈值即为异常。

消融与敏感性：

- 比较 CBCL-AE 与 GRU-AE，验证 CBCL 模块贡献。
- 分析 α 和 λ 对 precision、recall、F1-score 的影响。
- 可视化聚类中心迭代轨迹，比较完整 CBCL-AE、去掉中心距离约束、去掉 CBCL 的差异。
- 使用 t-SNE 展示隐空间工况分离效果。
- 比较模型复杂度，包括内存、训练 batch 时间、测试 batch 时间。

结果核查：

- 公开数据集上，CBCL-AE 并非最优，只达到中等或可接受水平。
- 私有变工况数据集上，CBCL-AE 显著领先。
- 配对 t 检验显示，CBCL-AE 相比其他模型在两个私有数据集上的 F1-score 优势达到 1% 显著性水平。
- 重构可视化显示，正常数据能被较好重构，异常区域重构较差，从而形成较大残差。

## 8. 关键结果、结论与证据

最核心结果是：CBCL-AE 的优势主要出现在变工况场景，而不是普通公开数据集。

在 SMD、MSL、SMAP 三个公开数据集上，CBCL-AE 的 F1-score 分别约为 0.8445、0.8255 和 0.7295。这个表现不差，但不是最优。论文对此的解释是合理的：这些公开数据集并不明显具有变工况结构，因此 CBCL 模块的优势无法充分发挥。

在 MSPD 和 MSFD 两个私有变工况数据集上，CBCL-AE 明显领先。MSPD 上 precision、recall、F1-score 分别达到 0.951、0.9302、0.9407；MSFD 上分别达到 0.8931、0.8425、0.8671。相比之下，去掉 CBCL 的 GRU-AE 表现明显下降，说明提升不是单纯来自 GRU 自编码器，而是来自隐空间工况结构约束。

聚类可视化提供了方法机制层面的证据。完整 CBCL-AE 中，三个聚类中心逐渐收敛，并保持明显间距；去掉中心距离约束后，中心虽然收敛但靠得较近；去掉 CBCL 后，聚类过程不再稳定。这说明论文中的两个设计都有效：对比学习负责形成工况簇，中心距离约束负责增强簇间分离。

t-SNE 图进一步显示，三种工况在隐空间中可以分开，同工况样本聚集。异常样本的特征多落在正常特征空间附近，这对重构式检测反而是有利的：模型倾向于把异常输入重构为正常形态，从而扩大输入和重构之间的残差。

论文最终结论是：CBCL-AE 能在无监督条件下实现自适应工况识别，并提升变工况工业设备的异常检测性能。

## 9. 局限性与待解决问题

第一，方法依赖工况数 K。私有数据中作者知道有三种工况，所以直接设置 K=3；但真实部署时工况数可能未知、变化甚至连续。论文提到可通过敏感性分析选择 K，但这还不是完整解决方案。

第二，阈值选择策略偏理想化。论文在残差范围内选择最优阈值，这通常需要测试标签或验证标签支持。真实无监督部署中，异常标签往往不可用，如何可靠设定每个工况阈值仍是关键问题。

第三，私有数据不可公开复核。论文最强结果来自 MSPD 和 MSFD，但这两个数据集是私有工业数据。外部研究者很难验证数据划分、异常标注、工况分布和阈值选择是否具有普遍性。

第四，理论收敛证明依赖较强假设。论文假设参数有界、梯度有界，并在局部凸区域讨论 regret bound。对深度 GRU 自编码器来说，这种证明更像是合理性说明，而不是严格保证全局训练稳定。

第五，公开数据集结果并不突出。CBCL-AE 在非变工况数据上没有压倒性优势，说明该方法的适用边界比较明确：它更适合存在多个正常运行模式的设备监测，而不是所有时间序列异常检测任务。

第六，正文没有充分披露复现细节。窗口长度、归一化方式、batch size、K 的选择流程、γ 的搜索范围、候选阈值生成方式等对结果影响较大，但正文包中信息不完整。虽然本次正文包未截断，但复现实验仍需回到 PDF 的表格、图注、可能的补充材料或作者代码进一步核查这些细节。

## 10. 与本项目的关系

从“入侵检测与网络异常检测”的角度看，这篇论文属于弱相关但有方法启发。

相关之处在于，网络流量也常有多种正常模式：工作日/周末、白天/夜间、业务系统差异、用户群差异、协议类型差异、流量突增等。这些正常模式变化类似工业变工况。如果直接训练单一自编码器，可能同样面临概念漂移、阈值不稳定和误报率高的问题。因此，CBCL-AE 的“无标签模式识别 + 分模式阈值 + 重构异常检测”可以迁移到网络异常检测中。

但它与网络安全仍有明显距离：

- 论文没有攻击者建模，也不讨论对抗行为。
- 异常主要是机械故障或旋转异常，不是入侵、扫描、横向移动、DDoS 等安全事件。
- 特征是低维物理传感器指标，不是高维网络流、日志或图结构事件。
- 私有实验中的工况类别较少且结构清晰，而网络环境中的正常模式可能更复杂、更动态。

因此，本项目可借鉴其思想，而不是直接照搬模型。更合适的迁移方向是：面向多业务、多时段、多协议场景的网络流量无监督异常检测，先在隐空间识别正常流量模式，再进行模式条件化阈值或模式条件化重构。

## 12. 本篇精华

- 这篇论文的真正问题意识是“正常数据并不单峰”：工业设备正常运行也有多个工况分布，异常检测必须先处理正常模式差异。
- CBCL-AE 的核心不是单纯换一个自编码器，而是在隐空间中同时做重构学习和工况结构学习。
- batch 内 k-means 被用来生成无监督伪工况标签，从而把传统需要标签的对比学习改造成适合变工况异常检测的训练机制。
- 聚类中心距离约束是关键细节，它解决的是“聚类能收敛但簇间不够可分”的问题。
- 分工况阈值比统一阈值更符合变工况异常检测逻辑，但真实无标签部署中阈值如何选仍是薄弱点。
- 公开数据集结果说明 CBCL-AE 不是通用最强模型；它的优势集中在存在显著工况变化的工业数据。
- 对网络异常检测的启发是：可以把业务模式、时间模式、协议模式视作“网络工况”，用隐空间聚类降低正常概念漂移导致的误报。

## 13. 建议精读路线

建议先读 Introduction，重点抓住作者为什么认为普通重构式异常检测不适合变工况设备。这里是全文动机的核心。

第二步读 Section III-B 和 III-C，弄清 CBCL 如何用 k-means 生成伪标签，以及总损失中 MSE、对比损失、中心距离约束分别承担什么作用。

第三步读实验部分的私有数据描述。MSPD 和 MSFD 是论文贡献成立的主要证据，需要特别关注三维特征、三种工况、训练/测试设备数量和异常数量。

第四步读消融和可视化。Fig. 6、Fig. 8、Fig. 9 比单纯性能表更重要，因为它们解释了为什么 CBCL 有效。

最后再读收敛证明。建议把它当作方法合理性的辅助论证，而不是严格数学保证。精读时应重点检查假设是否适用于真实深度模型训练。
