# [325] WF-Transformer: Learning Temporal Features for Accurate Anonymous Traffic Identification by Using Transformer Networks

## 2. 中文翻译与核心摘要

这篇论文提出 WF-Transformer，用 Transformer 替代以往网站指纹攻击中常见的 CNN 特征提取器，核心目标是从 Tor 流量包方向序列中学习更长距离的时间依赖关系，从而提升匿名流量网站识别效果。

作者认为，已有 DF、AWF、Var-CNN 等深度网站指纹方法主要依赖卷积结构。CNN 擅长局部模式提取，但 Tor 访问网站时，前后请求与响应可能因网页资源加载、队列、并发连接、延迟等因素产生长距离关联，仅看局部包方向片段会损失部分可区分信息。WF-Transformer 因此使用自注意力机制，特别是相对位置编码，让模型学习不同包之间的相对时序关系。

实验表明，在 DF 数据集上，WF-Transformer 在闭世界、开世界、无防御和多种防御场景下均优于 CUMUL、AWF、DF。最突出的结论是：WF-Transformer 使用 2000 个 cell 的短输入，已经能超过 DF 使用 5000 个 cell 的效果。这说明论文真正强调的不是“换一个更大的模型”，而是“用更适合长序列依赖建模的结构，从更短的匿名流量片段中提取更多可识别信息”。

## 3. 论文解决的具体问题

论文解决的是 Tor 匿名通信中的网站指纹识别问题：攻击者无法看到明文、目标 IP 或 URL，只能在用户与 Tor 入口节点之间被动监听加密包序列，但仍希望判断用户正在访问哪个网站。

具体问题可以拆成三层：

1. **传统手工特征不够强**  
   CUMUL、k-FP 等方法依赖包方向、突发、累计长度等人工特征，闭世界准确率约 91% 左右，面对复杂网页加载模式和防御填充时表达能力有限。

2. **CNN 深度方法忽视长距离时间依赖**  
   DF 等 CNN 方法显著提升了攻击效果，但卷积核本质上从局部窗口中提特征。虽然堆叠卷积可扩大感受野，但对“远距离包之间的依赖关系”建模并不直接。

3. **攻击者希望更早、更短、更稳地识别网站**  
   以往深度 WF 通常使用 5000 长度输入。论文试图证明：如果模型能更好学习时间特征，那么只用 2000 个 cell 也能达到甚至超过长输入 CNN 的识别性能，这对真实攻击有实际意义，因为监听时间更短。

## 4. 创新点深度提炼

1. **把 Transformer 引入网站指纹攻击**  
   论文声称 WF-Transformer 是首个用 Transformer 做 WF 攻击的工作。其意义不只是替换网络骨干，而是将 WF 从“局部形状匹配”推进到“序列关系建模”。

2. **针对流量序列设计相对位置注意力**  
   普通绝对位置编码只能告诉模型某个包在第几个位置，而相对位置编码更适合表达“第 i 个包与第 j 个包之间的距离关系”。对于 Tor trace，这种相对关系比单纯绝对序号更贴近访问行为模式。

3. **只使用包方向，仍获得更高识别性能**  
   输入仅为 `+1/-1` 包方向，不使用包大小和时间戳。由于 Tor cell 大小固定，方向序列本身已经承载大量页面加载结构信息。论文用结果说明：更强的时序建模可以从极简输入中挖出更多信息。

4. **短输入优势明确**  
   WF-Transformer 2000 长度输入在闭世界无防御场景达到 98.7%，超过 DF 5000 长度的 98.3%。这是论文最有价值的实证点之一，因为它把模型结构优势转化为攻击采集成本优势。

5. **加入信息泄漏测量作为解释证据**  
   作者使用 WeFDE 衡量模型倒数分类层前特征的信息泄漏量。WF-Transformer 2000 长度特征泄漏 7.7 bits，高于 DF 5000 长度的 7.2 bits，用来支撑“Transformer 提取了更多网站相关信息”的主张。

## 5. 科学问题与研究假设

**科学问题：**  
在匿名加密流量中，仅基于包方向序列，是否存在足够稳定的长距离时间依赖模式，使得 Transformer 比 CNN 更适合网站指纹识别？

论文隐含的研究假设包括：

- Tor 网站访问 trace 不是简单的局部片段集合，而是包含跨较长范围的请求-响应依赖。
- 包方向序列足以表达网站访问行为的主要指纹，不必依赖包大小或时间戳。
- CNN 的局部感受野限制会遗漏部分判别性模式。
- 自注意力与相对位置编码能捕获远距离包之间的关系。
- 若长程依赖被有效学习，模型可在更短 trace 上完成高精度识别。
- 在防御流量中，填充包会扰乱局部统计，但不一定完全破坏全局时序模式。

## 6. 科学方法与技术路线

技术路线如下：

1. **威胁建模**  
   攻击者位于用户与 Tor entry node 之间，只能被动记录包序列和时间戳，不能解密、修改、丢弃或延迟包。攻击目标是识别用户访问的网站。

2. **输入构造**  
   每条 trace 转换为方向序列：出站包记为 `+1`，入站包记为 `-1`。实验考察输入长度 1000、2000、3000、4000、5000。

3. **模型结构**  
   WF-Transformer 包含输入嵌入、LayerNorm、多头注意力、相对位置编码、1D 卷积前馈层、GELU、dropout、shortcut connection 和最终全连接分类器。

4. **优化目标**  
   使用带 label smoothing 的多分类交叉熵。平滑系数在 `{0, 0.001, 0.005, 0.01, 0.5}` 中搜索，最终取 `0.005`。

5. **对比实验**  
   与 CUMUL、AWF、DF 比较；防御场景包括 TAMARAW、WTF-PAD、FRONT、Mockingbird。

6. **解释性补充**  
   使用 WeFDE 对模型提取特征的信息泄漏量进行估计，比较 DF 与 WF-Transformer 的特征含网站信息量。

## 7. 实验设计与实验步骤

**数据**

- 使用 Sirinam 等人发布的 DF 数据集。
- 闭世界：Alexa Top 100 中最终保留 95 个网站，每站 1000 条 trace；训练 76000，测试 9500。
- 开世界：排除闭世界前 100 网站后采集 Alexa Top 5000，清洗后 40716 条未监控网站 trace。
- 防御数据：包含无防御、TAMARAW、WTF-PAD、FRONT、Mockingbird 场景。

**预处理**

- 从原始 Tor trace 中提取包方向。
- 出站方向编码为 `+1`，入站方向编码为 `-1`。
- 按设定长度截断或补齐到 1000、2000、3000、4000、5000。
- 对 FRONT，由于数据集缺少时间戳，作者按包比例对 trace 前 50% 添加 dummy packet。

**模型/基线**

- 非深度基线：CUMUL。
- 深度基线：AWF、DF。
- 主模型：WF-Transformer。
- WF-Transformer 用 Transformer encoder 风格结构，分类器为全连接层。
- AWF 在本文实验中使用 CNN/LSTM 混合结构。

**训练**

- 框架：PyTorch。
- GPU：RTX 3090。
- 优化器：AdamW。
- 初始学习率：`3e-4`，前 30 epoch 使用；后 10 epoch 降为 `3e-5`。
- batch size：16。
- dropout：0.5。
- 总 epoch：40。
- label smoothing：0.005。

**指标**

- 闭世界：classification accuracy。
- 开世界：TPR、FPR、Precision-Recall 曲线。
- 信息泄漏：WeFDE 估计的 bit 数。
- 计算开销：单条 trace 推理时间。

**消融/敏感性**

- 输入长度敏感性：1000 到 5000。
- 开世界未监控训练样本规模：1000、5000、10000、15000、20000。
- label smoothing 系数网格搜索。
- 防御方法敏感性：TAMARAW、WTF-PAD、FRONT、Mockingbird。
- 收敛性：比较 WF-Transformer 与 DF 的训练/测试 loss 和 accuracy 曲线。

**结果核查**

- 闭世界无防御：检查不同输入长度下 WF-Transformer 是否持续优于 DF。
- 闭世界有防御：重点核查 WF-Transformer 2000 长度是否仍超过 DF 5000 长度。
- 开世界：检查 TPR 高时 FPR 是否仍低，避免只看准确率。
- PR 曲线：由于开世界数据不平衡，PR 曲线比单点 accuracy 更有解释力。
- 信息泄漏：比较分类器前特征的 WeFDE bits，验证“更多可识别信息”不是只来自最终分类器调参。

## 8. 关键结果、结论与证据

1. **闭世界无防御达到新高**  
   WF-Transformer 输入长度 5000 时准确率 99.1%。输入长度 2000 时准确率 98.7%，已经高于 DF 5000 长度的 98.3%。

2. **WTF-PAD 不能有效抵抗 WF-Transformer**  
   在 WTF-PAD 防御 trace 上，WF-Transformer 2000 长度仍达到 92.1%，说明轻量级 gap padding 并未破坏足够多的判别性时序结构。

3. **FRONT 更有效但仍未完全防住**  
   FRONT 将 WF-Transformer 准确率降到 82.4%，比 WTF-PAD 更有效。这也支持 FRONT 论文中的判断：trace 前部是信息密集区域。但 WF-Transformer 仍是对比攻击中最强的。

4. **TAMARAW 防御强但代价过高**  
   TAMARAW 下各攻击准确率低于 15%，但带来约 403% 带宽开销和较高延迟，现实部署性差。

5. **开世界表现更贴近真实攻击**  
   当未监控训练 trace 数为 20000 时，WF-Transformer 2000 长度在无防御开世界中 TPR 约 0.965，FPR 约 0.007；5000 长度 TPR 约 0.969，FPR 约 0.007。

6. **信息泄漏证据支持模型解释**  
   在 WTF-PAD trace 上，DF 5000 长度特征泄漏 7.2 bits；WF-Transformer 2000 长度为 7.7 bits，5000 长度为 7.9 bits。作者据此说明 Transformer 特征含有更多网站身份信息。

7. **代价是计算时间更高**  
   2000 长度下 DF 每条 trace 约 0.0026 秒，WF-Transformer 约 0.0070 秒；5000 长度下 DF 约 0.0027 秒，WF-Transformer 约 0.019 秒。Transformer 更慢，但作者认为短采集和快收敛可部分抵消该开销。

## 9. 局限性与待解决问题

- **数据集单一**：主要依赖 DF 公开数据集，采集环境为 Tor Browser Bundle 7.0.6 和校园环境，未充分验证跨时间、跨地区、跨 Tor 版本的泛化性。
- **真实开放世界仍更复杂**：实验开世界虽然包含未监控网站，但真实 Web 空间更大、网站动态内容更多，用户行为也不只访问首页。
- **防御评估有限**：涵盖 TAMARAW、WTF-PAD、FRONT、Mockingbird，但没有系统讨论更多现代自适应防御、流量分流、防御组合或真实部署开销。
- **攻击训练前提较强**：防御场景中攻击模型也使用 defended traces 训练，这相当于攻击者已知防御机制并能采集同分布训练数据。
- **只用方向序列既是优势也是限制**：方向输入简洁，但时间戳、burst duration、并发连接行为等信息可能带来不同结论。论文没有充分比较多模态输入下 Transformer 与 CNN 的差异。
- **“时间特征”的因果解释仍不够细**：信息泄漏实验证明特征更有信息量，但没有明确指出注意力具体捕获了哪些网页加载阶段或协议行为模式。
- **计算开销更高**：Transformer 推理时间明显高于 DF，长序列注意力复杂度仍是部署瓶颈。
- **缺少代码复现支撑**：本地未发现论文代码包，正文虽给出主要超参，但模型层数、head 数、embedding 维度等实现细节需要从表格和原论文图表进一步复核后才能严格复现。

## 10. 与本项目的关系

这篇论文与“加密流量分类与应用识别”高度相关，也能直接启发异常检测、日志/KPI 时序分析和云原生安全监测。

可借鉴点包括：

- **把局部模式检测升级为长程依赖建模**：在异常检测中，单点指标或短窗口异常往往不够，跨阶段、跨请求链路的依赖更关键。
- **短序列高效识别思想**：WF-Transformer 证明模型结构改进可以减少观测长度，这对在线异常检测中的早期告警很有价值。
- **仅用弱特征实现强分类**：论文只用方向序列，类似在日志或流量场景中只用低敏元数据做检测，适合隐私约束环境。
- **防御与攻击对抗视角**：WTF-PAD、FRONT、Mockingbird 对应不同扰动策略，可类比异常检测中的规避样本、噪声注入和对抗鲁棒性评估。
- **信息泄漏度量可迁移**：WeFDE 的思路可转化为“模型中间表示到底泄漏了多少类别/业务/租户信息”的度量。

## 11. 代码对照分析

本地代码包状态为“未发现；无”，因此不能给出真实源码文件级对应关系。若要复现论文，代码目录大概率应拆成以下模块：

- `data/` 或 `preprocess.py`  
  对应论文输入部分：读取 DF dataset trace，提取包方向，编码为 `+1/-1`，按长度截断/补齐，生成闭世界和开世界训练测试集。

- `models/wf_transformer.py`  
  对应 WF-Transformer 主体：embedding、LayerNorm、多头注意力、相对位置编码、1D convolution feed-forward、GELU、dropout、shortcut、classifier。

- `models/df.py`、`models/awf.py`、`baselines/cumul.py`  
  对应基线复现：DF、AWF、CUMUL。

- `train.py`  
  对应训练设置：AdamW、batch size 16、40 epochs、学习率前 30 epoch 为 `3e-4`、后 10 epoch 为 `3e-5`、label smoothing 0.005。

- `eval_closed_world.py`  
  对应闭世界 accuracy 表格，尤其是不同输入长度和防御场景下的重复实验、均值和标准差。

- `eval_open_world.py`  
  对应 TPR、FPR、PR 曲线，包含阈值扫描和未监控训练样本规模变化。

- `defenses/`  
  对应 TAMARAW、WTF-PAD、FRONT、Mockingbird trace 生成或加载。论文中 WTF-PAD 使用开源 defended dataset，FRONT 因无时间戳改用前 50% 包比例填充。

- `analysis/info_leakage.py`  
  对应 WeFDE 信息泄漏分析，输入为 DF 和 WF-Transformer 分类器前一层特征。

如果后续找到官方或第三方代码，优先核查三处：相对位置编码实现是否与公式一致、label smoothing loss 是否按论文公式实现、开世界阈值和 unmonitored 类别处理是否严格复现。

## 12. 本篇精华

- WF-Transformer 的核心贡献是用自注意力学习 Tor trace 的长距离时间依赖，而不是继续堆叠 CNN 局部特征。
- 只用包方向 `+1/-1`，WF-Transformer 仍能在闭世界无防御场景达到 99.1% accuracy。
- 2000 长度 WF-Transformer 超过 5000 长度 DF，是论文最有实践意义的结果：更短监听即可完成更强识别。
- WTF-PAD 对深度攻击尤其是 WF-Transformer 防御不足；FRONT 更有效，但仍不能完全抵抗。
- 开世界实验中 WF-Transformer 同时保持高 TPR 和低 FPR，说明优势不只存在于理想闭世界。
- 信息泄漏实验显示 WF-Transformer 中间特征比 DF 特征包含更多网站身份信息，支撑其时序特征提取能力。
- 主要代价是计算开销更高，尤其在 5000 长度输入下明显慢于 DF。
- 对异常检测研究的启发是：在弱特征、短观测、强噪声环境中，长程依赖建模可能比局部模式提取更关键。

## 13. 建议精读路线

1. 先读威胁模型，明确攻击者只能被动监听 Tor 入口侧流量，不能看到明文和目标地址。
2. 再读输入设计，重点理解为什么只使用包方向，以及输入长度为什么影响攻击现实性。
3. 精读模型结构图和相对位置注意力公式，这是论文区别于普通 Transformer 套用的关键。
4. 对照闭世界无防御表格，抓住 2000 vs 5000 输入长度的比较逻辑。
5. 继续读防御实验，重点比较 WTF-PAD、FRONT、TAMARAW 的防御效果和开销。
6. 最后读信息泄漏与计算开销讨论，判断论文关于“时序特征更强”的证据是否充分。
7. 若要复现，先实现无防御闭世界，再扩展到 defended traces 和 open-world PR 曲线。
