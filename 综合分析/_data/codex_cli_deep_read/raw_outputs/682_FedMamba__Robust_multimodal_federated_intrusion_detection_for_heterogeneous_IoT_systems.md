## 2. 中文翻译与核心摘要

这篇论文试图解决一个现实工业场景中的组合难题：智能工厂里同时存在系统日志、工控传感器和网络流量三类安全数据，但这些数据通常分散在不同设备或部门，不能集中上传；同时，各边缘节点的数据分布严重非独立同分布，并且检测模型在推理阶段还可能被对抗样本规避。

作者提出 FedMamba，把三类数据纳入一个多模态联邦学习框架。核心设计是：每种模态使用自己的输入适配器和分类头，中间共享一个 Mamba 状态空间模型骨干；联邦训练使用 FedProx 抑制非 IID 客户端漂移；聚合时按参数块区分共享骨干和模态私有模块；对 HDFS 和 SWaT 这两个脆弱模态做选择性 PGD 对抗训练，而 CICIoMT-2024 保持标准训练。

论文的核心结论是：标准 FedMamba 在干净测试集上接近集中式模型，HDFS、SWaT、CICIoMT-2024 的 Macro F1 分别为 0.9584、0.9795、0.9665；但 HDFS 和 SWaT 在白盒 PGD 下会显著崩溃到 0.3791 和 0.5147。加入选择性联邦对抗训练后，FedMamba-AT 在 PGD 下恢复到 0.9480、0.8357、0.9645，说明干净精度、联邦隐私约束、多模态融合和对抗鲁棒性可以在一个工程框架里被共同处理。

## 3. 论文解决的具体问题

论文解决的不是普通单数据集入侵检测，而是更接近工业部署的四重耦合问题。

第一是模态异构。HDFS 是离散日志事件序列，SWaT 是连续工控传感器时间窗，CICIoMT-2024 是网络流统计特征。三者输入空间、序列长度、任务类型都不同，直接把它们当成同构客户端做 FedAvg 并不合理。

第二是统计异构。作者用 Dirichlet α=0.3 构造严重非 IID 客户端分布，意味着某些客户端可能只见到少数类别甚至缺失正常类。这个设置更接近真实边缘节点：不同车间、设备或网络区域看到的攻击类型并不均衡。

第三是隐私与通信约束。论文不允许上传原始日志、传感器或流量，只交换模型更新，并讨论了与安全聚合兼容的加权聚合形式。

第四是推理阶段规避攻击。作者明确把训练时投毒、拜占庭和后门排除在核心威胁模型之外，主要研究白盒 PGD、Auto-PGD、迁移黑盒攻击和噪声扰动下模型是否还能检测攻击。

## 4. 创新点深度提炼

1. 架构创新在于“共享骨干 + 模态私有两端”。输入适配器和输出头不共享，分别处理日志、传感器、网络流量的结构差异；Mamba 骨干共享，用于学习跨模态可迁移的安全表示。这比简单拼接多模态特征更适合一客户端一模态的联邦场景。

2. 聚合创新在于按参数块加权。共享骨干由所有参与客户端共同加权平均；某个模态的输入适配器和分类头只由同模态客户端平均。这避免了网络流客户端更新日志嵌入层、日志客户端更新 SWaT 头部这类无意义干扰。

3. 训练稳定性来自 FedProx。论文没有声称提出新的收敛定理，而是说明分块聚合后每个参数块仍能获得对应子目标的无偏更新，因此可沿用 FedProx 的非凸优化直觉。实验上，FedAvg 在 CICIoMT-2024 非 IID 场景 Macro F1 从 0.9550 掉到 0.8550，而 FedProx 恢复到 0.9665。

4. 鲁棒性设计是选择性的。作者先发现 HDFS 和 SWaT 对 PGD 很脆弱，而 CICIoMT-2024 几乎不受影响，于是只对 HDFS 和 SWaT 做 PGD 对抗训练。这降低了客户端代价，也减少了对本来稳定模态的负迁移。

5. Mamba 的价值不是单纯追求最高分，而是边缘部署折中。FedTransformer 在 HDFS 上 F1 更高，但参数量和上传开销约为 FedMamba 的两倍以上。论文把 Mamba 定位为 IIoT 场景中精度、通信、延迟之间更合适的折中。

## 5. 科学问题与研究假设

论文背后的科学问题可以概括为：在多模态、非 IID、隐私受限且存在对抗规避的工业物联网环境中，是否能训练一个统一而鲁棒的入侵检测模型？

主要研究假设包括：

- 不同安全模态虽然输入形态不同，但在异常检测层面存在可共享的时序/状态转移表示，因此共享 Mamba 骨干能带来跨模态迁移。
- 模态私有适配器和头部足以隔离输入空间与任务差异，不需要为每个模态维护完全独立模型。
- FedProx 的近端项可以缓解严重标签偏斜造成的客户端漂移，尤其是在多类网络流任务上。
- 对抗鲁棒性可以通过共享骨干在联邦聚合中传播；即使只对部分脆弱模态做对抗训练，也能得到全局鲁棒特征。
- 安全聚合与模态感知加权并不冲突，因为客户端可先按样本数预缩放更新，服务器只需要看到聚合后的和。

## 6. 科学方法与技术路线

FedMamba 的技术路线是从单模态基线开始，再构造统一联邦模型。

单模态部分，HDFS 使用事件嵌入层把长度 50 的日志序列映射到隐空间；SWaT 使用线性投影处理长度 60 的传感器窗口；CICIoMT-2024 把 39 维流量特征视作长度 1 的序列。三者都进入 Mamba 骨干，再接任务头。HDFS 和 SWaT 是二分类，用加权 BCE；CICIoMT-2024 是三分类，用加权交叉熵。

统一模型参数被拆为三块：`θin`、`θback`、`θcls`。`θin,m` 和 `θcls,m` 是模态私有，`θback` 是共享 Mamba。Mamba 的线性序列复杂度被用来支持日志和传感器时序，而不承担 Transformer 自注意力的二次复杂度。

联邦训练采用 FedProx：每个客户端在本地损失外加上与当前全局参数距离的二范数惩罚，论文设 μ=0.01。聚合时，骨干参数按所有参与客户端样本数加权，模态块只按该模态客户端样本数加权。安全聚合只做模拟，核心是证明这种预缩放和分块除法可嵌入标准 secure aggregation。

鲁棒训练部分，作者使用 PGD 生成对抗样本。SWaT 和 CICIoMT-2024 直接在输入特征空间扰动；HDFS 因为 token 离散，在 embedding 空间扰动。最终只把 HDFS、SWaT 纳入对抗训练目标，CICIoMT-2024 继续标准 FedProx。

## 7. 实验设计与实验步骤

可复核流程如下：

1. 数据准备：使用 HDFS、SWaT、CICIoMT-2024 三个数据集。样本量分别约为 575,061、449,919、6,957,003；特征/事件规模分别为 29 个日志事件、51 个传感器变量、39 个网络流特征。任务分别是日志异常二分类、工控攻击二分类、网络流三分类。

2. 数据划分：每个数据集划分为训练、验证、测试，比例为 70%、15%、15%。二分类任务在验证集上以 Macro F1 最大化选择阈值，搜索区间为 0.05 到 0.95，步长 0.05；多分类任务直接取 argmax。

3. 预处理：HDFS 形成长度 50 的 token 序列并左填充；SWaT 构造长度 60 的滑动窗口，并用训练集统计量标准化；CICIoMT-2024 标准化后作为长度 1 的表格序列输入。标签映射为 HDFS Normal/Anomaly，SWaT Normal/Attack，CICIoMT-2024 Normal/DoS/Other。

4. 联邦划分：用 Dirichlet α=0.3 按类别把训练样本分配到客户端，制造严重非 IID。默认总客户端数 35，每轮按每个模态抽取 ρ=0.4 的客户端参与训练。

5. 模型设置：共享骨干为 Mamba，`dmodel=256`、`dstate=16`、`dconv=4`、expand=2；池化使用最后 token 加 LayerNorm；三类任务使用各自分类头。

6. 训练设置：优化器为 AdamW，权重衰减 1e-2；共享骨干学习率 5e-6，适配器和头部学习率 1e-4；batch size 64；全局轮数 15；本地 epoch 为 2；梯度裁剪 L2=1.0；FedProx μ=0.01。

7. 基线比较：集中式单模态 Mamba 作为性能上界；标准 FedMamba 评估联邦干净性能；FedMamba-AT 评估对抗训练收益；Weighted FedAvg 用于 IID/非 IID 消融；No-Share baseline 检验共享骨干价值；FedTransformer 检验 Mamba 与 Transformer 的架构取舍。

8. 鲁棒评测：噪声测试使用 Gaussian noise；迁移黑盒攻击由替代模型生成 PGD 扰动后零查询迁移；白盒攻击使用 PGD 和 Auto-PGD。HDFS 在 embedding 空间 ε=0.01、step=0.002、10 次迭代；SWaT 和 CICIoMT-2024 在输入空间 ε=0.05、step=0.01、10 次迭代。

9. 指标核查：主指标是 Macro F1，因为三组任务都有类别不平衡。另报告 Accuracy、Precision、Recall、ROC-AUC；二分类还报告 FPR，多分类使用 one-vs-rest macro ROC-AUC。

10. 消融与敏感性：包括 FedAvg vs FedProx、共享骨干 vs 三套独立模型、Mamba vs Transformer、35/70/105 客户端规模扩展、安全聚合通信开销估算、附录中的后门探针。

## 8. 关键结果、结论与证据

干净数据上，FedMamba 基本达到集中式专用模型水平。集中式/FedMamba 的 Macro F1 分别为：HDFS 0.9900/0.9584，SWaT 0.9852/0.9795，CICIoMT-2024 0.9495/0.9665。CICIoMT-2024 中联邦模型反而优于集中式单模态模型，作者解释为共享骨干带来正迁移和正则化效果。

对抗攻击揭示了干净性能的脆弱性。标准 FedMamba 在 HDFS PGD 下从 0.9584 跌到 0.3791，SWaT 从 0.9795 跌到 0.5147；CICIoMT-2024 在 PGD 下仍为 0.9665，表现出较强天然稳定性。这个结果很关键：多模态联邦模型不是天然鲁棒，不同模态的攻击面差异很大。

FedMamba-AT 显著恢复鲁棒性。HDFS PGD Macro F1 从 0.3791 提升到 0.9480；SWaT 从 0.5147 提升到 0.8357；CICIoMT-2024 在未做本地对抗训练的情况下仍保持 0.9645。代价是 SWaT 干净 F1 从 0.9795 降到 0.8578，体现明显的精度-鲁棒性折中。

FedProx 的必要性主要体现在复杂多类任务。CICIoMT-2024 中 Weighted FedAvg 在非 IID 下 Macro F1 只有 0.8550，而 FedProx 达 0.9665。HDFS 上 FedAvg 非 IID 反而高于 FedProx，说明 FedProx 并非所有任务都提升干净精度，但它对困难非 IID 多类场景更稳。

共享骨干的证据很强。No-Share baseline 在 SWaT 上崩到 0.5850，即使调参和 warm-start 后也只有 0.9448，低于统一 FedMamba 的 0.9806。同时统一模型只有 0.54M 参数、2.04MB，而三套独立模型为 1.41M 参数、5.39MB。

Mamba 与 Transformer 的比较体现部署取舍。FedTransformer 在 HDFS 上 0.9977，明显高于 FedMamba 的 0.9584；但参数量 1.18M、平均上传约 4.2MB，而 FedMamba 0.54M、约 1.8MB。对于边缘 IIoT，这个通信差距比单一任务上的小幅精度优势更重要。

## 9. 局限性与待解决问题

第一，安全聚合只是数值模拟，没有真实密码协议实现。论文说明其目标是隔离学习动态，但实际部署还需要验证掩码生成、掉线恢复、同步等待、定点量化等开销。

第二，威胁模型偏窄。核心方法只防推理时规避攻击，训练时投毒、后门、拜占庭客户端被排除在主要研究范围外。附录虽做了后门探针，但没有给出系统防御方案。

第三，一客户端一模态的假设过于规整。真实工业边缘节点可能同时持有日志、传感器和流量，也可能缺失某些模态。论文没有处理多模态共存客户端、模态缺失、模态动态接入等问题。

第四，选择性对抗训练依赖先验脆弱性诊断。HDFS/SWaT 被训练、CICIoMT 不训练，是基于当前实验观察；换数据集、换特征尺度或换攻击预算后，这个选择可能不再成立。

第五，SWaT 的鲁棒收益代价较高。FedMamba-AT 干净 Macro F1 在 SWaT 上从 0.9795 降至 0.8578，这不是轻微代价。若用于高误报成本的工业现场，需要进一步调节鲁棒损失权重或阈值策略。

第六，数据范围仍有限。三类数据覆盖日志、传感器和流量，但没有视频、音频、控制指令、资产拓扑、告警文本等更复杂模态，也没有跨工厂迁移实验。

第七，代码不可复核。本次正文包完整，未因截断造成理解缺口；但没有随包提供可运行代码，论文也仅给出“upon request”的代码可用性说明，因此复现实验仍依赖作者后续释放脚本、配置和数据划分索引。

## 10. 与本项目的关系

这篇论文与“异常检测、入侵检测、多源异构数据融合、联邦协同、边缘安全”方向高度相关，尤其适合作为工业互联网或车联网分布式安全监测的参考框架。

对本项目最可借鉴的不是具体分数，而是方法组织方式：把不同来源的安全观测先通过模态私有适配器投影到统一隐空间，再用共享序列骨干学习跨源异常表示；训练时用 FedProx 控制非 IID 漂移；评测时同时看干净精度、对抗鲁棒性、通信成本和可扩展性。

如果本项目关注多源流量、日志、主机行为或边缘设备协同检测，FedMamba 可作为“系统架构级”基线。若项目更偏开放集、加密流量或多模态融合，也可以借鉴其分块聚合思想，把共享部分和模态私有部分明确拆开，避免联邦聚合时参数语义混乱。

需要谨慎的是：论文使用的数据模态和项目中的网络流/加密流/行为序列未必完全一致；Mamba 是否优于 Transformer、TCN、GRU 或轻量 CNN，需要在本项目数据上重新验证。

## 12. 本篇精华

- FedMamba 的核心不是“用了 Mamba”，而是把多模态联邦 IDS 拆成共享骨干和模态私有块，并为这种拆分设计对应的聚合规则。
- 干净测试集高分并不能证明安全性：HDFS 和 SWaT 在 PGD 下几乎崩溃，说明 IIoT 检测模型必须把规避攻击纳入主评测。
- FedProx 的价值在复杂非 IID 多类任务上最明显，尤其是 CICIoMT-2024 这种类别倾斜严重的网络流场景。
- 选择性对抗训练是本文最实用的工程取舍：只训练脆弱模态，既提升鲁棒性，又避免对稳定模态引入不必要成本。
- 共享 Mamba 骨干带来了参数和通信收益：0.54M 参数、约 1.8MB 上传，明显轻于独立三模型和 FedTransformer。
- SWaT 上存在明显鲁棒性-干净精度代价，说明对抗训练不能只看攻击后 F1，还要看正常运行时误报/漏报成本。
- 论文把安全聚合作为兼容性设计而非真实实现，适合作为算法论文参考，但距离部署级隐私保护还有工程缺口。
- 对本项目有直接启发的是“多源异构安全数据 + 联邦非 IID + 对抗鲁棒 + 边缘开销”四维联合评测框架。

## 13. 建议精读路线

先读 Introduction 和 Related Work，重点抓住论文声称的空白：以往 IoT/ICS 联邦 IDS 多为单模态，以往 MMFL 多在非安全数据集上验证，以往对抗鲁棒联邦学习又很少处理模态异构。

第二步读 Section 3.3 到 3.5，画出参数分块图：`θin,m`、`θback`、`θcls,m` 分别由哪些客户端更新，聚合时分母为什么不同。这是理解 FedMamba 的关键。

第三步读 Section 3.6，对照 HDFS、SWaT、CICIoMT-2024 三种输入空间，理解为什么 HDFS 要在 embedding 空间攻击，为什么作者只对 HDFS/SWaT 做 AT。

第四步读 Table 2、3、4、5、6。建议按问题读表：干净性能是否接近集中式？攻击下掉多少？AT 恢复多少？FedProx 是否必要？共享骨干是否真的比三套模型强？Mamba 相比 Transformer 省了什么？

最后读附录 B、C、D。附录 B 是复现实验的关键；附录 C 暴露安全聚合只是预计开销；附录 D 提醒该框架对后门/投毒仍缺乏系统防御。
