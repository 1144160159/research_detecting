# [080] Embedding Blockchain Technology Into IoT for Security: A Survey

## 1. 基本信息

- 编号：080
- 题名：Embedding Blockchain Technology Into IoT for Security: A Survey
- 作者：Li Da Xu, Yang Lu, Ling Li
- 年份：2021
- 来源：IEEE Internet of Things Journal
- DOI：10.1109/JIOT.2021.3060508
- 类型：综述论文
- 主题：区块链嵌入 IoT 后的安全机制、攻击面、应用场景与挑战
- 相关性判断：与“异常检测”弱相关。论文直接讨论 DDoS 异常连接检测、恶意设备隔离、链上告警共享，但主体不是机器学习异常检测方法，而是 IoT 安全架构综述。

## 2. 中文翻译与核心摘要

本文讨论的问题是：传统 IoT 依赖中心化服务器完成设备管理、身份认证、数据存储和访问控制，但 IoT 设备数量巨大、异构性强、计算与存储资源弱，导致数据采集、传输、存储、认证、访问控制和基础设施层面都存在系统性安全风险。作者认为，区块链的去中心化、共识机制、不可篡改账本、加密机制和智能合约，可以为 IoT 提供一种不完全依赖可信第三方的安全基础设施。

论文不是提出单一算法，而是构建一套综述性框架：先梳理 IoT 的主要安全风险，再解释区块链嵌入 IoT 后可提供哪些安全能力，随后从结构层和功能层两条线分类 IoT 安全问题，进一步讨论区块链化 IoT 面临的新型攻击，最后总结医疗、交通、智慧城市、数据溯源、固件更新、DDoS 防御等应用场景与未来挑战。

核心结论是：区块链确实能缓解 IoT 中的信任缺失、单点故障、数据篡改、身份认证和访问控制问题，但它不是免费安全。IoT 的弱计算能力、弱存储能力、无线链路不稳定、海量节点广播开销、共识延迟和账本一致性问题，会反过来限制区块链在 IoT 安全中的实际落地。

## 3. 论文解决的具体问题

本文解决的不是“如何检测某一类攻击”的窄问题，而是“区块链能否成为 IoT 安全基础设施”的体系化问题。具体包括：

1. IoT 为什么不适合继续完全依赖中心化安全架构。  
   IoT 终端数量大、分布广、设备弱、协议异构，中心服务器既是性能瓶颈，也是攻击者重点打击的单点。

2. 区块链的哪些机制可映射到 IoT 安全需求。  
   例如共识机制对应设备间信任，哈希链和时间戳对应数据完整性与可追溯性，非对称加密对应身份与传输安全，智能合约对应自动化访问控制和安全响应。

3. IoT 不同层次的安全风险如何分类。  
   作者将其拆成传感层、网络层、应用层，以及设备监控与同步问题。

4. 区块链引入后，IoT 安全是否会出现新的攻击面。  
   论文列出 abandon attack、DoS、DDoS、equipment injection、falsify、link、modify、public block modify、time interval destruction 等攻击。

5. 区块链 IoT 安全系统有哪些可落地应用。  
   包括固件安全升级、隐私保护查询、访问控制、身份认证、数据保证、反 DDoS、医疗、交通、智慧城市、供应链溯源等。

## 4. 创新点深度提炼

第一，论文把区块链与 IoT 安全的关系从“技术拼接”提升为“安全能力映射”。作者不是简单说区块链安全，所以 IoT 安全，而是逐项对应：去中心化缓解中心节点失效，共识缓解设备间不信任，时间戳和哈希链支撑数据追溯，非对称加密支撑身份与隐私，智能合约支撑自动化策略执行。

第二，论文提出结构安全与功能安全的双视角分类。结构安全对应 IoT 的传感层、网络层、应用层；功能安全对应固件升级、隐私保护、访问控制、身份认证、数据保证、DDoS 防御和网络自调节。这种分类对写综述很有用，因为它能同时覆盖“攻击发生在哪里”和“安全机制解决什么”。

第三，论文强调区块链嵌入 IoT 后的攻击面并不会消失，而是迁移。传统 IoT 的攻击是设备伪造、数据篡改、认证绕过、DDoS；链化之后还会出现链上账本伪造、共识周期破坏、跨链交易关联、恶意节点丢弃交易等问题。

第四，论文给出较具体的反 DDoS 架构思路。其关键不是单点检测，而是让 IoT 网关节点共享可疑 DDoS 连接信息，通过链上账本和智能合约传播告警、确认受害目标、奖励提交者，并推动其他网关过滤类似连接。

第五，论文提出双链式 IoT 安全方案作为未来方向：数据链负责原始数据采集、完整性和防篡改；交易链负责支付、行为记录和跨实体交互。这一点对工业互联网、车联网、供应链场景尤其重要，因为数据可信和业务交易并非同一种链上负载。

## 5. 科学问题与研究假设

核心科学问题可以概括为：

1. 在缺少中心可信第三方的 IoT 网络中，设备之间能否通过区块链共识建立可验证信任？
2. 区块链不可篡改、可追溯、分布式账本等性质，能否有效提升 IoT 数据安全、身份认证和访问控制能力？
3. 在 IoT 设备资源受限、链路不稳定、节点规模极大的条件下，区块链安全收益是否大于性能和存储代价？
4. 区块链是否能把 IoT 安全从被动防御转向自动化协同防御，例如链上告警共享、智能合约隔离恶意设备？
5. 公有链、联盟链、私有链分别适合 IoT 安全中的哪些场景？

隐含研究假设包括：

- IoT 的中心化架构是许多安全问题的根源之一。
- 大量 IoT 场景不要求所有数据上链，只需要关键身份、摘要、权限、审计和告警信息上链。
- IoT 安全更适合轻量化、分层、联盟链或私有链方案，而不是直接套用 Bitcoin/Ethereum 式公有链。
- 智能合约可以把安全策略从人工配置转化为自动执行规则。
- 区块链可以提升信任和可审计性，但无法替代底层异常检测、恶意流量识别和设备侧加固。

## 6. 科学方法与技术路线

论文采用综述研究方法，技术路线大致是：

1. 从 IoT 原生风险出发，梳理数据采集、传输、标签嵌入、数据存储、认证访问控制、基础设施六类安全问题。
2. 分析区块链嵌入 IoT 的关键特征：去中心化、共识与信任、时间序列化分布式数据、数据加密、智能合约。
3. 建立 IoT 安全分类框架：结构安全和功能安全。
4. 对结构安全，讨论传感层、网络层、应用层以及设备监控同步。
5. 对功能安全，讨论固件升级、隐私保护查询、访问控制、身份认证、数据保证、反 DDoS、网络自调节。
6. 反向审视链化 IoT 的新攻击，包括账本篡改、链路关联、伪造共识、时间间隔破坏等。
7. 按公有链、联盟链、私有链区分信息共享安全机制。
8. 在医疗、交通、智慧城市、数据溯源等场景中讨论落地方式。
9. 总结性能、共识、带宽、通信可靠性、账本一致性等挑战，并提出边缘计算、双链架构、6G 融合等方向。

这篇论文没有传统意义上的实验数据集、模型训练或指标对比。可复核流程应按综述和架构分析方式理解：

2. 预处理  
   将文献按两类组织：IoT 安全综述、区块链 IoT 安全综述。进一步抽取安全问题、区块链机制、攻击类型、应用场景和未来挑战。

3. 模型/基线  
   本文没有机器学习模型。概念基线是传统中心化 IoT 安全架构，比较对象是区块链支持的去中心化 IoT 安全架构。

4. 训练  
   无训练过程。若将其转化为后续研究，可把“DDoS 异常连接检测”作为可训练模块，例如对 TCP SYN flood 使用协议状态特征，对 UDP flood 使用历史包内容聚类或流量行为建模。

5. 指标  
   论文未给出量化实验指标。适合后续复现实验的指标包括检测率、误报率、告警确认延迟、链上写入延迟、吞吐量、存储开销、共识开销、网关隔离响应时间、恶意节点容忍度。

6. 消融/敏感性  
   论文没有消融实验。可设计的敏感性分析包括：节点规模变化、共识算法变化、区块大小变化、无线链路丢包率变化、上链数据比例变化、恶意节点比例变化。

7. 结果核查  
   对本文结论的核查应重点看三点：区块链是否真的降低单点风险；链上访问控制和身份认证是否比中心化方案更可靠；IoT 资源受限条件下，额外共识和存储开销是否可接受。

## 8. 关键结果、结论与证据

论文的关键结论主要是体系性判断：

1. 区块链能改善 IoT 的信任机制。  
   证据来自其去中心化账本、共识机制和非对称密钥体系，可减少对中心 CA 或中心服务器的依赖。

2. 区块链能提升 IoT 数据完整性和可追溯性。  
   哈希链、时间戳、Merkle Tree 和分布式副本使数据更难被单点篡改或删除。

3. 智能合约适合 IoT 自动化安全策略。  
   例如设备访问授权、固件升级验证、DDoS 告警奖励、恶意设备隔离，都可被写成自动触发逻辑。

4. 区块链不是 IoT 安全的完整答案。  
   IoT 设备计算弱、存储弱，公有链吞吐低、延迟高，BFT 类算法通信复杂度高，无线链路不可靠会破坏账本同步。

5. 反 DDoS 是本文与异常检测最接近的部分。  
   作者提出先由节点检测可疑连接，再将初步检测结果提交到链上共享，由智能合约分析目标 IP 相关告警，并推动网关过滤连接。这体现了“本地检测 + 链上协同 + 合约响应”的安全闭环。

## 9. 局限性与待解决问题

本文是综述，不是系统实现论文，因此局限比较明显：

1. 缺少定量实验。  
   论文没有给出真实 IoT 网络中的吞吐、延迟、存储、能耗、检测率或误报率数据。

2. 对异常检测算法讨论较浅。  
   DDoS 部分提到 TCP 状态判断、UDP 历史包聚类，但没有展开特征、模型、阈值、训练数据和评估指标。

3. 区块链代价分析不足。  
   论文承认共识、带宽、存储是瓶颈，但没有系统比较 PoW、PBFT、Raft、Paxos、PoS 在 IoT 场景中的实际成本。

4. 对隐私风险的讨论不够细。  
   区块链可追溯性和用户隐私之间存在张力，尤其是 link attack 会把多个交易或链上的匿名身份关联起来。

5. 落地架构仍偏概念化。  
   例如反 DDoS 架构、双链方案、边缘计算融合方案都具有启发性，但缺少完整协议、威胁模型和安全证明。

6. 本次正文包未截断，因此理解覆盖了提供正文的完整内容；仍建议在引用图表或表格编号时回到 PDF 复核排版细节。

## 10. 与本项目的关系

如果本项目关注异常检测，这篇论文的价值不在于直接提供模型，而在于提供安全架构背景和研究切入点。

可借鉴方向包括：

1. IoT 异常检测结果上链。  
   异常检测模型可在边缘网关运行，检测结果、摘要、证据哈希和处置记录上链，保证审计性。

2. 多网关协同检测。  
   不同网关对可疑 DDoS、恶意设备、异常流量的初步判断可以通过链上共享，减少单点视角不足。

3. 恶意设备隔离闭环。  
   检测、告警、共识确认、智能合约触发访问控制或断连策略，可以形成自动响应流程。

4. 数据可信与训练数据治理。  
   对异常检测来说，训练数据是否被污染很关键。区块链可用于记录数据来源、采集时间、设备身份和处理链路。

5. 联邦学习关联。  
   论文虽不是联邦学习论文，但其“分布式节点 + 隐私保护 + 信任机制”可服务于 IoT 联邦异常检测中的模型更新审计、参与者身份认证和恶意更新追踪。

## 11. 代码对照分析

本地信息显示该论文未发现对应开源代码，因此没有可直接运行的代码目录、训练脚本或评估脚本。

如果后续要按论文思想实现原型，代码结构可以这样对应：

- 智能合约模块：实现权限验证、告警确认、奖励分配、恶意设备隔离规则。
- 训练模块：若引入机器学习，可训练流量异常检测模型或设备行为模型。
- 评估模块：测试检测率、误报率、链上延迟、吞吐、存储开销、共识开销和隔离响应时间。

## 12. 本篇精华

1. 本文的主线是“用区块链重构 IoT 安全信任基础”，不是提出单一检测算法。

2. 区块链对 IoT 的核心价值在于去中心化信任、不可篡改数据、可追溯审计、智能合约自动执行和降低单点故障。

3. IoT 安全可从结构层和功能层理解：结构层看传感层、网络层、应用层；功能层看固件升级、隐私、访问控制、认证、数据保证、DDoS 和自调节。

4. 区块链化 IoT 并非天然安全，会引入 abandon、link、falsify、public block modify、time interval destruction 等新攻击面。

5. 反 DDoS 架构体现了异常检测与区块链结合的典型范式：本地检测、链上共享、智能合约确认、网关协同过滤。

6. 公有链、联盟链、私有链应按 IoT 场景分层使用，资源受限和隐私敏感场景更适合联盟链、私有链或双链结构。

7. 真正落地的关键瓶颈是计算、存储、带宽、共识延迟、无线链路不可靠和账本一致性，而不是单纯选择某个区块链平台。

8. 对异常检测研究来说，本文最有价值的是提供“可信检测协同与审计”的系统框架。
