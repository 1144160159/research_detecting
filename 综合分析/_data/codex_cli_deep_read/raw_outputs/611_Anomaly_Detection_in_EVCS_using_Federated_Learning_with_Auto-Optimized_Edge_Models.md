# [611] Anomaly Detection in EVCS using Federated Learning with Auto-Optimized Edge Models

## 1. 基本信息

- 编号：611
- 题名：Anomaly Detection in EVCS using Federated Learning with Auto-Optimized Edge Models
- 年份：2026
- 来源：IEEE Transactions on Industry Applications
- DOI：10.1109/TIA.2026.3661521
- 主题归类：联邦学习、隐私保护与分布式协同
- 关联方向：EV 充电站网络异常检测、工业控制系统安全、智能电网异常检测、边缘智能
- 代码状态：本地未发现该论文对应开源代码包

这篇论文研究的是分布式电动汽车充电站 EVCS 中的网络攻击检测。它不是把所有充电站数据集中到服务器训练一个模型，而是让每个 EVCS 节点在本地训练轻量模型，再通过联邦学习协同提升检测能力。论文提出的框架叫 FedNAS，核心是“每个站点自动搜索适合自己的轻量神经网络结构 + 服务器端用集成式元聚合融合各客户端预测”。

## 2. 中文翻译与核心摘要

论文要解决的问题可以概括为：在多个地理分散的 EVCS 中，如何在不上传原始运行数据的前提下，对中间人攻击引起的充电控制异常进行准确、低延迟、可部署的检测。

传统集中式异常检测要求收集每个充电站的电压、频率、功率、SoC 等运行数据，这会带来通信开销、数据治理和隐私风险，也不适合边缘实时响应。普通联邦学习虽然能避免上传原始数据，但大多假设所有客户端使用同一模型结构，并采用 FedAvg 进行参数平均；这在 EVCS 场景中不够理想，因为不同站点的负载模式、充电桩数量、攻击模式和特征维度并不一致，数据天然非 IID。

FedNAS 的思路是让每个 EVCS 客户端先用神经架构搜索 NAS 找到适合本地数据的轻量 SimpleNN，然后在本地训练。服务器端不强行要求这些异构模型参数对齐，也不简单做权重平均，而是收集各客户端模型在服务器验证集上的概率预测，再通过类似逻辑回归的元学习聚合器学习每个客户端预测的权重，形成全局集成判别器。推理阶段则回到边缘侧执行，每个 EVCS 使用本地个性化模型进行实时检测，不依赖服务器在线参与。

实验基于 IEEE 123-bus 配电系统，集成 4 个 EVCS 节点，并通过 OPAL-RT 实时仿真生成接近工业环境的运行数据。攻击模型主要是中间人攻击篡改有功功率参考信号，包括单脉冲攻击和多脉冲攻击。结果显示，FedNAS 在全局模型上达到 98.25% accuracy、96.62% precision、100% recall、98.28% F1，优于 FedAvg 和 FedProx，并具有较低的通信与推理延迟。

## 3. 论文解决的具体问题

论文聚焦的不是泛化意义上的“异常检测”，而是一个具体工业网络安全问题：EVCS 接入配电网后，攻击者通过中间人攻击篡改充电控制参考信号，造成电压、频率、功率、SoC 等运行状态异常，系统需要在多个分散充电站中及时发现这种异常。

具体挑战包括：

1. EVCS 数据不宜集中  
   数据包含站点运行状态、用户充电行为、功率变化和电网状态。即使论文也承认这些主要是 operational data 而非强个人数据，但集中上传仍会带来数据治理、带宽和攻击面问题。

2. 客户端数据非 IID  
   不同 EVCS 接入不同母线，充电桩数量不同，局部负载、充电行为和攻击扰动也不同。用一个统一模型结构去拟合所有站点，容易牺牲本地适配性。

3. 传统 FedAvg 不适合异构模型  
   FedAvg 依赖参数维度一致和结构一致，本质上对客户端模型做平均。若每个客户端需要不同网络结构，FedAvg 就难以直接使用；即便结构相同，在非 IID 数据下也可能收敛到偏向某些客户端的折中模型。

4. 需要边缘实时推理  
   EVCS 异常检测不只是离线分类任务，真实部署需要低延迟检测。论文强调训练阶段可以联邦协作，但推理阶段必须本地执行。

5. 以往验证环境不够贴近电力系统  
   论文批评一些既有研究使用普通 benchmark 或合成数据，没有放到 IEEE test system 和 EVCS 接入场景中检验，因此缺少电网动态响应、空间分布和站点异质性。

## 4. 创新点深度提炼

第一，论文将 NAS 引入 EVCS 联邦异常检测，使每个客户端自动选择轻量神经网络结构。  
这比“所有 EVCS 使用同一个固定模型”更贴近实际。EVCS1 和 EVCS3 只有两个 XFC，特征总数为 16；EVCS2 和 EVCS4 有四个 XFC，特征总数为 28。数据维度和复杂度不同，模型复杂度也应不同。FedNAS 通过受限搜索空间在边缘可承受范围内选择 12 或 16 个神经元、ReLU 或 LeakyReLU 等结构。

第二，论文用预测级元聚合替代参数级平均。  
传统 FedAvg 聚合权重，要求模型结构一致；FedNAS 聚合各客户端输出的概率预测，因此允许客户端模型结构不同。服务器通过带 L2 正则的逻辑回归式元聚合器学习各客户端权重，相当于对“谁在当前验证分布上更可靠”进行加权，而不是按样本数机械平均。

第三，论文把“隐私保护”重新解释为 EVCS 场景中的“数据保留/数据本地性”。  
作者意识到 EVCS 的电压、频率、功率、SoC 主要是基础设施运行数据，并不完全等同于医疗或金融中的个人敏感数据。因此 FL 在这里的价值不只是 privacy preservation，更是 data preservation：减少原始数据搬移，降低通信负担，维护站点数据完整性和本地治理边界。

第四，论文强调训练-推理解耦。  
训练阶段客户端进行 NAS、本地训练和预测上传；服务器进行元聚合。推理阶段服务器不参与，每个 EVCS 使用自己的个性化模型做本地检测。这一点对工业部署很重要，因为异常检测不能依赖持续云端通信。

第五，验证场景比普通数据集更接近电力网络。  
论文使用 IEEE 123-bus test system，接入 4 个 EVCS，设置 12 个极快充 XFC-EV 单元，并通过 OPAL-RT 获取实时仿真数据。攻击不是抽象标签，而是通过篡改有功功率参考信号形成可观察的电压、频率、功率扰动。

## 5. 科学问题与研究假设

核心科学问题可以表述为：

在分布式、非 IID、边缘资源受限的 EVCS 网络中，是否可以通过个性化模型结构搜索与预测级联邦聚合，在不共享原始数据的情况下实现高准确率、低通信开销、低延迟的网络攻击检测？

论文隐含了几个关键研究假设：

1. EVCS 异常具有可从运行信号中识别的统计特征  
   攻击会改变频率、电压、功率和 SoC 的动态行为；经过滑动窗口提取均值和方差后，这些特征足以支持分类模型识别攻击。

2. 客户端异质性不是噪声，而是应被保留的本地知识  
   不同 EVCS 的数据差异不应被 FedAvg 平均掉，而应通过个性化模型结构和元聚合来利用。

3. 轻量 SimpleNN 足以覆盖该任务的主要判别边界  
   论文没有使用复杂深度时序模型，而是用窗口统计特征 + 小型前馈网络，假设攻击模式在这些统计特征中已经足够明显。

4. 服务器验证集可以代表全局正常/攻击分布  
   元聚合依赖一个服务器端 labeled validation set。如果这个验证集代表性不足，学习到的客户端权重可能偏向某些场景。

5. 预测级共享比权重共享更适合异构联邦  
   论文假设上传预测可以兼容不同结构、降低通信，并在一定程度上降低从参数反推数据的风险。

## 6. 科学方法与技术路线

论文方法可以分为五层。

第一层是系统建模。  
4 个 EVCS 作为 4 个联邦客户端，接入 IEEE 123-bus 配电系统的 bus 25、51、54、97。EVCS1 和 EVCS3 各有 2 个 XFC，EVCS2 和 EVCS4 各有 4 个 XFC，总共 12 个 XFC-EV 单元。每个 XFC-EV 被简化为等效 P-Q load，并加入 SoC 计算和充放电管理。

第二层是威胁建模。  
攻击者是中间人 MitM，篡改充电控制中的有功功率参考信号。单脉冲攻击用一个矩形脉冲扰动参考信号；多脉冲攻击用多个幅值、持续时间、占空比和间隔不同的矩形脉冲构成更隐蔽的扰动序列。攻击体现在电压、频率、功率等信号的异常振荡或突变上。

第三层是特征构造。  
采集每个 EVCS 的 frequency、voltage、power、SoC 等信号。用 20,000 samples 的滑动窗口对应 1 秒运行片段，对每个信号计算均值和方差，把高分辨率时序数据转成结构化特征矩阵。不同客户端特征数不同，最后通过 zero-padding 对齐到最大 28 维。

第四层是本地 NAS + SimpleNN。  
每个客户端在本地数据上执行受限 NAS，搜索小型网络结构，例如隐藏层数量、神经元规模和激活函数。搜索空间包括 1-2 个隐藏层、4-8/8-16/16-32 神经元范围、ReLU 和 LeakyReLU。训练使用 Adam、BCE loss、batch size 32、local epochs 20、dropout 0.2、batch norm。

第五层是服务器端元聚合。  
客户端不上传原始数据，论文主体更强调上传预测 Pi 到服务器。服务器用带标签验证集学习各客户端预测的组合权重，形式上类似 softmax 归一化权重下的加权概率融合，并用 L2 正则的 meta-loss 训练。最终形成 global meta-model，同时客户端保留本地个性化模型用于推理。

## 7. 实验设计与实验步骤

1. 数据生成  
   在 IEEE 123-bus 配电系统中接入 4 个 EVCS，位置分别为 bus 25、51、54、97。构造正常运行、单脉冲攻击、多脉冲攻击三类场景。正常场景包括 EV 渐进接入，有 ramp 和无 ramp 两种；攻击场景通过 MitM 修改有功功率参考信号。

2. 原始信号采集  
   采集每个 EVCS 的频率、电压、功率、SoC，以及 PCC frequency 等关键运行量。客户端特征分布为：Client 1 和 Client 3 各 16 个特征，Client 2 和 Client 4 各 28 个特征。

3. 预处理  
   使用长度为 20,000 samples 的滑动窗口，对应 1 秒运行片段。对每个窗口内信号计算 mean 和 variance，形成机器学习输入。使用 StandardScaler 标准化特征。对特征维度不足 28 的客户端使用 zero-padding。训练中还使用 Gaussian noise，σ=0.02，作为数据增强。

4. 数据划分  
   客户端数据按 80/20 划分训练和测试。服务器端另建一个 balanced normal/attack validation set，用于元聚合器学习客户端预测权重。论文称该验证集来自仿真生成的代表性运行场景，不包含用户特定信息。

5. 模型与基线  
   提出方法是 FedNAS：每个客户端 NAS 搜索轻量 SimpleNN，再进行本地训练，服务器做预测级 meta-ensemble。对比方法包括 FedAvg、FedProx，以及文中提到的 centralized learning。FedProx 设置 μ=0.01。

6. 训练流程  
   联邦训练共 20 rounds。每轮中，每个客户端并行执行本地 NAS，得到架构 Ai；训练本地模型 Mi；在服务器验证集上生成预测 Pi；服务器用这些预测训练或更新元聚合器；最后将 meta-model 或相关聚合信息返回客户端。

7. 指标  
   分类性能使用 Accuracy、Precision、Recall、F1-score、ROC AUC、Average Precision。部署性能使用 computation time、communication time、inference latency、inference communication。论文特别重视 recall，因为漏报攻击在 EVCS 安全中代价较高。

8. 消融与敏感性  
   正文中的消融比较主要体现在 FedNAS vs FedAvg vs FedProx，以及 NAS 搜索到的架构分布分析。更严格的敏感性实验仍不足，例如客户端数量扩展、攻击强度变化、服务器验证集规模变化、非 IID 程度变化、恶意客户端比例变化等。

## 8. 关键结果、结论与证据

第一，FedNAS 的全局检测性能最高。  
表 II 显示 Global Model 达到 98.25% accuracy、96.62% precision、100% recall、98.28% F1。所有客户端 recall 都是 100%，说明模型在实验设置下没有漏检攻击。

第二，FedNAS 优于 FedAvg 和 FedProx。  
表 III 中 FedNAS accuracy 为 0.9825，高于 FedAvg 的 0.9625 和 FedProx 的 0.9575；Average Precision 为 0.9955，高于 FedAvg 的 0.9302 和 FedProx 的 0.9330。论文据此认为预测级元聚合能更好处理非 IID 和客户端异构。

第三，FedNAS 在概率排序能力上优势明显。  
ROC AUC 达到 0.9960，Average Precision 达到 0.9955。这对安全运维有意义，因为实际系统不仅需要二分类，还需要根据风险分数排序和触发告警优先级。

第四，边缘推理延迟很低。  
表 IV 中 FedNAS inference latency 为 0.0208 ms，且 inference communication 为 Local Only。也就是说，部署后每个 EVCS 可在本地完成检测，不需要把实时数据发给服务器。

第五，NAS 搜索确实产生了不同客户端结构。  
表 V 显示 16-neuron ReLU 和 12-neuron LeakyReLU 各出现 2 次。这说明在该实验中客户端之间存在一定结构偏好差异，但差异幅度不大，搜索出的都是很轻量的网络。

第六，攻击在物理信号上可见。  
正常场景下 EV 接入会造成短暂频率振荡和电压下降，但系统迅速恢复；单脉冲和多脉冲攻击会造成更明显的频率、电压扰动，SoC 在攻击期间也可能异常停滞。这为统计特征分类提供了物理依据。

## 9. 局限性与待解决问题

1. 正文内部存在关键数值不一致  
   表 II/III 中 FedNAS 全局 accuracy 为 98.25%，但结论段写 95.63%；表 IV 中 FedNAS computation time 为 18.76s，但结论段写 35.87s；摘要说 reduced communication overhead，结论又提到 0.16 MB 和 45% lower than centralized methods，但表 IV 只列 communication time。说明作者版本可能有遗留内容或版本混合，正式引用前应复核最终 PDF。

2. “共享什么”表述不完全一致  
   引言和方法强调客户端分享 predictions，不分享 raw data 或 weights；但系统模型部分又写客户端分享 Wk 和 Ak，结论部分也写 sharing only model weights。图注还特别说明数学表示中有 Wi,A，但实际用于 ensemble aggregation 的是 Pi。这是方法描述上的重要歧义。

3. 隐私保护缺少形式化保证  
   预测级共享降低了参数泄露风险，但不等于严格隐私。模型输出仍可能遭受 membership inference、property inference 或 validation-set probing。论文自己也承认未来需要 differential privacy 和更严格 adversarial testing。

4. 客户端规模太小  
   实验只有 4 个 EVCS 节点。虽然适合 IEEE 123-bus 案例展示，但不足以证明大规模联邦部署中的收敛性、通信稳定性和客户端掉线鲁棒性。

5. 攻击类型仍偏受控  
   主要是参考信号上的单脉冲和多脉冲 MitM 扰动。现实 EVCS 还可能面临 false data injection、DoS、充电协议攻击、固件篡改、后门模型更新、恶意客户端投毒等更复杂威胁。

6. 特征工程较简单  
   论文使用窗口均值和方差，没有充分比较时序模型、频域特征、变化率特征、物理约束残差等。当前高性能可能部分来自攻击扰动在统计特征上较明显。

7. 元聚合依赖服务器验证集  
   如果服务器验证集不覆盖新站点、新攻击强度或新运行季节，meta-weight 可能失效。这个问题在实际部署中很关键，但论文没有系统分析。

8. 统计显著性不足  
   附录提到固定随机种子为 42，但没有多随机种子均值/方差、置信区间或显著性检验。对于 1-2% 的性能提升，统计稳定性需要进一步验证。

## 10. 与本项目的关系

这篇论文与“异常检测”项目的关系属于中高相关，尤其适合放在“联邦学习、隐私保护与分布式协同”章节下，同时可作为“智能电网/EVCS 工业异常检测”的案例。

它对本项目有三点直接参考价值：

1. 分布式异常检测范式  
   论文提供了一个清晰的边缘站点协同检测框架：数据留在本地，模型协同学习，推理本地执行。这适用于电力、工业控制、车联网、边缘 IoT 等多站点异常检测场景。

2. 异构客户端处理思路  
   对非 IID 客户端，不一定要强制统一模型并做 FedAvg。预测级集成、个性化模型、元学习权重，是可迁移到其他网络安全场景的设计。

3. 实验构造方式  
   论文把攻击注入到物理控制参考信号，再观察电压、频率、功率、SoC 的变化。这种“网络攻击-物理响应-检测特征”的链条，比单纯拿公开网络流量数据训练分类器更适合网络物理系统安全研究。

不过，本项目若要借鉴该论文，应避免直接照搬其结果。更稳妥的做法是吸收其技术路线：非 IID 多客户端 + 个性化轻量模型 + 预测级聚合 + 本地推理，然后在自己的数据集上重新验证。

## 12. 本篇精华

1. FedNAS 的本质是个性化联邦异常检测：每个 EVCS 自己搜索轻量网络结构，服务器只学习如何融合各站点预测。

2. 论文最有价值的设计不是 NAS 本身，而是用预测级 meta-ensemble 绕开了异构模型无法 FedAvg 的问题。

3. EVCS 场景下 FL 的意义不只是隐私保护，更是数据本地性、通信节省和边缘实时推理。

4. 攻击建模有明确物理链条：MitM 篡改有功功率参考信号，造成电压、频率、功率和 SoC 异常，再由模型检测。

5. 实验基于 IEEE 123-bus + OPAL-RT + 4 个 EVCS，比普通 benchmark 更贴近电力网络异常检测。

6. FedNAS 在表格结果中达到 98.25% accuracy、100% recall 和 0.9955 average precision，优于 FedAvg/FedProx。

7. 论文存在方法和数值表述不一致，尤其是共享 predictions 还是 weights、98.25% 还是 95.63%，正式综述引用时必须谨慎。

8. 后续研究空间很明确：更多客户端、更复杂攻击、恶意客户端、差分隐私、服务器验证集偏移和统计显著性验证。

## 13. 建议精读路线

建议先读 Introduction，重点抓住作者批评的四个痛点：固定模型结构、FedAvg 不适合非 IID、集中式数据不适合 EVCS、已有实验环境不真实。

第二步读 Section II，弄清楚系统模型和威胁模型。尤其要理解单脉冲、多脉冲攻击如何作用到功率参考信号，以及为什么这种扰动会反映到频率、电压、功率、SoC。

第三步读 Section III，重点看 FedNAS 的训练流程和 Algorithm 1。这里要特别标注“预测级聚合”与“权重级聚合”的差别，同时记录正文中关于 Wk/Ak/Pi 的不一致表述。

第四步读 Case Study，整理实验复现条件：IEEE 123-bus、4 个 EVCS、12 个 XFC-EV、20,000 samples 窗口、mean/variance、StandardScaler、zero-padding、20 rounds。

第五步读 Results，优先看表 II、III、IV、V。不要只记最高 accuracy，要同时关注 recall、average precision、推理延迟和 NAS 搜索出的结构分布。

最后读 Conclusion 和 Appendix Table VI，核查实验配置，并把结论段中的数值与正文表格逐一对比。该论文适合作为综述中的“FL + 个性化边缘模型 + EVCS 异常检测”代表，但引用具体数值前应回到正式 PDF 版本复核。
