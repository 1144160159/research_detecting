# [035] MaMPF: Encrypted Traffic Classification Based on Multi-Attribute Markov Probability Fingerprints

## 1. 基本信息

- 中文题名：MaMPF：基于多属性马尔可夫概率指纹的加密流量分类。
- 来源：IWQoS 2018，DOI：10.1109/iwqos.2018.8624124。
- 任务定位：SSL/TLS 加密流量的闭集应用识别，不解密 payload，仅使用可见握手消息类型和包长序列。
- 数据：2017 年 7 月 20 日起校园网 7×24 小时采集，初始约 160 万 SSL/TLS flows、1860 万 packets；最终得到 95.6 万余条、18 类应用流。
- 正文包完整到参考文献，未见截断标记；代码包位于 `source\MaMPF`。

## 2. 中文翻译与核心摘要

本文认为，加密后虽然应用层内容不可见，但 SSL/TLS 流中的“消息类型序列”和“包长时间序列”仍携带应用行为模式。MaMPF 的核心做法是：先把原始包长按应用内的幂律频率分布压缩成长度块序列 LBS，再分别为每个应用训练消息类型 Markov 模型和长度块 Markov 模型；对一个待分类流，计算它在所有应用模型下的出现概率，做根归一化后作为概率指纹送入分类器。

它不是简单地用某个最大似然 Markov 模型直接判类，而是把“所有应用模型怎么看这个流”作为特征。论文中默认逻辑回归版本达到 AVE-TPR 94.0%、AVE-FPR 0.33%、FTF 0.9333；随机森林版本达到 96.4%、0.2%、0.960，对应摘要中的最好结果。

## 3. 论文解决的具体问题

传统端口识别和 DPI 在加密、动态端口、伪装端口场景下失效；TLS 握手明文字段和流统计特征虽然可用，但区分能力有限。

已有 Markov 方法主要建模 TLS message type sequence，问题是不同应用会出现大量相同 MTS。论文展示了 2000 多种 MTS 重合情况，这意味着只靠握手/消息类型转移，很多流在特征空间里天然不可分。

后续方法加入证书包长度或首个通信包长度，但这两个孤立长度值容易在不同应用间聚类到一起，而且 TLS session resumption 会让证书过程缺失。MaMPF 要解决的是：在不解密内容、不依赖证书必然存在的前提下，构造更稳定、更有区分力的加密流量指纹。

## 4. 创新点深度提炼

- LBS 是本文最关键的增量：它把完整包长序列作为时间序列建模，而不是只取证书长度或首个 application data 长度。
- 幂律划分不是等宽分箱。每个应用按包长出现频率排序，取能覆盖一定比例流量的高频包长作为代表长度块，再把其他长度映射到最近长度块；这保留了应用特有的包长偏好。
- “多属性”有两层含义：一是 MTS 与 LBS 两种序列属性；二是使用所有应用 Markov 模型输出的相对概率，而不是只看目标应用的最大概率。
- 根归一化解决 Markov 连乘概率随流长度指数级衰减的问题，使不同包数的 flow 概率可比较。
- 特征与分类器解耦：线性 SVM、逻辑回归、GBDT、随机森林都能工作，说明 MaMPF 的贡献主要在特征构造，而非某个分类器调参。

## 5. 科学问题与研究假设

科学问题可以概括为：在 payload 不可见且 TLS 握手信息不完整的条件下，应用层行为是否仍会在可观测的协议状态序列和包长序列中留下稳定指纹？

论文隐含了几个研究假设：

- 同一应用的 TLS message type 转移和包长转移具有统计稳定性。
- 不同应用的包长频率分布近似幂律，且幂律曲线参数和高频长度块具有判别性。
- 一阶 Markov 模型虽然粗糙，但足以捕获 MTS/LBS 的主要局部转移规律，并能避免高阶模型矩阵稀疏。
- 全体应用模型输出的概率向量比单一最大似然决策更稳健，因为误分类往往来自多个应用之间的相对相似性。
- SNI 与 Whois 结合能构造足够可信的监督标签，尽管它不是完美 ground truth。

## 6. 科学方法与技术路线

技术路线是“观测重合问题 → 引入包长序列 → 幂律压缩 → Markov 概率化 → 分类器判别”。

1. 从 SSL/TLS flow 中抽取服务器侧 message type sequence 和 raw packet length sequence。
2. 对每个应用统计包长频率，按频率降序排列；选择累计覆盖率达到阈值附近的高频长度作为 length blocks。
3. 将每条包长序列映射成 LBS：每个原始长度替换为最近的代表长度块。
4. 对每个应用分别训练两个一阶 Markov 模型：MTS Markov 和 LBS Markov，因此 18 类应用对应 36 个模型。
5. 对每条流计算它在所有应用模型下的出现概率，并做根归一化。
6. 将归一化概率作为 MaMPF 指纹，训练逻辑回归或其他分类器。

## 7. 实验设计与实验步骤

1. 数据：校园网真实流量，过滤 SSL/TLS；用 SNI 子串匹配应用域名，并用 Whois 解析结果交叉确认，得到 18 类应用数据。
2. 预处理：进行流重组和流规约；抽取 message type、packet length；论文主要使用服务器侧 message type，以减少客户端配置差异。
3. 模型与基线：比较 FoSM、SoSM、SOCRT、SOB、SMPF、SLaveMPF、MaMPF。FoSM/SoSM 是一阶/二阶 MTS Markov；SOCRT/SOB 加入证书长度和首个通信包长度；SMPF 只用 MTS 概率指纹；SLaveMPF 用等宽长度分箱。
4. 训练：5 折交叉验证，每次 4 份训练、1 份测试；MaMPF 默认长度覆盖率为 90%，分类器默认逻辑回归 L2。
5. 指标：TPR、FPR、加权 FTF；AVE-TPR 和 AVE-FPR 按各应用流量规模加权。
6. 消融/敏感性：比较只用 MTS、等宽长度分箱、幂律长度块；测试覆盖率 50% 到 95%；测试 LinearSVM、LogicR、GBDT、RandomF。
7. 结果核查：除总指标外，论文还用混淆矩阵观察 SOB 与 MaMPF 的误分类结构，重点验证 JD、QQ、Taobao 等重合严重类别是否被拉开。

## 8. 关键结果、结论与证据

| 方法 | AVE-TPR | AVE-FPR | FTF | 读法 |
|---|---:|---:|---:|---|
| FoSM | 0.6206 | 0.0211 | 0.6125 | 一阶 MTS 不够 |
| SoSM | 0.6488 | 0.0195 | 0.6415 | 二阶略好但有限 |
| SOB | 0.6652 | 0.0186 | 0.6563 | 加孤立长度仍不稳 |
| SMPF | 0.6962 | 0.0169 | 0.6725 | 概率指纹有帮助 |
| SLaveMPF | 0.8261 | 0.0097 | 0.8064 | 加包长序列明显提升 |
| MaMPF-LR | 0.9400 | 0.0033 | 0.9333 | 幂律 LBS 是关键 |
| MaMPF-RF | 0.9640 | 0.0020 | 0.9600 | 论文最好结果 |

最有说服力的证据不是平均值，而是误分类结构变化。SOB 会把大量 JD 流错分到 Youdao，说明证书长度和首包长度不能解除 MTS 重合；MaMPF 的混淆矩阵明显更接近对角线。JD 的 TPR 从 SOB 的 18.36% 到 MaMPF-LR 的 86.10%，QQ 从 19.23% 到 94.93%，Taobao 从 30.02% 到 76.27%，这些类别正是长度序列贡献最大的地方。

## 9. 局限性与待解决问题

本文是强监督闭集分类，默认测试应用都在训练类别中；未知应用、混合业务、恶意伪装流量没有作为开放集问题处理。

ground truth 依赖 SNI 与 Whois，空 SNI、解析失败、假 SNI 会被丢弃或影响可信度。这个过程提升了标签质量，但也引入选择偏差：最终数据更偏向“可被域名确认”的 TLS 流。

数据来自单一校园网、单一时间窗口，应用类别和用户行为具有场景性；是否跨网络、跨时间、跨版本稳定，论文没有系统验证。

长度特征有可规避性。若应用或攻击者使用 padding、流量整形、批量复用连接，LBS 的判别力可能下降。

一阶 Markov 是工程上稳妥的折中，但它只捕获局部转移；论文没有解决长程依赖，只是通过概率指纹和 LBS 缓解。

正文包未截断；本次局限不是正文缺失导致的。真正的复现局限来自代码包缺少原始数据、缺少 PCAP 到 `.num` 的转换脚本，也没有论文 5 折交叉验证的完整实验驱动。

## 10. 与本项目的关系

这篇与“加密流量分类与应用识别”强相关，也能服务异常检测项目的前置能力：先识别应用上下文，再在同类应用内部做异常建模。

对跨域异常检测的价值在于 MaMPF 输出的是低维、可解释的相对概率指纹。某条流若在所有已知应用模型下概率都低，或概率分布异常平坦，可以进一步构造成未知类/异常分数。

但它本身不是异常检测论文。它解决的是已知 18 类应用的分类问题；若用于本项目，需要补上开放集识别、时间漂移评估、攻击流验证和现代协议场景下的再采集实验。

## 12. 本篇精华

- MaMPF 的核心不是“用了 Markov”，而是把每个应用 Markov 模型的相对概率变成分类特征。
- 只用 TLS message type 会遇到大量跨应用重合；包长序列是解除重合的关键补充信息。
- 幂律长度块比等宽分箱更贴近应用真实流量分布，能减少维度又保留高频判别长度。
- 根归一化是必要步骤，否则长 flow 的 Markov 连乘概率会天然接近 0。
- 论文最强证据来自 MaMPF 对 JD、QQ、Taobao 等难分类应用的大幅提升。
- 90% 覆盖率是性能和长度块规模之间的折中；95% 可继续提分但长度块数量急剧增加。
- 代码可作为方法骨架，但不是完整复现实验包：缺数据、缺上游解析、缺 5 折实验脚本，且融合实现与论文描述存在差异。
