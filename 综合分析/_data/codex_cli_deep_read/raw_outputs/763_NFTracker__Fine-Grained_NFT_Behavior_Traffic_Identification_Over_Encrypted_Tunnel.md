# [763] NFTracker: Fine-Grained NFT Behavior Traffic Identification Over Encrypted Tunnel

## 1. 基本信息
- 年份/来源：2026，IEEE Transactions on Cognitive Communications and Networking。

## 2. 中文翻译与核心摘要
这篇论文研究的问题不是“识别用户访问了哪个 NFT 平台”，而是进一步判断用户在加密隧道中做了什么 NFT 操作：浏览、钱包登录、购买、出售或铸造。作者认为 V2Ray/VMess/TLS 这类隧道会隐藏真实目的地址、端口和应用层内容，但仍保留包长、方向、时间间隔、突发结构等侧信道特征。

NFTracker 的核心思路是三段式：先用 burst 与 Wasserstein Distance 找行为边界，再用滑动窗口提取局部动作级时空特征，最后用 CNN-Transformer 混合模型分类五类 NFT 行为。实验显示其平均 F1 为 0.9212，优于 GraphDApp、ActiveTracker、PACKETPRINT、Hou 等方法和 BehavSniffer。

## 3. 论文解决的具体问题
论文解决的是：在加密隧道把 NFT 平台通信封装为长连接 HTTPS-like 流量后，如何从被动抓包中识别具体 NFT 用户行为。

关键难点有两个。第一，行为边界不清楚：连续浏览、登录后购买、铸造后出售等行为会混在同一双向 session flow 中，固定时间窗或协议帧对齐都不可靠。第二，特征同质化：同一 NFT 应用界面和业务流程相近，加密隧道又二次封装，使购买、出售、铸造中的钱包确认和交易验证阶段高度相似。

## 4. 创新点深度提炼
- 论文把 NFT 监管分析从平台/DApp 级识别推进到行为级识别，分析对象从“访问 OpenSea/LooksRare”变成“浏览、登录、购买、出售、铸造”。
- burst-WD 分割是关键创新：不依赖明文协议字段，而利用 burst 起点作为候选边界，再用左右窗口包长/方向分布的 Wasserstein 距离判断是否是真边界。
- 滑动窗口不是简单扩增样本，而是为了捕捉行为内部的动作片段，例如钱包验证、资源加载、上传媒体、签名确认等局部指纹。
- CNN-Transformer 的组合有明确分工：CNN 处理包长方向矩阵中的局部空间模式，Transformer 处理时间间隔序列中的跨动作依赖。
- 论文较系统地刻画了五类 NFT 行为的网络交互模式，这对后续 NFT 取证和异常交易检测有参考价值。

## 5. 科学问题与研究假设
科学问题：加密隧道是否会完全抹除 NFT 细粒度行为差异？如果不会，哪些不可见内容之外的流量侧信道还能稳定表征行为？

核心假设有三点。第一，不同行为虽然被 VMess/TLS 封装，但请求-响应、钱包验证、资源加载、媒体上传等动作仍会留下包长、方向和时间结构。第二，真实行为边界附近左右流量分布会发生可度量变化，WD 能比简单距离更稳定地刻画稀疏直方图差异。第三，行为差异主要藏在局部动作片段中，而非完整长序列的全局统计中。

## 6. 科学方法与技术路线
技术路线是“分割-表征-分类”。

分割阶段：从双向 session flow 去除 ACK 和零 TCP payload 包，提取 burst 起点作为候选边界；在候选点左右各取 r 个包，计算包长分布和方向分布的 WD；用随机森林过滤伪边界。

表征阶段：对已分割行为段构造两类序列。包长带方向符号形成空间特征矩阵；相邻包到达时间差形成时间特征矩阵。滑动窗口大小 W、步长 s 决定局部动作覆盖程度。

分类阶段：空间矩阵进入 CNN，时间矩阵进入 6 层 Transformer encoder；两路 embedding 拼接，经全连接层和 softmax 输出五类行为概率。

## 7. 实验设计与实验步骤
1. 数据：D1 含 81 个复合行为 pcap、2116 个候选分割点，用于训练/验证分割随机森林；D2 含五类 NFT 行为，每类 2000 条双向 session flow，用于行为分类。
2. 采集：V2Ray TCP 传输、VMess 加密、关闭 multiplexing，关闭 TCP Segmentation Offload；用 Tshark 抓包，Selenium 与人工操作模拟行为，跨地域服务器降低网络环境偏差。
3. 预处理：过滤 ACK 与零载荷包，保留包长、方向、时间戳；将行为边界标注为真实点或伪点。
4. 模型/基线：NFTracker 对比 GraphDApp、ActiveTracker、PACKETPRINT、Hou et al.、BehavSniffer，以及仅 CNN、仅 Transformer 的变体。
5. 训练：D2 按 8:1:1 切分训练、验证、测试；分割模型和分类模型分别训练。
6. 指标：分割和分类均使用 Accuracy、Precision、Recall、F1-score。
7. 消融/敏感性：搜索分割窗口半径 r=10 到 60；搜索滑动窗口 W=10 到 50、步长 s=1 到 7；用 t-SNE 对比原始特征与滑窗特征可分性。
8. 结果核查：查看分割 F1、分类平均 F1、混淆矩阵，重点核查购买/出售、铸造/出售这类相似流程的误分。

## 8. 关键结果、结论与证据
- 分割模块最佳 r=25，NFTracker 分割 F1=0.902，优于 ActiveTracker 和 PACKETPRINT。
- 滑动窗口最佳组合为 W=40、s=5，说明完整动作片段通常需要中等长度窗口覆盖，过小丢依赖，过大混入多动作噪声。
- 分类平均 Precision=0.9245，Recall=0.9179，F1=0.9212，是所有方法中最高。
- NFT 浏览几乎最好识别，原因是周期性请求-响应和大量 MTU 响应包形成强指纹。
- 最难区分的是购买与出售，因为二者都包含钱包验证、签名/授权、交易确认等相似阶段；铸造也会因钱包授权与出售产生部分混淆。

## 9. 局限性与待解决问题
正文包未截断，本次理解基于完整提供文本；仍建议回到 PDF 复核图表细节、混淆矩阵具体数值和表格排版。

主要局限包括：实验关闭了 V2Ray multiplexing，而作者承认多路复用会把多个逻辑流混入单 TCP 连接，显著破坏包长与时间间隔特征；对 packet padding 的鲁棒性只做讨论，没有实验证明；数据集中平台主要是 OpenSea、LooksRare，跨平台、跨 Layer2、跨钱包和真实用户长期行为的泛化仍需验证；方法也可能被针对性对抗混淆干扰，例如构造局部 WD 相似但全局方向关系紊乱的伪流量。

## 10. 与本项目的关系
该文与“异常检测、恶意流量、暗网与攻击检测”强相关，因为它提供了从加密隧道中恢复高层行为语义的路线。对本项目而言，它可作为细粒度行为识别模块：先识别 NFT/DApp 平台，再识别具体操作，再把高频购买、异常出售、批量铸造、重复钱包登录等行为送入风险检测或取证分析链路。

更重要的是，论文把“加密流量分类”与“链上行为监管”连接起来：链上只能看到地址和交易，网络侧能补足真实访问与操作时序，两者结合才可能形成更强的异常检测证据。

## 12. 本篇精华
- NFT 行为识别的核心不是破解加密，而是利用加密无法完全隐藏的流量形态侧信道。
- 分割比分类更基础；没有可靠行为边界，后续模型容易学习到混合行为噪声。
- WD 适合这里的原因是它能度量左右窗口分布迁移，而不是只比较均值、方差或逐 bin 差异。
- 滑动窗口的价值在于动作级局部指纹，尤其适合购买/出售/铸造这类由多个相似子流程组成的行为。
- CNN-Transformer 的效果来自互补：一个抓局部包长方向图案，一个抓跨窗口时间依赖。
- 购买与出售仍是最难类别，说明业务语义相近时，仅靠网络侧侧信道存在天然上限。
- 多路复用和主动 padding 是该方向走向真实部署前必须解决的问题。
