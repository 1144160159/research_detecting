# [392] DACAD: Domain Adaptation Contrastive Learning for Anomaly Detection in Multivariate Time Series

## 1. 基本信息

- 题名译名：DACAD：面向多变量时间序列异常检测的领域自适应对比学习
- 年份与来源：2025，IEEE TKDE，DOI：`10.1109/TKDE.2025.3569909`
- 任务定位：有标注源域 + 无标注目标域的多变量时间序列异常检测。
- 数据集：MSL、SMAP、SMD、Boiler，另有合成数据用于可扩展性测试。
- 本地代码：`source\DACAD`，PyTorch 实现；正文包未截断。

## 2. 中文翻译与核心摘要

这篇论文处理的问题不是普通无监督 TSAD，而是“跨域异常检测”：目标域没有标签，但有一个相关源域带有正常/异常标签。传统 UDA 往往假设源域和目标域类别空间一致，并主要对齐主分布；在异常检测里，异常是少数类，而且目标域可能出现源域没见过的异常类型，这会导致负迁移。

DACAD 的核心想法是：不要直接对齐“异常类”，而是利用源域标签、目标域时间邻近性和人工注入异常，共同学习“正常模式的跨域稳定边界”。模型用 TCN 提取窗口表示，用源域监督对比学习拉近正常窗口、推远真实或合成异常；用目标域自监督三元组学习把当前窗口拉近时间邻近窗口、推远注入异常；再用梯度反转的域判别器做源/目标特征对齐，最后用中心距离式分类器给目标窗口打异常分。

## 3. 论文解决的具体问题

论文瞄准的是现实运维、传感器和工业系统中很常见的一类困境：目标系统刚上线或缺少标注，不能训练可靠异常检测器；但另一个相关系统已有异常标注，可作为源域。

难点在于：源域异常和目标域异常未必同类。例如一台服务器的异常可能是资源泄露，另一台服务器可能是网络抖动或磁盘故障；如果强行把异常类当成可迁移类别，会把少数异常分布错误对齐。DACAD 的问题定义因此是：给定源域有标签窗口 `S` 和目标域无标签窗口 `T`，在目标域中检测异常，同时避免异常类别不一致带来的负迁移。

## 4. 创新点深度提炼

- 把 UDA 明确引入多变量 TSAD，并把核心矛盾放在“异常类别跨域不一致”上，而不是泛泛做分布对齐。
- 使用异常注入作为负增强：源域正常窗口和目标域窗口都可生成合成异常，缓解真实异常稀缺，也让模型见到更宽的异常变体。
- 源域和目标域采用不同对比机制：源域有标签，做监督三元组/均值边界对比；目标域无标签，依赖时间邻近窗口构造正样本，注入异常构造负样本。
- 用域判别器学习域不变表示，但不是单独依赖对抗对齐，而是与异常边界学习一起优化。
- CEC 分类器把 DeepSVDD 的中心思想改成有监督边界学习：正常靠近中心，异常远离中心，推理时距离就是异常分数。

## 5. 科学问题与研究假设

科学问题可以概括为：当目标域异常类型未知、源/目标分布存在偏移时，源域异常标签能否仍然帮助目标域异常检测？

论文隐含的研究假设有四个：第一，跨域最可迁移的是“正常行为边界”，不是具体异常语义；第二，目标域相邻时间窗口大概率语义相近，可作为自监督正样本；第三，合成异常虽然不等于真实异常，但足以提供“远离正常流形”的方向性约束；第四，降低对比损失有助于降低类条件分布差异，从而改善领域自适应。

## 6. 科学方法与技术路线

DACAD 先把多变量时间序列切成窗口，论文设定窗口大小 `WS=100`、步长为 1。源域窗口按是否包含异常点分为正常和异常；目标域训练阶段不使用目标标签。

表示层使用 TCN，将窗口编码成向量。源域三元组中，anchor 和 positive 都来自源域正常窗口，negative 来自真实异常窗口或注入异常窗口。目标域三元组中，anchor 是目标窗口，positive 是时间上邻近的目标窗口，negative 是该窗口的注入异常版本。

总损失由四部分组成：源域监督对比损失、目标域自监督三元组损失、域判别器损失、CEC 分类损失。推理阶段只需目标窗口经过 `φR` 和 `φCL`，计算到中心 `c` 的平方欧氏距离，距离越大越异常。

## 7. 实验设计与实验步骤

- 数据：MSL、SMAP 为空间飞行器遥测，SMD 为服务器多传感器数据，Boiler 为工业锅炉故障数据；每个实体/机器/锅炉可作为一个 domain。
- 预处理：标准化多变量序列；按 `WS=100`、stride=1 切窗口；窗口内任一点异常则该窗口标为异常。
- 模型/基线：DACAD 对比 AE-MLP、AE-LSTM、RDC、VRADA、SASA、CLUDA、ContextDA、OmniAnomaly、THOC、TS2Vec、AnomalyTransformer、DCdetector。
- 训练：源域提供正常/异常标签；目标域只参与自监督对比和域对齐；论文主实验使用三层 TCN `[128, 256, 512]`，表示维度 1024，margin 为 1，训练 20 epoch。
- 指标：Best F1、AUPR、AUROC、Affiliation F1；明确不使用 Point Adjustment，因为 PA 会高估 TSAD 能力。
- 消融/敏感性：分别去掉源域对比、目标域对比、域判别器、分类器、异常注入，并比较 CEC、BCE、DeepSVDD。
- 结果核查：多实体数据不直接平均 F1，而是先汇总混淆矩阵再算整体 F1；Aff-F1 用于考察事件级早检和覆盖质量；合成数据考察序列长度和维度扩展下的时间/显存。

## 8. 关键结果、结论与证据

DACAD 在 SMD、MSL、SMAP 的 F1、AUPR、AUROC 上整体领先，论文认为这说明源域标签、目标域自监督和异常注入的组合比单纯重构、预测或普通 UDA 更适合跨域 TSAD。

与 ContextDA 的 UDA 对比最能体现论文主张：SMD 上 ContextDA 平均 Macro F1/AUROC 为 0.63/0.75，DACAD 为 0.81/0.86；Boiler 上 ContextDA 为 0.50/0.65，DACAD 为 0.63/0.71。消融也支持结构必要性：MSL 以 F-5 为源域时，完整模型 F1/AUPR/AUROC 为 0.595/0.554/0.787；去掉分类器跌到 0.299/0.170/0.503，是最大退化；去掉异常注入也明显下降且更不稳定。

## 9. 局限性与待解决问题

这篇论文的前提是存在“相关且有标签”的源域；如果源域和目标域正常模式差异过大，或者源域异常标签质量差，仍可能负迁移。

异常注入是双刃剑：它扩大了负样本空间，但注入模式是人工设定的 Global、Seasonal、Trend、Shapelet、Contextual，未必覆盖真实网络攻击、云原生故障或复杂联动异常。目标域 anchor 默认多数正常，如果目标训练数据污染严重，自监督正负样本构造会被破坏。

实验层面，ContextDA 因无公开实现而只能引用论文结果，公平性弱于同代码复现。阈值使用 Best F1 对科研比较有用，但部署时需要无标签阈值策略。论文也承认未来要改进异常注入、扩展到单变量时间序列，并探索 TCN 之外的特征提取器。

## 10. 与本项目的关系

与“网络安全与异常检测”项目是弱到中等相关：论文没有直接处理入侵检测、恶意流量或日志语义，但它非常适合迁移到云原生 KPI、主机遥测、微服务指标、工业控制传感器等跨实体异常检测场景。

可借鉴的部分是：把一个已有标注环境作为源域，把新环境作为无标签目标域；不要假设异常类型一致，而是迁移正常边界和异常可分性。对网络安全场景而言，DACAD 的异常注入可替换为更贴近攻击机理的流量扰动、KPI 突刺、日志频率漂移或调用链延迟异常。

## 11. 代码对照分析

代码入口和复现路径在 README 与三个主脚本中：[README.md](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/README.md>) 给出安装、数据目录和运行方式；[main_MSL.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/main/main_MSL.py>)、[main-SMD.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/main/main-SMD.py>)、[main_Boiler.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/main/main_Boiler.py>) 批量枚举源/目标 domain 并调用训练与评估。

论文中的训练流程主要落在 [train.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/main/train.py>) 和 [algorithms.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/main/algorithms.py>)。`algorithms.py` 中 `DACAD.step` 计算域判别损失、源域分类损失、源域监督三元组损失和目标域注入三元组损失，对应论文总损失。但代码权重名是 `weight_loss_disc / pred / src_sup / trg_inj`，不是论文里的 `α, β, γ, λ` 原样命名。

模型主体在 [dacad.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/main/models/dacad.py>)：`DACAD_NN` 使用 TCN 编码器、MLP projector、`ReverseLayerF` 梯度反转、`Discriminator` 域判别器和 `DeepSVDD` 距离分类器。需要注意，论文写 CEC 是 `φCL(φR(w))` 到中心的距离，代码中 MLP 分类器基本被注释掉，实际更接近“TCN 表征直接到可学习中心”的 DeepSVDD 变体。

数据预处理和三元组构造在 [dataset.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/utils/dataset.py>)：MSL/SMD/Boiler 都做标准化、`100` 长度滑窗、窗口级标签；源域 positive 从正常窗口随机取，negative 以小概率取真实异常、大概率取注入异常；目标域 positive 取邻近窗口，negative 取注入窗口。异常注入在 [augmentations.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/utils/augmentations.py>)，但源码里 `get_injector()` 实际读取的是 `Injector.__init__` 生成的 `inject_anomaly`，并未真正调用 `__call__` 中五类异常随机选择逻辑，这是论文与当前实现的一个差异。

损失函数在 [loss.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/utils/loss.py>)：`get_sup_cont_tripletloss` 对应源/目标三元组对比；`deep_svdd_loss` 用距离作为异常分数训练源域边界。评估在 [eval.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/main/eval.py>) 和 [util_progress_log.py](<F:/泉城实验室/二期/论文/异常检测/source/DACAD/utils/util_progress_log.py>)，输出 `predictions_test_target.csv`、Best F1、AUPR、AUROC；Affiliation 指标另在 `main/affiliation.ipynb` 后处理。

复现时要小心几个工程问题：README 写 `main_SMD.py`，但实际文件是 `main-SMD.py`；`main_Boiler.py` 把 `--algo_name` 写成 `cluda`，而 `get_algorithm()` 只识别 `dacad`；若直接运行 Boiler 脚本，大概率需要先修正。代码中部分数据类默认 `.cuda()`，无 GPU 环境可能直接失败；若做本项目复用，应先解耦 CUDA、路径和数据 split。

## 12. 本篇精华

- DACAD 的核心不是“迁移异常类别”，而是迁移正常边界与异常可分性。
- 源域监督对比负责利用已知标签，目标域自监督对比负责适应目标局部时间结构。
- 异常注入是桥梁：它把“未见过异常”转化为可训练的负样本方向。
- 域判别器解决源/目标整体表示偏移，CEC 解决异常检测所需的中心边界。
- 不使用 Point Adjustment 是实验设计中的优点，结果更接近真实检测能力。
- 最大消融退化来自去掉分类器，说明中心距离边界是 DACAD 的检测核心。
- 代码可复现主思路，但存在脚本命名、Boiler 参数、CEC 实现和异常注入调用方式上的不一致。
