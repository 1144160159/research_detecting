# [444] FIR-GNN: A Graph Neural Network Using Flow Interaction Relationships for Intrusion Detection of Consumer Electronics in Smart Home Network

## 1. 基本信息

- DOI：10.1109/TCE.2025.3548798。
- 主题：智能家居消费电子设备的网关侧入侵检测。
- 方法标签：流图构建、GNN、边特征注意力、半监督节点分类、SHAP 特征选择。
- 正文包：标记未截断。
- 代码：两个本地仓库 `source\FIR-GNN` 与 `source\MengyiFu_FIR-GNN` 关键文件哈希一致，可视为同一实现。

## 2. 中文翻译与核心摘要
题名可译为：**FIR-GNN：一种利用流交互关系图神经网络检测智能家居消费电子设备入侵的方法**。

论文的核心思想是：不要把每条网络流孤立看成一个表格样本，而是把一段时间内有交互关系的流组织成图。图中节点是五元组定义的流，节点特征来自 CICFlowMeter 等工具提取的流级统计特征；边表示流之间在时间窗口内由源/目的 IP 关系形成的交互；边特征由两条流前若干个带方向的包长序列拼接而来。随后用 GCN、边级 GAT、GCN 组成 FIR-GNN 做节点分类，只在有标签节点上计算损失，借此支持半监督场景。SHAP 用于筛选少量关键流特征，以适配资源受限的智能家居网关。

## 3. 论文解决的具体问题
论文针对的是网关侧 NIDS 在智能家居 CIoT 场景中的三重困难。

第一，攻击样本难收集。智能摄像头、音箱、告警器、VR/AR 设备、家电等设备协议异构，攻击行为隐蔽，难以获得足够覆盖不同攻击形态的标注数据。

第二，传统流量特征表达不够。只看单条流的统计特征，容易忽略攻击在多条流之间的时序传播、控制链路和横向影响，例如某设备被攻陷后向其他家电发送异常指令。

第三，网关资源有限。智能家居网关同时承载数据转发、控制指令与安全检测，不能默认使用大模型或高成本特征全集。

## 4. 创新点深度提炼
- **FIRG 流交互图**：把网络流转成有向图，节点是流，边是时间窗口约束下的 IP 交互关系，比普通表格 IDS 更适合表达非欧式流量结构。
- **边特征建模**：边不只是连接关系，还带有两条流前 N 个包长序列拼接后的微观交互特征，试图捕捉攻击流量早期包长模式。
- **半监督节点分类**：训练时只对有标签节点计算损失，但图传播允许有标签节点吸收无标签邻居信息，降低对全量标注的依赖。
- **面向部署的 SHAP 特征选择**：用 Shapley 值衡量流级特征贡献，选择 top-K 特征，目标不是单纯提精度，而是减少网关侧计算与存储开销。
- **场景闭环设计**：论文把方法放入智能家居网关，检测后可触发云端告警、设备隔离、流量阻断、密码重置等策略，形成安全响应链路。

## 5. 科学问题与研究假设
科学问题可以概括为：**网络入侵检测中，流之间的交互拓扑和包长级边特征，能否比孤立流特征更有效地区分正常行为与攻击行为，并在少标签、低资源环境下保持可用？**

主要假设如下：
- 时间接近且 IP 关系相关的流更可能共享同一通信行为或攻击上下文。
- 同源 IP 的多条流，以及上一条流目的 IP 等于下一条流源 IP 的关系，可以近似描述攻击传播或设备交互路径。
- 包长方向序列包含比普通统计特征更细的早期流量行为线索。
- 用边级注意力区分不同邻居流的重要性，可以提升节点分类效果。
- SHAP 选出的少量高贡献流特征足以保留主要判别信息，并降低资源消耗。

## 6. 科学方法与技术路线
技术路线是：PCAP 流量进入网关侧检测系统后，先提取两类特征。

一类是流级统计特征，如持续时间、包数、包长均值/方差/最大最小值、IAT、标志位、速率等；另一类是包级序列特征，即前 N 个包的长度与方向。之后进行清洗、归一化和 SHAP 特征排序，选取 top-K 作为节点特征。

构图时，在时间窗口 T 内枚举流对：若两条流源 IP 相同，则建双向边；若前一条流目的 IP 等于后一条流源 IP，则建单向边。边特征由两条流的包长序列拼接形成。最终得到 `G=(V,E,F,P,A)`，其中 `F` 是节点特征，`P` 是边特征，`A` 是邻接矩阵。

模型结构是 GCN 层先聚合基础拓扑信息，Edge-wise GAT 层根据节点与边特征计算邻居注意力，再通过 GCN 做最终节点级入侵分类。

## 7. 实验设计与实验步骤
1. 数据：使用 BoT-IoT 与 CICIDS2017。BoT-IoT 原有 8 类，因 UDP DoS 与 Keylogging 样本过少被排除；CICIDS2017 包含 13 类攻击样本。每类最多取 3000 条，不足则全取；不做类别平衡增强；80% 训练、20% 测试。

2. 预处理：从 PCAP 提取流级特征与包长序列，清洗重复、缺失和异常值，Min-Max 归一化；SHAP 排序后取 K 个流级特征构造节点特征。

3. 图构建：设定时间窗口 T 与包数量 N，在时间窗口内按同源 IP 和目的到源 IP 规则建边，边特征维度为 `2N`。

4. 模型与基线：FIR-GNN 对比 CNN、AE、VAE、ET-BERT，以及 GCN、GAT、GCN+GAT。GNN 基线使用同一 FIRG 构图方法，隐藏维度为 32。

5. 训练：论文环境为 i7-13700KF、16GB 内存、RTX 4080、CUDA 12.2、CUDNN 9.1.0、Python 3.9.12、PyG。默认标签比例 0.8，少标签实验从 0.1 到 0.9，每组独立运行 10 次。

6. 指标：分类性能看 Accuracy、Precision、Recall、F1；资源侧看 Max GPU Used、FIRG Data Size、Testing Time。

7. 消融/敏感性：比较 SHAP、UFS、RFE、RFI、IG；测试 K=5/10/15/20；分析 T、N、K 对精度和资源消耗的影响。

8. 结果核查：应重点核查边数量、图密度、不同类别混淆情况、测试集是否参与模型选择、边特征是否真正进入注意力层。

## 8. 关键结果、结论与证据
论文结论是 FIR-GNN 在两个数据集上总体优于普通 GNN 与多数 DL 基线，完整方法表述中称其仅次于 ET-BERT，但计算形态更适合网关部署。

从仓库图 4 对应数据看，GNN 系列中 FIR-GNN 最强：CICIDS2017 上 AC/PR/RC/F1 约为 0.9859/0.9841/0.9859/0.9849；BoT-IoT 上约为 0.9801/0.9790/0.9801/0.9789。BoT-IoT 上相对 GAT 的准确率提升约 3.55%。

SHAP 特征选择表现稳定。正文称 BoT-IoT 在 5 个节点特征时准确率 0.9648，20 个特征时 0.9901；CICIDS2017 在 5 个特征时 0.9505，20 个特征时 0.9806。说明少量特征已能保留较强判别能力。

参数敏感性结论是：T 和 K 增大会提升可利用上下文和特征信息，但会增加图数据大小、GPU 占用和测试时间；N 对精度影响相对小。资源充足时可取较大 T 与 K，资源受限时可取较小 T、N 和中等 K。

## 9. 局限性与待解决问题
论文的场景是智能家居消费电子，但实验主要用 BoT-IoT 和 CICIDS2017，真实家庭网关、真实 CE 协议异构、长期在线流量漂移没有被充分验证。

实验硬件是 RTX 4080 级别桌面环境，不等同于资源受限网关。论文讨论了资源消耗，但还缺少实际网关吞吐、延迟、内存上限和在线检测压力测试。

半监督设定更接近 transductive 图学习，即测试/无标签节点可先进入图中参与消息传播；在线 NIDS 中新流到达时是否能动态增量构图，论文没有展开。

正文包未截断，但纯文本中的若干表格数值版式不完整；尤其是表 II、III、IV、VI、VII 的精确单元格仍建议回 PDF 复核。正文中 BoT-IoT 部分还出现 FIR-GNN 0.9926 与图 4 中 0.9801 口径不完全一致的现象，需要核对表格上下文。

## 10. 与本项目的关系
这篇论文与“入侵检测与网络异常检测”强相关，尤其适合作为**流图建模类 IDS**的代表文献。它不是单纯换一个分类器，而是把流量表达从表格样本提升为“流-流关系图”，对综述中讨论图学习、IoT/边缘安全、少标签检测、轻量化部署都有直接价值。

对本项目可借鉴的部分是：用时间窗口和通信端点关系构建流图；把包长序列放到边上表达微观交互；在资源受限场景下用特征选择控制输入维度。需要谨慎采用的是其实验与代码复现部分，尤其要重新验证是否存在标签泄露、边特征未生效和测试集调参问题。

## 11. 代码对照分析
两个仓库实现基本一致。主要入口是 [generate_graph.py](F:\泉城实验室\二期\论文\异常检测\source\FIR-GNN\generate_graph.py:1) 和 [train.py](F:\泉城实验室\二期\论文\异常检测\source\FIR-GNN\train.py:1)。

- 数据预处理：`utils/extract_pktlen.py` 负责从 PCAP/CSV 生成带 `Pkt Len` 的流级 CSV；`utils/file_label.py` 提供 ISCX、CICIDS、BoT-IoT 标签映射。
- 图构建：[graph_constructor.py](F:\泉城实验室\二期\论文\异常检测\source\FIR-GNN\utils\graph_constructor.py:92) 合并 CSV、归一化、编码标签、抽样，并在 [第 139 行](F:\泉城实验室\二期\论文\异常检测\source\FIR-GNN\utils\graph_constructor.py:139) 后按时间窗口与 IP 关系构造边。
- 数据加载：[data_processor.py](F:\泉城实验室\二期\论文\异常检测\source\FIR-GNN\utils\data_processor.py:25) 读取 `nodes.csv` 和 `edges_T*_P*.csv`，生成 PyG `Data`。
- 模型：[gnn.py](F:\泉城实验室\二期\论文\异常检测\source\FIR-GNN\utils\gnn.py:7) 定义 FIRGNN、GCN、GAT、GCNGAT。
- 训练评估：[train.py](F:\泉城实验室\二期\论文\异常检测\source\FIR-GNN\train.py:63) 只在 `train_mask` 上计算交叉熵，指标包括 accuracy、weighted precision/recall/F1、AUC。

关键复现风险：
- `generate_graph.py` 默认找 `configs/default.yaml`，但仓库实际是 `default.yaml`。
- `default.yaml` 中 `model.name=GCNGAT`，而工厂只识别 `GCN_GAT`，因此会落入默认 FIRGNN 分支。
- `data_processor.py` 默认非 FS 实验没有排除 `Label` 列，存在标签泄露风险。
- 边文件写出列名是 `pkt_len`，读取时检查 `Pkt_Len`，边特征可能没有进入 `edge_attr`。
- `GATConv` 未设置 `edge_dim`，即使传入 `edge_attr`，常见 PyG 实现也不会真正把边特征纳入注意力。
- `train.py` 用 test mask 做验证并保存 best model，最终又在同一 test mask 测试，存在模型选择偏差。

## 12. 本篇精华
- 论文最有价值的点是把 NIDS 从“单流分类”改造成“流交互图上的节点分类”。
- FIRG 的核心建边逻辑很朴素：时间接近、同源 IP、目的到源 IP，但刚好贴合攻击传播与设备交互直觉。
- 包长序列被放到边特征中，意图捕捉两条流之间的微观交互，而不是只看节点统计特征。
- 半监督学习的实质是只对少量标注流计算损失，但利用全图邻居传播增强表示。
- SHAP 在这里服务于网关部署，价值不只是解释性，也包括减少特征维度和资源消耗。
- 实验结论支持 FIR-GNN 优于普通 GCN/GAT，但真实网关部署、在线增量检测和跨家庭泛化仍未充分证明。
- 本地代码与论文方法存在明显落差，复现实验前必须先修正标签泄露、边特征读取和模型选择流程。
