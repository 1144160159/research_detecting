# [615] Balancing Timeliness and Accuracy: A Hybrid Data-Control Plane Framework for Volumetric DDoS Defense in IoT

## 1. 基本信息

论文发表于 IEEE Transactions on Network and Service Management，2026 年，DOI 为 `10.1109/TNSM.2026.3693266`。作者来自东南大学，主题是面向工业物联网环境中高容量 DoS/DDoS 的跨数据平面与控制平面协同防御。

这不是一篇单纯的离线异常检测模型论文，而是一篇系统型安全论文：核心目标是在 IoT 设备承受能力很低的场景下，同时满足“攻击初期快速削峰”和“后续高精度定位攻击源”两个要求。

## 2. 中文翻译与核心摘要

题名可译为：**“在及时性与准确性之间取得平衡：一种面向 IoT 高容量 DDoS 防御的混合数据平面-控制平面框架”**。

论文的主张是：工业互联网中的 IoT 设备性能弱、更新少、缺少自防护能力，单靠服务器侧深度模型太慢，单靠 P4 数据平面又受限于寄存器、算术能力和模型复杂度。作者提出一种两阶段框架：数据平面用 EWMA 方差阈值、Bloom filter、meter 先把高频低方差流量限速；同时用双哈希表提取双向流特征并通过 digest 上传；控制平面将多个时间窗口拼成序列，用 CNN-GRU-Attention 模型确认攻击源，再把源 IP 写入数据平面阻断表。

一句话概括：**先用数据平面“毫秒级止血”，再用控制平面“分钟内定责封源”。**

## 3. 论文解决的具体问题

论文瞄准的是工业物联网中面向摄像头、传感器、网关、控制器等弱资源设备的高容量 DoS/DDoS 攻击。攻击者可通过 botnet 发起 UDP、DNS、NTP、Chargen、SYN 等高频流量，目标是耗尽受害设备带宽或计算资源。

传统方案存在两类断裂：服务器侧 ML/DL 模型能做复杂推理，但上传报文、提特征、推理、下发策略的链路过长；P4/可编程交换机能线速处理，但只能承载简单统计、有限寄存器和受限算术，难以直接部署复杂模型。论文要解决的不是“能否检测 DDoS”，而是：**在攻击刚开始时如何不让 IoT 设备被打垮，同时又不牺牲后续源定位准确率。**

## 4. 创新点深度提炼

第一，论文把 DDoS 流量的判别依据从单点阈值推进到“时间不变性”：攻击流不仅大，而且在连续窗口内包长、速率、间隔等统计量更稳定；正常 IoT 流量可能短时突发，但长期更不规则。

第二，数据平面没有强行塞入复杂模型，而是设计了适合 P4 的 EWMA 方差检测。作者用 `alpha=2^-3` 将乘法转为右移，推导定点误差上界，并用实验说明平均方差相对误差约 1.37%，足以支撑低方差异常筛选。

第三，框架把“初筛、限速、特征提取、确认、封禁”做成闭环。Bloom filter 记录可疑 IP，meter 对可疑源限速，双向双哈希表记录流特征，控制平面再依据序列模型更新 blocklist。

第四，双向流与双哈希设计很实用。DDoS 场景中攻击方向与返回方向统计差异大，合并双向流能降低表项需求；主表碰撞时用校验哈希和 resubmit 转入备表，在相同量级内存下显著降低碰撞。

第五，控制平面模型不是简单堆深度学习，而是服务于系统时序假设：用长度为 5 的窗口序列、21 维统计特征及差分、移动平均、比率等增强特征，让 CNN-GRU-Attention 捕获局部模式、长短期依赖和关键时间片。

## 5. 科学问题与研究假设

核心科学问题是：**高容量 DDoS 与正常 IoT 突发流量能否通过“高流量、低方差、持续稳定”的时间结构区分开，并且这种区分能否拆分到数据平面与控制平面分别完成？**

论文隐含并验证了几个假设：攻击脚本生成的流量在包长和发送节奏上更稳定；正常 IoT 流量虽然也可能周期性或突发，但跨时间窗口的统计波动更高；EWMA 方差低于正常基线并持续命中，可以作为可疑源初筛依据；经过数据平面筛选后的可疑流，再用时序深度模型可减少误报并定位源 IP。

## 6. 科学方法与技术路线

技术路线从经验观察开始。作者先用 Booters 真实攻击数据和 CIC/IoT 类正常数据做 ANOVA 特征分析，发现字节率、包率、包长、包间隔等特征在正常与攻击之间有数量级差异，并且攻击流的时间序列更平滑。

系统上分两层。数据平面在预检测模式下转发正常流量并更新正常方差基线；进入检测模式后先查 blocklist，再查 Bloom filter。非可疑流更新 EWMA 均值、平方均值和方差；若低方差命中次数超过阈值，就把源 IP 标为可疑。可疑源立即经 meter 限速，并开启更完整的双向流统计。

控制平面通过 P4Runtime 接收 digest，按源、目的和协议维护固定长度队列。队列满后计算速率、差分、三点移动平均、字节/包比率等增强特征，送入 CNN-GRU-Attention。模型判为攻击后，将源 IP 写回数据平面 blocklist，完成从初筛限速到最终封禁的闭环。

## 7. 实验设计与实验步骤

可复核流程如下：

1. **数据**：正常流量来自 CIC-IoT-2023、CIC-DDoS-2019、IEEE-TMC-2018、CIC-IDS-2017、CIC-UNSW-NB15；攻击流量来自 CIC-DDoS-2019 的 SYN/UDP/SSDP/NTP 等，以及 Booters 的 Chargen/DNS 真实 DDoS。模型训练攻击类型严格使用 CIC-DDoS-2019 的 SYN/UDP，未见类型用于泛化测试。

2. **预处理**：Pcap/流记录按数据平面窗口切分，最大流持续窗口约 10s，空闲超时约 5s；按流组织为长度 `L ∈ {3,5,8,12}` 的序列。控制平面补算数据平面不便计算的速率类特征，并加入差分、移动平均和比率特征。

3. **模型/基线**：主模型为 CNN-GRU-Attention，输入形状约为 `B=64, L=5, F=21`。系统对比基线包括 Euclid 和 P4RTHENON；同时做只启用主防御、不启用后续流级特征提取的消融。

4. **训练**：攻击记录约 5,361,343 条，正常记录约 5,680,779 条，训练/验证/测试比例为 64%/16%/20%。损失函数为带正类权重的 BCEWithLogitsLoss，学习率采用 OneCycleLR，从 `5e-4` 升至 `1.25e-3` 后余弦退火。

5. **指标**：数据平面看 TPR/FPR、吞吐、pps、EWMA 数值误差、哈希碰撞率、单包处理延迟；控制平面看 Accuracy、F1、PR-AUC、ROC-AUC、TPR/TNR；系统级看攻击流量削减率、源阻断时间、正常流量误丢率。

6. **消融/敏感性**：测试 `alpha ∈ {0.5,0.25,0.125,0.0625}` 的定点 EWMA 误差；测试触发阈值 `tau ∈ [25,200]` 对 FPR/TPR 的影响；比较单表 `2^16` 与双表 `2 × 2^15` 哈希碰撞；比较序列长度 `L=3/5/8/12`。

7. **结果核查**：用 iperf 建立 bmv2 基线吞吐；用 1/5/10 个源 IP、每源 1kpps 的 UDP/TCP 攻击测试检测；用 8000pps、70s Chargen DDoS 加正常背景流测试缓解率；用随机 500-700 字节 payload 测试规避鲁棒性。

## 8. 关键结果、结论与证据

数据平面方面，bmv2 软件交换机基线约为 86.40 Mbps、7455 pps。`alpha=0.125` 时，包长 EWMA 最大绝对误差约 5.47，符合理论小于 7 的界，平均方差相对误差约 1.37%，没有引入误分类。选择 `alpha=0.125, tau=200` 后，在实验区间内实现接近或超过 99.5% 的攻击包标记率，并对正常流量保持 0% 误报。

双哈希表在 10,000 并发流时，碰撞率只有单哈希表的 18.86%，主表仍承载 78.81% 的流。单表平均处理延迟约 644.6 微秒，双表约 689.29 微秒，额外开销约 44.68 微秒，说明碰撞降低并没有换来不可接受的延迟。

控制平面方面，所有测试序列长度在常规测试集上都达到 99.93% 以上准确率和 0.9992 以上 F1。`L=5` 的 PR-AUC 达 0.9977，并且对正常 IoT 流量 TNR 最高约 99.09%；`L=8` 攻击 TPR 更高，但综合误报与响应时延，论文最终选 `L=5`。

系统级结果最关键：主防御阶段对各类攻击包标记率超过 99%，正常流量无误报；Chargen DDoS 下攻击字节量下降 86.70±0.13%，攻击包数下降 86.25±0.12%。完整源封禁约 51-52 秒，主要由 5 个 10 秒统计窗口决定。Euclid 对多源 DDoS 可检测，但漏掉单源 DoS，且对 CIC-IoT-2023 正常流量误报高达 50.61%；P4RTHENON 初筛表现接近，但缺少流级特征抽取和后续时序模型支撑。

## 9. 局限性与待解决问题

本次正文包标注为未截断，因此不存在因正文包截断导致的主要理解缺口；但正文中的 Table IV 和 Table III 在纯文本中没有完整展开，复现实验时仍应回到 PDF 核对默认参数表和完整特征列表。

方法对高容量、持续、低方差攻击很有效，但对低速、脉冲式、强随机化攻击仍有天然压力。论文只测试了 500-700 字节随机 payload，说明随机包长会带来约 100ms 额外触发延迟；更强的自适应攻击仍需要频域、周期性或更复杂源行为建模。

部署层面仍停留在 bmv2 软件交换机。若移植到 Tofino 等 ASIC，需要重新处理状态寄存器访问、流水线阶段、MathUnit extern、meter 行为和 resubmit 成本。数据平面延迟会下降，但最终封禁时间仍受 `L × 窗口长度` 约束。

系统假设也较强：所有流量经过防御设备，首包方向能代表发起方，正常基线阶段相对干净。实际工业网络中的非对称路由、NAT、源地址欺骗、反射攻击路径、基线污染，都可能影响双向流方向判定和方差阈值。

## 10. 与本项目的关系

这篇与“恶意流量、DDoS、IoT/工业互联网边缘安全”高度相关，适合作为综述中“可编程数据平面 + 控制平面深度时序检测”的代表工作。它的价值不在于提出一个更复杂分类器，而在于把异常检测模型放回真实网络防御链路中，回答了延迟、内存、误报、封禁闭环这些工程约束。

对本项目有三点直接启发：一是异常检测特征不应只看单窗口强度，还应看跨窗口稳定性；二是边缘/网关侧可先做低成本可疑流筛选，再把复杂推理留给服务器；三是评估必须同时报告检测率、误报率、缓解率、封禁时延和数据平面资源开销，而不能只报离线 Accuracy/F1。

## 12. 本篇精华

- 这篇的核心不是“DDoS 流量大”，而是“高容量攻击在连续时间窗口内低方差、低波动”，这是数据平面初筛和控制平面时序模型的共同依据。
- 数据平面只做适合 P4 的事情：EWMA 方差、Bloom filter、meter、哈希寄存器；复杂判断留给控制平面。
- “先限速、后确认、再封禁”是该框架平衡及时性与准确性的关键策略。
- 双向流记录利用了 DDoS 攻击方向与返回方向的不对称性，既降低表项需求，也给模型提供了强判别信息。
- 双哈希表不是简单扩大内存，而是用校验哈希和 resubmit 在有限寄存器下显著降低碰撞。
- `L=5` 是系统折中点：足够提供时序上下文，又把最终封禁时间控制在约 1 分钟内。
- 实验最有说服力的证据是系统级对比：Euclid 误报高且漏单源 DoS，P4RTHENON缺少流级时序确认，而本文能同时覆盖 DoS/DDoS 并保持正常流量零误报。
