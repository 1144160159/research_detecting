# 多数据集特征采集与实验视图分析（2026-08-03）

## 1. 决策结论

当前正式预处理应继续生成统一 v3 特征库，不应为某个数据集或某个模型减少包数、
载荷长度或字段。数据集差异应在后续“特征视图”解决，而不是产生互不兼容的 CSV。

本项目采用两层契约：

1. **采集层**：每个数据集均保存相同的可复用特征库，包括前 64 包、前 4096 字节
   payload、前 2048 字节脱敏 L4、完整流段统计、协议结构和构图原语。
2. **实验层**：默认三模态仍为 payload 语义、包行为、包交互图；不同数据集只调整
   模态优先级和消融，不改变原始 CSV 列。

现有 v3 字段对当前论文主任务总体充分。无需为了流统计、首包相对方向、signed packet
length、burst 或缺失掩码重新读取 PCAP，这些都能从现有字段派生。当前主要缺口不是
“少采了字段”，而是尚未冻结模型字段白名单、泄漏门和跨数据集特征选择协议。

## 2. 三类字段必须分开

### 2.1 模型可用字段

**Payload 语义模态**：`payload_b64`、256 维 `payload_histogram`、双向 payload 字节数；
原始字节基线可单独使用 `sanitized_l4_b64`。Payload 是未解密传输层内容，不声称是
应用明文。

**包行为模态**：流持续时间、双向包数/字节数、长度和 IAT 统计、速率、分片计数，
以及长度、IAT、方向、协议、TCP flags、TTL、window、payload 长度等前 64 包序列。
TLS record/handshake 和 QUIC 字段仅作为可缺失的加密协议结构子视图。

**包交互图模态**：从包序列构造节点，以时间相邻、同方向 burst、请求-响应切换构造
边。主实验禁止把端点哈希、端口、capture 或文件名作为图节点属性。

### 2.2 只用于分组、追溯和泄漏审计的字段

`dataset_id`、`capture_id`、`sample_id`、源文件/成员、全部 SHA、绝对时间、端点哈希、
流键哈希、`flow_segment_index` 和标签来源不得进入模型。这些字段用于 capture/fingerprint
分组、重复检查、结果追溯和错误定位。

### 2.3 目标标签

`traffic_class`、`binary_label`、`attack_category`、`attack_subcategory`、`fine_label` 和
`family_label` 只能作为目标或分层变量，不能混入输入特征。最终 CSV 中不得出现 Pending。

## 3. 为什么默认禁用端口、IP 哈希和应用提示

端口、端点哈希、绝对时间、文件名和 `application_protocol_hint` 很容易编码采集拓扑、
攻击脚本或数据集来源。它们能显著提高同数据集准确率，却通常降低跨 capture、跨设备和
跨数据集泛化，并可能造成“已知准确率超过 95%”的虚假闭环。

因此主表使用 safe view：不含端点、端口、绝对时间和应用提示。端口只能进入单独的
`port-enabled diagnostic`，用于量化捷径增益；不得用该结果替代主结果。

| CICIoT2022 | 跨年份 IoT 攻击及独立良性安全 | 包行为 + payload；三模态确认 | capture/设备仅用于分组 | Active 良性 capture 训练测试重叠 |
| Edge-IIoTset | 协议异构，含 payload 对照 CSV | 三模态均为主特征 | 应用协议结构只做有掩码子视图 | 单攻击单 capture、协议即标签 |
| CICIDS2017 | 经典企业网络，多种 Web/暴力破解/DoS | 包行为为主，payload 与图为辅 | Web/Brute Force 的 payload 专项 | 日时段、IP、端口和场景泄漏 |
| CIC-BoT-IoT | 大量短流、Botnet、DDoS/DoS/扫描 | 包行为 + payload | 图模态用于 burst/请求响应，不用设备端点 | 高频重复流、攻击事件和端点捷径 |
| CIC-ToN-IoT | IoT/IIoT 异构攻击，含扫描、注入、后门等 | payload + 包行为 | 图模态为辅 | 网络/遥测混用、时间窗标签错配 |
| CICDDoS2019 | 高强度、多类型 DDoS | 包行为绝对主导 | 图为辅；payload 仅消融 | 端口、目标 IP、速率和采集日捷径 |
| DoHBrw2020 | NonDoH、良性 DoH、恶意 DNS 隧道 | TLS 结构 + 长度/IAT/方向行为 | 加密 payload 分布、图交互 | 工具指纹、时区、TLS 实现而非攻击语义 |
| Tor/NonTor、VPN/NonVPN | 加密隧道与良性域偏移 | 长度/IAT/方向行为 | payload 仅作高熵/实现指纹消融 | 把隐私技术错误当作恶意标签 |
| PARROT2025 | 良性应用流，配套 TLS key log | 不解密三模态只做良性安全 | 可作 payload 编码器预训练诊断 | 不含恶意，不能参与攻击阈值选择 |
| CrossPlatform/MApps | Android/iOS 良性应用域偏移 | 包行为 + payload 可用性 | 应用/平台只用于分层报告 | 应用类别和平台不能冒充攻击标签 |

## 5. 各专项任务的特征视图

### 5.1 已知攻击识别

主视图为三模态 safe view。流统计并入包行为模态，不额外宣称第四模态。报告 Macro-F1、
Balanced Accuracy、每类 Recall 和 Benign FPR。端口/IP/时间/文件名结果不进入主表。

### 5.2 未知攻击拒识

未知检测需要保留三模态质量和缺失掩码，让冲突、距离、能量和支持度能够区分“确实未知”
与“只是 payload/TLS 模态缺失”。特征选择和归一化只能拟合训练集与 known-only validation；
禁止根据 unknown test 的 AUROC 或 FPR95 回选字节长度、包长度或字段组合。

### 5.3 跨数据集确认

使用不含来源身份的 safe view，并分别报告：跨数据集恶意 unknown rejection、已知类迁移、
外部良性误报。不能把三者混成单一 accuracy。跨数据集测试必须保留真实模态缺失率，不能
只筛选“有 payload/TLS 的容易样本”。

### 5.4 DDoS 与 DoH 专项

CICDDoS2019 以流统计、包长度、IAT、方向和 flags 为主，payload 增益必须通过消融证明。
DoHBrw2020 以 TLS record 长度/类型、握手存在性、方向和 IAT 为主；payload 只使用未解密
字节及分布，必须做 payload shuffle 和工具留一验证，防止模型只记住 dns2tcp、dnscat2、
iodine 的实现字节模式。

## 6. 长度选择

采集层继续冻结 `64 packets / 4096 payload bytes`，实验层比较：

- 包序列/图节点：8、16、32、64；
- payload token：256、512、1024、2048、4096；
- 当前实现的 16 包、512 字节作为计算成本基线，不视为最终最优值。

长度只能根据 known-only validation 的已知识别、校准、推理成本和模态质量选择。冻结后再
揭盲 unknown test。不得每个 unknown 家族单独选择最优长度。

## 7. 必做分析与消融

1. **可用性**：按数据集/攻击类报告 payload、TLS、QUIC、双向流、完整 64 包比例及截断率。
2. **泄漏审计**：分别运行 port-only、endpoint-hash-only、time-only、source-only 单特征基线；
   这些基线高分不是成果，而是分组或特征污染证据。
3. **重复审计**：payload prefix hash、包序列 hash、五元组时间指纹必须 capture-grouped 去重。
4. **模态消融**：M1、M2、M3、三组两两组合、M1+M2+M3。
5. **反事实消融**：payload 字节顺序打乱、包时间置换、图边置换、TLS 子视图开关。
6. **缺失鲁棒性**：payload/TLS/图分别 dropout，并报告已知、未知和良性 FPR 的变化。
7. **域迁移**：同数据集 capture 留出与跨数据集分开报告，不能用跨域测试反向调特征。
8. **统计稳定性**：至少 5 个种子，以场景×种子配对，报告均值、标准差、bootstrap CI 和
   Holm-Wilcoxon。

## 8. 预处理完成后的准入表

每个数据集生成最终 CSV 后，特征实验开始前必须新增一份 feature-profile：

| 检查项 | 通过条件 |
|---|---|
| 行与标签 | 全行均为正式标签；无 Pending、冲突或未批准未匹配 |
| 序列 | 序列长度与 `packet_count_stored` 一致；最大 64 |
| Payload | Base64 可解码；长度与计数字段一致；直方图和等于总 payload 字节 |
| 模态率 | payload/TLS/QUIC/双向流可用率按类报告，不隐瞒缺失 |
| 截断 | 64 包、4096 payload、2048 sanitized L4 的截断比例按类报告 |
| 泄漏 | safe view 不含默认禁用字段；分组键与输入字段隔离 |
| 重复 | capture 内和跨 capture 重复指纹均有统计与处置规则 |
| 归一化 | 仅训练折拟合；validation/test 只变换 |

未完成这些分析前，只能说“基础特征已采集”，不能说“特征已经确定”或开始正式 SOTA 主表。

## 9. 对当前代码的直接判断

当前三模态模型使用 `payload_semantics`、`packet_behavior`、`packet_interaction_graph`，但仅
消费 512 字节和前 16 包。方向正确，尚未完成的环节是：

1. 把 v3 安全流统计显式并入 packet behavior；
2. 从已有序列统一派生首包相对方向和 burst，而不是使用端点排序方向解释语义；
3. 冻结 safe view 字段白名单；
4. 在五种子、known-only validation 下选择 16/32/64 包和 512/1024/2048/4096 字节；
5. 完成上述模态、泄漏、缺失和跨数据集消融。

机器可读契约为 `configs/unified_multimodal_v5.feature_views.json`。该配置只约束实验视图，
不改变正在进行的标签严格适配，也不提前启动特征提取。
