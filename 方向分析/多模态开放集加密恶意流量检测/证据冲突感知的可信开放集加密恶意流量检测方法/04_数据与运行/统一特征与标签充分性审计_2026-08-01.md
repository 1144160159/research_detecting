# 统一特征与标签充分性审计（2026-08-01）

## 结论

原 v1 特征可以支撑 payload、包序列和图结构的初步三模态实验，但不足以满足“全面 SOTA 且以后不再读取 PCAP”。主要缺口是：没有脱敏 L4 原始字节，无法公平适配常见字节级模型；没有 TCP seq/ack、IP 长度、分片和头长等不可从原 v1 CSV 恢复的信息；TLS/QUIC 仅能由下游重复解析；最终 CSV 允许出现延迟标签和 `binary_label=-1`。

因此 v1 只保留为审计证据，不进入全量解析；正式基础数据升级为 v2。

## v2 特征覆盖

| 模态/用途 | v2 字段组 | 充分性判断 |
|---|---|---|
| Payload 语义 | 前 4096 字节可逆 Base64、完整流段 256 维字节直方图、逐包 payload 长度 | 足以支持 CNN/Transformer/字节统计及消融 |
| 脱敏原始字节 | 前 2048 字节 L4 header+payload，清零校验和，不包含 IP/MAC | 足以适配主要原始字节基线，同时控制存储量和隐私风险 |
| 包序列 | 长度、IAT、方向、协议、TCP flags、TTL、window、IP 长度、DSCP/ECN、分片、L4 头长、TCP seq/ack | 足以支持序列模型和大多数 flow/packet 基线 |
| 流统计 | 双向包数/字节数/payload 数、min/max/mean/std、pps、Bps | 可直接选择特征，不需重复计算基础统计 |
| 加密协议行为 | TLS record 类型/版本/长度、握手类型、ClientHello/ServerHello 标志、QUIC long-header/version、应用协议提示 | 足以支持加密协议行为模态；字段是协议提示而非攻击标签 |
| 图结构 | 数据集内稳定端点哈希、端口、流 key、时间、方向、capture ID | 足以构造端点流图、时间图和跨流关联图 |
| 追溯 | 源容器 SHA-256、归档成员、capture/sample/flow ID、schema/manifest 哈希 | 满足数据血缘和复现实验要求 |

v2 的边界是“满足当前论文及工程检测任务”，而不是通用取证格式。它不保存原始 IP/MAC、不保存全部 payload、不解密 TLS/QUIC，也不承诺支持地理位置、ASN 或完整内容取证。这些信息不是当前开放集加密恶意流量检测的必要输入，且会显著增加泄漏和存储风险。

## 最终 CSV 标签契约

每一行最终 CSV 必须同时包含：

| 字段 | 含义 | 允许值/要求 |
|---|---|---|
| `traffic_class` | 正常/恶意总标签 | `Benign` 或 `Malicious` |
| `binary_label` | 机器可读二分类标签 | `0` 正常，`1` 恶意 |
| `attack_category` | 统一攻击大类 | `Benign`、`DDoS`、`DoS`、`Reconnaissance`、`Brute_Force`、`Spoofing_MITM`、`Botnet_Malware`、`DNS_Tunneling`、`Web_Attack`、`Other_Attack` |
| `attack_subcategory` | 攻击细粒度类别 | 数据集原生细类经规范化后的名称；正常流同样填 `Benign` 或应用类别 |
| `dataset_native_label` | 数据集原始标签 | 用于追溯映射，不得为空 |
| `label_source` | 标签依据 | capture path、官方 flow CSV、安全事件表等 |
| `label_mapping_version` | 统一映射版本 | `caeos_attack_taxonomy_v1` |
| `label_status` | 标签绑定状态 | 最终 CSV 不允许 `pending`、`unmapped`、`unresolved` |
| `fine_label` / `family_label` | 旧代码兼容字段 | 保留，但不替代上述显式标签 |

正常流量也必须完整填充标签：`traffic_class=Benign`、`binary_label=0`、`attack_category=Benign`。恶意流量必须具有攻击大类和细粒度标签，不能只写 `Attack`。

## 强制门禁

1. 延迟真值连接、未映射或无法判定的流只能写入 `_pending_labels/<dataset>.features.part`。
2. 任何含 `Pending`、空攻击类别、空细粒度类别或 `binary_label=-1` 的数据不得生成 `<dataset>.csv`。
3. 标签连接完成后必须全行复验 `traffic_class` 与 `binary_label` 一致性，并验证攻击大类属于冻结集合。
4. 每个数据集最终仍只允许一个 `<dataset>.csv` 和一个 manifest。
5. Edge-IIoTset、CICIDS2017、CIC-ToN-IoT、CICDDoS2019 等混合/需交叉核对的数据必须使用五元组、时间窗口和官方真值连接，禁止仅凭捕获文件名给全部流贴同一标签。

## 当前运行处置

远端 v1 协调进程已在源文件 SHA-256 阶段暂停，尚未开始 PCAP 解析，也未产生任何最终 CSV。哈希子进程继续完成源清单，避免浪费已经读取的数百 GB 数据；v2 schema、标签门禁和代码在本地通过 6 项测试后，才允许发布到 GPU 并启动正式解析。

补充资源门禁：GPU 服务端口已改为 `25696`。新端点容器 cgroup v1 的 `memory.limit_in_bytes` 实测为 200 GiB，GPU 为 48 GiB RTX A6000；系统可见 80 个逻辑 CPU，但用户分配额度为 32 核。后续解析按 26 个进程、每进程 25,000 个活跃流、140 GiB 匿名 RSS 硬停机线运行；模型实验可把显存目标设为 40-44 GiB，但预处理本身不应人为占用 GPU。
