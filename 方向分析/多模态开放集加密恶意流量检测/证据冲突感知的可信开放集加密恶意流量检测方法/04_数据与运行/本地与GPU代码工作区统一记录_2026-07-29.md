## 2. 统一后的角色

| 位置 | 新角色 |
|---|---|
| 本地`source/CAEOS-EMTD` | 唯一编辑源和代码审查位置 |
| GPU `CAEOS-EMTD/current` | 原子指向最新有效发布的唯一新实验入口 |
| GPU `CAEOS-EMTD/releases/<release>` | 通过编译与定向pytest的不可变发布 |
| GPU `CAEOS-EMTD/active` | 仍有watcher引用的工作区，只允许既有进程完成 |
| GPU `CAEOS-EMTD/legacy` | 所有非活动历史代码、runs、caches和部署包，原样保留 |
| GPU顶层三个兼容链接 | `current`旧入口及两个活动旧路径，实际内容均在统一根目录 |

## 3. 发布规则

本地`sync_to_gpu.cmd`不再直接覆盖远端工作目录。它上传到`CAEOS-EMTD/releases/.incoming-*`，远端通过compileall及合同/指标pytest后生成`SOURCE_MANIFEST.sha256`，再移动为不可变release并原子更新`CAEOS-EMTD/current`。失败时current保持不变。

发布排除datasets、results、runs、checkpoints、cache、PDF、文献目录和嵌套历史源码。每个正式实验必须保存解析后的release路径和文件清单摘要，不能只写“使用最新代码”。

## 5. 活动兼容链接退役条件

只有同时满足以下条件，才可另开审核任务移除活动兼容链接：

1. 所有引用该路径的活动进程为零；
2. 正式结果、日志、manifest和completion marker完成归档；
3. 旧目录中远端独有代码完成只读差异清单；
4. 需要保留的修复已回收到本地并通过测试；
5. 用户明确批准移除链接。

实际目录已归总到`active`，本轮不删除内容。
