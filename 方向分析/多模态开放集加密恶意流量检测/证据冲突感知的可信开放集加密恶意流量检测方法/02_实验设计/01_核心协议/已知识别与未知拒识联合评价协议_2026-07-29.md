# 已知识别与未知拒识联合评价协议

日期：2026-07-29

权威边界：本文定义“三层开放集研究指标”。95%/5%绝对门以[自有算法95%/5%安全验收协议](自有算法95_5安全验收协议_2026-07-29.md)和机器合同`caeos_delivery_contract_v1`为准；历史实验脚本中的同名门不得覆盖新合同。

## 1. 结论

建议的核心判断正确，采纳程度为“主体采纳、三处修正、两处条件采纳”。

1. **主体采纳**：已知类识别与未知类检测不是同一任务，但必须在相同数据拆分、相同模型和相同测试流下联合报告。
2. **修正一**：建议的六项指标只作为论文的“开放集研究主表”，不能替代已经冻结的 95%/5% 操作验收表。
3. **修正二**：`FPR@95TPR` 必须在字段名中写明正类约定。本项目固定 unknown 为正类，字段为 `FPR_known@95TPR_unknown`，表示未知召回达到至少 95% 时已知样本被误拒的比例；它不等于告警系统的 `Benign FPR`。
4. **修正三**：正式统计不能把“场景×种子”直接当作相互独立的 Wilcoxon 样本。种子先在场景内聚合，场景才是主推断块；种子波动由嵌套 bootstrap 或分层模型保留。
5. **条件采纳一**：ECE、Brier 和 NLL 只对有明确概率空间的输出报告。当前默认报告 known-only K 类概率的校准；任意 risk、tail rank 或 conformal p-value 不得直接包装为“未知概率”。
6. **条件采纳二**：capture/session 分组是首选拆分；fingerprint 分组是重复泄漏控制，不是 capture 独立性的等价替代。数据不具备足够 capture 时，必须明确降级并补充时间外或跨数据集测试。

## 2. 为什么不能合并成一个 Accuracy

闭集识别回答“已知样本属于哪个已知类别”；开放集检测回答“样本是否应被拒识为未知”。二者共享编码器和测试流，但决策对象与代价不同。强闭集分类器通常有助于开放集识别，但这种相关性不能证明未知拒识已经解决。Vaze 等人在 ICLR 2022 证明了闭集准确率和开放集性能的强相关关系，结论是应保留强闭集基线，而不是把两个任务合并成一个指标：

- Vaze et al., ICLR 2022: <https://arxiv.org/abs/2110.06207>
- Oxford VGG 项目页：<https://www.robots.ox.ac.uk/~vgg/research/osr/>

Dhamija 等人提出 OSCR 曲线，直接耦合“正确识别已知”与“未知不被接纳为已知”。其横轴是未知样本被接纳为任一已知类的 FPR，纵轴是已知样本被正确分类且达到接纳阈值的 CCR：

- Dhamija et al., NeurIPS 2018: <https://proceedings.neurips.cc/paper_files/paper/2018/file/48db71587df6c7c442e5b76cc723169a-Paper.pdf>

AUROC 只衡量已知/未知风险排序，不包含已知类别是否分对。OpenAUC 的分析也明确指出，单独的 novelty-detection AUC 会忽略闭集性能。因此本项目继续保留 OSCR，而不以 AUROC 单项替代联合评价：

- Wang et al., NeurIPS 2022: <https://proceedings.neurips.cc/paper_files/paper/2022/hash/9f73d65a4186198152357be871345771-Abstract-Conference.html>

## 3. 冻结后的双主表

### 3.1 表A：95%/5%操作验收主表

该表直接回答本项目的部署目标，是绝对门而不是 SOTA 排名表。

| 指标 | 语义 | 方向/门 |
|---|---|---|
| Alert Accuracy | 良性与全部攻击的告警二分类准确率 | `>=0.95` |
| Alert Precision | 发出攻击告警后为真实攻击的比例 | `>=0.95` |
| Attack Recall | 已知与未知攻击被告警的比例 | `>=0.95` |
| Benign FPR | 良性被误告警为攻击的比例 | `<0.05` |
| Known attack type Accuracy | 已知攻击同时被告警、未被拒为未知且类型正确的比例 | `>=0.95` |
| Unknown attack alert Recall | 未知攻击至少被识别为攻击的比例 | 工程安全门 `>=0.95` |
| Unknown label Recall | 未知攻击被明确标注 Unknown 的比例 | 论文完整开放集门 `>=0.95` |

正式验收不能只看点估计。主张达到 95%/5% 时，场景块 bootstrap 的准确率/召回单侧 95% 下界也应达到 0.95，Benign FPR 单侧 95% 上界应低于 0.05。单场景附加报告 capture-block 或保守二项置信区间。

### 3.2 表B：开放集研究主表

接受建议中的六项，但固定字段语义。

| 指标 | 固定定义 |
|---|---|
| Known Macro-F1 | 仅在 Benign + 已知攻击家族上计算，不应用拒识门 |
| Known Balanced Accuracy | 同一已知集合上的逐类 Recall 宏平均 |
| Unknown AUROC-Out | unknown 为正类，risk 越高越未知 |
| Unknown AUPR-Out | unknown 为正类，避免与 AUPR-In 混写 |
| `FPR_known@95TPR_unknown` | 测试曲线上 Unknown TPR 首次达到至少 0.95 时的 known rejection rate |
| OSCR | 已知正确分类 CCR 与未知被接纳为已知的 FPR 曲线面积 |

`FPR_known@95TPR_unknown` 是测试后的曲线摘要，不是部署阈值。OpenOOD 使用 ID 为正类的 `FPR@95/AUPR-In` 约定，和本项目方向相反，因此论文表头不得只写 `FPR95`：

- Yang et al., NeurIPS 2022 OpenOOD: <https://proceedings.neurips.cc/paper_files/paper/2022/file/d201587e3a84fc4761eadc743e9b3f35-Paper-Datasets_and_Benchmarks.pdf>

### 3.3 附表

附表报告每类 Recall、Unknown-F1、Known Acceptance Rate、Unknown Rejection Rate、单项 risk AUROC、自然流量比例结果和校准结果。Unknown-F1、Acceptance 和 Rejection 必须使用部署前冻结的 known-only 阈值。

校准字段固定为 `Known-ECE15`、`Known-Brier`、`Known-NLL`，只在 known test 和 K 类概率矩阵上计算。若模型未来产生有定义且归一化的 K+1 概率，再单列 joint calibration；不得把经验尾秩直接作为未知概率。Brier/NLL 是 proper scoring rules，ECE 保留为易读诊断但受分箱影响：

- Ovadia et al., NeurIPS 2019: <https://proceedings.neurips.cc/paper/2019/hash/8558cb408c1d76621371888657d2eb1d-Abstract.html>

## 4. 阈值与选择协议

1. 告警阈值仅由 known-only validation 中的 Benign 预算确定。
2. Unknown 拒识阈值仅由 known-only validation 的风险分布或已知攻击类内伪未知任务确定。
3. 风险公式、权重、路由、原型、支持统计和温度等超参数不得读取外层真实未知标签。
4. AUROC、AUPR-Out、`FPR_known@95TPR_unknown` 和 OSCR 可以在测试标签揭盲后计算，但不得反向用于阈值、算法或场景选择。
5. 使用真实 unknown test 选择候选、阈值或 risk formula 的旧产物只能标记为 development，不能升级为 confirmation。

当前 FHMM 固定评估器满足第1至第4项。更早的部分自有算法开发网格读取了真实 unknown 进行配置选择，继续保留为开发证据，不进入正式确认。

## 5. 数据拆分

1. 外层按恶意攻击家族 leave-one-family-out，真实未知家族只进入 test。
2. known 内部分裂优先采用 capture/session/时间分组，并保证 train、validation、test 的组交集为零。
3. 所有特征 fingerprint 跨分裂重复必须独立审计；fingerprint grouping 不能替代 capture 独立性。
4. 每个外层场景重新拟合标签映射、预处理、模型、原型/支持统计、风险归一化和阈值。
5. 训练可采用类平衡采样；validation/test 不改变真实样本比例。为避免 Accuracy、F1 和 AUPR 的流行率依赖，另报等家族诊断表，不能只报重平衡测试结果。

当前 FHMM 的 CICIDS2017 packet-sequence pilot 按 `flow_id` 哈希分层，不是 capture-grouped。因此 Botnet 两种子结果仍是开发资格证据，不能直接进入论文正式确认。正式七场景前必须增加 capture/session 可行性审计；若原始捕获结构无法为每个 known 类提供至少三个独立组，则降级为 fingerprint 防重复加时间外/跨数据集确认。

## 6. 种子与统计推断

1. 功能 smoke 可用 1 个种子，资格 pilot 可用 2 个预注册种子；正式确认至少 5 个种子。
2. 同方法与基线必须共享数据身份、拆分、种子和测试流，形成真正配对。
3. 主推断单位为攻击家族场景。先在每个场景内聚合种子，再执行 paired Wilcoxon 或精确配对置换。
4. 场景块 bootstrap 生成均值/中位差的 95% CI；需保留种子不确定性时使用“场景外层、种子内层”的层级 bootstrap。
5. Holm 校正只覆盖预注册的相对比较主端点。当前 SOTA 比较继续对 AUROC-Out、AUPR-Out、`FPR_known@95TPR_unknown` 和 OSCR 做 Holm；Known Macro-F1 与 Balanced Accuracy 作为非劣门。
6. 同时报告配对中位差、Hodges-Lehmann 位置差或 matched rank-biserial effect size，不只报告 p 值。

直接把 7 场景×5种子当作 35 个独立 Wilcoxon 样本会高估样本量，正式协议不采纳。若只有 CICIDS2017 的 7 个家族，场景级检验功效有限；这足以做绝对 95%/5%资格判断，但不足以单独支撑跨数据集 SOTA。

## 7. 实现落地

新增版本化实现：

- `strict_v4_open_set_metric_contract_v2.py`：分层输出 Known Macro-F1、Balanced Accuracy、每类 Recall、AUROC-Out、AUPR-Out、显式方向 FPR95、exact OSCR、Unknown-F1、Acceptance/Rejection 和 known-only 校准。
- `evaluate_strict_v4_family_heldout_meta_pilot_v2.py`：保留v1评估器及其冻结SHA不变，在后选择、无候选搜索的v2结果中附加 `research_metric_contract`。
- 当前FHMM缓存未保存K类概率矩阵，因此校准字段如实为 unavailable。下一版训练协议只有在结果为零并重新冻结实现SHA后，才可增加 validation/test K 类概率缓存并计算 Known-ECE/Brier/NLL。

历史 `caeos.metrics.open_set_classification_rate` 使用最多 300 个风险分位点近似 OSCR。已有冻结结果保持原值和原 SHA；新实现字段明确命名为 `oscr_exact_v2`。任何正式基线比较都必须让候选和基线从同一版本实现重新计算，禁止把 legacy OSCR 与 exact v2 直接排名。

## 8. 对当前自有算法路线的影响

本节及第9节记录指标协议形成时的历史诊断，不是2026-07-29最新状态。当前结论以[双交付线研究与工程路线图](../../00_总览/双交付线研究与工程路线图_2026-07-29.md)为准。

FHMM Botnet 两种子均值为 Alert Accuracy `0.940930`、Benign FPR `0.046544`、Known attack type Accuracy `0.946501`、Unknown attack alert Recall `0.757724`、Unknown label Recall `0.261382`。其中 seed31 接近基本门，但 seed29 明显回退；同一 1230 条 Botnet 测试流的攻击概率 Pearson 相关仅 `0.07777`。这说明当前主要问题是种子稳定性和跨家族边界，而不是缺少一个更好看的汇总指标。

因此，指标协议修订不授权七场景正式扩展，也不改变 FHMM pilot 的阴性资格结论。已有两种子研究指标已按v2合同只读复算：Known Macro-F1 `0.912975`、Balanced Accuracy `0.953785`、AUROC-Out `0.909433`、AUPR-Out `0.671632`、`FPR_known@95TPR_unknown=0.255249`、exact OSCR `0.902548`。seed31操作告警更强，但开放集排序指标低于seed29，进一步证明两任务不可互相替代。后续只允许预注册的稳定化机制进入新的两种子 Botnet pilot；通过两种子绝对门后，才扩展到七场景和至少五种子确认。

## 9. 稳定化候选的实证复核

FP32一阶meta稳定训练已消除旧成员的NaN，并在split43/47各训练三个A6000成员。六个完整性与资源门全部通过，但固定候选只在split43通过；split47的Alert Accuracy为`0.901818`、Benign FPR为`0.038082`、Known type Accuracy为`0.950449`、Unknown alert Recall为`0.573984`、Unknown rejection Recall为`0.382114`。其Known Macro-F1为`0.965516`、Balanced Accuracy为`0.968207`、Unknown AUROC为`0.886194`、OSCR为`0.883679`。这证明闭集与开放集排序达门仍不能推出部署告警达门。

该候选的路由配置在旧拆分37/41上曾用真实Botnet标签排序，虽然split43/47确认期没有后选择，仍不满足“目标未知家族从配置选择到测试均完全不可见”的最强协议。故新增硬规则：下一版attack source、aggregation和预算必须由嵌套leave-one-known-family validation的最坏家族召回与Benign FPR联合选择；split43/47降级为已揭盲诊断，不再复用为确认。只有全新拆分逐一通过95%/5%操作门，才允许启动七场景五种子与层级统计。
