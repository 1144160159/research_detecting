# 自有算法95%/5%安全验收协议

日期：2026-07-29  
合同版本：`caeos_delivery_contract_v1`

## 1. 适用范围

本协议只评价自有算法的绝对安全目标。基线用于相对比较，不要求全部达到95%/5%，也不能替自有算法豁免绝对门。机器可读事实源位于`source/CAEOS-EMTD/contracts/caeos_delivery_contract_v1.json`；本文与代码冲突时停止实验并修复合同，不由单个实验脚本自行解释。

## 2. 样本与决策

测试流分成Benign、Known Attack和Unknown Attack三类真实状态。模型输出两个决策：

1. `alert`：是否认为样本为攻击；
2. `open_set_label`：Benign、某个已知攻击家族或Unknown。

已知类型正确要求同一样本同时满足“已告警、未被拒为Unknown、已知家族预测正确”。这样可防止只在被模型挑选的容易样本上计算条件准确率。

## 3. 七项指标

设攻击集合为已知与未知攻击的并集：

| 字段 | 分子/分母 | 门 |
|---|---|---|
| `alert_accuracy` | 全部测试样本中告警二分类正确数 / 全部测试样本数 | `>=0.95` |
| `alert_precision` | 被告警样本中的真实攻击数 / 被告警样本数 | `>=0.95` |
| `attack_recall` | 被告警的全部攻击数 / 全部攻击数 | `>=0.95` |
| `benign_fpr` | 被误告警的Benign数 / 全部Benign数 | `<0.05` |
| `known_attack_type_accuracy` | 同时告警、接纳为已知且家族正确的已知攻击数 / 全部已知攻击数 | `>=0.95` |
| `unknown_attack_alert_recall` | 被告警的Unknown Attack数 / 全部Unknown Attack数 | `>=0.95` |
| `unknown_label_recall` | 被明确输出Unknown的Unknown Attack数 / 全部Unknown Attack数 | `>=0.95` |

`attack_recall`是已知与未知攻击按自然样本量合并的总检出率，不能替代单独的`unknown_attack_alert_recall`。`benign_fpr`是告警误报，不是开放集曲线上的`FPR_known@95TPR_unknown`。

## 4. 两个验收门

### 4.1 工程安全门

`engineering_safety_95_5`要求前六项全部通过。它证明系统可以在低误报下告警已知/未知攻击，并对已知攻击给出正确类型；不要求未知攻击进一步被细分成不存在的已知家族。

### 4.2 论文完整开放集门

`paper_full_open_set_95_5`要求七项全部通过，即在工程门之外，Unknown Attack被明确拒识为Unknown的Recall也达到95%。论文线还必须独立满足异构多模态、三层指标、消融和统计协议；七项点估计通过不是论文充分条件。

## 5. 点估计与置信验收

每个场景、种子都先单独出表，禁止只报宏平均。正式“达到95%/5%”需要：

1. 至少五个预注册种子；
2. 先在场景内聚合种子，场景作为主推断块；
3. 所有`>=0.95`指标的场景块单侧95%下置信界达到0.95；
4. `benign_fpr`的场景块单侧95%上置信界低于0.05；
5. 单场景补充capture-block bootstrap或保守二项区间；
6. 任一必需指标缺失、不可重算或只来自有利子集，整门失败。

开发阶段可以报告“点估计通过但置信未确认”，不得简称“已达标”。

## 6. 阈值与无泄漏

- 告警阈值只由known-only validation的Benign预算确定。
- Unknown阈值只由known-only validation风险分布或内层leave-one-known-family伪未知任务确定。
- 外层Unknown测试标签不得参与特征选择、权重、路由、模型、checkpoint、风险公式或阈值选择。
- 读取外层Unknown选择候选的结果标记为`development_postselected`，永不升级为confirmation。
- AUROC/AUPR/FPR95/OSCR在测试揭盲后计算，但不得反向改变算法。

## 7. 自然流与平衡诊断

验收表使用保留自然比例的validation/test。为观察小类可另报按家族等权或重采样诊断，但不能用它替代自然流的Alert Accuracy、Precision和Benign FPR。训练阶段允许类平衡采样，所有采样状态必须记录。

## 8. 结果资格

| 资格 | 最低要求 | 可用结论 |
|---|---|---|
| smoke | 合成或小样本、一个种子 | 代码可运行 |
| development | 冻结拆分、可有内层搜索 | 候选方向，不声称达标 |
| qualification | 全新外层未知、至少两个种子、无后选择 | 是否值得扩展 |
| confirmation | 多场景、至少五种子、完整SHA/资源/置信证据 | 可作正式验收 |

CPU训练、缺少CUDA来源或GPU资源采样的模型结果不具备正式资格。本地pytest通过只证明代码，不证明实验效果。

## 9. 机器校验

代码入口：

```text
python audit_project_contract.py --delivery-line engineering --metrics-json metrics.json
python audit_project_contract.py --delivery-line paper --metrics-json metrics.json
```

校验器对缺失字段失败关闭，并严格区分`benign_fpr < 0.05`与其他指标的`>=0.95`。置信界、拆分、泄漏、模态和GPU资格由正式汇总审计器另行验证，不能因为点估计校验器返回通过而省略。
