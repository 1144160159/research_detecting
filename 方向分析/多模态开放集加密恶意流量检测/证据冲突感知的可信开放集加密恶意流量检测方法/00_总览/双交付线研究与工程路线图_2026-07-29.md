# 双交付线研究与工程路线图

日期：2026-07-29  
状态：第一阶段统一规范

## 1. 单一目标，双交付线

项目最终目标不变：自有算法需要检测已知和未知网络攻击，在自然测试流上达到预警准确率不低于95%、良性误报率低于5%，并给出攻击类型或Unknown结论。实现分成两条不能互相替代的交付线。

| 项目 | 工程实现线 | 论文研究线 |
|---|---|---|
| 直接目标 | 稳定告警、已知攻击分类、未知攻击检出 | 可信多模态开放集识别与可解释证据冲突 |
| 表示输入 | 可沿用流统计、包长序列、IAT序列 | 统计/时序主干 + 载荷语义、通信图或应用行为至少一种 |
| 绝对验收 | 工程95%/5%六项门 | 工程六项门 + Unknown明确拒识95% |
| 研究评价 | 三层指标均报告，允许作为诊断 | 三层指标、校准、模态消融、冲突消融均为正文证据 |
| 对比要求 | 精简工程基线和资源/吞吐 | 同拆分经典基线、强域近邻基线和统计推断 |
| 结论边界 | 通过后可声明工程预警达标 | 通过后才能声明论文多模态方法达标；SOTA另设相对门 |

流表按列拆成多个视图只能称为工程多视图。论文中的“多模态”必须证明信息来源异构，例如原始包序列与载荷字节、主机通信图或应用/设备行为上下文。

## 2. 三层指标

### 第一层：已知类识别

`Known Macro-F1`、`Known Balanced Accuracy`、逐类Recall和`Benign FPR`。计算对象为Benign加已知攻击，未知拒识不能掩盖已知类分错。

### 第二层：未知类检测

`Unknown AUROC-Out`、`Unknown AUPR-Out`、`FPR_known@95TPR_unknown`和冻结阈值下的`Unknown-F1`。unknown固定为正类，风险越大越未知。

### 第三层：联合开放集

exact OSCR、冻结阈值下的Known Acceptance Rate和Unknown Rejection Rate。OSCR同时要求已知分类正确和未知不被接纳为已知。

`Known-ECE15`、`Known-Brier`和`Known-NLL`只在有效K类概率矩阵上报告，不能把经验尾秩或风险分数包装为概率。

## 3. 95%/5%验收关系

工程线必须同时通过：

1. Alert Accuracy `>=0.95`；
2. Alert Precision `>=0.95`；
3. 全部攻击Attack Recall `>=0.95`；
4. Benign FPR `<0.05`；
5. Known attack type Accuracy `>=0.95`；
6. Unknown attack alert Recall `>=0.95`。

论文完整开放集门在上述六项之外增加Unknown label Recall `>=0.95`。缺项按失败处理。正式达标声明还要求场景块单侧95%置信界通过，不以均值或单个有利种子代替。

详细定义见[自有算法95%/5%安全验收协议](../02_实验设计/01_核心协议/自有算法95_5安全验收协议_2026-07-29.md)；开放集计算见[已知识别与未知拒识联合评价协议](../02_实验设计/01_核心协议/已知识别与未知拒识联合评价协议_2026-07-29.md)。

## 4. 当前证据与结论

### 4.1 工程线

FHMM稳定化确认在split43/47上的均值为Alert Accuracy `0.946098`、Benign FPR `0.035261`、Known type Accuracy `0.952355`、Unknown alert Recall `0.774390`、Unknown rejection `0.436585`。两拆分不同时通过，工程门未通过。

Neural/Empirical-Tail只读筛选的宏平均为Alert Accuracy `0.986031`、Benign FPR `0.037429`、Known type Accuracy `0.954743`、Unknown alert Recall `0.947954`、Unknown rejection `0.830505`。该结果使用旧CPU XGBoost工件并读取外层unknown进行筛选，且Unknown alert Recall仍低于0.95，只能证明结构有潜力，不能作为工程确认。

因此当前状态为：**工程95%/5%未正式通过**。

### 4.2 论文线

现有稳定主线主要是流统计、包长和IAT等同源多视图，尚未完成“时序/统计 + 载荷语义或图或应用行为”的正式联合训练、模态消融和五种子确认。故当前状态为：**论文多模态要求未完成**。

### 4.3 SOTA

已有大规模方法筛选和局部相对优势不能替代新的双交付线绝对门。正式SOTA只在自有算法先达到基本安全要求后，对预注册指标和精简基线做同拆分、同种子、场景块比较。当前不授权“全面SOTA”表述。

## 5. 数据路线

| 数据 | 作用 | 当前边界 |
|---|---|---|
| CICIDS2017原始PCAP | 工程线已知/未知家族；论文线包序列、载荷和通信图主套件 | 需要capture/session分组可行性审计 |
| CICIoT2023原始PCAP | 多攻击家族的第二恶意套件 | 必须按capture/目录组防止泄漏 |
| CICIoT2022 | 设备交互、场景和应用行为补充 | 攻击大类有限，不能单独承担全面恶意SOTA |
| PARROT2025 | 外部良性/应用安全测试 | 是良性启动流量，不用于攻击细分类 |
| CrossPlatform | 应用类处理数据的辅助材料 | 不是MApps；缺少严格源分组旁证时不进入正式主表 |

## 6. 后续实验顺序

### 工程实现线

1. 将Neural/Empirical-Tail候选改成全GPU训练与已知验证选择，禁止读取外层unknown选结构。
2. 用全新family-held-out拆分做两种子资格试验，六项工程门全部通过后才扩展。
3. 完成至少七个家族、至少五种子正式确认，并同时输出三层指标、置信界和GPU资源证据。
4. 冻结可部署证据包、阈值、延迟、吞吐和内存报告。

### 论文研究线

1. 在CICIDS2017构建统计/时序主干与载荷语义或通信图的可辩护双模态缓存。
2. 在CICIoT2023或CICIoT2022增加恶意/应用行为外部验证，严格冻结组身份。
3. 依次运行单模态、简单融合、无冲突、完整冲突感知模型消融。
4. 正文主表固定七项：XGBoost、MSP、Energy、OpenMax、Mahalanobis++、Open-Detect、RoNeTC；不继续无门槛扩张基线数量。
5. 只有绝对安全门满足后，选择AUROC-Out、AUPR-Out、FPR95和OSCR中的预注册端点做可解释的选择性SOTA主张。

## 7. 执行与代码规则

- 本地仅做代码测试、结果汇总和文档更新；正式训练只在GPU。
- 训练活动期GPU平均利用率最低50%、目标80%，采样间隔不超过5秒；CPU数据准备单列，不冒充GPU训练负载。
- 本地代码是唯一可编辑事实源；远端`CAEOS-EMTD/current`只指向通过测试的不可变发布。
- 旧工作区已零删除归总到`CAEOS-EMTD/active`和`CAEOS-EMTD/legacy`；active在现有watcher结束前只读保留。
- 每份正式结果记录代码release、SHA清单、数据/拆分指纹、CUDA设备、阈值来源和资源摘要。
