# 中文全文缩译式精读规范与验收标准

更新日期：2026-08-05  
适用项目：证据冲突感知的可信开放集加密恶意流量检测方法（CAEOS-EMTD）  
适用范围：`07_论文精读/01_核心论文精读` 中所有核心论文

## 0. “精读”的核心定义

本项目中的“精读”应理解为：**以中文覆盖论文全文内容的结构化缩译，并在缩译之后增加独立的技术分析**。

它不是只写摘要、方法定位或证据字段，也不是逐句逐词的机械翻译。每篇精读文档必须让未阅读英文原文的人，能够沿着原论文的章节顺序理解作者为什么研究、如何设计、怎样实验、得到什么结果、结论边界在哪里；随后再看到本项目对协议、证据、缺陷和可用性的分析。

每篇交付由两个严格分离的部分组成：

1. **第一部分：原文结构化全文缩译。** 按原论文的 Abstract、Introduction、Related Work、Problem/Formulation、Method、Experiments、Results、Discussion、Conclusion、Appendix 顺序覆盖全文。允许压缩重复背景和常规叙述，但不能跳过研究动机、任务定义、方法链路、关键公式、实验协议、主要表图数字、消融和局限。
2. **第二部分：独立分析。** 在不冒充作者原意的前提下，分析任务边界、unknown 泄漏、多模态真实性、指标与基线公平性、创新性、局限、复现难点，以及对 CAEOS-EMTD 的采纳或否决。

全文缩译与分析必须使用显式标题隔开。凡是本项目的判断，统一放入“分析”部分，不能插进缩译正文造成作者观点与读者判断混淆。

## 1. 当前状态与重建原则

1. 原有批量精读文件及中断生成的逐篇卡片已全部清空。
2. 当前有效精读卡数量从 `0` 重新计数。全文已下载或已抽取不等于已经精读。
3. 后续实行“一篇论文、一份中文全文缩译与分析、一个唯一记录号”，禁止把多篇论文压缩成标题加摘要式条目。
4. 所有结论必须来自论文全文中的可定位证据；标题、摘要、搜索片段和二手综述只能用于初筛。
5. 找不到的信息统一写“全文未定位”，不得根据常识、标题或相邻论文补写。
6. 论文自报结果、项目复现实验结果和本项目推断必须分栏记录，不能混为同一种证据。
7. 精读完成不等于论文观点正确，也不等于方法适合 CAEOS-EMTD；必须单独做有效性和可迁移性判断。
8. 没有 Zotero Item、Citation Key、中文全文缩译、分析记录和页码/表号定位的文献，不得进入论文正文。

## 2. 全文缩译的覆盖范围与压缩尺度

### 2.1 必须覆盖的正文内容

| 原文章节 | 中文缩译要求 | 允许压缩程度 |
|---|---|---|
| 标题、摘要、关键词 | 标题准确翻译；摘要接近完整翻译；关键词保留中英文 | 低 |
| 引言 | 覆盖背景、具体问题、现有缺口、研究动机、贡献和全文结构 | 中 |
| 相关工作 | 按主题合并翻译，保留与本文差异及关键引用关系 | 高，但不能只列论文名 |
| 问题定义/预备知识 | 保留任务、符号、假设、输入输出、known/unknown 和威胁模型 | 低 |
| 数据与预处理 | 保留数据集、样本、标签、划分、过滤、特征和增强 | 低 |
| 方法 | 按模块和信息流详细缩译，保留关键公式、算法和变量含义 | 最低压缩 |
| 实验设置 | 保留基线、指标、训练配置、阈值、种子和硬件 | 低 |
| 主结果 | 翻译表图结论，并记录关键绝对数值、最强基线和差值 | 最低压缩 |
| 消融/敏感性/鲁棒性 | 覆盖每个实验控制变量及作者结论 | 低 |
| 讨论/局限 | 区分作者明确承认的边界和未来工作 | 低 |
| 结论 | 接近完整翻译，不人为扩大贡献 | 低 |
| 附录/补充材料 | 只要影响方法、协议、结果或复现，就必须纳入 | 按重要性 |
| 参考文献 | 不逐条翻译；只维护关键引用关系 | 可省略 |

### 2.2 可以合并缩译的内容

- 同一背景事实在引言中反复出现。
- 与本项目无直接关系的通用行业背景和常识性描述。
- 相关工作中结构相同的逐篇罗列，可按方法族合并。
- 方法中不影响复现的常规网络层描述，但网络结构和关键超参数仍要保留。
- 实验结果中完全重复正文结论的描述，但表格中的关键数字不能丢失。

### 2.3 不能因为“缩译”而省略的内容

- 作者贡献列表及其实际对应模块。
- 任务操作性定义、known/unknown 构造和阈值来源。
- 数据集版本、样本单位、划分与标签层级。
- 会改变实验结论的预处理、采样、平衡和过滤规则。
- 关键公式、损失函数、风险分数和推理判定。
- 主表、消融表、鲁棒性表中的关键数字。
- 负结果、失败案例、限制条件和附录中的关键协议细节。
- 作者是否使用目标 unknown 训练、调参、早停或定阈值。

全文缩译不规定机械字数比例。判断标准是“章节覆盖和信息完整”，不是篇幅。方法与实验可以较详细，背景和重复叙述可以明显压缩。

## 3. “精读完成”的严格定义

一篇论文只有同时满足以下条件，才能标记为“精读完成”：

| 门禁 | 必须满足的条件 | 不通过时状态 |
|---|---|---|
| G0 缩译门 | 原文章节覆盖表完整，方法、实验、主结果和结论均有中文缩译 | `缩译未完成` |
| G1 全文门 | 已获得可读全文，正文、表格、图和参考文献可访问 | `全文缺失` |
| G2 身份门 | 标题、作者、年份、期刊/会议、DOI/URL、本地 PDF 一致 | `元数据待核` |
| G3 任务门 | 明确任务、输入、输出、样本单元、已知/未知定义和威胁模型 | `任务未厘清` |
| G4 协议门 | 明确训练/验证/测试、unknown 使用、阈值来源和数据泄漏风险 | `协议未厘清` |
| G5 方法门 | 能复述模型流程、关键模块、损失、训练与推理决策 | `方法未厘清` |
| G6 结果门 | 至少定位一项核心定量结果及其数据集、协议、指标、页/表/图 | `结果未定位` |
| G7 对比门 | 明确主要基线、公平性、消融、敏感性和统计报告情况 | `比较不充分` |
| G8 局限门 | 区分作者自述局限与本项目复核发现的局限 | `局限未审计` |
| G9 项目门 | 给出 CAEOS-EMTD 的采纳、拒绝或待实验结论及理由 | `项目映射缺失` |
| G10 引用门 | Zotero Item、Citation Key 和引用定位全部可用 | `引用待核` |

“全文读过”“已有摘要”“已生成 Markdown”“验证脚本计数通过”均不能单独作为完成依据。尤其禁止用第二部分的分析表格替代第一部分的全文缩译。

## 4. 精读层级与投入边界

### 4.1 L0：检索命中

只确认题目或关键词相关，不产出技术结论，不计入精读完成数。

### 4.2 L1：初筛

阅读标题、摘要、关键词、结论，判断是否进入全文精读。只允许输出纳入/排除理由和初步主题标签。

### 4.3 L2：结构化细读

阅读引言、相关工作、方法、实验、结论，填写结构化字段。适用于间接相关论文，但仍不能作为关键创新或 SOTA 结论的唯一证据。

### 4.4 L3：全文缩译式精读

按原文结构完成全文中文缩译，再逐节核对方法、公式、算法、数据协议、结果表、消融、附录和复现材料，并完成独立分析。核心论文最低必须达到 L3。

### 4.5 L4：复现级精读

在 L3 基础上进一步核对官方代码、配置、数据处理、依赖、随机种子和公开模型，并运行最小复现实验。只有实际运行后才能填写“已复现”。

## 5. 单篇论文的标准精读流程

### 步骤 0：建立原文章节覆盖表并完成全文缩译

开始分析之前先读取整篇论文，列出原始章节、子章节、页码范围、图、表、公式和附录。随后按原顺序写中文缩译：

1. 使用连续中文段落表达作者论证，不能只堆字段或项目符号。
2. 每个原文一级章节必须有对应中文标题；重要二级章节也必须对应。
3. 每节开头标注原文章节名和 PDF 页码范围。
4. 关键术语首次出现时保留英文，例如“开放集识别（Open-Set Recognition, OSR）”。
5. 公式保留原编号，先说明公式解决什么问题，再解释变量和作用。
6. 图至少翻译图题并说明图表达的流程或现象；关键表至少翻译表意和核心行列数字。
7. 作者的因果解释使用“作者认为/论文解释为”；本项目不同意时留到第二部分分析。
8. OCR 无法识别的公式、表格或图必须回看 PDF；仍无法确认则明确标注。
9. 完成后填写章节覆盖表，确保没有跳过影响结论的章节。

建议的章节覆盖表：

| 原文章节 | PDF 页码 | 缩译位置 | 图/表/公式 | 覆盖状态 | 省略内容及理由 |
|---|---:|---|---|---|---|

只有全文缩译完成后，才进入后续分析步骤。

### 步骤 1：论文身份核验

核对标题、作者、年份、来源、卷期页码、DOI、预印本版本、正式发表版本、本地 PDF 文件名、Zotero Item 和 Citation Key。若预印本与正式版并存，必须说明精读的是哪一版以及版本差异。

### 步骤 2：相关性与证据角色判定

每篇只能设置一个主角色，可附多个次角色：

- `A-直接核心`：同时涉及开放集/未知检测、恶意或加密流量，并能直接决定本项目协议、方法或基线。
- `B-方法支柱`：证据学习、主观逻辑、冲突融合、开放集/OOD、校准、强表征或多模态学习的基础方法。
- `C-实验支撑`：数据集、预处理、标签、指标、统计检验、效率或部署证据。
- `D-背景/反例`：只能提供背景、术语、失败模式或不适用方案。
- `X-排除`：全文核对后不相关、重复、无法验证或证据质量不足。

必须写明它将支持论文中的哪一个具体主张，不能只写“与本项目相关”。

### 步骤 3：研究问题与威胁模型复述

用自己的中文完整回答：

1. 论文试图解决什么问题，现有方法为何不足？
2. 被检测对象是应用流量、恶意软件流量、攻击流量、网络入侵、异常、设备、网站指纹还是其他对象？
3. 攻击者能力是什么，能否修改包长、时序、方向、握手、流量形态或模态可用性？
4. 检测器部署在哪里，观察窗口和决策时点是什么？
5. 训练时可见哪些类别、设备、域、采集批次和标签？
6. 测试时新增的未知是什么：未知攻击家族、未知细粒度类、未知设备、未知域、未知数据集还是分布漂移？
7. 方法的目标是分类、检测、拒识、聚类、发现、增量学习、校准，还是其中的组合？

### 步骤 4：任务类型严格归类

至少从以下维度分别标注，禁止用“开放集”笼统代替：

| 维度 | 可选项 |
|---|---|
| 监督范式 | 监督、半监督、自监督、无监督、弱监督、少样本、增量学习 |
| 类空间 | 闭集、开放集、开放世界、OOD、异常检测、一类分类、零样本 |
| 安全任务 | 良恶二分类、已知攻击大类分类、已知攻击细粒度分类、未知攻击检测、未知类别发现 |
| 泛化范围 | 同数据集、跨时间、跨设备、跨网络、跨域、跨数据集 |
| 输出形式 | 单标签、层级标签、多标签、unknown 拒识、风险分数、证据/概率、未知簇 |

如果论文把 OOD、开放集、异常检测或零日检测混用，必须记录其操作性定义，而不是沿用作者术语。

### 步骤 5：数据集与样本单元审计

逐个数据集记录：

1. 数据集全名、版本、来源和公开可用性。
2. 原始数据形态：PCAP、PCAPNG、NetFlow、CSV、日志、字节序列、图、主机遥测。
3. 是否为加密流量；若是，协议和加密范围是什么。
4. 原始采集环境、设备、应用、攻击工具、时间跨度和捕获点。
5. 样本单元：包、双向流、单向流、会话、burst、时间窗、主机、设备或图节点/子图。
6. 流构建规则：五元组、双向归并、超时、截断、包数、字节数、方向编码。
7. 总样本数、良性数、恶意数、各大类/细粒度类数和类别不平衡。
8. 删除、过滤、采样、去重、重放、合并和标签对齐规则。
9. 是否使用官方划分；若自行划分，按流、文件、捕获、设备、时间还是指纹分组。
10. 数据集是否存在重复流、近重复、同源泄漏、合成样本或训练测试重叠风险。
11. 作者声称的规模与表格实际总数是否一致。
12. 本项目是否拥有对应原始数据、标签和许可，能否真正复现。

### 步骤 6：标签空间与 unknown 构造审计

必须画清标签层级：

`benign/malicious -> attack category -> attack family -> fine-grained class`

并回答：

1. 良性是否作为已知类参与训练？
2. 已知攻击的层级和数量是什么？
3. unknown 是按细类、攻击家族、大类、设备、域还是随机样本留出？
4. unknown 类之间是否与 known 存在父子类或语义重叠？
5. 是否每个场景重新编码 known 类映射？
6. 是否采用 leave-one-class-out、leave-family-out、leave-category-out 或固定 unknown 集？
7. 是否覆盖多个 unknown 难度，而非只选最容易拒识的类别？
8. 是否存在训练测试同指纹、同会话、同捕获片段或相邻切片泄漏？
9. 是否区分 unknown attack 与 benign，还是把二者混为“非已知类”？
10. 被拒识的 known 样本在已知分类指标中如何处理？

### 步骤 7：unknown 使用与阈值泄漏审计

这是本项目的硬门禁。分别核对 unknown 是否进入：

| 环节 | 必须记录 |
|---|---|
| 预训练 | 是否含目标 unknown 类或同源数据 |
| 特征选择 | 是否看过 unknown test 的区分效果 |
| 归一化/PCA | 是否在全数据上拟合 |
| 模型训练 | 是否使用 auxiliary unknown、outlier exposure 或生成 unknown |
| 超参数搜索 | 是否用 unknown validation 或 test 选择配置 |
| 风险组合 | 各风险项权重是否用 unknown 优化 |
| 阈值选择 | 阈值来自 known-only validation、辅助 OOD、unknown validation 还是 test |
| 早停/模型选择 | 是否依据 unknown 指标 |
| 结果选择 | 是否从多次运行中挑最好 test 结果 |

协议标签统一为：

- `P0-strict`：目标 unknown 完全不进入训练、调参、阈值和模型选择。
- `P1-auxiliary-unknown`：使用与目标 unknown 不同的辅助未知数据。
- `P2-target-unknown-validation`：目标 unknown 的一部分用于调参或定阈值。
- `P3-test-tuned`：直接或间接在测试 unknown 上调参，结果不能作为严格开放集证据。
- `P?-unclear`：全文无法确认，禁止默认归为 P0。

### 步骤 8：输入特征与多模态真实性审计

对每个输入视图单独记录来源、形状、长度、处理和可用条件：

- 字节/载荷：完整包、payload、前 N 字节、TLS 握手、头部是否去除、匿名化方式。
- 包级序列：包长、方向、到达间隔、TCP 标志、窗口、协议字段。
- 流统计：持续时间、包/字节数、均值、方差、分位数、burst 和上下行统计。
- 图结构：包图、流图、主机交互图、边/节点定义及时间窗口。
- 上下文：域名、证书、SNI、JA3/JA4、端点、设备、应用、日志或主机遥测。

多模态必须进一步归类：

- `真多源多模态`：模态来自不同传感源或不同数据生成过程。
- `同源多视图`：多个视图均从同一 PCAP/流派生，但统计语义和建模方式不同。
- `多尺度单模态`：同一输入只使用不同尺度或不同编码。
- `特征拼接`：没有独立编码器、对齐或融合机制。
- `作者称多模态但证据不足`：命名与真实结构不一致。

还需记录缺失模态、噪声模态、冲突模态、异步对齐和推理时模态不可用是否被实验覆盖。

### 步骤 9：预处理与数据增强复原

必须按可执行顺序写出：

1. 原始文件读取与解析工具。
2. 流重组、会话化和超时参数。
3. 包/流过滤规则及删除比例。
4. 标签映射和冲突标签处理。
5. 截断、填充、采样、归一化和离散化。
6. 特征选择、降维和统计量拟合的训练范围。
7. 类别平衡、上/下采样和损失加权。
8. 数据增强、掩码、裁剪、扰动、mixup 或合成样本。
9. 随机性控制和预处理缓存。
10. 训练、验证、测试是否使用完全相同且无泄漏的转换链。

论文未给参数时必须标注缺失，不得自行补全为作者设置。

### 步骤 10：方法结构与信息流复原

至少完成一幅文字流程或 Mermaid 图，说明：

`原始输入 -> 各模态编码器 -> 表征/证据 -> 对齐或交互 -> 冲突度量 -> 可信度折扣 -> 融合 -> 分类头/风险分数 -> 阈值 -> known 类或 unknown`

对每个模块记录：

1. 模块名称、输入、输出、张量维度和参数共享关系。
2. 是论文原创、已有模块改造还是常规组件。
3. 训练阶段和推理阶段是否都使用。
4. 模块解决的具体失败模式。
5. 去掉模块后预期影响哪个指标。
6. 与相似论文同名模块的实质差异。

### 步骤 11：公式、变量和优化目标精读

#### 公式排版硬约束（2026-08-05 修订）

1. 精读正文不得保留 LaTeX 源码、反斜杠命令、下划线下标或反引号公式。
2. Markdown 交付统一使用可直接阅读的 Unicode 论文公式，例如 αₖ、xᵢ、L = Lᵣₑ꜀ + μL꜀ₗₛ、∑、∏、√、≤、→。
3. 复杂分式应先用独立公式行和括号明确分子、分母；若 Unicode 无法无歧义表达，则配套给出逐变量中文定义，不得退回 LaTeX 源码。
4. 进入 Word 论文稿时，公式必须转换为 Word 原生 OMML 公式对象；Unicode 精读稿仅作为可读中间证据，不能用普通文本冒充最终排版。
5. 公式审计字段统一记录为 `unicode-display` 或 `word-native-equation`，不再以 `latex` 作为通过状态。

核心论文不能只写“使用证据学习/对比学习/融合”。至少记录：

1. 关键符号表及每个变量的语义、维度和取值范围。
2. 输入到 logits、evidence、Dirichlet 参数、belief、uncertainty 的变换。
3. 单模态损失、融合损失、正则项、冲突约束和总损失权重。
4. 损失项的梯度作用对象及可能的退化解。
5. 训练调度、warm-up、annealing、温度、margin 和阈值参数。
6. 风险分数的方向：数值越大是越已知还是越未知。
7. 推理规则、拒识判据和并列/冲突处理。
8. 公式与代码是否一致；不一致时分别记录。

公式必须标注论文中的公式编号和 PDF 页码。无法从文本抽取的公式需要回看 PDF 页面，不能以 OCR 乱码为依据。

### 步骤 12：证据、不确定性与冲突机制专项审计

凡涉及可信学习、证据融合或不确定性，必须回答：

1. 使用 aleatoric、epistemic、distributional、vacuity、dissonance 还是未区分的不确定性？
2. 证据是非负映射、Dirichlet 参数、质量函数、概率、能量还是距离？
3. 可信度是样本级、模态级、类别级还是全局参数？
4. 冲突如何定义：预测分歧、证据冲突、距离分歧、KL/JS、互信息或逻辑冲突？
5. 冲突是否对称，是否有界，是否能区分“共同无知”和“高置信冲突”？
6. 折扣发生在证据、belief、logit、特征还是最终概率层？
7. 融合规则在高冲突、全低证据、单模态缺失时是否数值稳定？
8. 独立性假设是否成立？多视图同源派生是否导致相关证据被重复计算？
9. 证据强度与分类置信度是否可校准？
10. unknown 风险是否来自冲突、低支持、高能量、原型距离或多个风险的组合？
11. 风险组合权重与归一化量如何得到，是否触碰 unknown？
12. 该机制相对 TMC、ECML、Discounted Belief Fusion、ECNet、RoNeTC 等到底新增了什么？

### 步骤 13：训练配置和复现条件

记录硬件、框架、版本、优化器、学习率、批大小、epoch、早停、权重衰减、调度器、随机种子、初始化、预训练模型、参数量、FLOPs、显存、训练时间和推理吞吐。区分论文明确报告、代码可查和完全缺失三种状态。

代码公开时还需核对：

- 仓库 URL、commit/tag、许可证和最后更新时间。
- 默认配置是否对应论文主表。
- 数据处理脚本是否公开且能产生相同划分。
- 运行命令、依赖、checkpoint 和日志是否齐全。
- 代码中是否存在未在论文说明的 auxiliary unknown、test tuning 或数据筛选。

### 步骤 14：基线和比较公平性审计

对每个主基线记录：

1. 基线名称、原论文、官方代码与实现来源。
2. 是否使用相同原始输入、特征、预训练数据和标签信息。
3. 是否使用相同训练/验证/测试划分和 unknown 定义。
4. 阈值选择是否同协议。
5. 超参数预算、训练轮数和模型规模是否相当。
6. 是作者复现、引用原文数字还是第三方实现。
7. 是否缺少当时或当前真正有竞争力的基线。
8. 闭集强模型是否配套通用拒识分数，避免把表征收益误算成新拒识机制收益。

CAEOS-EMTD 至少应持续检查以下基线族，而不是只列单篇：

- 闭集强表征：ET-BERT、YaTC/同类预训练流量模型、现代 CNN/Transformer/图模型。
- 通用开放集/OOD：MSP、Maximum Logit、Energy、Entropy、Mahalanobis、OpenMax、ODIN（适用时）。
- 开放集优化：Open-Detect、RoNeTC、OpenAUC、FOSS、网络流量开放集方法。
- 证据与融合：EDL、TMC、ECML、Discounted Belief Fusion、ECNet 及可靠多视图方法。
- 消融基线：单模态、直接拼接、平均融合、无冲突、无折扣、无距离、无能量、单风险。

### 步骤 15：指标定义与方向核对

每项结果必须同时记录“计算对象、正类定义、方向、阈值和平均方式”。同名指标定义不同不能直接比较。

#### 第一层：已知类识别

- Known Macro-F1。
- Balanced Accuracy。
- Known Accuracy，必须说明 rejected known 是否计错。
- 每类 Precision、Recall、F1 和 support。
- 已知恶意大类/细粒度分类准确率。
- 良性 FAR/FPR：良性被判为任意恶意或 unknown 的比例，必须给出分母。
- 已知恶意 FNR：已知恶意被判为良性或被错误拒识的比例。

#### 第二层：未知类检测

- Unknown AUROC，unknown 必须明确为正类或负类。
- AUPR-Out/Unknown AUPR，必须说明正类。
- FPR@95TPR，必须说明 TPR 针对 unknown 还是 known。
- Unknown-F1 及阈值来源。
- Unknown Rejection Rate。
- 风险分数分布和 known/unknown 分离情况。

#### 第三层：联合开放集性能

- OSCR 及实现来源。
- Known Acceptance Rate。
- Unknown Rejection Rate。
- 正确识别且接受的 known 比例。
- selective risk、coverage 或 AURC（适用时）。
- 开放集混淆矩阵，必须保留 benign、known attacks、unknown。

#### 校准与可信性指标

- ECE：bin 数、等宽/等频和统计对象。
- Brier Score。
- NLL。
- reliability diagram。
- 错误检测 AUROC、风险-覆盖曲线或置信度分层准确率。

不能用单个 overall accuracy 替代上述三层指标，也不能由闭集提升推断未知检测提升。

### 步骤 16：95%/5% 安全验收口径

精读时必须判断论文是否提供足以核对安全门槛的数据。CAEOS-EMTD 的正式验收表至少包括：

| 验收项 | 目标 | 严格定义 | 防止取巧的约束 |
|---|---:|---|---|
| 已知恶意识别 | `>=95%` | 已知恶意测试样本的大类及细粒度识别准确率分别报告 | 被拒识或判良性的已知恶意计为错误 |
| 已知类宏观性能 | `>=95%` 或明确差距 | Known Macro-F1、Balanced Accuracy | 不以多数类 accuracy 替代 |
| 良性误报 | `<=5%` | benign 被判为任意恶意或 unknown 的比例 | 分母为真实 benign 总数 |
| 未知检测 | `FPR@95TPR <=5%` | unknown 为正类的风险检测，阈值只由 known-only validation 确定 | 禁止用目标 unknown 调阈值 |
| 联合性能 | 报告而非隐藏 | OSCR、known acceptance、unknown rejection | 不允许靠大量拒绝 known 换取 unknown 指标 |
| 校准 | 越低越好 | ECE、Brier、NLL | 必须在独立测试集报告 |

对论文只报告均值而没有逐场景结果的情况，必须标注“不能证明所有场景满足 95%/5%”。

### 步骤 17：定量结果逐项抽取

至少抽取以下四类结果中的三类，核心论文应尽量全部抽取：

1. 主结果表：作者方法与最强基线的完整比较。
2. 开放集/unknown 专项结果：AUROC、AUPR、FPR95、OSCR 或拒识率。
3. 消融表：模块、损失、模态和风险组件贡献。
4. 效率/鲁棒性/敏感性：运行代价、超参数、噪声、缺失模态、跨域结果。

每条数字使用统一记录：

| 字段 | 内容 |
|---|---|
| `result_id` | 本卡内唯一编号 |
| 数据集/场景 | 数据集、known/unknown 设置、开放程度 |
| 划分/种子 | split、seed、运行次数 |
| 方法 | 作者方法或基线及配置 |
| 指标 | 全名、正类、方向、平均方式 |
| 数值 | mean、std、CI 或单次值 |
| 对照 | 最强公平基线及差值 |
| 证据位置 | PDF 页、正文页、表/图/公式编号 |
| 证据类型 | 论文自报、官方代码复现、本项目复现、推断 |
| 可比性 | 同协议、部分可比、不可比及原因 |

禁止只摘“提升 X%”而不记录绝对值、比较对象和协议。

### 步骤 18：消融、敏感性和反事实分析

逐项核对：

- 是否有单模态结果和所有模态组合。
- 是否有无冲突、无折扣、无证据、无距离、无能量、无支持项。
- 是否把骨干网络收益与新组件收益分开。
- 是否测试损失权重、温度、阈值、原型数、证据先验和模态权重。
- 是否测试类别不平衡、未知比例、开放程度和少样本条件。
- 是否测试噪声、对抗扰动、概念漂移、缺失/损坏模态。
- 是否测试跨种子、跨场景、跨数据集和跨时间稳定性。
- 是否提供失败案例、混淆矩阵或错误类别分析。
- 消融是否与主结果使用同一协议和同一骨干。

没有消融时要明确写“无法把性能归因到该组件”，不能替作者补做因果解释。

### 步骤 19：统计显著性与结果稳定性

记录：

1. 随机种子数和运行次数。
2. 均值、标准差、置信区间或分位数。
3. 配对单元是样本、种子还是场景。
4. 使用的检验、显著性水平、多重比较校正和效应量。
5. 是否只报告最优运行或最优数据集。
6. 指标差值是否大于运行方差。

本项目优先采用“场景 × 种子”为配对单元，主指标使用 paired Wilcoxon、Holm 校正和 scenario-block bootstrap CI。论文未做这些分析，只能记录其自报结论，不能替换为本项目的显著性结论。

### 步骤 20：局限、失败模式与外部有效性

分开记录：

#### 作者明确承认的局限

按原文定位，不能用读者推测冒充作者观点。

#### 精读复核发现的局限

- 数据集陈旧、单一、过小或类别过于容易。
- 随机划分导致同源泄漏。
- unknown 参与调参或阈值。
- 非加密数据支撑加密流量结论。
- 只做良恶二分类却声称细粒度/开放集能力。
- 只报 accuracy、AUROC 或最好结果。
- 模态定义不成立或同源信息被重复计权。
- 基线过弱、协议不一致或未调参。
- 缺少跨数据集、跨时间和跨设备验证。
- 没有代码、划分、种子、运行成本或原始结果。
- 真实部署无法获得某个输入特征。

#### 对 CAEOS-EMTD 的风险

说明如果直接采用该方法，会在哪些数据集、模态、类别或协议下失效。

## 7. 跨论文综合必须产生的矩阵

单篇卡完成后，不能直接写综述；必须先形成以下横向矩阵：

1. 任务定义矩阵：分类、检测、拒识、发现、增量学习分别对齐。
2. 协议合规矩阵：P0/P1/P2/P3/P?、unknown 使用、阈值来源、split 风险。
3. 数据集矩阵：数据形态、加密性、标签层级、类数、样本量、开放场景。
4. 模态矩阵：payload、时序、统计、图、上下文及真多模态判定。
5. 方法组件矩阵：编码器、证据、冲突、折扣、融合、风险、阈值。
6. 指标矩阵：三层指标、校准指标和 95%/5% 可核性。
7. 基线矩阵：原始输入、骨干、协议、实现来源和公平性。
8. 定量结果矩阵：只在同数据、同 split、同 unknown、同阈值协议下排序。
9. 消融矩阵：每个自有组件是否有直接反事实证据。
10. 复现矩阵：代码、数据、配置、checkpoint、license、运行状态。
11. 局限矩阵：泄漏、偏差、模态不可用、部署成本和外部有效性。
12. 实验缺口矩阵：按必做、应做、可选和否决实验分级。

## 8. 质量等级与状态字段

### 6.1 证据质量等级

- `E3-直接证据`：正文、公式、表、图或附录中可定位的直接证据。
- `E2-可复核推导`：由多个直接证据得到的有限推论，必须写出推导链。
- `E1-作者陈述`：摘要、引言或结论中的主张，尚未被实验细节充分支持。
- `E0-未定位`：全文没有找到或文本损坏，不能用于结论。

### 6.2 阅读状态

- `not_started`
- `metadata_verified`
- `fulltext_read`
- `protocol_audited`
- `evidence_located`
- `project_mapped`
- `zotero_verified`
- `complete`
- `blocked_fulltext`
- `blocked_metadata`
- `excluded`

只有 G0-G10 十一道门禁全部通过才能标 `complete`。

### 6.3 可比性等级

- `C3-同协议可比`：数据、split、unknown、输入、阈值和指标一致。
- `C2-部分可比`：存在可解释差异，只能支持趋势。
- `C1-弱可比`：任务或协议显著不同，只能作背景。
- `C0-不可比`：不得横向比较数值。

## 9. 禁止事项

1. 禁止只根据题目、摘要或关键词生成“精读”。
2. 禁止用批量相似句式替代每篇论文的真实技术内容。
3. 禁止把“使用多个特征”直接称为多模态。
4. 禁止把异常检测、OOD、开放集、开放世界和零日检测视为同一任务。
5. 禁止把 auxiliary unknown 或 test-tuned 方法标成 strict unknown-free。
6. 禁止遗漏阈值来源；未说明时必须标 `P?-unclear`。
7. 禁止把 rejected known 从已知分类分母中静默删除。
8. 禁止只抄作者的相对提升而不记录绝对值和比较协议。
9. 禁止跨数据集、跨 split、跨 unknown 定义直接排名并称 SOTA。
10. 禁止把作者代码存在等同于已复现。
11. 禁止把单次运行、运行 PID 或冒烟测试标为实验完成。
12. 禁止用综合文字替代单篇页码/表号/图号证据。
13. 禁止在无 Zotero Item、Citation Key 和证据卡时写入论文正文。
14. 禁止隐藏未找到字段；所有缺失必须可统计。
15. 禁止根据预期方向改写或筛掉不利结果。

## 10. 自动验收要求

后续验证脚本至少检查：

1. 队列中的每篇论文与一份卡片一一对应，不允许仅按文件数判断。
2. `rank`、标题、本地 PDF、全文文本和 Citation Key 可关联。
3. 模板 A-X 的必填章节全部存在。
4. 协议等级、unknown 使用和阈值来源非空。
5. 至少一条定量结果含页/表/图定位；没有则状态不能为 complete。
6. 至少一项局限和一项 CAEOS-EMTD 采纳/否决结论。
7. 直接核心论文至少包含公式或算法定位、消融和强基线公平性审计。
8. “全文未定位”字段被单独计数并进入缺口报告。
9. 重复模板文本、异常高相似卡片和标题错配触发人工复核。
10. `complete` 数只统计 G0-G10 十一道门禁全部通过的文档。
11. 随机抽样回看 PDF 页面，验证数字与定位真实一致。
12. 输出审计 CSV：完成状态、缺失字段、证据等级、协议等级、可比性等级和复核人。

## 12. 首轮重建的优先顺序

1. 先完成直接核心论文：开放集加密恶意流量、未知攻击检测、可信多视图/证据冲突融合。
2. 再完成协议和指标支柱：OSR/OOD 定义、OSCR、OpenAUC、Energy、校准与 FPR95。
3. 再完成强表征和关键基线：ET-BERT、YaTC、Open-Detect、RoNeTC、ECNet、FOSS 等。
4. 再完成数据集、预处理和多模态输入论文。
5. 最后处理间接支撑、综述和背景论文。

首轮不追求“120 篇全部完成”的表面数量，先用 10 篇直接核心论文验证模板、人工复核和自动门禁；模板稳定后再扩展到 40、80、120 篇。

- 缺失证据清单。
- PDF 页码/表格随机抽查记录。
- 任务与协议矩阵。

- CAEOS-EMTD 采纳/否决表。
- 可执行实验动作清单。
- Zotero Item 与 Citation Key 对应表。
- 验证脚本的真实输出和人工抽查结论。

在这些材料齐备前，只能报告“正在精读”或“完成部分字段”，不能报告“论文精读已经完成”。
