# UNSW 代理未知与 v20-v22 实验增量报告

更新日期：2026-07-30

## 1. 当前结论

本轮完成了 UNSW-NB15 原始 PCAP 的三模态适配、外部代理未知缓存冻结，以及
三项 GPU 开发实验。三个方案均未达到工程线 95%/5% 或论文线三层指标门槛，
因此全部作为负结果保留，不替换当前候选：

- 工程候选仍为 `v15`。
- 论文开放集候选仍为 `v8`。
- `v20`：UNSW 外部异常暴露及二分类头增强，否决。
- `v21`：仅用 UNSW 增强二分类头，否决。
- `v22`：目标域包行为、图节点和融合证据的 GPU XGBoost 头，否决。
- 未进入确认种子，不允许声称达到 95%/5% 或 SOTA。

## 4. 归因判断

### 4.1 v20：外部异常暴露

UNSW 代理样本在模型中形成较高不确定性和恶意概率，但其跨数据集域特征没有
迁移到 CICIoT2023。DDoS AUROC 相对 v15 从 0.5169 提升到 0.6039，但 DoS
降到 0.5038，Mirai 从 0.9457 降到 0.9268；工程攻击召回同时大幅下降。
因此不能用局部 DDoS 改善掩盖整体退化。

### 4.2 v21：只增强工程预警头

关闭表示层 OE 后，论文指标接近原训练分布，但预警准确率和攻击召回仍低于
v15。说明 UNSW 类别主要提供数据集域信号，不是目标 DDoS/DoS/Mirai 的稳定
代理未知。后续不再扫描 UNSW 权重、采样比例或事后阈值。

### 4.3 v22：目标域行为 XGBoost

XGBoost 2.1.4 使用 CUDA 训练，输入不含 IP/端口，包含包序列、图节点、质量、
融合嵌入、证据、冲突和可靠性。训练头对已知攻击可拟合，但 leave-family-out
未知召回接近零，表明当前问题不是分类器容量不足，而是已知家族判别特征不能
自然泛化为未知家族的统一恶意边界。

## 5. 下一步实验

下一轮不再做以下实验：

- 不再调整 UNSW OE 权重或把 UNSW 样本重复加入二分类头。
- 不再扫描 XGBoost 树深、估计器数或利用未知测试结果选阈值。
- 不再组合已经被 `v16/v19` 否决的多支路 OR 预算。

应优先开展：

1. 在目标数据内部构造 capture-level 域泛化训练：每个已知攻击家族按捕获组
   做 episodic train/query，直接优化跨捕获的二元攻击边界。
2. 将“攻击类型识别”和“未知拒识”保持分头训练，使用共享三模态编码器，但
   不再要求同一个嵌入同时承担家族分类和通用恶意检测。
3. 在不访问真实未知测试标签的条件下，以已知家族轮流作为 meta-unknown，
   只在 known-only validation 上选择元损失和阈值。
4. 先做固定协议的单种子开发；只有三场景均通过完整门槛后，才开放 3-5 个
   确认种子、统计显著性和基线主表。
