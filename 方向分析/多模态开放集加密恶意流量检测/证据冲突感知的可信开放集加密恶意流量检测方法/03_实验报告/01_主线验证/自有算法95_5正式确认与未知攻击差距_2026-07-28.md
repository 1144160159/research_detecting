# 自有算法 95%/5% CPU 后端诊断、GPU 纠偏与未知攻击差距

更新时间：2026-07-28

## 1. 当前可写结论与计算后端纠偏

当前最优候选自有方案是 **Empirical-Tail Hybrid CAEOS**：以 XGBoost 作为已知攻击专家，以 Pairwise-CAEOS 的冲突、不确定性和经验尾部作为开放集头。原配置只在开发种子 `7` 的 14 个场景中选择一次，随后冻结为：

`alert_variant=tail_noisy_or`、`alert_budget=0.04`、`open_variant=tail_noisy_or`、`open_budget=0.04`。

在 fresh 种子 `907/911/919`、42 个 CICIDS2017 细分类留一场景上，该候选方案的 **CPU 后端诊断结果**为三个种子全部通过基本预警门。但是，检查服务器现场与训练代码后确认：旧 XGBoost 使用 `tree_method=hist`，未声明 `device=cuda`；Pairwise/RRC 也使用 CPU 后端。服务器位置不能替代计算后端证明，因此这些结果不得作为“GPU 正式确认”写入论文主结论。

真实 CUDA 攻击大类开发现已完成，结论为阴性。因此当前仅可写：

> GPU 服务器上的 CPU 后端诊断表明，Empirical-Tail Hybrid CAEOS 在 CICIDS2017 细分类留一任务上具有达到基本 95%/5% 门的可行性；但真实 CUDA 的攻击大类 seed17 开发未通过基本门，因此尚无可进入 fresh 确认的 GPU 配置。

不能写“基本目标正式完成”或“完整目标已经完成”。前者没有通过 GPU 开发门，后者还因为 Unknown 类型召回未达到 95%。

## 2. 指标与基线

基本预警门固定为：Alert Accuracy、Alert Precision、Attack Recall、Known attack type Accuracy 均 `>=0.95`，Benign FPR 严格 `<0.05`。完整开放集门在此基础上另要求 Unknown attack Recall `>=0.95`。均值通过不替代逐种子通过。

论文部署主表报告上述指标及 Unknown alert Recall、Unknown type Recall、Unknown precision；开放集科学主表继续报告 Known Macro-F1、Unknown AUROC/AUPR/FPR95、OSCR。FPR95 是未知 TPR 达到 95% 时的已知误拒率，不等于 Benign FPR。

正文基线压缩为五项：XGBoost 闭集/预警锚点、Energy 简单现代 OOD、OpenMax 经典开放集、OpenDetect 同协议强比较器、RoNeTC 流量领域比较器。MSP、Mahalanobis++、kNN、ViM、ARPL 和 CADE 保留在补充材料，不删除既有结果。

## 4. 为什么此前已知分类低于 95%、误报高于 5%

旧的单级决策把“开放集拒识”与“恶意告警”做并集：`predicted_alert = open_rejected OR predicted_nonbenign`。这会把被开放集头拒识的良性流量直接记为误报，同时又把已知类型正确率限制在“未被判 Unknown”的子集上。原 102 场景诊断因此只有 Known Accuracy `78.73%`、Benign FPR `26.84%`。

分层决策将二者拆开：第一级只用 known-validation 良性样本标定预警阈值，第二级只在已告警样本中决定已知类型或 Unknown。CPU 后端诊断中，Pairwise 的已知类型均值升至 `96.36%`、误报均值降至 `4.50%`；Hybrid 进一步使三个 fresh 种子全部通过基本门。这支持“此前主要问题是决策耦合和跨种子阈值稳定性”的工作假设，但仍需由新 CUDA fresh-seed 实验确认。

## 5. 当前真正缺口

GPU 服务器上的 CPU 后端失效分析把 Unknown 类型召回缺口分为两段：`15.52%` 的未知攻击在预警前漏掉，另有 `11.58%` 已预警但没有标为 Unknown；Pairwise 距离 95% Unknown 类型召回仍差 `22.10` 个百分点。最低场景集中在 Web XSS、Bot、Infiltration 和 PortScan，细粒度攻击与相邻已知子型在同一流级特征空间中重叠。

Hybrid 的 CPU 后端诊断将 Unknown 类型召回从 `72.90%` 提升到 `79.42%`，但仍不足以支撑“已知和未知攻击类型均 95%”的完整主张。攻击大类 GPU 开发进一步表明，整类未见时 Unknown alert Recall 只有 `76.50%`，不是简单标签合并即可解决。当前科学结论应是“细分类 CPU 诊断显示基本门可达，但攻击大类 GPU 开发、fresh 确认和未知细分类均未完成”。

后续顺序调整为：

1. 不启动失败配置的 `953/967/971` fresh 确认，保持种子未读。

4. 下一自有候选采用训练期 leave-one-known-family 伪未知或对比表征；只用 development seed17 选型，过基本门后才新冻结 fresh 协议。

## 10. 细分类均衡实验的纠偏结论

FB-FSX-CAEOS使用按细分类最多5000条的`49193`条流，而不是按恶意大类最多5000条的`23116`条流；划分继续采用`capture_grouped`，未知家族的全部细分类同时从训练与验证中移除。7个CUDA任务在`167.48`秒内完成且零失败，随后在4种攻击概率与945种告警/开放集配置的笛卡尔积上评估`3780`个候选。

开发选择仍失败。Botnet未知告警召回仅`1.42%`，Reconnaissance为`42.44%`；BruteForce虽达到`85.84%`，仍低于95%。DDoS、Exploit和WebAttack通过基本门，但Exploit只有47条原始细分类样本，不能支撑稳定结论。细分类均衡改善已知类型分类，却没有产生跨家族恶意公共表征，因此不得启动`953/967/971`确认。

## 11. 当前最优算法与下一实验

当前不能指定一个“已全面达标”的最优自有算法。按不同目标形成Pareto前沿：

- 本轮新增分支中，PSF-CAEOS的Alert Accuracy和Unknown alert Recall最高。
- 历史双CUDA XGBoost Hybrid的Unknown alert Recall为`79.39%`、Known family Accuracy为`95.92%`，但Alert Accuracy只有`92.37%`，仍未过基本门。
- CPU后端Empirical-Tail Hybrid CAEOS是唯一三fresh种子通过基本门的诊断候选，但不能替代GPU正式结果。

下一轮不再继续扩展同一阈值网格。优先实验是：在包序列与流统计联合编码器中引入训练期leave-one-known-family伪未知、跨家族恶意对比学习和良性边界约束；第一级只做良恶预警，第二级在已告警样本中做已知类型/Unknown判定。仍只用开发种子选型，只有7/7场景基本门和完整门同时通过后，才冻结并启动fresh确认。

本轮新增轻量证据位于`results/06_自有算法95_5目标证据_20260728/gpu_cuda_development_snapshot_20260729/`，共87个JSON及协调日志，不含原始数据、NPZ分数或模型权重。

## 12. DMC-CAEOS Botnet 定向纠偏结果

### 12.1 设计与预注册边界

在不读取 fresh `953/967/971` 的前提下，新增 DMC-CAEOS 开发分支：包序列编码、家族/二分类双度量头、已知家族监督对比损失、训练内伪未知混合及轮换留一家族余弦间隔。Botnet seed29 先做单场景资格试验，预注册扩展门槛为 `FPR<5%`、`Known type>=95%`、`Unknown alert Recall>=60.37%`；未过门不得运行 7 场景。

### 12.2 效果结果

| 分支 | Alert Accuracy | FPR | Known type | Unknown alert Recall |

统计 dropout 明显恢复了未知 Botnet 预警召回，证明全统计 DMC 存在统计捷径；但严格清零统计特征后仍比 PSF 低 `4.39` 个百分点，说明捷径不是唯一原因。DMC 的已知类聚类更好，却没有形成跨恶意家族可迁移的共享判别边界。

### 12.3 无效分支与互补性诊断

初始 `dropout=1.0` 分支只在训练阶段清零统计特征，验证和测试仍输入完整统计特征，因此保留原始工件但标记为“不能解释为纯序列”。修正后 v3 只提高 `0.24` 个百分点，未改变结论。

PSF-DMC 后融合按内容指纹在测试集对齐 `5612/5615` 条流，7 个融合候选只用验证集已知攻击选权，Botnet 测试标签不参与选权。验证规则最终选回 `dmc_only`；Unknown alert Recall仍为`50.98%`。开放证据并集把 Unknown 类型召回提高到`21.22%`，但 Known type 降至`94.31%`，说明这是冲突交换而非可用互补。

### 12.4 资源与当前决策

所有训练均有 A6000 CUDA 证据。并行 dropout 两分支观测的整卡均值为`58.51%/61.95%`，达到最低50%负载；单任务 v1/v3 均值仅`20.44%/20.91%`，资源验收不通过。后续训练必须多场景并行，不能用峰值`100%/96%`替代均值。

DMC 不进入 7 场景和 fresh 确认，当前 Botnet 候选仍以 PSF 为优。下一自有算法只保留一条高价值改动：在每个元训练 episode 中从攻击头内循环排除一个已知恶意家族，并在外循环显式要求该家族仍被判为恶意，从目标函数层面模拟“未见攻击家族”；不再追加静态对比损失或分数融合。
