## 3. 必须新建的强真值数据

现有远端数据不足以单独支持完整 `process→file→socket→remote process` 攻击链评价。正式主结论必须新增隔离靶场数据：

- 6-8 个攻击场景族，每族至少 3 次，共 18-24 次独立运行；
- Windows+Linux；至少两个攻击族仅测试；
- 同步采集端点溯源、认证/系统/安全日志、Zeek/Suricata/DNS/NetFlow/PCAP 和攻击编排器日志；
- 建立 exact/ambiguous/unmatched 的跨源对齐真值；
- 有纯良性对照、传感器健康和时钟偏移记录；
- 原始数据直接写入远端项目数据目录，不在本地落盘。

建议远端目录：

```text
/opt/data/private/wangwt/ParkAttackKE/APT-Chain-Reconstruction/datasets/strong_truth/
  raw/<run_id>/<sensor>/
  truth/<run_id>/steps.jsonl
  truth/<run_id>/alignment_edges.jsonl
  manifests/<run_id>.json
```

## 4. 本地允许保存的内容

本地代码根：`F:\泉城实验室\二期\论文\异常检测\source\EACR-APT`

允许：

- `.py/.yaml/.toml/.md/.cmd/.ps1` 等源码、配置模板和同步脚本；
- 单元测试代码；
- 不含原始事件的 schema 示例；
- 数据/模型 manifest、文件哈希、远端相对路径；
- 聚合后的轻量指标、表格和论文图所需小型统计。

禁止：

- PCAP、CSV/JSONL 原始事件、图数据库 dump；
- `.pt/.pth/.ckpt/.onnx/.joblib/.pkl` 模型参数；
- embeddings、缓存特征、训练日志、大型结果和临时文件；
- 通过符号链接、压缩包或 Git LFS 将远端重资产回流本地。

## 5. 历史本地第三方资产

`source/TeRed`、`source/Euler`、`source/Krystal`、`source/eaGle`、`source/TraceCluster`、`source/DIDS-MFL` 等为本项目之前存在的第三方仓库/存量资产，其中部分目录带样例数据或既有运行产物。处理原则：

1. 不再向这些本地目录新增数据、模型或实验结果；
2. 它们只作为代码/小样例/复现参考，不是 EACR-APT 的权威数据位置；
3. 后续迁移或清理必须先核验文件来源、论文证据链接和可重建性，禁止为满足目录整洁而破坏现有结果映射；
4. 正式实验统一在远端独立环境和远端数据路径运行。

## 6. 不可直接用于主结论的资产

- 从同一原始溯源记录拆出的日志/流量派生视图；
- 只有节点标签而无事件/边/链真值的数据；
- 原论文报告数字；
- 不同场景、不同时间的数据后验拼接；
- SAGA 等合成日志作为唯一主训练/测试集；
- LANL 未标注事件作为确定良性样本；
- CICAPT/DIDS 的 flow 指标作为完整链指标。
