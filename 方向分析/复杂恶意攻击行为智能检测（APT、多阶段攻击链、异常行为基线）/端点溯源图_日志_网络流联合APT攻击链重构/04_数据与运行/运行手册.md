> 当前执行顺序以 `02_实验设计/问题假设实验闭环.md` 和两周否证性 pilot 为准。KRYSTAL、TeRed 等旧仓库只在相应基线阶段运行，不再先于强真值与硬匹配基线扩展。

## 1. 当前环境原则

- Windows 主工作区使用 PowerShell。
- 优先显式使用 `D:\soft\Anaconda3\python.exe`，不要假设裸 `python` 指向正确环境。
- 每个旧仓库单独记录 Python、PyTorch/TensorFlow 和 PyG 版本；优先隔离环境，不在同一环境强行兼容全部基线。
- 正式实验、数据转换和 smoke test 均在 GPU/Linux 服务器运行；本地只完成基本代码、单元测试、文档、manifest 和轻量指标检查，不落地原始数据、模型参数或完整结果。
- 远端项目根：`/opt/data/private/wangwt/ParkAttackKE/APT-Chain-Reconstruction`；Conda 环境：`/opt/data/private/wangwt/anaconda3/bin/conda run -n py3.9`。

## 4. 可选基线：KRYSTAL 链重构 smoke test

KRYSTAL 是当前最接近输出任务的可运行候选。先以 `live-store: false` 或隔离 GraphDB 仓库跑通一个 CDM18 小样例：

1. 冻结 `config.yaml`、Java/Maven 版本与输入文件哈希；
2. 执行 `CDM JSON → RDF provenance → alert/POI → backward-forward attack subgraph`；
3. 核验每条子图边的原始事件映射；
4. 在没有链真值前只报告运行成功、数量和案例，不报告 chain F1；
5. README 的示例命令重复了 `java -jar`，实际命令必须以构建出的 JAR 名称为准。

默认配置依赖 GraphDB 和预建 repository；本地当前只有 `target/classes`，没有核验 fat JAR，先执行 Maven 构建，不假设已可直接运行。

## 5. 可选效率基线：TeRed

当前已知配置问题：`main.py` 使用 `DATA_TO_COMPRESS`、`reduce_by_template.py` 使用 `COMPRESSED_FOLDER`，而 `settings.py` 分别定义 `DATA_TO_REDUCE`、`REDUCED_FOLDER`。修复时应建立单独补丁并记录，不直接覆盖上游语义。

预期运行顺序：

1. 固定一个正常日志集学习模板；
2. 对一个含攻击的JSON执行压缩；
3. 统计原始/压缩节点与边、运行时间、恶意事件保留率；
4. 在原始与压缩数据上运行同一检测器；
5. 生成 `run_id` 和轻量摘要。

## 6. 阶段1：强真值与统一事件转换

转换器命令的目标接口：

```text
python -m eacr_apt.data.convert \
  --dataset <name> \
  --raw-root <path> \
  --output-root <path> \
  --manifest <path> \
  --strict
```

转换完成必须生成：事件计数、字段缺失、丢弃原因、时间范围、实体覆盖、真值覆盖和划分重叠报告。

## 7. 阶段2-3：对齐与重构 pilot

目标接口：

```text
python -m eacr_apt.align --config configs/alignment.yaml --run-id <id>
python -m eacr_apt.reconstruct --config configs/reconstruct.yaml --run-id <id>
python -m eacr_apt.evaluate --run-id <id> --ground-truth-root <path>
```

当前基础包只包含 schema、对齐和重构骨架，上述完整 CLI 尚未实现；接口只用于约束未来产物命名和职责分离。

## 8. 运行目录约定

```text
/opt/data/private/wangwt/ParkAttackKE/APT-Chain-Reconstruction/runs/<run_id>/
  config.resolved.yaml
  environment.json
  data_manifest.json
  alignment_summary.json
  metrics.json
  predictions.jsonl
  evidence_packages/
  stdout.log
  stderr.log
  status.json
```

本地 `results/` 只同步轻量、聚合且不含原始事件的 `config.resolved.yaml`、`environment.json`、`data_manifest.json`、`metrics.json`、`status.json`；不同步 `predictions.jsonl`、原始日志、完整图或模型权重。

## 9. run_id

格式建议：`YYYYMMDD-HHMM_<dataset>_<protocol>_<method>_s<seed>_<shortsha>`。

示例：`20260720-2130_tc-e3_loso_eacr_s7_a1b2c3d`。
