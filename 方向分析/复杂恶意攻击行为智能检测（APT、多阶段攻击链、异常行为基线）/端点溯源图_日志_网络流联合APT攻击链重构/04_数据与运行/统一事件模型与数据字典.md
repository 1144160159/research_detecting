# 统一事件模型与数据字典

版本：`schema-v0.2-design`

## 1. 文件集合

```text
dataset_root/
  manifest.json
  events/
    endpoint_events.jsonl
    host_log_events.jsonl
    network_flows.jsonl
  entities/
    entities.jsonl
  links/
    observed_edges.jsonl
    alignment_candidates.jsonl
  ground_truth/
    malicious_events.jsonl
    attack_stages.jsonl
    attack_chains.jsonl
  splits/
    train.json
    validation.json
    test.json
```

正式实现可使用 Parquet；JSONL 作为人类可审计交换格式。

## 2. 通用事件字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `event_id` | string | 是 | 数据集内稳定唯一ID |
| `source_type` | enum | 是 | `endpoint`/`host_log`/`flow`/`alert` |
| `source_record_id` | string | 是 | 原始记录ID或可重定位索引 |
| `event_type` | string | 是 | 规范化事件类型 |
| `time_start_ns` | int64 | 是 | 校正后的 UTC 时间区间起点 |
| `time_end_ns` | int64 | 是 | 区间终点；瞬时事件可等于起点 |
| `original_time` | string/int | 是 | 原始时间值、时区和精度可回溯 |
| `clock_offset_ns` | int64/null | 否 | 已估计的主机/传感器时钟校正量 |
| `time_uncertainty_ns` | int64 | 是 | 校时残差、精度和采集延迟形成的不确定半径 |
| `ingest_time_ns` | int64/null | 否 | 采集到达时间 |
| `host_id` | string/null | 否 | 规范化主机实体ID |
| `user_id` | string/null | 否 | 规范化账号实体ID |
| `process_id` | string/null | 否 | 不能只用PID，应含host和生命周期 |
| `object_id` | string/null | 否 | 文件/注册表/服务/域名等实体 |
| `attributes` | object | 是 | 不同源的扩展字段 |
| `raw_ref` | string | 是 | 原始文件与行/偏移引用 |
| `derived_view` | bool | 是 | 是否从另一观测派生 |
| `sensor_health` | object | 是 | 在线状态、丢包/丢日志、采样率和已知故障 |
| `converter_version` | string | 是 | 转换器Git提交或版本 |

## 3. 网络流扩展字段

`start_time_ns`、`end_time_ns`、`src_ip`、`src_port`、`dst_ip`、`dst_port`、`protocol`、`packets_fwd`、`packets_rev`、`bytes_fwd`、`bytes_rev`、`direction_basis`，以及可选 `dns`/`tls`/`http` 元数据。

## 4. 实体表

| 实体类型 | 稳定键建议 | 注意事项 |
|---|---|---|
| Host | dataset+sensor+host alias | IP不能单独视为主机ID |
| User | domain/realm+account | 区分服务账号和共享账号 |
| Process | host+pid+start_time | PID会复用 |
| File | host+canonical path+inode/uuid | 路径重命名与临时文件 |
| Socket | host+process+five-tuple+interval | NAT和连接复用 |
| Flow | sensor+five-tuple+interval | 双向合并规则必须固定 |
| Alert | source+rule+record id | 规则版本需要保留 |
| ATT&CK | STIX ID+snapshot version | 禁止使用无版本名称匹配 |

## 5. 边记录

```json
{
  "edge_id": "...",
  "src_id": "...",
  "dst_id": "...",
  "edge_type": "spawn|read|write|connect|authenticate|align|maps_to",
  "time_start_ns": 0,
  "time_end_ns": 0,
  "source_refs": ["..."],
  "observed": true,
  "match_probability": null,
  "time_delta_ns": null,
  "evidence_breakdown": {},
  "ambiguity_id": null,
  "rule_or_model": "...",
  "version": "..."
}
```

`observed=false` 表示推断/候选对齐边，必须带校准概率、候选集合、证据分解和生成依据。候选边不得与真实观测边混用同一布尔语义。

## 6. 对齐候选

每个源事件保留：候选目标、各子分数、校准概率、候选排名、时间区间/偏差、竞争候选数量和熵、是否拒绝、最终决策、`exact|ambiguous|heuristic|unmatched` 人工核验标签。只保存最终硬边不足以评价对齐质量。

## 7. 攻击真值

### 7.1 恶意事件

`event_id`、`campaign_id`、`run_id`、`step_id`、`stage_id`、`technique_id`、`truth_source`、`truth_confidence`。

### 7.2 攻击阶段

`stage_id`、`campaign_id`、`tactic_or_phase`、`start_time_ns`、`end_time_ns`、`host_ids`、`event_ids`。

### 7.3 攻击链

`chain_id`、`campaign_id`、`ordered_stage_ids`、`event_ids`、`edge_ids`、`alternative_valid_edges` 和 `truth_notes`。

允许一个场景存在多个合理路径，评估器不得强迫唯一线性真值。

### 7.4 攻击步骤与传感器状态

每个 `step_id` 记录 `start/end UTC`、源/目标主机、账号/session、PID/GUID、父进程、文件、五元组、预期前驱/后继、攻击编排器证据、传感器健康和时钟偏移。关键跨源边允许候选集合，不为方便训练而强制唯一真值。

## 8. manifest

`manifest.json` 至少包含：数据集名称/版本、来源、许可、下载时间、文件哈希、事件计数、时间范围、传感器、独立源/派生源说明、转换器提交、真值版本、划分版本、已知问题和负责人。

## 9. 数据验证

- `event_id`、`edge_id` 唯一；引用存在。
- 时间范围与精度一致，不能静默截断。
- 进程生命周期与PID复用检查。
- flow方向规则固定且可逆追溯。
- truth字段不出现在模型输入文件。
- 划分间 campaign/run 不重叠，并输出 host/user/template overlap 报告。
- 转换前后事件计数、丢弃原因和字段缺失率完整记录。
