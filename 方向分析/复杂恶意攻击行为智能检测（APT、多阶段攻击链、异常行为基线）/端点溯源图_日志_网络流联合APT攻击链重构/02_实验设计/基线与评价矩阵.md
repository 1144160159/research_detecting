# 基线与评价矩阵

## 1. 对齐基线

| ID | 基线 | 作用 |
|---|---|---|
| A0 | Oracle/exact alignment | 强真值上界；隔离下游解码误差 |
| A1 | 原始时间精确连接 | 无校时下界 |
| A2 | 固定 `±1/5/30s` 窗口 | 常见时间窗基线 |
| A3 | 五元组、主机+账号或 session 硬匹配 | 确定性实体键基线 |
| A4 | 规则打分后阈值二值化 | 有特征但不传播不确定性 |
| A5 | 概率式候选对齐 | 主方法对齐模块 |

## 2. 单源与融合基线

| ID | 基线 | 输入 | 主要输出 |
|---|---|---|---|
| F0 | 频次/时间启发式 | 单源 | 事件排序 |
| F1 | provenance-only | 端点溯源 | 节点/边 seed |
| F2 | log/auth-only | 日志/认证 | 日志段/异常边 seed |
| F3 | flow-only | 网络流 | 异常 flow seed |
| F4 | 两两组合 | P+L、P+F、L+F | 事件/边 |
| F5 | 分数平均/最大/late fusion | 单源 seed 分数 | 事件排序 |
| F6 | feature concatenation | 硬对齐多源特征 | 事件/阶段分类 |
| F7 | naive union/hard-link graph | 固定窗硬连接 | 调查子图 |
| F8 | UCTEG | 三源候选概率 | 最小证据子图 |

必须增加辅助源时间/实体置乱和高风险标识字段删除实验，防止把关联捷径解释为多源互补。

## 3. 攻击链重构基线

| ID | 基线 | 机制 | 角色 |
|---|---|---|---|
| R0 | temporal BFS / bidirectional BFS | 时间尊重邻域扩张 | 最低复杂度下界 |
| R1 | k-shortest temporal paths | 多候选路径 | 路径排序下界 |
| R2 | KRYSTAL-like | backward-forward、规则/RDF 查询 | 知识/规则基线 |
| R3 | EAGLE-like | 规则+异常 seed 的异常子树 | 单机重构基线 |
| R4 | CCLog-like | 贪心近似 Steiner | 紧凑路径强基线 |
| R5 | HADES-like | session/GUID 约束前后向溯源 | 跨机身份基线 |
| R6 | SParse-like | POI 驱动路径剪枝 | 实时调查基线 |
| R7 | 无阶段最小子图 | 概率对齐+最小证据，不用 ATT&CK | 阶段约束消融 |
| R8 | 完整最小证据子图 | 概率、操作性依赖、软阶段、冗余惩罚 | 主方法 |

若官方代码不能在统一数据上运行，标为“概念重实现”，不能冒充官方复现。原论文数字只作背景，不与本地重跑结果做统计检验。

## 4. 可选效率基线

| ID | 基线 | 条件 |
|---|---|---|
| S0 | 无归约 | 默认主实验 |
| S1 | 频率/随机裁剪 | 规模下界 |
| S2 | TeRed | 正常模板归约；本地有代码/小样例 |
| S3 | SParse-like pruning | POI 路径裁剪 |

首稿只允许 S2/S3 中一种进入主方案；评价必须同时报告跨源连接点和攻击证据保持。

## 5. 指标

### 5.1 数据与对齐

- 解析率、字段缺失、重复/乱序、时间残差；
- alignment edge P/R/F1、Top-k recall、false cross-host link rate；
- ambiguity coverage、Brier、NLL、ECE、reliability diagram。

### 5.2 事件与告警

- PR-AUC 为主、AUROC 为辅；
- Recall@固定调查预算、`FP/host-day`、TTFD；
- 按攻击族/阶段分层的 Macro-F1/Recall。

### 5.3 阶段与子图

- stage Macro-F1、coverage、order accuracy、normalized edit distance；
- node/edge P/R/F1、Graph IoU、GED；
- redundancy ratio、fragment count、错误桥接数和断链率。

### 5.4 整链与分析负担

- Chain Recall@k、Path/Edge-F1、MRR；
- 每链节点/边/原始记录数；
- Analyst Reduction、risk-coverage、abstention rate、高置信错误率；
- 最小证据反事实删除的 decision flip 和稳定性。

### 5.5 效率

- events/s、构图时间、p50/p95/p99 重构延迟；
- CPU/GPU 峰值内存、磁盘和完整图/候选图大小；
- 候选缩减率、超时率、攻击节点/边与跨源连接点保留率。

## 6. 主表规划

1. **表1 数据/对齐质量**：规模、覆盖、时间残差、歧义、Alignment-F1/ECE；
2. **表2 多源互补**：P/L/F 组合、置乱/捷径检查、PR-AUC、Recall@budget、FP/host-day；
3. **表3 强真值链主结果**：node/edge F1、stage coverage、GED、冗余、Chain Recall@k；
4. **表4 机制消融**：概率、时间/会话、跨源支持、阶段、unknown、冗余；
5. **表5 鲁棒性**：缺源、偏移、别名/NAT、噪声和删日志失效曲线；
6. **表6 规模**：181GB 下吞吐、p95、内存、存储和证据保持。

## 7. 公平比较规则

1. 同一数据转换、划分、seed 预算、候选预算和评估器；
2. 对齐比较固定下游解码器，重构比较固定输入 seed；
3. 各基线获得合理且登记的调参预算；
4. 输入能力不同分组报告，不把额外真值/CTI 方法混入同一公平组；
5. 统计单位是 run/scenario/host-day，不把事件当独立样本；
6. 结果包含负例、失败运行和置信区间，不只报最好 seed。
