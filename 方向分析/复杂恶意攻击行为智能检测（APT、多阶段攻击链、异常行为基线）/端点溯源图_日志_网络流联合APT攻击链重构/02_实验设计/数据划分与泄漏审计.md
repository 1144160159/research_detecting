# 数据划分与泄漏审计

- 版本：v0.2-research-design
- 状态：Strong-Truth 与 LANL split 生成时执行
- 目标：保证评价的是跨场景攻击链重构能力，而不是记忆主机、攻击脚本或时间邻近关系。

## 1. 划分原则

正式实验优先使用 `campaign-disjoint`；同一攻击活动的任何事件、派生子图、流记录和日志模板不得跨集合。若样本量允许，再叠加 `host-disjoint` 与 `time-disjoint`。随机事件级划分只可作为诊断，不可作为论文主结果。

Strong-Truth 至少两个完整攻击族只进入测试。LANL 使用连续时间切分，阈值只在验证窗确定；未标注事件不得自动作为确定良性样本进入监督负类。

| split ID | 训练/验证/测试隔离单位 | 用途 | 是否可作主结果 |
|---|---|---|---|
| S1 | campaign | 主协议 | 是 |
| S2 | campaign + host | 跨主机泛化 | 是 |
| S3 | campaign + time | 时间漂移 | 是 |
| S4 | event random | 排错上限 | 否 |
| S5 | cross-dataset | 外部泛化 | 是，但需统一真值定义 |

## 2. 强制泄漏检查

- [ ] 同一原始事件 ID、flow ID、告警 ID 无跨集合重复。
- [ ] 同一 campaign、攻击脚本实例、回放批次无跨集合重复。
- [ ] 主机名、IP、用户名、路径和进程 UUID 不成为标签捷径；必要时匿名化后重测。
- [ ] 日志模板由训练集拟合，测试集不得参与模板抽取或词表统计。
- [ ] 标准化、实体映射、负采样分布仅由训练集估计。
- [ ] ATT&CK technique/stage 真值只用于训练标签或评价，不得作为测试时输入特征。
- [ ] 时间窗口不能跨越 split 边界；候选子图构建不得读取未来事件。
- [ ] 合成攻击的生成参数、模板和随机种子与测试集隔离。
- [ ] 同一 PCAP 派生的 packet、flow、session 不得被拆到不同集合。
- [ ] 论文报告去重前后数量、每个 split 的事件/实体/边/链统计与哈希。
- [ ] CALDERA/Atomic 默认路径、测试 GUID、固定 payload 名称和步骤顺序已随机化或从特征中移除。
- [ ] Strong-Truth 的 `steps/alignment_edges/chain` 真值文件与模型输入物理隔离。

## 3. 对齐泄漏专项

跨源对齐器若使用真实映射训练，必须只在训练集学习。测试时对齐候选只能依赖部署时可见字段。对齐评估单独报告：候选召回率、Top-1 准确率、误匹配率、无匹配拒绝率、时间偏差分布。

## 4. 审计产物

每次正式划分生成：

1. `split_manifest.json`：数据版本、规则、种子与统计；
2. `leakage_audit.json`：每项检查及反例数量；
3. `entity_overlap.csv`：跨集合实体重叠及处理理由；
4. `hashes.sha256`：输入、映射、split 文件哈希。

任一强制项失败，该 run 标记为 `invalid_leakage`，不得进入主结果表。
