# 问题—假设—实验闭环

- 版本：`v0.2-research-design`
- 状态：正式训练前预注册并冻结
- 原则：每个创新必须对应独立可证伪假设、直接消融和失败判据

## 1. 闭环总表

| 科学问题 | 假设 | 直接实验 | 主要数据 | 核心指标 | 支持条件 |
|---|---|---|---|---|---|
| SQ1 跨源对齐 | H1 概率式对齐优于硬连接 | E0、E2 | 自建强真值 | alignment edge P/R/F1、Top-k recall、错误跨主机率、ECE/Brier | edge F1 +5pp 且 95% CI 不跨 0 |
| SQ2 多源互补 | H2 三源不是单源捷径 | E1、E4 | LANL 11GB+强真值 | PR-AUC、Recall@budget、FP/host-day、链边 F1 | PR-AUC 相对 +10% 或 Recall +5pp，FP 增幅 <=20% |
| SQ3 最小证据链 | H3 约束子图更完整且紧凑 | E3 | 自建强真值 | node/edge F1、stage coverage/order、GED、冗余、碎片数 | edge F1 +5pp，或冗余 -20% 且覆盖降幅 <=2pp |
| SQ4 可信退化 | H4 缺源/偏移下平滑退化并可拒绝 | E5 | 强真值+LANL | 性能保持率、链断裂率、risk-coverage、误连边 | 30% 缺源或 ±5s 后保持 >=80% |
| SQ5 规模 | H5 可扩展而不破坏关键证据 | E7 | LANL 181GB | events/s、p95、RAM、存储、链召回 | 吞吐 >=2×峰值；p95 <=60s；证据召回达门槛 |

## 2. 数据协议

### D1：自建强真值多源靶场

这是链重构主结论的唯一强真值来源，最低规模为 6-8 个攻击族、每族 3 次，总计 18-24 次独立运行。至少两个攻击族完全留作测试。每次运行必须有同拓扑、同业务负载的纯良性对照。

采集源：

- Windows：Security、Sysmon、PowerShell、域控认证；
- Linux：auditd 与 eBPF/sysdig 中至少一种；
- 网络：Zeek/Suricata、DNS、NetFlow，必要时保留 PCAP；
- 真值：CALDERA/Atomic Red Team/自编排器的步骤日志和人工确认记录。

每个攻击步骤记录：

```text
attack_id, run_id, step_id, ATT&CK technique, start/end UTC,
source/target host, account/session, PID/process GUID, parent PID,
file/artifact, src/dst five-tuple, expected predecessor/successor,
sensor health, clock offset, exact/ambiguous link label
```

### D2：LANL Cyber1 comprehensive 11GB

包含 auth、DNS、flows、proc 和 redteam 锚点，用于：

- auth/DNS/flow/proc 单模态、两两和多源消融；
- 横向移动/红队事件检测和候选路径排序；
- 长时间极端不平衡下的 `FP/host-day` 与告警预算；
- 固定窗口与概率对齐的弱标签对比。

禁止把所有未标注事件当作良性；使用 positive-unlabeled 训练/分析或以 redteam anchor 为中心的 Recall@k、MRR 和路径紧凑度。

### D3：LANL unified host-network 181GB

只用于规模、吞吐、内存、存储和归约实验，不因数据更大而自动获得更强攻击链真值。

### D4：CICAPT-IIoT2024 与 DIDS-MFL

只验证 flow seed/encoder 的外部检测和迁移，不进入完整三源攻击链主表，也不与不相干端点数据后验拼接。

### D5：DARPA TC/现有 provenance 样例

用于 KRYSTAL、EAGLE、TeRed、CCLog-like 端点基线和转换器 smoke test。只有在独立网络/日志观测和映射真值被确认后，才可进入三源主实验。

## 3. 划分与统计单位

1. 训练、验证、测试按 campaign/run 划分；同一运行的相邻窗口不得跨集合。
2. 至少一个 `leave-one-attack-family-out` 测试；另报告 time-disjoint 和 host-disjoint 结果。
3. LANL 按连续时间切分：第一条 redteam 事件之前的连续窗用于训练候选，训练尾部正常窗用于验证，后续时间用于测试；阈值只在验证集确定。
4. 统计单位是攻击运行、场景或 host-day，不是数百万条相互相关事件。
5. 学习模型运行 5 个种子；确定性方法登记配置哈希。
6. 按攻击运行 bootstrap 95% CI；多重比较用 Holm 校正；同时报告绝对差值、相对差值和效应量。
7. 记录 host/user/process image/template overlap，检查 IP、主机名、攻击文件名和脚本顺序等捷径。

## 4. 实验 E0：数据与对齐真值门

### 目的

先证明数据可用于研究，而不是让模型吸收预处理错误。

### 检查

- 事件解析率、字段缺失、重复率、乱序率；
- 每源时钟残差和采集延迟分布；
- `flow↔socket/process`、`auth↔session/process` 的 exact/ambiguous/unmatched 比例；
- 每个攻击步骤的传感器覆盖和真值可追溯性；
- 两名标注者的关键边一致性。

### 准入门

- 关键字段解析率 `>=99%`；
- 强真值对齐边 F1 `>=0.90`；
- p95 校时残差 `<=1 s`，否则事件必须携带扩大后的时间区间；
- 歧义边比例 `<=5%`，或完整保留候选集；
- 标注一致性 `κ>=0.8`。

低于门槛时先修数据，不比较复杂模型。

## 5. 实验 E1：单源、组合与捷径检查

### 设置

1. provenance-only；
2. auth/log-only；
3. DNS/flow-only；
4. 三种两两组合；
5. 三源 naive union；
6. 特征拼接；
7. 分数平均/最大/late fusion；
8. 完整 UCTEG+最小证据链。

所有方案使用相同时间范围、候选预算、异常 seed 预算和评估器。再进行两类置乱：

- 保留单源、随机置换辅助源时间/实体；
- 删除 IP、主机名、攻击文件名等高风险捷径字段。

### 指标

事件 PR-AUC、Recall@k、`FP/host-day`、TTFD；对强真值同时报告链 node/edge F1 和阶段覆盖。

### 失败判据

三源不优于最佳单源，或辅助源置乱后结果不降，则论文不得声称真实多源互补。

## 6. 实验 E2：跨源对齐

### 基线

- oracle 对齐上界；
- 无校时精确连接；
- 固定 `±1/5/30 s` 窗口；
- 仅五元组/主机+账号硬匹配；
- 固定窗口+学习分数但不保留候选概率；
- 完整概率对齐。

### 消融

- 无时间区间；
- 无实体候选/别名表；
- 无行为一致性；
- 无传感器可靠度；
- 概率在构图后二值化；
- 完整方法。

### 指标

- alignment edge Precision/Recall/F1；
- Top-1/Top-k entity match recall；
- false cross-host link rate；
- ambiguity coverage；
- Brier、NLL、ECE 和 reliability diagram；
- 对下游链 edge F1、碎片数和冗余的影响。

### 关键预期

干净数据上概率方法应接近 oracle/精确连接而非凭模型容量显著领先；偏移、缺失和歧义增加时下降曲线应更缓。

## 7. 实验 E3：攻击链重构

### 基线

1. temporal BFS/双向 BFS；
2. k-shortest path；
3. KRYSTAL backward-forward/规则查询；
4. EAGLE-like 异常子树；
5. CCLog-like greedy Steiner；
6. HADES session constrained tracing；
7. SParse-like POI 路径剪枝；
8. 完整最小充分证据子图。

### 消融

- 去掉对齐概率；
- 去掉时间单调/会话连续约束；
- 去掉跨源互证奖励；
- 去掉 ATT&CK 软阶段约束；
- 去掉 `unknown` 松弛；
- 去掉冗余惩罚/证据预算；
- 把概率候选边当硬事实；
- 完整方法。

### 指标

- node/edge Precision、Recall、F1；
- stage coverage、Macro-F1、order accuracy、stage edit distance；
- graph edit distance、chain recall、MRR；
- 冗余节点/边率、链碎片数、错误桥接数；
- 每条链证据数、人工调查缩减率；
- 反事实删除后的 decision flip 与最小证据稳定性。

### 支持门

相对最佳基线 edge F1 绝对 `+5pp`，或在阶段覆盖下降 `<=2pp` 时冗余减少 `>=20%`。若仅节点检测提升而链级无提升，论文降级为“调查子图排序”。

## 8. 实验 E4：LANL 弱标签路径评价

以 redteam 事件作为锚点而非完整链真值：

- redteam anchor recall；
- MRR、Recall@k；
- 锚点前后相关事件的时间/主机覆盖；
- 路径紧凑度和 `FP/host-day`；
- 不同告警预算下的 analyst workload；
- auth、proc、DNS、flow 的贡献和置乱检查。

不报告 LANL 的“完整链 edge F1”，除非另有独立人工真值。

## 9. 实验 E5：缺源、失配和对抗性噪声

采用受控因子实验，至少覆盖：

| 因子 | 水平 |
|---|---|
| 随机事件丢失 | 5%、10%、20%、30%、50% |
| 连续传感器离线 | 1、5、30 分钟或按运行比例 |
| 时钟偏移 | ±1、±5、±30 秒；固定和随机漂移 |
| 实体别名 | DHCP 变化、主机别名、共享账号、PID 复用 |
| 网络歧义 | NAT、代理、端口复用、双向流聚合错误 |
| 良性边注入 | 与攻击路径邻近的合法认证/连接/进程事件 |
| 攻击者删日志 | 删除关键步骤、跨源桥接事件或整段传感器 |

指标包括相对性能保持率、断链率、误连边、校准误差、risk-coverage、拒绝率和高置信错误率。方法应在无跨源身份锚点时主动拒绝高置信完整链。

## 10. 实验 E6：跨场景与未见攻击族

- leave-one-attack-family-out；
- Windows→Linux 或相反的可比子任务；
- 新主机/账号；
- 新背景业务负载；
- 可行时做 DARPA/自建之间结构角色迁移。

报告 seen/unseen 分离结果、性能降幅和置信校准，不用总体平均掩盖未见族失败。

## 11. 实验 E7：规模与效率

在 LANL 181GB 上按事件规模、时间窗和模态数递增：

- 预处理和构图 events/s；
- p50/p95/p99 重构延迟；
- 峰值 RAM/GPU、存储和中间图大小；
- 候选边/节点缩减率；
- 每个锚点的搜索规模和超时率；
- 无归约、TeRed 或 SParse 单一效率层的链证据保持率。

效率层只有在攻击节点/边召回达到预注册容差时才算成功，不能用高压缩率掩盖证据丢失。

## 12. 实验 E8：网络流外部验证

在 CICAPT-IIoT2024 和 DIDS-MFL 上只验证 flow seed/encoder：PR-AUC、Macro-F1、Recall@固定 FPR、跨域降幅和推理吞吐。该实验不进入整链核心结论。

## 13. 结果解释规则

| 观察 | 解释与动作 |
|---|---|
| 对齐 F1 提升，链 F1 不升 | 链解码或种子是瓶颈；不能只凭对齐宣称完整方案有效 |
| 节点 PR-AUC 提升，链边 F1 不升 | 降级为事件检测/调查排序 |
| 三源只在随机切分有效 | 判定为泄漏或场景记忆，停止主张泛化 |
| ATT&CK 消融无影响 | ATT&CK 只保留为结果标注，不列创新 |
| 最小证据减少 20% 但覆盖大幅下降 | 证据预算过强，不能称“充分” |
| 干净数据胜过 oracle 很多 | 优先排查输入泄漏、阈值不公平或模型容量差异 |
| 无身份锚点仍高置信补链 | 判定为过度补全，增加拒绝/不完整输出 |
| LANL 好、强真值差 | 只支持弱标签排序，不支持链重构 |

## 14. 运行登记

每个 run 必须登记：数据 manifest/hash、split ID、代码提交、配置/hash、随机种子、完整命令、环境、开始/结束时间、退出码、指标原始文件、模型/大图远端路径和轻量结果摘要。原始数据、模型参数、检查点和完整大图只保存在 GPU 服务器；本地只保留基本代码、配置模板、manifest 和轻量指标。
