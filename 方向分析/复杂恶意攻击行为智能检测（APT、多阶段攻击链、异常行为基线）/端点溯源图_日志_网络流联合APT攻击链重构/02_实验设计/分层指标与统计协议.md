# 分层指标与统计协议

- 版本：`Metric Protocol v1.1-deep-read`
- 日期：2026-07-29
- 适用实验：EX0—EX12
- 精读依据：L01–L71，完整来源与新增实验矩阵见 `08_论文精读/跨论文指标与实验标准.md`

## 1. 协议原则

1. 数据、检测、对齐、重构、归因、系统六层分别评价。
2. 主指标在 P1 冻结，测试集只使用一次。
3. 未标注不等于良性；未知样本按弱标签/PU 或排序协议处理。
4. 所有比较使用相同真值粒度、候选预算、告警预算和硬件。
5. 同时报告效应量、95% CI 和失败分布，不只报告均值和 p 值。
6. 缩减率、吞吐或节点 F1 不能替代攻击链证据质量。
7. campaign/run 是主要统计重复单位，不能把相关单事件当成独立样本虚增显著性。
8. 复现失败、OOM、超时、模型/标签缺失均按真实状态报告，不估算或记为零。

## 2. EX0：数据和真值质量

| 指标 | 定义/统计单位 | 工程门 | 论文门 |
|---|---|---:|---:|
| 文件覆盖率 | manifest 已取得文件/应有文件 | 100% 或明确缺失 | 所有使用文件冻结哈希 |
| 有效记录解析率 | 成功解析记录/支持格式记录 | 冻结门，目标 `>=99%` | 按源报告 CI/错误类型 |
| 关键字段缺失率 | host/time/action/object 等字段缺失 | 不静默填充 | 分源、分时间、分场景报告 |
| 重复/乱序率 | 事件级 | 可检测、可定位 | 扰动敏感性分析 |
| p95 时钟残差 | 传感器对或 run | `<=1s` 或扩大不确定区间 | 报告完整分布 |
| 真值覆盖率 | 已标注关键步骤/应标注步骤 | 每 run 可回溯 | 关键边和步骤覆盖透明 |
| 标注一致性 | 两名标注者 Cohen's κ | pilot 可计算 | 目标 `κ>=0.8`；分歧仲裁 |
| 歧义边比例 | ambiguous/(exact+ambiguous) | 保留歧义 | 不强制唯一化 |
| 攻击显眼度 | 攻击事件相对背景的简单可分性 | 审计 | 与简单规则基线共同报告 |

## 3. 检测层

### 3.1 主指标

- PR-AUC；
- Matthews correlation coefficient (MCC)；
- `Recall@fixed alert budget`；
- `FP/host-day`；
- campaign/attack detection recall；
- Time-to-First-Detection。

### 3.2 辅助指标

- event/node precision、recall、F1；
- 每个 run/host/day 的告警数分布；
- 在不同基率下的 precision；
- 告警阈值—工作负担曲线。

accuracy 和 ROC-AUC 可以报告，但不能单独支持极端不平衡场景的主结论。

## 4. 跨源对齐层

### 4.1 边指标

```text
Precision = TP_align / (TP_align + FP_align)
Recall    = TP_align / (TP_align + FN_align)
F1        = 2PR / (P + R)
```

单位为候选跨源边，不是事件分类。exact、ambiguous、unmatched 分层报告。

### 4.2 排序与身份错误

- Top-1/Top-k Recall；
- mean reciprocal rank (MRR)；
- 错误跨主机率；
- 错误身份合并率；
- unmatched 识别 recall/precision；
- 每事件候选数和候选爆炸率。

### 4.3 概率质量

- Brier score；
- negative log-likelihood；
- expected calibration error；
- reliability diagram；
- high-confidence error rate。

ECE 必须披露 binning 方案；不能只展示一张校准图。

## 5. 攻击链重构层

### 5.1 节点、边和步骤

- chain node precision/recall/F1；
- chain edge precision/recall/F1；
- attack-step precision/recall/F1；
- 关键步骤召回：入口、执行、凭据、横移、持久化、提权、C2/外传；
- Chain Recall@k。

### 5.2 结构与顺序

- 阶段覆盖率；
- 阶段顺序准确率或 normalized edit distance；
- Graph/Edge Edit Distance；
- 链碎片数和断链率；
- 错误桥接率；
- 时间/因果逆序率；
- 分支召回与多余分支数。

### 5.3 最小充分性

- 冗余节点比例；
- 冗余边比例；
- evidence reduction ratio；
- 攻击节点保留率；
- 攻击边保留率；
- 跨源连接点保留率；
- 在固定阶段覆盖/关键步骤召回下的最小图规模。

## 6. 归因质量和分析员负担

参考 NoDoze、NODLINK、KAIROS、ORTHRUS、DEPCOMM 等工作提出的调查质量问题，统一报告：

- Quality of Attribution（按复现基线可获得定义实现；若定义不完全可比，单独说明）；
- 每次告警需检查的节点、边和原始事件数；
- 从检测点到根因/入口的正确覆盖；
- 每条预测边可追溯率；
- 不可解释边比例；
- 分析员确认一个链所需时间，仅在有规范化用户研究时才报告，不用主观估计。

## 7. 不确定性和拒绝

- abstention rate；
- risk–coverage curve；
- selective risk；
- high-confidence wrong-chain rate；
- 正确链覆盖率随阈值变化；
- `incomplete` 状态的正确识别率。

拒绝不是简单删除困难样本。必须同时报告覆盖率，防止通过拒绝大部分输入获得虚高精度。

## 8. 鲁棒性与泛化

| 因素 | 水平 |
|---|---|
| 随机事件缺失 | 5%、10%、20%、30%、50% |
| 连续日志缺口 | 1s、5s、30s、5min 或按场景尺度 |
| 时钟偏移 | `±0.5s`、`±1s`、`±5s`、`±30s` |
| 时钟漂移 | 线性/分段漂移 |
| NAT/代理 | 一对多、多对一、连接复用 |
| 身份别名 | hostname/IP/user/process alias 冲突 |
| 良性边注入 | 分级注入，报告候选爆炸 |
| 日志删除/重排 | 随机和定向 |
| mimicry/evasion | 保持攻击目标的良性样式动作 |
| 未见攻击族 | leave-one-family-out |

报告相对性能保持：

```text
Retention(r) = Metric_under_perturbation(r) / Metric_clean
```

并展示完整失效曲线，不只选一个扰动点。

## 9. 系统指标

按流水线阶段分别报告：

- parse events/s；
- candidate pairs/s；
- graph update events/s；
- reconstruction chains/s；
- p50/p95/p99 延迟；
- CPU、RAM、VRAM、磁盘、网络 I/O；
- 候选数、图节点/边数和裁剪率；
- checkpoint/恢复时间；
- 24h 或冻结时长稳定性；
- 失败运行比例和重试成本。

H5 的具体 p95 SLO 在测得目标输入峰值后冻结；预冻结阶段不得事后调整峰值定义。

## 10. 数据划分

### 10.1 强真值

- 外层按 attack family/campaign 隔离；
- 至少两个完整攻击族只用于测试；
- 同一 run 的派生事件不能跨 split；
- 实体别名表若由数据学习，只能使用 train；
- 阈值和校准只用 validation。

### 10.2 LANL

- 连续时间切分；
- host/time/campaign overlap 审计；
- redteam 只作锚点，不把其余事件全部标良性；
- 报告 fixed-budget ranking 和 FP/host-day。

### 10.3 跨数据集

不把不同数据集后验拼成“同一三源 campaign”。跨数据集实验只用于 external validation 或 domain shift。

## 11. 基线公平协议

基线分五组：

1. **硬对齐**：oracle、精确时间、固定窗、五元组、session。
2. **追踪/搜索**：BackTracker、BFS、k-shortest、Steiner/NODLINK-like。
3. **规则/匹配**：SLEUTH、HOLMES、POIROT、SAQL/AIQL 查询式下界。
4. **检测/表示**：Log2vec、UNICORN、ATLAS、THREATRACE、KAIROS、FLASH、MAGIC。
5. **归约/系统**：Dependence Compaction、SEAL、DEPCOMM、NodeMerge、TeRed。

若官方代码不可运行，明确标记 `reimplemented`、`partial` 或 `unrun`；不以论文原数字充当本项目复现结果。

## 12. 统计分析

1. 学习模型至少 5 个随机种子；
2. 统计单位优先为 attack run/campaign/host-day，不把海量相关事件当独立样本；
3. 使用 run/campaign 级 bootstrap 95% CI；
4. 配对比较报告差值及 CI；
5. 多重比较用 Holm 校正；
6. 同时报告适当效应量；
7. 非正态/小样本优先报告 bootstrap 或配对非参数结果；
8. 主分析和探索分析分开；
9. 超时/OOM/失败运行计入运行成功率，不静默删除；
10. 所有排除规则在 P1 冻结。

## 14. 报告最小字段

每个实验结果行至少包含：

```text
run_id, experiment_id, method, code_commit, config_hash,
dataset_manifest_hash, split_hash, seed, hardware,
status, runtime, primary_metric, CI_low, CI_high,
failure_reason, output_hash
```
