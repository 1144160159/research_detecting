# 消融与鲁棒性实验

## 1. 核心组件消融

| 编号 | 变化 | 检验假设 | 关注指标 |
|---|---|---|---|
| A1 | 概率对齐改为最佳固定窗/硬匹配 | 不确定性传播减少伪边 | Alignment-F1/ECE、错误跨主机率、链 edge F1 |
| A2 | 去掉时间区间/时钟残差 | 时间不确定性是否必要 | 对齐 F1、逆序率、断链率 |
| A3 | 去掉实体候选和歧义惩罚 | 一对多映射是否必要 | ambiguity coverage、误连边 |
| A4 | 去掉传感器可靠度 | 缺源/丢包信息是否改善置信 | risk-coverage、高置信错误 |
| A5 | 去掉跨源支持奖励 | 多源互证是否提升链 | edge F1、Chain Recall@k |
| A6 | 去掉时间/会话/信息流约束 | 纯分数连接是否产生不合理链 | 逆序率、GED、错误桥接 |
| A7 | 去掉 ATT&CK 软阶段兼容 | 阶段先验是否有独立贡献 | stage order、edit distance、链 F1 |
| A8 | 去掉 `unknown` 松弛 | 硬阶段模板是否压制未见行为 | 未见族召回、错误阶段传播 |
| A9 | 去掉冗余惩罚/证据预算 | 最小性是否减少分析负担 | 冗余、证据数、stage coverage |
| A10 | 简单解码换学习式 GNN/排序 | 复杂模型是否必要 | 效果、参数、训练/推理成本 |

图压缩不是核心消融。只有规模实验启用效率层时，才比较无归约、TeRed 或 SParse 单一方案。

## 2. 数据源与捷径消融

- P：端点溯源；L：日志/认证；F：网络流；
- 比较 `P`、`L`、`F`、`P+L`、`P+F`、`L+F`、`P+L+F`；
- 缺失源用显式 mask/absence 表示，不用零值伪装正常观测；
- 保留主源，随机置换辅助源时间和实体；
- 删除 IP、主机名、攻击文件名、脚本序号等高风险标识；
- 独立传感器与同源 `derived_view` 分组报告。

若三源收益在置乱后仍存在，优先判定为不公平预算或数据泄漏。

## 3. 时间失配

| 条件 | 档位 |
|---|---|
| 固定全局偏移 | ±1s、±5s、±30s |
| 主机级独立偏移 | 每台主机从相同档位独立采样 |
| 随机漂移 | 随时间线性/分段变化，峰值 1s、5s、30s |
| 到达延迟 | 1%、5%、10%、30% 事件延迟 |
| 局部乱序 | 在 1s、5s、30s 窗内随机置换 |

同时报告对齐和下游链的退化曲线，不只报告最终 F1。

## 4. 缺源与删日志

- 单源随机事件丢失：5%、10%、20%、30%、50%；
- 多源独立丢失和相关丢失；
- 连续传感器离线：1、5、30 分钟或运行比例；
- 删除一个关键跨源桥接步骤；
- 删除连续攻击步骤；
- 删除攻击者可接触主机的日志，但保留网络侧；
- 保留端点侧但丢 DNS/flow，反向设置亦然。

关键指标：性能保持率、断链率、abstention、错误完整链率和高置信错误。

## 5. 实体与网络歧义

- DHCP/IP 变化、hostname 别名；
- PID、端口、socket 标识复用；
- 共享账号与 session hijack；
- NAT、代理、负载均衡和 CDN；
- 双向流聚合错误；
- 同一时间窗注入相同五元组或相似命令活动。

评价 Top-k alignment recall、候选熵、错误跨主机率、链分支爆炸和拒绝率。

## 6. 噪声与背景扩张

- 正常背景 2×、5×、10×；
- 在攻击路径邻域注入合法认证、进程和连接；
- 错误规则/告警 seed；
- 重复/模板日志；
- 与攻击相似的管理员运维活动；
- 稀有但良性的跨主机行为。

目标不是在所有噪声下保持不变，而是错误率随证据质量下降可校准、可解释。

## 7. 攻击变化与迁移

- leave-one-attack-family-out；
- 已知 tactic、未见 technique；
- 新主机、账号、时间段和背景业务；
- Windows/Linux 或采集器变化下的可比子任务；
- 训练正常模板/校准器与测试攻击背景严格分离。

完整开放世界学习不进入首稿；`unknown` 只作为阶段/链输出的保守状态。

## 8. 校准与拒绝

- 对齐边：Brier、NLL、ECE、reliability diagram；
- 攻击链：risk-coverage、abstention rate、高置信错误率；
- 分别比较全数据、缺源、偏移和实体冲突；
- 无跨源身份锚点时，应拒绝高置信完整链；
- 正确拒绝优于虚假补全，不把 coverage=100% 作为默认成功。

## 9. 失败案例分类

1. 数据真值或标注不完整；
2. 时钟失配；
3. 实体/NAT/session 歧义；
4. 关键传感器或桥接事件缺失；
5. 异常 seed 漏检/误报；
6. 阶段约束过强；
7. 最小证据预算过强或搜索截断；
8. 可选归约删除关键连接点；
9. 未见攻击族/业务漂移；
10. 标签/身份捷径。

每个失败样本记录：发生层级、可观察证据、是否可由更多数据或算法修正，以及是否需要收缩论文主张。
