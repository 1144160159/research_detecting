# 问题定义与威胁模型

## 1. 任务定义

给定观测时间窗内来自多个主机和网络观测点的端点溯源事件集合 `E_p`、主机/认证/安全日志集合 `E_l` 与网络流集合 `E_f`，构建带类型、时间区间、来源、候选实体映射和置信度的不确定跨源时序证据图 `G=(V,E)`，输出一个或多个最小充分攻击证据子图 `C={c_1,...,c_k}`，并允许 `incomplete/abstain`。

每条候选链必须包含：

- 参与实体：主机、账号、进程、文件、套接字、IP/域名、会话与告警；
- 事件序列及因果/关联边；
- 预测 ATT&CK tactic/technique 或粗粒度攻击阶段；
- 每个节点与边的异常分数、对齐置信度和跨源支持；
- 原始事件 ID、数据源、时间戳与可回放证据。
- 未决歧义、置信区间和证据不足时的拒绝状态。

本文的“因果”限于审计 provenance/会话/信息流所表达的操作性依赖，不宣称从观测数据识别严格结构因果模型。

## 2. 输入数据边界

### 2.1 端点溯源事件

典型事件包括进程创建、进程执行、文件读写、套接字创建、连接建立、IPC、权限或注册表操作。溯源边提供系统内部因果骨架，但并不假设所有事件都带攻击标签。

### 2.2 主机与安全日志

典型来源包括认证日志、系统日志、EDR/IDS 告警、服务管理、计划任务、PowerShell/Shell 记录和目录服务事件。日志可能存在模板化、重复、缺字段、延迟和时区差异。

### 2.3 网络流

至少包含开始/结束时间、源/目的 IP、源/目的端口、协议、包数、字节数和方向；可选 TLS/DNS/HTTP 元数据。研究不要求解密载荷，也不假设能获得完整 PCAP。

## 3. 输出层级

| 层级 | 输出 | 主要评价 |
|---|---|---|
| 事件级 | 恶意/关键事件排序 | AUROC、AUPR、Recall@K、FPR |
| 边级 | 因果边或跨源对齐边 | Precision、Recall、误连边率 |
| 阶段级 | 攻击阶段/TTP 标签及顺序 | Macro-F1、edit distance、order accuracy |
| 子图级 | 攻击事件子图 | node/edge F1、graph IoU、冗余率 |
| 整链级 | Top-k 攻击链 | Path-F1、chain recall、MRR、analyst reduction |

## 4. 攻击者能力

研究考虑攻击者能够：

- 使用合法账号、系统工具和低频行为隐藏在正常操作中；
- 跨主机移动并把阶段分散到较长时间窗；
- 使用加密通信或常见端口降低流量可辨识度；
- 使部分传感器没有观测、延迟上报或产生冲突证据；
- 通过背景噪声和重复活动增加候选图规模。

## 5. 防御者能力与假设

- 防御者至少能获得一种端点因果观测，以及日志或网络流中的一种辅助观测；完整三源是目标设置，双源是退化设置。
- 数据采集器和时间同步机制总体可信，但允许有限时间偏差与丢失。
- 训练阶段可使用正常历史数据和部分有标签攻击场景；测试攻击场景、主机或时间段必须隔离。
- ATT&CK 知识提供阶段和技术的兼容关系，不提供测试样本的真实阶段标签。

## 6. 不在当前论文范围内

- 攻击组织或真实攻击者归因；
- 对已被完全控制的采集器、系统时间和日志完整性进行密码学证明；
- 载荷解密、恶意代码语义分析或自动响应执行；
- 仅从 CTI 文本生成攻击图而不使用运行时观测；
- 宣称覆盖全部 ATT&CK tactic/technique。

## 7. 数据泄漏边界

1. 同一攻击运行、主机身份或模板不得跨训练/测试重复泄漏。
2. 任何从 ground truth 生成的节点、边、时间窗和阶段字段不能进入模型输入。
3. 数据转换、候选图裁剪和阈值选择只能使用训练/验证集统计。
4. ATT&CK 映射规则在测试前冻结；测试结果不得反向修改映射后重新报告同一测试集。
5. 派生网络流或日志视图必须标明共同来源，不能把同源复制误称为独立互证。
