# 不确定跨源时序证据图与最小证据链方案

## 1. 方案概述

方案由四个可独立验证的模块组成：

1. 可审计统一事件与传感器状态；
2. 概率式实体—时间对齐和不确定跨源时序证据图 UCTEG；
3. 插件式异常 seed 和受约束最小充分证据子图；
4. 校准、拒绝和证据包输出。

正常模板压缩、动态图神经网络和在线更新不是首稿必需模块。工作代码目录沿用 `EACR-APT`，方法投稿名在实验成立后再确定。

## 2. 模块 A：可审计统一事件

所有输入转换为：

```text
event_id, source_id, source_type, source_record_id,
event_type, subject, action, object,
time_start, time_end, ingest_time, time_uncertainty,
host_id, user_id, session_id, process_id, process_guid,
parent_process_id, socket_id, src_ip, src_port, dst_ip,
dst_port, protocol, attributes, raw_ref, sensor_health
```

要求：

- 保留原始字段和 `raw_ref`，模型特征不能替代证据；
- 统一时间单位/时区，但同时保留原始时间和校正量；
- 标明独立传感器或 `derived_view`；
- exact、ambiguous、heuristic、unmatched 真值类型分开；
- 数据质量报告先于任何模型训练。

## 3. 模块 B：概率式实体—时间对齐

### 3.1 候选生成

不直接强制一一匹配，按可用锚点生成 Top-k 候选：

1. 主机：hostname、设备 ID、IP 租约、MAC、采集器 ID；
2. 进程：host、PID/GUID、启动区间、映像路径、父进程；
3. 网络：host、socket/PID、五元组、方向、时间区间和连接状态；
4. 会话：host、user、logon/session ID、登录/注销区间；
5. 日志/告警：host、进程、对象、规则、IOC 和时间区间。

NAT、代理、共享账号、PID/端口复用和 DHCP 变化均可能产生候选集合，不允许用任意单一键强行唯一化。

### 3.2 对齐概率

先以可解释模型建立基线：

```text
z(i,j) = w_key f_key + w_time f_interval + w_id f_entity
       + w_ctx f_behavior + w_sensor f_health - w_amb f_ambiguity
p(i↔j) = calibrate(sigmoid(z(i,j)))
```

- `f_key`：GUID、session、socket 等确定性标识；
- `f_interval`：区间重叠、持续时间、时钟残差；
- `f_entity`：主机、账号、进程、五元组和别名一致；
- `f_behavior`：动作、父子关系、连接方向和局部上下文；
- `f_health`：传感器在线、丢包和采集延迟；
- `f_ambiguity`：竞争候选数和熵。

输出包括 Top-k、归一化概率、证据分解和拒绝状态。只有精确标识和时间同时可靠时才生成事实边；其余保留为候选边。

### 3.3 UCTEG 图模式

节点：Host、User、Session、Process、File、Socket、IP/Domain/Service、Alert、Event。

边分三类：

- **观测事实边**：spawn/read/write/exec/connect/authenticate/flow/resolve；
- **候选对齐边**：same-entity、same-session、flow-of、corroborates；
- **知识软边**：maps-to-stage、compatible-before/after。

每条边保存：

```text
source_refs, relation_type, observed_or_candidate,
time_delta, time_interval, match_probability,
evidence_breakdown, ambiguity_id, rule_or_model, version
```

ATT&CK 节点或标签只提供软语义先验，不成为运行时事实证据。

## 4. 模块 C：异常 seed 与最小充分证据子图

### 4.1 插件式 seed

统一接口：

```text
seed_id, event/entity ref, source_type, score,
calibrated_confidence, detector_version, reason
```

候选提供器包括：

- provenance 节点/边异常；
- 日志语义或认证异常；
- flow/C2/横向移动异常；
- 规则、Sigma/ATT&CK、人工 POI 和 redteam anchor。

主方法不能依赖某个特定深度 seed。所有重构基线尽量使用相同 seed 隔离解码贡献。

### 4.2 最小充分目标

给定 UCTEG 和终端候选 `T`，寻找有向子图 `C`：

```text
Score(C) = α SeedCoverage(C)
         + β SourceSupport(C)
         + γ StageCompatibility(C)
         + η OperationalReachability(C)
         - λ AlignmentCost(C)
         - μ TemporalViolation(C)
         - ν UnsupportedBridge(C)
         - ρ Redundancy(C)
```

其中 `AlignmentCost=-log p(edge)`；低置信候选边越多，链代价越高。约束包括：

- 时间单调，允许有明确时间不确定区间的局部重叠；
- 进程/会话/主机连续；
- 跨主机边应有 flow、auth/session 或多个独立源支持；
- 阶段顺序是软约束，允许跳阶段、并行和 `unknown`；
- 证据节点/边预算和低置信桥接预算；
- 每条输出边可回溯原始记录。

### 4.3 首个解码器

优先顺序：

1. temporal BFS/k-shortest 下界；
2. prize-collecting Steiner/arborescence 或小图整数规划；
3. beam search 近似；
4. 只有简单方法在至少两个场景出现一致瓶颈时，才引入学习式图编码/排序。

图社区或异常邻域不能直接称为攻击链；必须保留方向、时间、跨机桥接和证据充分性。

### 4.4 可选效率层

核心方法通过 H1-H4 后，若 LANL 181GB 规模不达标，可在解码前启用 TeRed 或 SParse 一种：

- 折叠高置信正常区域但保留跨源连接点、异常邻域和时间边界；
- 同时报压缩率、攻击节点/边保留率、跨源连接点保留率和链 F1；
- 不以压缩率替代证据保持。

## 5. 模块 D：校准、拒绝与证据包

首稿从 temperature scaling、isotonic 或 conformal/coverage-risk 中选择一种，校准对齐边和链总分。证据不足、关键源缺失或候选熵过高时，允许输出 `incomplete` 或 `abstain`。

每条 Top-k 链输出：

```json
{
  "chain_id": "...",
  "status": "complete|incomplete|abstain",
  "score": 0.0,
  "score_interval": [0.0, 0.0],
  "predicted_stages": [],
  "events": [],
  "edges": [],
  "source_coverage": {},
  "alignment_uncertainty": {},
  "unresolved_ambiguities": [],
  "score_breakdown": {},
  "raw_record_refs": [],
  "model_rule_data_versions": {}
}
```

证据包不包含测试真值；评估器通过独立 truth mapping 读取真值。

## 6. 复杂模型启用条件

满足以下全部条件后，才讨论异构 TGN/GNN、最优传输或学习式子图生成：

1. E0 数据门通过；
2. oracle、硬匹配和简单概率对齐已公平比较；
3. 简单解码器在至少两个独立攻击族出现相同瓶颈；
4. 新模型有针对该瓶颈的最小新增机制；
5. 参数量、训练资源和推理延迟与等预算基线一并报告；
6. 新模型的贡献能由独立消融证实。

LLM、GAN、完整 CTI 抽取、联邦/隐私和自动持续学习不在首稿启用范围。
