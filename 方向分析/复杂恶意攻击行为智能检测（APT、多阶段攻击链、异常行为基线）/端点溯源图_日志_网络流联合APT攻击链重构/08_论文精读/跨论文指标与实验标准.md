# 跨论文指标与实验标准

- 版本：`Experiment Standard v1.0`
- 证据范围：L01–L71
- 原则：数据质量、检测、对齐、链重构、归因负担和系统性能分别评价；工程跑通不替代科学有效性

## 1. 评测对象与统计单位

| 层 | 评测对象 | 主统计单位 | 不能混用 |
|---|---|---|---|
| 数据层 | 原始事件、字段、传感器 | source-run、host-day | 文件数不能代替有效事件覆盖 |
| 检测层 | event/node/window/alert | 明确标注的预测单位 | 不同粒度的 P/R/F1 不直接横比 |
| 对齐层 | 跨源候选边 | source-pair edge | 候选召回不能代替最终 precision |
| 链层 | 节点、边、步骤、阶段、完整链 | campaign/run | 节点 F1 不能代替 chain F1 |
| 归因层 | 根因、目标、关键连接点 | campaign/run | 压缩比不能代替 QoA |
| 系统层 | event、batch、query、run | 独立重复运行 | 单次平均值不能代替 p95/p99 |

## 2. 数据质量门 EX0

正式训练前必须报告：

| 指标 | 定义 | 退出门 |
|---|---|---:|
| 解析覆盖率 | 成功进入统一事件模型的原生记录比例 | 每源 ≥99%，否则分层说明 |
| 文本/字段缺失率 | 关键字段为空或不可解析比例 | 全量报告，不以均值掩盖 |
| 时钟残差 | 同一强真值动作在不同源的时间偏差 | p50/p95/p99 |
| 重复/乱序率 | 重复 event 和逆序 event 比例 | 每源/每 run |
| 传感器丢失 | 采集器/内核报告的 drop | 0 或显式失败标签 |
| 真值覆盖率 | 真值步骤有至少一个原生事件支持的比例 | 主 strong-truth ≥95% |
| 攻击显眼度 | 简单关键词/规则能区分攻击的程度 | 必做置乱和名称去标识对照 |
| 背景多样性 | 用户、进程、服务、时间、主机活动覆盖 | 按 run 和 split 报告 |
| 基率 | 恶意事件/边/链相对总体比例 | 作为 PR/MCC 解释前提 |

若 EX0 未过，不得用模型高分宣称有效。

## 3. 数据划分与泄漏审计

优先级：

1. leave-campaign-out；
2. leave-technique/variant-out；
3. leave-host/identity-out；
4. 时间外推；
5. 跨数据集/跨平台；
6. 随机划分仅用于调试，不进入论文主表。

强制泄漏检查：

- 攻击文件名、固定 IP、脚本路径、campaign ID、真值时间窗；
- 同一攻击模板/同一镜像复制到 train/test；
- 同一用户/主机/进程 GUID 跨 split；
- 归一化、词表、图模板、负采样使用测试分布；
- 训练期间读取测试标签或在测试集选阈值；
- 由原始事件派生的多个视图被错误计为独立模态。

每个 split 由 manifest 冻结并记录 SHA-256。

## 4. 六层指标

### 4.1 检测层

主指标：

- PR-AUC；
- MCC；
- Recall@固定告警预算；
- FP/host-day；
- time-to-first-detection。

辅助指标：

- event/node/window P/R/F1；
- ROC-AUC 仅作补充；
- confusion matrix 和基率。

### 4.2 对齐层

```text
Precision_edge = TP_edge / (TP_edge + FP_edge)
Recall_edge    = TP_edge / (TP_edge + FN_edge)
F1_edge        = 2PR / (P + R)
```

另报：

- candidate Recall@K；
- MRR；
- unmatched recall；
- wrong-host merge rate；
- wrong-session merge rate；
- ambiguity-set size；
- Brier、NLL、ECE；
- reliability diagram。

### 4.3 链重构层

分别报告：

- node P/R/F1；
- edge P/R/F1；
- key-step P/R/F1；
- stage coverage；
- Chain Recall@K；
- temporal order violation；
- unsupported bridge rate；
- chain fragmentation；
- redundancy ratio；
- normalized GED / WL similarity仅作辅助。

链级主张优先使用 edge F1、key-step coverage 和错误桥接率，不以图相似度单独定论。

### 4.4 归因与分析员负担

- root-cause hit@K；
- impact/target hit@K；
- QoA；
- 关键连接点保留率；
- 需检查节点、边、原始事件数；
- 不可解释边比例；
- 每个 case 的复核时间；
- 相同证据预算下的步骤覆盖。

### 4.5 归约/压缩

必须成对报告：

| 效率指标 | 保真指标 |
|---|---|
| node/edge/event reduction ratio | attack node/edge recall |
| 磁盘/RAM 下降 | 关键连接点保留率 |
| query speedup | 原始/归约查询结果等价 |
| throughput 增益 | 下游检测/对齐/链指标变化 |
| 训练/预处理成本 | forensic validity |

### 4.6 系统与复现

- events/s、flows/s；
- p50/p95/p99 latency；
- peak/steady RAM、VRAM、disk；
- CPU/GPU 利用率；
- backpressure/drop；
- 冷启动、恢复时间；
- 每个阶段训练/推理时间；
- 运行成功率与失败类型；
- 硬件、系统、依赖、代码提交、配置 hash、5 seeds。

## 5. 核心实验矩阵

| ID | 问题 | 数据 | 对照 | 主指标 | 判定 |
|---|---|---|---|---|---|
| EX0 | 数据是否有捷径/真值缺口？ | 所有准入集 | 名称/IP/时间置乱、简单规则 | 质量指标、简单基线 | 未过则停 |
| EX1 | 三源是否互补？ | strong-truth + 可审计公开集 | endpoint/log/flow 单源、双源、三源 | PR-AUC、MCC、Recall@budget、chain edge F1 | 支持 H2 |
| EX2 | 概率对齐是否优于硬连接？ | strong-truth | fixed window、5-tuple、session-only、oracle | edge F1、wrong-host、ECE | 支持 H1 |
| EX3 | 最小子图是否更好？ | strong-truth | BFS、shortest path、Steiner/NODLINK、EAGLE/SPARSE | edge F1、step coverage、冗余、错误桥接 | 支持 H3 |
| EX4 | 收益是否来自数据捷径？ | strong-truth | 辅助源置乱、关键标识掩码 | 主指标下降模式 | 否证 H2 |
| EX5 | 缺源/时钟/NAT 下是否可信退化？ | strong-truth | 无拒绝、固定窗 | risk–coverage、F1 保持率、高置信错链 | 支持 H4 |
| EX6 | 横向移动是否正确？ | 多主机/AD | login-only、flow-only、Hopper/EULER/HADES 简化 | lateral edge F1、wrong-session、FP/host-day | 跨主机主张 |
| EX7 | 能否达到工程 SLO？ | OpTC/LANL/规模集 | 单线程、无裁剪 | throughput、p95/p99、RAM/disk/drop | 工程门 |
| EX8 | ATT&CK 是否只改善解释？ | strong-truth | no prior、hard prior、soft prior | chain F1、unknown recall、TTP accuracy | 限定语义主张 |
| EX9 | 组件是否必要？ | strong-truth | 移除每项损失/约束 | 效应量和 CI | 机制证据 |
| EX10 | mimicry/问题空间攻击是否鲁棒？ | 可执行攻击 | L22/L52 风格系统动作 | 攻击成功、检测/链退化、拒绝 | 鲁棒性边界 |
| EX11 | 归约是否取证有效？ | 通过 H1–H4 后的数据 | SEAL/DEPCOMM/TeRed/无归约 | 效率+保真双指标 | 启用 M9 |
| EX12 | 是否跨 campaign/平台泛化？ | 外部公开数据 | 域内结果 | 相对退化、失败类型 | 外部有效性 |

## 6. 统计协议

1. 主模型和随机基线至少 5 seeds；确定性算法重复运行验证一致性。
2. 以 campaign/run 为 bootstrap 单位，不能以高度相关的单事件虚增样本量。
3. 主结果报告效应量、95% CI 和原始分布；p 值不是唯一结论。
4. 成对比较优先 paired bootstrap 或 permutation test。
5. 多个主假设使用 Holm 校正；探索性分析明确标识。
6. 阈值、候选 K、时间窗、拒绝门限只在验证集冻结。
7. 同一硬件、同一输入可见性、同一告警/证据预算比较基线。
8. 失败运行保留并报告，禁止只汇报成功种子。
9. 若某基线因工件缺失无法复现，报告“不可复现/未运行”，不估算结果。

## 7. 预注册支持门

| 假设 | 最低支持门 |
|---|---|
| H1 对齐 | edge F1 绝对提升 ≥5pp，95% CI 不跨0，且 wrong-host merge 下降 |
| H2 多源互补 | 相对最佳单源 PR-AUC ≥10%，或 Recall@budget 绝对提升 ≥5pp；FP/host-day 增幅 ≤20% |
| H3 最小证据 | edge F1 绝对提升 ≥5pp；或 step coverage 下降 ≤2pp 时冗余 ≥20% 下降 |
| H4 可信退化 | 单源缺失30%或±5s偏移后主指标保持 ≥80%，risk–coverage 优于不拒绝 |
| H5 工程规模 | 吞吐 ≥实测峰值2倍，p95/p99 达到冻结 SLO，关键连接点保留达到门限 |

这些值是项目预注册决策门，不是引用论文中的已发表数字。

## 8. 工程版与论文版的不同验收

| 维度 | 工程版 | 论文版 |
|---|---|---|
| 目标 | 稳定、可恢复、可审计地跑通 | 证明可证伪假设并排除替代解释 |
| 数据 | 允许 fixture 和 smoke data | strong-truth + 外部协议 |
| 基线 | 至少简单下界 | 简单、经典、近期强基线且预算公平 |
| 重复 | 确定性 smoke test | 5 seeds、CI、效应量 |
| 性能 | 达 SLO | 性能不能掩盖科学无效 |
| 失败 | 可定位、可恢复 | 系统性失败边界和负结果 |
| 交付 | CLI、schema、run manifest、报告 | 预注册、主张—证据矩阵、匿名复现包 |
