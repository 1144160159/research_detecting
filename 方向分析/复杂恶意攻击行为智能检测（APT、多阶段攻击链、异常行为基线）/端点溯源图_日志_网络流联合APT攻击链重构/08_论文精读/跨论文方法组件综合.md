# 跨论文方法组件综合

- 版本：`Component Synthesis v1.0`
- 证据范围：L01–L71 全文精读
- 目的：把论文组件分成“主方法、强基线、工程依赖、实验规范、暂缓项”，避免把多个已知模块简单拼接成伪创新

## 1. 从71篇得到的研究缺口

现有研究已经分别解决了 provenance 采集、单源异常检测、攻击调查、TTP 解释、日志压缩和横向移动检测，但仍有一个直接缺口：

> 当端点 provenance、主机/认证/应用日志和网络流异步、缺失、冲突且身份存在 NAT、代理、别名、会话复用时，如何在不把候选关联硬化为事实的前提下，恢复带校准置信和拒绝机制的最小充分 APT 证据链？

该缺口由以下证据链共同支持：

- L26、L33证明应用日志与系统审计能细化单机因果，但没有独立 flow 对齐；
- L64证明认证路径存在因果歧义，并明确提出可用 flow 的时间与流量大小消歧；
- L68证明 logon session 可把跨主机相关关系收紧为因果候选；
- L31、L42、L54、L67证明“缩小图”必须接受取证有效性和关键证据保真；
- L09、L15、L60、L62证明数据捷径、不公平基线和不可复现足以使高分失去科学意义；
- L22、L48、L49、L52证明模型必须面对问题空间逃逸、丢失、重排和传感器受攻击。

## 3. 主方法的最终组件选择

### 3.1 M0：采集健康与真值隔离

输入侧对每个 source 记录：

```text
sensor_id, source_type, capture_start, capture_end, clock_source,
estimated_clock_error, drop_count, reorder_count, parser_coverage,
integrity_status, health_confidence, raw_pointer
```

设计规则：

1. `integrity_status=failed/unknown` 不得被模型自动改写为可信；
2. 传感器健康既是输出解释字段，也是鲁棒性分层变量；
3. `E_truth` 由独立评测接口读取，不进入候选生成、训练或阈值选择；
4. 采集失败与模型拒绝分开报告。

### 3.2 M1：统一不确定跨源时序证据图 UCTEG

UCTEG 不把所有边混成同一种“关系”：

```text
E = E_native ∪ E_session ∪ E_align_candidate ∪ E_lateral_candidate
    ∪ E_ttp_soft ∪ E_prediction ∪ E_truth
```

| 边类 | 含义 | 是否可作为事实 | 最低证据 |
|---|---|---:|---|
| `native_prov` | 端点采集器直接形成的信息流/操作边 | 条件性可以 | 采集健康通过、raw pointer 可回溯 |
| `same_session` | 同一登录/进程/请求会话内关系 | 条件性可以 | 稳定 session ID 或可验证映射 |
| `align_candidate` | 两源事件可能对应同一动作 | 否 | 时间+身份/对象/上下文之一 |
| `lateral_candidate` | 可能的跨主机移动 | 否 | 认证/登录候选与网络连接共同支持 |
| `ttp_soft` | ATT&CK 兼容或阶段偏好 | 否 | 规则或识别模型及其版本 |
| `prediction` | 方法选择的边 | 否 | 分数、校准、支持/冲突证据 |
| `truth` | 独立人工/编排真值 | 仅评测 | 双人复核或强真值 manifest |

### 3.3 M2：分层候选生成

候选生成采用由便宜到昂贵的级联：

1. 时间不可能性过滤；
2. host/user/session/PID/PPID/process GUID 候选解析；
3. 正反向五元组、连接区间、bytes/packets；
4. DNS/SNI/域名/证书/代理/NAT 上下文；
5. 一至两跳 provenance 祖先/后继；
6. 同一认证或应用请求会话；
7. 传感器健康与缺失模式。

候选层的第一目标是 `Recall@K`，不是最终 precision。任何后续模型无法恢复在本层被裁掉的真值边。

### 3.4 M3：可校准跨源边评分

首个论文版本选择可解释的 pairwise scorer：

```text
z_ij = w^T φ_ij + b
p_ij = Calibrate(sigmoid(z_ij))
```

候选特征 `φ_ij` 分为：

- 时间：区间重叠、时间差、时钟不确定区间；
- 身份：host/user/session/process/agent 的一致与冲突；
- 网络：方向归一化五元组、连接区间、流量大小；
- 对象：路径、命令、域名、IP、端口和协议；
- 上下文：端点一跳/两跳行为、前后日志序列；
- 质量：来源可靠度、字段缺失、NAT/代理标记；
- 冲突：同一事件竞争候选数、身份或时间矛盾。

输出必须包括 `top_k`、`margin`、`ambiguity_set`、`support`、`conflict`、`calibration_version`。逻辑回归/GBDT 只有在否证性 pilot 失败后才升级为图/序列编码器。

### 3.5 M4：跨主机横向移动候选

吸收 Hopper 与 HADES 的共同结论，定义：

```text
P(lateral | auth_session, src_host, dst_host, network_flow,
                   credential_switch, access_novelty, sensor_health)
```

硬规则：

1. 仅网络连接不能形成横向移动事实；
2. 仅成功登录也不能确定真正的发起主体；
3. 优先使用 logon GUID/session ID 连接访问主机和被访问主机；
4. 缺少会话 ID 时保留多个竞争路径；
5. flow 用于验证方向、时间和流量活动，不把 NAT 后 IP 等同主机身份。

### 3.6 M5：最小充分证据子图解码

给定种子集合 `A` 和候选图 `G`，输出 Top-k 子图：

```text
S* = argmax_S [
      α SeedCoverage(S)
    + β NativeEvidence(S)
    + γ CrossSourceSupport(S)
    + η KeyStepCoverage(S)
    + κ SessionContinuity(S)
    - λ AlignmentRisk(S)
    - μ UnsupportedBridge(S)
    - ν TemporalViolation(S)
    - ρ Redundancy(S)
]
```

最低约束：

- 至少连接一个入口/根因、一个告警/POI 和一个影响/目标；
- 每个跨源桥必须有可定位证据；
- 时间顺序允许区间重叠、并发、循环/重试和 unknown；
- 不强制完整 ATT&CK 顺序；
- 证据不足时输出多个竞争子图或 `incomplete`；
- 每个被裁边保留裁剪原因。

实现顺序：

1. BFS/最短路/固定窗硬连接下界；
2. prize-collecting Steiner/NODLINK 类强基线；
3. 本项目受约束 beam search；
4. 小图整数规划 oracle；
5. 只有前四者无法支持 H3 时再研究学习式解码。

### 3.7 M6：校准与拒绝

分别校准“边”和“链”，不得把任意打分称为概率：

- 边：Brier、NLL、ECE、reliability；
- 链：风险—覆盖率、错误桥接风险、链完整性置信；
- 拒绝：`no_candidate`、`ambiguous_identity`、`clock_uncertain`、`sensor_unhealthy`、`insufficient_cross_source_support`；
- 阈值：仅用验证集冻结，测试集不得调参。

### 3.8 M7：解释与证据包

每条预测链交付：

- 原始事件指针和 hash；
- 原生、候选、预测边分类；
- 对齐特征分解、置信、校准版本；
- 支持与冲突证据；
- 关键攻击步骤及可选 ATT&CK 标签；
- 被拒绝路径和原因；
- 图规模、运行 ID、配置、代码提交；
- 分析员最小复核清单。

## 4. 强基线的最终清单

| 任务 | 必跑基线 | 论文来源 | 公平性设置 |
|---|---|---|---|
| 单源追踪 | BackTracker/BFS、SLEUTH 类传播 | L01、L03 | 同一 native graph、同一 POI |
| 依赖精化 | MCI、MPI/分区式简化 | L34、L39、L59 | 同一事件可见性 |
| 节点检测 | 简单频率/稀有度、THREATRACE、KAIROS/FLASH 代表项 | L04、L12–L13、L25、L60 | 统一 split、预算和输入字段 |
| 攻击场景 | HOLMES、NODLINK、EAGLE、SPARSE | L05、L10、L66、L69 | 统一种子和链真值 |
| 横向移动 | 固定窗+登录、Hopper、EULER、HADES 简化 | L64–L65、L68 | 统一认证/flow 可见性 |
| 图归约 | 不归约、SEAL/保因果、DEPCOMM、TeRed | L28–L29、L31、L67 | 归约后重跑所有链指标 |
| TTP 解释 | 无先验、HOLMES 规则、TREC/ZOOMER 代表项 | L05、L17、L70 | 不允许 TTP 标签进入链真值 |

## 5. 暂缓和淘汰

| 项目 | 决策 | 重新启用条件 |
|---|---|---|
| 端到端大 GNN 解码 | 暂缓 | 可解释模型 H1/H3 失败且存在足够独立训练链 |
| LLM 自动生成攻击链 | 淘汰首稿 | 只能用于解释文本，且不得生成无原始证据边 |
| ATT&CK 硬状态机 | 淘汰 | 不设重新启用；始终保留 unknown、跳跃和并发 |
| 未经审计的合成数据主实验 | 淘汰 | 不设重新启用；只作受控压力/失败边界 |
| 只报告 ROC-AUC/accuracy | 淘汰 | 不设重新启用 |
| 只按时间窗口硬连接三源 | 保留为下界 | 仅作为 H1 对照 |
| 在 H1–H4 前做复杂压缩 | 暂缓 | 科学有效性门通过且出现真实性能瓶颈 |

## 6. 可证伪创新点

1. **不确定跨源对齐**：在候选生成、边评分、子图解码和最终输出全流程保留歧义，并证明比固定窗/硬五元组在强真值上减少错误合并。
2. **最小充分证据链**：在关键步骤覆盖几乎不下降的条件下，显著减少冗余和无支持桥接，并保持原始证据可回溯。
3. **可信退化与拒绝**：面对缺源、时钟偏移、NAT/别名冲突和传感器不健康，降低覆盖而不是维持虚假高置信完整链。

任何一个创新点若未达到预注册门，应降级为工程组件或从论文主张中删除。
