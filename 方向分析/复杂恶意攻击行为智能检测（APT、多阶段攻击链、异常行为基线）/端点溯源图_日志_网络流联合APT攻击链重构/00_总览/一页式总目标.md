# 一页式总目标

## 1. 一句话目标

构建一种面向端点溯源、日志和网络流失配/缺失条件的**不确定性感知最小 APT 证据链重构方法**：显式保留跨源实体—时间映射的候选与置信度，恢复最小充分、阶段一致、可拒绝且可回溯原始记录的攻击子图。

## 2. 要解决的核心问题

多源遥测并非越多越可信：

- 端点溯源提供进程、文件、套接字和信息流骨架，但跨主机身份与网络意图不足；
- 认证/系统/安全日志提供账号、会话、命令和策略语义，但字段、模板、时区和延迟不一致；
- 网络流提供跨主机通信与时序，但难以唯一归属到具体进程、账号和文件；
- 时间邻近、NAT/代理、PID/端口复用、共享账号和传感器缺失会产生伪跨源边。

因此本文不把“多模态融合”本身当作创新，而研究如何识别可信跨源联系，并让不确定性影响整条攻击链的评分与拒绝决策。

## 3. 四个核心科学问题

1. **跨源对齐**：如何在时钟漂移、一对多实体候选和传感器可靠度不同的条件下，输出可校准的跨源边概率而非硬连接？
2. **多源互补**：端点、日志和流量是否真实互补，还是结果由单源、身份字段或攻击脚本捷径主导？
3. **最小充分重构**：如何联合对齐置信、时间/会话/信息流一致和软 ATT&CK 阶段顺序，恢复高覆盖、低冗余的有向证据子图？
4. **可信退化**：缺源、延迟、冲突和噪声下，如何平滑退化并在证据不足时拒绝输出高置信完整链？

规模化是后续系统目标，不与上述四个科学问题并列堆成首稿创新。

## 4. 核心方案

`统一事件与原始指针 -> 时间区间/实体候选 -> 不确定跨源时序证据图 -> 插件式异常种子 -> 最小充分证据子图 -> ATT&CK软顺序与unknown -> 校准/拒绝 -> Top-k可审计链`

首稿只有四个必要组件：

1. 可审计统一事件模式；
2. 概率式实体—时间对齐器；
3. 受约束最小证据链解码器；
4. 强真值—弱标签双协议与失配压力测试。

日志/流量/端点模型只提供异常种子；TeRed、EULER、KRYSTAL、EAGLE、CCLog 分别作为效率层或基线。

## 5. 三个预期贡献

1. 将跨源匹配的不确定性从预处理层传递到链级推断和最终置信度；
2. 提出带未知松弛的最小充分攻击证据子图目标，显式平衡证据覆盖、阶段顺序和分析负担；
3. 建立自建强真值、LANL 弱标签和 181GB 规模化的分层协议，系统测量缺源、时钟偏移、实体冲突和噪声的失败边界。

## 6. 数据与实验总线

- **自建强真值**：6-8 个攻击族、每族至少 3 次，共 18-24 次；用于对齐边、攻击节点/边、阶段和整链评价；
- **LANL 11GB**：auth/DNS/flow/proc 模态消融、redteam 锚点排序和 `FP/host-day`；未标注事件不直接当良性；
- **LANL 181GB**：吞吐、内存、存储和候选缩减；
- **CICAPT-IIoT2024/DIDS-MFL**：只做 flow 外部验证；
- **DARPA/现有小样例**：转换器和 provenance 基线 smoke test，不自动视为独立三源真值。

## 7. 成功判据

- 概率对齐相对最佳硬连接，对齐边 F1 绝对提高至少 5 个百分点；
- 三源相对最佳单源 PR-AUC 相对提高至少 10%，或 Recall@固定预算绝对提高至少 5 个百分点，且误报增幅不超过 20%；
- 强真值链边 F1 至少 0.70、阶段覆盖至少 0.80；相对最佳重构基线 edge F1 +5pp，或冗余减少至少 20%；
- 丢失 30% 单一模态事件或加入 ±5 秒偏移后性能保持至少 80%；
- 输出每个节点/边的原始事件 ID、来源、时间、对齐概率和评分分解；证据不足时能够拒绝。

## 8. 停止条件

若两周 pilot 在中等失配条件下相对硬连接链 F1 提升不足约 8 个百分点，或干净数据下降超过 5 个百分点，则不增加 GNN/LLM/GAN，转向 ChainBreak 失败边界基准。若方法有效但规模不足，再独立研究跨源连接点保真的图压缩。

## 9. 当前状态

已完成 858 篇语料的组件级扫描、53 篇代表论文人工收敛、研究问题/创新/实验设计和 GPU 数据资产审计。尚未完成强真值 pilot 与正式算法比较，所有性能阈值均为待检验假设，不是结果。
