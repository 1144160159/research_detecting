# 工程版—论文版里程碑门禁

- 版本：`Gate v1.1-deep-read`
- 日期：2026-07-29
- 原则：**工程 v1.0 是论文版本启动的必要条件，但不是论文结论成立的充分条件。**

## 1. 版本状态机

```text
R0/71篇精读 → E0 → E1 → E2 → E3 → E4 → E5 → E6/Engineering v1.0
                                      ↓
                       P0 → P1 → P2 → P3 → P4 → P5 → P6/Submission
```

每个版本只有 `not-started / in-progress / failed / accepted` 四种状态。以下情况一律不得标记 `accepted`：

- 命令超时、OOM、环境缺失或状态未知；
- 只运行了部分数据/部分测试；
- 依赖人工观察但无记录；
- 使用测试集选择阈值或组件；
- 复现实验与主实验使用不同真值或预算；
- 关键失败被排除后未在报告中披露。

`R0` 已完成的最低证据为：71/71 PDF 可读、逐篇问题/方法/实验/边界/页码证据、跨论文组件综合、指标标准和蓝图修订说明。R0 不是工程或论文性能门，但没有 R0 不得使用“经71篇精读形成”的表述。

## 2. 工程版本门禁

| 版本 | 目的 | 必须交付 | 自动化验收 | 人工验收 | 失败后动作 |
|---|---|---|---|---|---|
| E0/v0.1 | 控制面和存储边界 | 路径配置、目录契约、manifest schema、本地策略、run ID 规则 | 本地禁存扫描；配置解析；凭据扫描 | 远端角色、权限和事实源复核 | 修复控制面，不进入数据开发 |
| E1/v0.2 | 数据适配和真值隔离 | 3+ adapters、统一事件、truth reader、质量报告 | schema/property tests、坏行测试、truth-leak tests | 随机抽样回溯原始记录 | 修适配器或收缩数据角色 |
| E2/v0.3 | 可解释下界 | oracle、固定窗、五元组/session、BFS、最短路、Steiner-like | 确定性、人工小图 golden tests、统一 evaluator | 人工复核 3 个小图 | 基线未可信前不开发主模型 |
| E3/v0.5 | 多源 MVP | 候选器、概率/评分器、Top-k、拒绝、UCTEG builder | 候选召回、边类型隔离、序列化回读、no-truth-access | 3 个多源场景证据向量复核 | 回退到规则/逻辑回归，定位错配 |
| E4/v0.8 | 攻击链闭环 | 最小子图、ATT&CK 软先验、证据包、CLI/流水线 | end-to-end fixture、恢复测试、幂等、原始定位符完整 | 分析员可复核链及拒绝原因 | 修闭环，不进入性能优化 |
| E5/v0.9 | 性能和可运维 | 流式/分片、监控、缓存、故障注入、SLO 报告 | 负载、长稳、内存、恢复、关键证据保留 | 资源曲线和异常点解释 | 只优化瓶颈，不改科学主张 |
| E6/v1.0 | 工程发布候选 | 锁定环境、版本、配置、全量回归、运维手册、验收报告 | 新环境复现；全量测试；输入/输出哈希闭环 | 签署 Engineering Acceptance Report | 保持论文 P0 未启动 |

### 2.1 工程验收的最低横向要求

所有 E0—E6 都必须满足：

1. 输入、输出和错误契约有版本号；
2. 运行记录包含 Git commit、配置哈希、数据 manifest、环境和随机种子；
3. 预测层不能覆盖事实层；
4. 原始数据、模型、checkpoint、大结果和日志不回流本地；
5. 同一输入和冻结配置能确定性重跑非学习模块；
6. 每次失败保留状态和错误，不把缺失记录成零或通过。

## 3. 论文版本门禁

| 版本 | 目的 | 工程 v1.0 之外新增要求 | 通过证据 | 不通过时 |
|---|---|---|---|---|
| P0/v0.1 | 可行性与复现审计 | 背景多样性、攻击显眼度、标签粒度、基率、强真值覆盖；端到端脚本、数据/标签/模型/环境可用性 | Data & Reproducibility Feasibility Report | 转 ChainBreak、归约或双源 |
| P1/v0.2 | 协议冻结 | SQ/H、威胁模型、split、主/次指标、阈值、预算、停止条件预注册 | protocol hash、split hash、leakage audit | 修协议后重新冻结 |
| P2/v0.3 | 强基线复现 | 同数据、真值、告警预算、硬件和调参预算 | baseline reproduction table | 解释复现偏差或删除基线 |
| P3/v0.5 | 否证性 pilot | H1/H3、关键消融、校准/拒绝、错误案例 | Go/No-Go Report | 不加大模型；按停止条件转向 |
| P4/v0.8 | 完整假设验证 | H1—H4、全消融、缺源/偏移/噪声、捷径检查 | CI、效应量、Holm 校正、failure curves | 收缩或删除不成立主张 |
| P5/v0.9 | 外部有效性 | 未见攻击族、跨数据/跨主机、规模、QoA、分析员负担 | external validity report | 限定适用域，不外推 |
| P6/v1.0 | 投稿冻结 | 主张—证据、引用、图表、匿名复现、局限性 | Submission Acceptance Checklist | 未通过不得投稿 |

## 4. 单向晋级映射

| 工程先决条件 | 论文用途 | 论文新增审查 | 通过前允许表述 |
|---|---|---|---|
| E0 控制面 | P0 数据可行性 | 数据真实性和代表性 | “路径和数据角色可审计” |
| E1 schema/适配器 | P1 任务定义 | 真值粒度、无泄漏 split | “三源事件可统一表达” |
| E2 下界基线 | P2 强基线 | 公平预算与复现偏差 | “基线实现可运行” |
| E3 多源 MVP | P3 pilot | H1/H3、校准、消融 | “可生成候选证据链” |
| E4 端到端闭环 | P4 完整验证 | H1—H4 和失败分析 | “端到端流程可复现” |
| E5 性能 | P5 规模/外部 | QoA、泛化、系统成本 | “达到冻结工程 SLO” |
| E6 工程 v1.0 | P6 复现基础 | 主张—证据与匿名复现 | “工程版本已验收” |

工程门通过前后都不能自动出现“优于 SOTA”“首次”“完整恢复”“开放世界泛化”“实时部署”。

## 6. 论文阶段回写工程的规则

论文实验若发现新需求，不直接修改已冻结工程结果：

1. 建立 engineering change request；
2. 工程版本升为 `v1.1+`；
3. 补单元、集成和回归测试；
4. 重新生成受影响的运行；
5. 在论文记录中披露版本变化和重跑范围。
