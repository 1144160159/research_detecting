# 研究设计总纲

- 版本：`v0.2-research-design`
- 日期：2026-07-15
- 状态：方案冻结候选；首个正式实验前仍允许按两周否证性 pilot 收缩，不允许先堆模型再改问题

## 1. 研究决策

本论文不把“端点、日志、网络流做多模态融合”本身当作创新。多源遥测一方面补足攻击阶段和跨主机证据，另一方面也会因时钟偏移、实体别名、NAT/代理、日志缺失和不同采样粒度产生更多伪关联。真正要解决的问题是：

> 在端点溯源、主机/认证日志和网络流异步、缺失且实体标识不一致时，如何区分真实的跨源证据联系与仅由时间邻近造成的伪联系，并将对齐不确定性传递到攻击链级推断，输出最小充分、可拒绝、可回溯的攻击证据子图？

首稿只保留一条主线：

`可审计统一事件 -> 概率式实体/时间对齐 -> 不确定跨源时序证据图 -> 受约束最小充分证据子图 -> 校准置信与拒绝输出 -> 链级鲁棒性评价`

异常检测器、日志编码器、流量编码器和横向移动检测器均作为可替换的异常种子提供器；TeRed、KRYSTAL、EULER、EAGLE、CCLog 类方法进入基线或可选效率层，不与主方法捆绑。

## 2. 总目标

构建面向跨主机 APT 调查的**不确定性感知最小证据链重构方法**：把端点溯源事件、认证/系统/安全日志和网络流统一为带来源、时间区间、候选实体映射及置信度的跨源时序证据图；在时钟失配、实体歧义和传感器缺失条件下，恢复阶段一致、证据紧凑且可回溯原始记录的攻击子图，并在无法形成充分证据时主动降低置信或拒绝输出完整链。

总目标由三个层级组成：

1. **方法目标**：对齐不确定性不能在预处理后丢失，而要进入跨源边代价、链评分与最终置信度。
2. **科学目标**：验证多源互补性是否真实存在，以及最小证据约束能否同时减少伪边和分析负担而不显著损失阶段覆盖。
3. **实证目标**：以自建强真值靶场验证边/链恢复，以 LANL 多源数据验证弱标签排序和长时间误报，以 LANL 181GB 数据验证规模；CICAPT-IIoT2024、DIDS-MFL 只验证网络流分支，不支撑完整攻击链结论。

## 3. 研究对象与输出

输入是在观测窗内来自三类遥测的事件集合：

- `E_p`：进程、文件、套接字、注册表/权限等端点溯源事件；
- `E_l`：认证、系统、安全、PowerShell/Shell、EDR/IDS 告警等日志；
- `E_f`：带开始/结束时间、五元组、方向、包/字节统计和可见协议元数据的网络流。

每个统一事件至少包含：

```text
event_id, source_id, source_type, host, subject, action, object,
time_start, time_end, time_uncertainty, raw_pointer, sensor_health
```

跨源对齐器输出候选边而非唯一硬连接：

```text
src_event, dst_event, relation_type, match_probability,
identity_evidence, temporal_evidence, behavior_evidence, ambiguity_set
```

最终输出为 Top-k 有向证据子图，每个子图必须包含：

- 事件、实体、跨主机桥接边及粗粒度 ATT&CK 阶段分布；
- 每条边的来源、对齐概率、时间偏差和支持/冲突证据；
- 总评分分解、证据规模、未决歧义和置信区间；
- 原始记录指针；证据不足时的 `abstain/incomplete` 状态。

本文使用“操作性因果/信息流依赖”描述溯源关系，不宣称识别严格结构因果模型。

## 4. 科学问题与可证伪假设

### SQ1：异步且有歧义的跨源对齐

在时钟漂移、一对多候选和标识别名同时存在时，带时间区间、实体候选和可靠度的概率式对齐，能否比固定时间窗、五元组硬匹配或简单图拼接更准确地恢复真实跨源边？

- **H1**：相对最佳固定窗口/五元组基线，强真值数据上的对齐边 F1 绝对提高至少 5 个百分点，并降低错误跨主机关联率；95% bootstrap CI 不跨 0。
- **反证**：干净数据上明显优于 oracle/精确连接，或只在随机切分有效，说明收益可能来自模型容量或数据捷径而非不确定对齐。

### SQ2：多源互补还是单源捷径

端点、日志和流量是否提供可重复的互补证据，还是性能由某一模态、主机/IP 标识或攻击脚本痕迹主导？

- **H2**：三源方案相对最佳单源方案，在 LANL 上 PR-AUC 相对提高至少 10%，或 `Recall@固定告警预算` 绝对提高至少 5 个百分点，同时 `FP/host-day` 增幅不超过 20%。
- **反证**：去掉任一辅助源不影响链级结果，或打乱辅助源后结果不降，则不能声称多源互补有效。

### SQ3：最小充分证据链

将对齐置信、时间单调、会话/进程依赖和软 ATT&CK 阶段顺序联合为最小证据子图目标，能否比 BFS、k-shortest path、KRYSTAL backward-forward、EAGLE 异常子树和 CCLog 式近似 Steiner 更完整且更紧凑地恢复攻击链？

- **H3**：在强真值数据上，相对最佳重构基线链边 F1 绝对提高至少 5 个百分点，或在阶段覆盖下降不超过 2 个百分点时将冗余节点/边减少至少 20%。
- **反证**：删除最小证据项、对齐代价或阶段软约束后链级结果不变，则相应组件不得列为贡献。

### SQ4：缺源、失配和冲突下的可信退化

当端点、日志或流量部分缺失，时钟产生偏移或实体映射冲突时，方法能否比硬连接更平滑地退化，并在证据不足时拒绝输出过度自信的完整链？

- **H4**：随机或连续丢失 30% 单一模态事件、加入 `±5 s` 时钟偏移后，链 F1 与检测 PR-AUC 保持完整数据结果的至少 80%；风险—覆盖曲线优于无校准方法。
- **反证**：关键源缺失后仍维持几乎不变的高置信完整链，优先检查标签泄漏或错误补全，而不是将其解释为鲁棒。

### SQ5：规模化是否破坏证据

该问题是系统目标而非首要方法创新：候选裁剪或 TeRed 式归约能否在 181GB 数据规模下降低内存和延迟，同时保持跨源连接点与攻击可达性？只有核心方法通过 H1-H4 后才启用该效率层。

## 5. 核心方法

### 5.1 不确定跨源时序证据图 UCTEG

图节点表示事件与实体，原生边表示端点信息流、认证/会话和真实网络观测；候选跨源边表示 `flow↔socket/process`、`auth↔session/process`、`alert↔event` 等映射。边概率由三类可审计证据组合：

- 身份一致性：主机、账号/session、PID/GUID、五元组、进程镜像和别名表；
- 时间一致性：事件时间区间、采集延迟、时钟残差和持续时间重叠；
- 行为一致性：动作类型、父子进程、连接方向、上下文邻域和传感器健康。

对齐模块必须保留候选集合和歧义度，不把低置信映射提前固化为事实。

### 5.2 最小充分证据子图解码

以异常种子、红队锚点或人工 POI 为终端候选，在 UCTEG 上求解带奖赏与代价的有向子图。概念目标为：

```text
maximize  seed_coverage + source_support + stage_compatibility
          - alignment_uncertainty - temporal_violation
          - unsupported_bridge - evidence_redundancy
```

约束包括时间单调、实体/会话连续、端点信息流可达、跨主机连接一致和证据预算。首个实现优先使用可解释的 prize-collecting Steiner/arborescence、beam search 或整数规划小图版本；只有简单解码器失败后才引入学习式图编码器。

### 5.3 ATT&CK 软先验与未知松弛

ATT&CK 只提供阶段兼容和语义标注，不作为硬模板。允许跳阶段、并行分支和 `unknown` 状态，防止已知阶段模板压制未见攻击。必须设置“无阶段约束”消融，证明它是否真正贡献链顺序而非仅美化标签。

### 5.4 校准与拒绝

先采用温度缩放、isotonic 或 conformal/coverage-risk 中的一种简洁方案。输出低置信候选链和拒绝状态，不在首稿同时叠加 Bayesian ensemble、EDL 与 Dempster-Shafer。

## 6. 预期创新点

### 创新 1：对齐不确定性贯穿攻击链推断

现有多源方法常在预处理阶段硬连接后再检测。本文将实体/时间匹配表示为候选分布，并把匹配概率、时钟残差和传感器可靠度直接纳入链边代价与最终置信度。创新不在“融合三类数据”，而在**不把不可靠连接伪装成事实**。

### 创新 2：带未知松弛的最小充分攻击证据子图

把攻击链恢复从“异常节点周围展示邻域”改写为覆盖必要种子、满足操作性依赖和软阶段顺序、同时惩罚冗余与无支持桥接边的子图优化。输出不是越完整越好，而是在证据充分性、阶段覆盖和分析负担之间显式权衡。

### 创新 3：强真值—弱标签双协议与失配失败边界

以自建多传感器靶场评价真实对齐边和攻击链，以 LANL 评价长时间弱标签排序与误报，以受控时钟偏移、模态丢失、别名冲突、NAT 歧义和良性边注入刻画失效曲线。该协议把“对齐、检测、重构”三层误差分开，避免只用节点分类指标替代攻击链证据。

## 7. 数据与结论边界

### 强真值主协议

- 6-8 个攻击场景族，每个至少 3 次独立运行，总计 18-24 次；
- Windows 与 Linux，至少两个完整攻击族只用于测试；
- 覆盖 initial access、execution、credential access、discovery、lateral movement、C2/exfiltration 中至少五个阶段；
- 同步采集 Sysmon/Security/PowerShell、auditd/eBPF、Zeek/Suricata/DNS/NetFlow/PCAP 和攻击编排器日志；
- 每一步记录 `attack_id, step_id, technique, start/end UTC, hosts, account/session, PID/GUID, parent, file, five-tuple, predecessor/successor, sensor_health, clock_offset`；
- 两名标注者独立复核关键边，目标 `κ>=0.8`。

### LANL 协议

- 11GB `Cyber1 comprehensive` 用于 auth/DNS/flow/proc 的模态消融、红队锚点排序和长时间误报；
- 未标注事件视为未知，不直接当作良性，采用 positive-unlabeled 或 anchor-ranking 评价；
- 181GB unified 数据只用于扩展性和资源曲线；
- LANL 不提供完整 `process→file→socket→remote process` 因果链真值，不能单独支撑“完整攻击链重构”结论。

### 外部流量协议

CICAPT-IIoT2024 与 DIDS-MFL 仅验证 flow seed/encoder 或跨域检测，不与不相干的端点日志拼接为三源数据。

## 8. 成功门与停止条件

### 数据门

- 关键字段解析率 `>=99%`；
- 强真值跨源对齐边 F1 `>=0.90`；
- p95 校时残差 `<=1 s`，否则逐事件记录更宽时间不确定区间；
- 歧义关联边比例 `<=5%`，或保留歧义集合进入推断。

### 方法门

- 自建强真值：链边 F1 `>=0.70`、阶段覆盖 `>=0.80`、因果/时间逆序率 `<=2%`；
- 缺失 30% 单源或 `±5 s` 偏移后性能保持 `>=80%`；
- 吞吐至少为目标峰值输入的 2 倍，在线模式 p95 重构延迟 `<=60 s`；
- 所有提升必须在 campaign/time/host-disjoint 协议下成立，并按攻击运行 bootstrap 95% CI。

### 明确停止或转向条件

出现任一情况时停止增加模型组件：

1. 三源不优于最佳单源，或收益由 IP、主机名、攻击文件名等捷径解释；
2. 两周 pilot 中等扰动下相对硬连接链 F1 提升不足约 8 个百分点，或干净数据下降超过 5 个百分点；
3. LANL 排序有效但强真值链边 F1 `<0.60`；
4. 去掉对齐概率、最小证据项或阶段约束后结果基本不变；
5. 收益只存在于已见脚本，留一攻击族测试无提升。

若主方法失败，优先转为 **ChainBreak：多源攻击链在缺源、时钟偏移和实体冲突下的失败边界基准**；若方法有效但规模不达标，再独立研究“跨源连接点保真的溯源图压缩”。
