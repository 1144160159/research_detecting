## 0. 已锁定决策

1. 研究对象：端点 provenance 图、主机/应用/认证日志和网络流联合的 APT 多阶段攻击链重构。
2. 工作题目：**面向不确定跨源对齐的最小充分 APT 攻击证据链重构**。
3. 中心矛盾：异步、缺失和歧义的跨源观测会产生多条候选关联；现有方法常把候选边硬化为事实边，使局部错配传播为整条错误攻击链。
4. 主方法：不确定跨源时序证据图 UCTEG + 最小充分证据子图解码 + ATT&CK 软先验 + 校准拒绝。
5. 本地只保存基本代码、测试、配置模板、论文和规划文档；不保存原始数据、模型参数、训练结果和大日志。
6. 原始数据、模型参数、运行结果和大日志只保存在 GPU 服务器项目目录。
7. 工程路线是必要条件，论文路线是更严格的充分性审查；**工程通过不自动等于论文通过**。
8. 目标期刊以 IEEE TIFS/TDSC 为主；若系统完整性、实时性和真实部署证据足够，可评估 USENIX Security/NDSS/IEEE S&P；RAID/ACSAC 为会议备选。正式投稿目标在论文路线 P4 后冻结。
9. 文献证据采用 2026 年第七版 CCF 目录口径：核心主张和强基线优先使用 IEEE TIFS/TDSC 与四大安全顶会（IEEE S&P、USENIX Security、ACM CCS、NDSS）；其他 CCF A 只在组件直接相关时纳入；CCF B 仅用于不可替代的组件、数据集或指标标准；CCF C/非 CCF 论文不得单独支撑核心创新主张。

## 1. 正式蓝图拟回答的问题

### 1.1 总目标

在多源日志异步、缺失、身份歧义和部分冲突条件下，输出：

1. 带置信度的跨源候选关联；
2. 可追溯到原始事件的攻击链节点与边；
3. 覆盖关键攻击步骤、同时尽量小的证据子图；
4. 对证据不足的链边明确拒绝或保留多假设；
5. 能在目标负载下稳定运行、可复现、可审计的工程系统。

### 1.2 工程目标

- 支持至少三类数据源的统一解析；
- 数据真值与预测结果物理分离；
- 能从数据适配到报告生成端到端运行；
- 每个阶段都有输入/输出契约、错误记录和可观测指标；
- 在 GPU 服务器上可重复执行，且本地没有原始数据和模型泄漏；
- 具备基线、单元测试、集成测试、性能测试和故障恢复能力。

### 1.3 科学问题

- SQ1：异步、有歧义的端点—日志—网络流如何对齐，并把对齐不确定性传给下游？
- SQ2：三源融合是否提供单源无法提供的互补证据，还是仅利用了数据集捷径？
- SQ3：如何在攻击步骤覆盖、因果连通和证据置信约束下得到最小充分证据子图？
- SQ4：缺源、时钟偏移、NAT、别名和冲突下能否平滑退化并在证据不足时拒绝？
- SQ5：候选裁剪和图归约能否在规模化时保持攻击可达性与跨源连接点？

### 1.4 可证伪假设

- H1：相对最佳固定窗口/五元组硬连接，对齐边 F1 绝对提高至少 5 个百分点，且 95% bootstrap CI 不跨 0，并降低错误跨主机关联率。
- H2：三源方案相对最佳单源，PR-AUC 相对提高至少 10%，或 `Recall@固定告警预算` 绝对提高至少 5 个百分点，同时 `FP/host-day` 增幅不超过 20%。
- H3：相对最佳重构基线，链边 F1 绝对提高至少 5 个百分点；或在阶段覆盖下降不超过 2 个百分点时，冗余节点/边减少至少 20%。
- H4：随机或连续丢失 30% 单一模态事件、加入 `±5 s` 时钟偏移后，链 F1 和检测 PR-AUC 保持完整数据结果的至少 80%，且风险—覆盖曲线优于无校准方法。
- H5：系统吞吐达到实测峰值输入的至少 2 倍，端到端 p95 不超过冻结 SLO，并保持关键证据召回门槛。H5 是系统目标，只有 H1—H4 通过后才用于论文主张。

## 2. 问题定义与边界

正式蓝图将固定以下内容：

1. 事件、实体、真实 provenance 边、跨源候选边、攻击步骤、阶段和攻击链的数学定义；
2. 主机、用户、进程、文件、socket、流、认证会话的统一 ID 规则；
3. 时间轴和时钟偏移模型；
4. 候选边概率及其特征；
5. 预测图、真值图和解释图的分层；
6. 攻击者能力、可信计算基、日志缺失和日志篡改边界；
7. 不解决的范围：自动响应、恶意代码语义还原、纯网络全流量检测、以 LLM 生成攻击链替代可验证推断。

## 3. 方法蓝图

### 3.1 数据适配层

- DARPA TC（CADETS/THEIA/TRACE 等）；
- OpTC；
- Windows/Linux 审计与 Sysmon/auditd 风格事件；
- 认证、进程、文件、DNS、代理、应用日志；
- NetFlow/Zeek/PCAP 派生流记录；
- LANL 类主机—认证—网络关联数据；
- 自建强真值靶场。

每个适配器必须输出统一 schema、解析覆盖报告、字段缺失报告和原始事件定位符。

### 3.2 候选生成与概率式对齐

对每对可对齐事件计算候选特征：

- 时间残差与事件类型相关窗口；
- host/IP/hostname/agent ID；
- user/session/logon ID；
- pid/ppid/process image/command line；
- 五元组、方向、连接开始/结束时间；
- bytes/packets；
- DNS/域名/证书/SNI；
- 前后文因果邻域；
- 数据源可靠性和缺失模式。

输出 Top-k 候选边、边概率、证据向量和拒绝原因，不输出无条件硬连接。

### 3.3 UCTEG

UCTEG 中至少区分：

- 可信 provenance 因果边；
- 同源时序/身份边；
- 跨源候选对齐边；
- 网络横移候选边；
- ATT&CK/TTP 软语义边；
- 预测攻击链边；
- 真值边。

不同边类型采用不同权重、传播规则和可见性，禁止预测边回写为原始事实。

### 3.4 最小充分证据子图

目标函数同时约束：

- 覆盖告警、关键攻击节点和阶段；
- 保持时间与因果可行性；
- 惩罚低置信跨源边；
- 惩罚冗余节点和边；
- 允许未知步骤和阶段跳跃；
- 在证据不足时输出多假设或拒绝。

基线依次为时间 BFS、最短路、BackTracker、Steiner Tree/NODLINK、规则阶段图和强学习检测器后处理。

### 3.5 校准、拒绝和解释

- 温度缩放/等距回归等校准；
- Brier、NLL、ECE；
- risk–coverage；
- 低置信边拒绝；
- 每条链边回溯到原始事件 ID、候选特征、模型/规则版本；
- 输出可供分析员检查的最小证据包。

## 4. 指标契约

正式蓝图按六层分别设门，不允许用一个总体 F1 替代：

1. 数据质量；
2. 检测；
3. 跨源对齐；
4. 攻击链重构；
5. 归因/分析员负担；
6. 系统性能和复现。

具体指标、统计和文献来源采用《规划蓝图候选文献核验清单_20260729.md》第 4 节。

### 4.1 文献与基线准入门

1. 每个核心方法组件至少由一篇四大安全顶会或 TIFS/TDSC 论文定义问题、设计约束或评测标准。
2. 每个强基线必须核验为正式发表的 Full/Regular paper；Short、Poster、Demo、Workshop 和 Findings 不按 CCF 会议等级计入。
3. 其他 CCF A/B 工作只有在没有同等级可替代证据，或提供关键数据、指标、实现时才进入核心表；普通期刊只作背景、局限性或反例证据。
4. “IEEE Transactions”不作为自动准入条件；必须核验具体期刊、当前 CCF 等级和与本课题的直接相关性，避免以 IEEE Access 等泛化替代 TIFS/TDSC。
5. 论文级别不能替代方法质量审查：仍需逐篇提取威胁模型、数据切分、真值粒度、指标、代码/数据可得性和不可复用边界。
