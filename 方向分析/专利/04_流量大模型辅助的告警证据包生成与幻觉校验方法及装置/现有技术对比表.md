# 现有技术对比表：流量大模型辅助的告警证据包生成与幻觉校验方法及装置

## 一、对比结论

本方案不是简单使用大模型进行流量分类或告警总结，而是将检测证据组织为结构化证据包，要求大模型基于证据生成解释，并通过证据引用、支持度、未见 IOC、禁止归因和结构 schema 校验降低幻觉风险。

## 二、最接近现有技术对比

| 对比对象 | 已有技术内容 | 主要不足 | 本方案区别 |
|---|---|---|---|
| [567] TrafficLLM | 使用大模型增强网络流量分析 | 更关注流量表示和任务适配，证据约束和幻觉校验不足 | 将大模型用于证据约束解释，并要求结论引用证据 |
| [594] LLM for encrypted traffic analysis with MoE LoRA | 使用 MoE-LoRA 高效适配加密流量分析服务 | 主要解决模型适配效率，不解决报告可信性 | 增加证据包、提示约束、幻觉校验和反馈闭环 |
| [755] Multimodal Reasoning with LLM for Encrypted Traffic Interpretation | 提供加密流量多模态推理与解释基准 | 偏基准和解释任务，缺少 SOC 告警闭环 | 形成告警接入、证据检索、生成、校验、反馈装置流程 |
| [848] ZTXPlainAI | 零信任网络中可解释加密流量异常检测 | 更偏检测可解释性，缺少大模型证据约束生成 | 将解释组织为可审计报告，并自动校验证据支持 |
| [604] Alert2Vec | 告警嵌入和告警疲劳抑制 | 主要聚合告警，不生成可审计自然语言报告 | 作为历史相似事件检索来源之一，报告仍需证据校验 |
| 普通 RAG 安全问答 | 检索文档后由大模型回答 | 检索内容未必与告警结构化证据绑定，结论可追溯性不足 | 每条关键结论必须引用证据 ID，并做 claim-evidence 校验 |

## 四、可主张的改进点

1. 将多源流量和安全运营上下文组织为结构化证据包。
2. 通过证据编号约束大模型输出，使关键结论可审计。
3. 设置幻觉校验模块，自动识别无证据结论、未见 IOC 和错误归因。
4. 将不通过校验的结论降级、删除或转人工复核。
5. 将复核结果回写历史事件索引、误报模式库、规则候选库和提示模板。

## 五、潜在规避与保护建议

| 潜在规避方式 | 建议保护方式 |
|---|---|
| 使用非大模型的小模型生成报告 | 表述为“语言模型或文本生成模型” |
| 使用不同证据格式 | 表述为“结构化证据包”，不限定 JSON |
| 使用向量检索而不是知识图谱 | 证据检索方式保持开放 |
| 使用人工校验替代自动校验 | 保护自动校验和人工复核结合 |
| 不输出 Markdown 而输出工单字段 | 输出形式表述为报告、工单或结构化记录 |
