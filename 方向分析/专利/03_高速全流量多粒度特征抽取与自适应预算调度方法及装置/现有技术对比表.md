# 现有技术对比表：高速全流量多粒度特征抽取与自适应预算调度方法及装置

## 一、对比结论

本方案不是单纯的高速流量采集系统，也不是离线多粒度流量建模方法，而是将高速采集、分层特征抽取、风险初筛、资源监测、队列感知调度和反馈更新组合为可部署装置。

## 二、最接近现有技术对比

| 对比对象 | 已有技术内容 | 主要不足 | 本方案区别 |
|---|---|---|---|
| [256] Marina | 面向 Terabit 级实时网络流量监测 | 更关注实时监测能力，对安全特征分层和风险驱动预算调度不足 | 在高速监测基础上加入 L0-L4 特征层级和风险/资源联合调度 |
| [619] BPF-DAG | 字节-包-流动态属性图融合 | 多粒度建模较强，但未突出高速全流量下的资源预算 | 将图特征作为高成本路径，按风险和资源状态触发 |
| [832] ADU length restoration | 从 HTTPS 流量恢复应用数据单元长度 | 关注单类协议语义特征，缺少全流量调度体系 | 将 ADU 作为 L2 协议字段特征，按需解析 |
| [835] UniNet | 统一多粒度流量建模框架 | 更偏模型框架，工程队列和吞吐指标不足 | 建立特征层级、队列优先级和预算调度装置 |
| [503] NTLFlowLyzer | 网络/传输层特征抽取和画像 | 偏基础特征工程，深度复核和资源调度不足 | 加入风险初筛、动态路径选择和反馈更新 |
| [766] NOS-Gate | 队列感知流式 IDS | 关注流式 IDS 和时序规避 | 将队列状态扩展到全流量特征路径调度 |
| [615] 数据平面/控制平面协同防御 | 高速网络防御协同 | 主要面向 DDoS 或控制策略 | 用于特征抽取和检测路径预算调度 |

## 四、可主张的改进点

1. 将特征抽取按计算成本分层，并根据风险动态调用。
2. 将队列状态、CPU/GPU/内存和链路速率纳入特征路径选择。
3. 在资源拥塞时仍保证高风险流获得较高特征层级。
4. 将关系图和深度特征作为按需复核路径，降低全量计算开销。
5. 使用误报、漏报和新攻击反馈调整调度策略。

## 五、潜在规避与保护建议

| 潜在规避方式 | 建议保护方式 |
|---|---|
| 使用不同采集技术，例如 DPDK 或 eBPF | 表述为“高速流量接入模块”，不限定具体采集方式 |
| 将 L0-L4 改名为不同层级 | 表述为“按照计算成本划分的多个特征层级” |
| 使用强化学习替代阈值调度 | 表述为“基于风险和资源状态选择特征路径” |
| 不使用图特征，只使用协议和深度特征 | 保护至少两级特征路径和按需复核机制 |
| 将反馈源改为自动模型评估 | 反馈来源包括检测结果、人工复核和自动评估 |

## 六、仍需补强的证据

1. 各层特征字段和单流计算成本表。
2. 调度阈值范围和更新策略。
3. 高峰流量、攻击突发、资源拥塞三类场景实验。
4. 深度解析调用减少比例和检测性能损失对比。
5. 吞吐、P95/P99 延迟、队列长度和丢弃率数据。
