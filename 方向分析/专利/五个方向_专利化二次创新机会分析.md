# 五个方向专利化二次创新机会分析

分析对象：`paper/` 论文库，当前已由原 850 篇扩展至 858 篇。  
分析目标：围绕课题一五个方向，筛选可通过二次创新形成专利交底书的技术方案。  
生成时间：2026-07-02。  

> 说明：本文是技术机会筛选，不构成法律授权结论。正式申请前仍需做专利检索、非专利文献检索和权利要求稳定性评估。

## 1. 专利化判断口径

针对 AI、网络安全、流量检测类方案，不能只写“换一个模型、提升准确率”。更稳妥的专利化表达应落到：

1. 明确的技术问题：例如高带宽下实时检测困难、未知攻击被高置信误判、跨园区数据不能共享、APT 证据链重构成本高。
2. 具体的技术手段：例如特征抽取流水线、图构建规则、证据融合流程、缓存更新机制、队列调度策略、边云协同训练协议。
3. 可验证的技术效果：例如减少计算量、降低误报漏报、缩短早期检测时间、降低告警疲劳、提升跨域泛化、减少原始流量传输。

参考口径：

- 国家知识产权局 2025 年《专利审查指南》修改决定强调，人工智能、大数据等包含算法特征的申请，应整体考察技术特征与算法特征是否共同解决技术问题并取得技术效果。来源：https://www.cnipa.gov.cn/art/2025/11/13/art_99_202568.html
- 国家知识产权局 2024 年修改解读指出，深度学习、分类、聚类等算法若与计算机系统内部结构存在特定技术关联，并能减少存储量、减少传输量、提高处理速度等，可作为技术方案评价。来源：https://www.cnipa.gov.cn/art/2024/1/18/art_2199_189877.html

## 2. 总体结论

五个方向中，最适合转专利的不是“单一深度模型结构”，而是“检测系统中的数据处理流程、在线运行机制、跨源证据融合机制和安全处置闭环”。从当前 858 篇论文证据看，可优先布局四类专利：

1. 可信开放集检测类：围绕未知攻击拒识、模态证据冲突、不确定性校准和低质量标签净化。
2. 多源知识融合类：围绕资产、日志、行为、流量、告警、威胁情报的实体对齐、图谱更新和置信传播。
3. APT 攻击链重构类：围绕端点溯源图、日志、网络流的多阶段攻击链识别、图压缩和 TTP 证据输出。
4. 高速全流量与 AI 分析系统类：围绕 Terabit 级特征抽取、队列感知流式检测、漂移感知模型编排和 LLM 证据包生成。

## 3. 方向一：多模态开放集加密恶意流量检测

该方向已有论文基础最厚，适合形成“可信开放世界检测”专利族。注意不要只保护一个网络结构，而应保护训练、推理、拒识、证据输出和在线更新的完整流程。

### P1. 证据冲突感知的可信开放集加密恶意流量检测方法

**等级：A。**  
**支撑论文：** [518] Reliable Open-Set Network Traffic Classification，[804] Trustworthy Detection of Encrypted Malicious Traffic via Uncertainty-Aware Fusion，[851] Towards Open Set Deep Networks，[853] Evidential Deep Learning，[855] Energy-Based OOD Detection，[856] FOSS，[857] M3S-UPD，[858] New Class Detection，[685] Mixed Noisy Labels。  

**二次创新点：** 把开放集拒识、不确定性估计、多模态冲突检测和加密恶意流量场景合成一个可落地流程。每个模态输出 belief、uncertainty、conflict，不再只做 attention 加权。

**技术问题：** 多模态加密流量中，TLS/QUIC 元数据、包长序列、流统计、关系图可能互相冲突，模型容易把未知攻击高置信误判为已知类。

**技术手段：**

1. 对每条流构造统计序列、协议字段、包间时间、字节摘要、流关系图等多粒度视图。
2. 为每个视图建立证据头，输出类别证据、不确定性和视图可靠度。
3. 计算视图间证据冲突矩阵，识别模态缺失、模态污染和模态不一致。
4. 通过证据折扣融合生成已知类概率、未知风险分数和冲突原因。
5. 当未知风险超过阈值时进入未知候选池，并输出证据包供复核。

**技术效果：** 降低开放集高置信误判，提升未知攻击拒识稳定性，并使检测结果具备可审计证据。

**权利要求骨架：** 一种证据冲突感知的开放集加密恶意流量检测方法，包括：采集加密流量多粒度特征；分别生成各模态证据分布；基于证据分布计算模态冲突系数；按照冲突系数对模态证据进行折扣融合；根据融合证据、不确定性和原型距离输出已知类别或未知类别。

### P2. 混合噪声标签下未知加密恶意流量样本净化与候选簇维护方法

**等级：A。**  
**支撑论文：** [685] Fine-Grained Detection and Analysis of Unknown Encrypted Malicious Traffic From Mixed Noisy Labels，[827] Robust Detection of Malicious Encrypted Traffic Using Only Low-Quality Training Data，[844] When Unknown Threat Meets Label Noise，[857] M3S-UPD。  

**二次创新点：** 把训练样本从“干净/噪声”二分升级为 clean-known、noisy-known、unknown-candidate 三分，并用双记忆队列维护已知类原型和未知候选簇。

**技术问题：** 实际安全系统标签来自规则、沙箱、威胁情报和人工复核，未知攻击常混入已知类训练集，导致模型边界被污染。

**技术手段：**

1. 使用小损失、跨模态一致性和图邻域一致性评估样本可信度。
2. 将样本动态划入已知干净集、已知噪声集和未知候选集。
3. 对已知干净集更新类别原型，对未知候选集维护聚类中心和漂移轨迹。
4. 对疑似未知样本只做风险排序，不强行伪标为已知类。
5. 引入主动复核接口，将复核结果回写原型和候选簇。

**技术效果：** 降低低质量标签对模型的污染，提高未知类发现能力，并减少人工复核样本量。

**权利要求骨架：** 一种混合噪声标签下未知流量样本净化方法，包括：基于多模态一致性和邻域一致性计算标签可信度；按可信度划分样本集合；分别更新已知类原型记忆和未知候选簇记忆；基于候选簇风险向分析端输出待复核样本。

### P3. 多流时序图驱动的早期未知加密恶意流量预警方法

**等级：A。**  
**支撑论文：** [129] Detecting Unknown Encrypted Malicious Traffic in Real Time via Flow Interaction Graph Analysis，[654] Early-Stage Detection of Encrypted Malware Traffic via Multi-Flow Temporal Graph Learning，[737] MalMoE，[443] FG-SAT。  

**二次创新点：** 将单流分类升级为多流时序子图风险排序，在流量尚未完整结束时完成早期未知风险预警。

**技术问题：** C2、僵尸网络、横向扫描常由多条短流共同呈现异常，单条流的前几个包信息不足，闭集分类难以及时发现。

**技术手段：**

1. 以主机、会话、证书指纹、JA3/JA4、QUIC 参数、目的域名为节点构建多流时序图。
2. 在前 N 个包或前 T 秒窗口内生成动态图快照。
3. 分别计算结构漂移、属性漂移、类别原型偏离和邻域异常。
4. 通过专家门控区分短流爆发、周期外联、扫描扩散和下载投递等子模式。
5. 输出异常子图、关键边和早期风险分数。

**技术效果：** 缩短未知恶意流量发现时间，提升对短流和多阶段通信的检测能力。

**权利要求骨架：** 一种基于多流时序图的早期未知恶意流量检测方法，包括：构建流交互动态图；在早期窗口内计算节点和边的时序表示；根据图漂移和开放集距离生成未知风险；输出风险子图及关联流集合。

### P4. 协议原生字段语义预训练与开放集迁移检测方法

**等级：B+。**  
**支撑论文：** [845] FlowSem-MAE，[836] QUIC Domain Recognition Pretraining，[857] M3S-UPD，[835] UniNet。  

**二次创新点：** 不把流量简单展开为字节序列或图像，而是以协议字段、包内结构和跨包演化为语义单元进行预训练。

**技术问题：** 纯字节化表示容易破坏协议字段边界，对 QUIC/TLS 新协议迁移和未知类识别不稳定。

**技术手段：**

1. 定义 Flow Semantic Unit，保留字段边界、字段类型和跨包位置。
2. 对可预测字段执行 mask 预训练，对随机字段、校验字段和偶然字段降低重建权重。
3. 使用字段轴和时间轴双通道编码。
4. 将协议语义一致性、跨视图对比和未知风险分离作为联合预训练目标。

**技术效果：** 提升跨协议、跨数据集迁移能力，降低模型对偶然字节模式的过拟合。

**权利要求骨架：** 一种协议原生加密流量表示学习方法，包括：解析加密流量可见协议字段；构造字段语义单元序列；按照字段可预测性设置掩码和重建权重；生成用于开放集检测的流量嵌入。

### P5. 面向在线预算的加密恶意流量级联检测方法

**等级：B+。**  
**支撑论文：** [464] HyperEye，[766] NOS-Gate，[256] Marina，[858] New Class Detection。  

**二次创新点：** 把高成本特征和低成本特征纳入一个在线预算调度流程，先用轻量特征筛选，再对高风险样本追加深度解析。

**技术问题：** 高带宽园区网络中，不能对所有流量都执行完整协议解析、图构建和深度模型推理。

**技术手段：**

1. 将特征分为 L0 快速统计、L1 包序列、L2 协议字段、L3 图关系和 L4 深度证据。
2. 根据队列长度、CPU/GPU 负载和风险初筛结果动态选择特征层级。
3. 对高风险或高不确定样本触发级联复检。
4. 对低风险样本只保留轻量摘要。

**技术效果：** 在有限计算资源下提升单位时间检测吞吐，减少高成本解析调用。

**权利要求骨架：** 一种加密恶意流量级联检测方法，包括：按计算成本划分特征层级；基于资源状态和初筛风险选择检测路径；对高风险流触发深层特征提取；融合多级输出生成最终风险。

## 4. 方向二：多源异构数据融合

该方向非常适合做系统型专利。关键不是“做一个知识图谱”，而是保护跨源实体对齐、置信传播、冲突消解、增量更新和告警压缩流程。

### P6. 资产-日志-行为-流量-情报知识图谱置信融合方法

**等级：A。**  
**支撑论文：** [88] Open-CyKG，[109] KRYSTAL，[125] Cybersecurity Knowledge Graphs，[126] knowledge graph construction and quality，[604] Alert2Vec。  

**二次创新点：** 将资产台账、流量五元组、登录日志、进程行为、告警和威胁情报统一为带置信度的安全实体图，并让检测结果在图上回流更新。

**技术问题：** 安全数据分散在不同系统中，同一 IP、账号、进程、域名、证书、告警之间缺少统一关联，导致误报难消解、攻击链难追踪。

**技术手段：**

1. 建立资产、账号、进程、会话、域名、证书、告警、IOC、漏洞等实体类型。
2. 使用时间、字段、上下文和威胁情报来源计算实体对齐置信度。
3. 对冲突实体进行版本化存储，保留证据来源。
4. 在图上进行风险传播和证据聚合。
5. 将人工处置结果回写为边权和节点可信度。

**技术效果：** 提升跨系统告警关联能力，降低重复告警，提高攻击路径溯源效率。

**权利要求骨架：** 一种多源安全数据知识图谱融合方法，包括：抽取多源安全实体；计算实体对齐置信度；构建带证据来源的异构图；基于图结构传播风险分数；根据处置反馈更新实体和关系置信度。

### P7. 告警子图嵌入聚合与告警疲劳抑制方法

**等级：A。**  
**支撑论文：** [604] Alert2Vec，[396] DeepDRAC，[695] HADES。  

**二次创新点：** 不是简单规则合并告警，而是把相近时间、相同资产、相似 TTP、共享 IOC 的告警聚合为子图，再做嵌入聚类和根因排序。

**技术问题：** SOC 中重复告警数量巨大，孤立告警缺乏上下文，分析员难以区分同一攻击活动和独立事件。

**技术手段：**

1. 将告警映射为告警节点，并连接资产、账号、进程、域名、漏洞和 IOC。
2. 以时间窗和证据共享关系抽取告警子图。
3. 对子图进行表示学习，聚类为事件簇。
4. 依据根因节点、证据覆盖度和攻击阶段生成处置优先级。

**技术效果：** 减少重复告警，提升事件聚合准确率，降低人工研判成本。

**权利要求骨架：** 一种安全告警聚合方法，包括：构建告警关联子图；对子图进行嵌入表示；根据嵌入相似性聚合告警事件；输出事件簇的根因节点和处置优先级。

### P8. 动态威胁知识图谱质量评估与冲突更新方法

**等级：B+。**  
**支撑论文：** [126] KG construction and quality，[245], [302], [560] 等知识图谱与威胁情报质量相关论文。  

**二次创新点：** 将安全图谱更新过程中的来源冲突、过期 IOC、资产变更和误报反馈作为可量化质量指标。

**技术问题：** 威胁情报和资产信息时效性强，低质量实体关系会造成误报传播。

**技术手段：**

1. 为图谱实体和边维护来源可信度、时间衰减、证据数量和反馈状态。
2. 对冲突关系建立候选版本，按证据链强度选择主版本。
3. 对过期 IOC 和失效资产执行自动降权。
4. 根据告警验证结果回写图谱质量分。

**技术效果：** 减少过期情报和错误关系对检测结果的影响，提升图谱长期维护质量。

**权利要求骨架：** 一种动态安全知识图谱质量控制方法，包括：为实体关系计算多维质量指标；识别冲突关系并生成版本；根据时间衰减和反馈结果更新质量分；基于质量分过滤风险传播路径。

### P9. 隐私保护的跨域威胁情报原型协同方法

**等级：B+。**  
**支撑论文：** [430] FeCoGraph，[637] DAIR-FedMoE，[805] federated machine unlearning，[345] privacy-preserving GNN。  

**二次创新点：** 跨机构不共享原始流量和日志，只共享原型、图嵌入摘要、漂移统计和低泄露风险的模型更新。

**技术问题：** 多园区、多机构之间安全数据敏感，无法集中训练，但单点数据又不足以覆盖未知攻击。

**技术手段：**

1. 本地生成攻击原型、正常原型和未知候选原型。
2. 对原型加入隐私预算和敏感特征过滤。
3. 服务器端聚合跨域原型，生成全局威胁嵌入空间。
4. 对遗忘请求或误报反馈执行原型删除和模型校正。

**技术效果：** 在不传输原始数据的前提下提升跨域检测能力，并降低隐私泄露风险。

**权利要求骨架：** 一种跨域威胁情报协同方法，包括：在本地提取安全事件原型；对原型执行隐私过滤；聚合多域原型生成全局风险空间；将全局原型下发用于本地检测。

## 5. 方向三：复杂恶意攻击行为智能检测

APT、多阶段攻击链和异常行为基线更适合写“攻击链重构、溯源图压缩、TTP 识别、回放验证平台”类专利。相比单点检测，这类专利更容易体现安全运营场景价值。

### P10. 端点溯源图、日志和网络流联合的 APT 攻击链重构方法

**等级：A。**  
**支撑论文：** [336] dynamic provenance graph APT detector，[416] End-to-End Attack Scene Reconstruction，[528] RT-APT，[557] TeRed，[847] Zoomer。  

**二次创新点：** 将主机溯源图、系统日志和网络流交互图统一到攻击阶段图中，输出可复核攻击链，而不是只输出异常分数。

**技术问题：** APT 攻击跨越进程、文件、注册表、账号、网络连接和远程域名，单一数据源无法完整恢复攻击路径。

**技术手段：**

1. 将进程、文件、账号、网络连接、域名、流量会话映射为统一事件节点。
2. 依据因果依赖、时间顺序、主机关系和网络通信构建跨源攻击图。
3. 使用正常行为基线过滤常见依赖边，压缩大规模溯源图。
4. 根据 ATT&CK 阶段约束识别初始访问、执行、持久化、横向移动、C2 和数据外传。
5. 输出攻击链、关键证据、置信度和缺失环节。

**技术效果：** 降低攻击溯源图规模，提高 APT 攻击链重构效率和可解释性。

**权利要求骨架：** 一种 APT 攻击链重构方法，包括：采集端点溯源事件、日志和网络流；构建跨源因果图；基于正常行为基线压缩图；按攻击阶段约束抽取攻击路径；输出带证据置信度的攻击链。

### P11. 正常行为基线驱动的大规模溯源图压缩方法

**等级：A。**  
**支撑论文：** [557] TeRed，[528] RT-APT。  

**二次创新点：** 将正常行为基线用于图压缩和异常边保留，解决大规模溯源图难以实时处理的问题。

**技术问题：** 主机溯源图边数量巨大，大量正常依赖关系淹没攻击路径，实时检测开销高。

**技术手段：**

1. 学习主机、进程和业务的正常依赖模板。
2. 对匹配正常模板的高频边执行压缩或摘要化存储。
3. 对罕见依赖、跨权限依赖、外联触发依赖和敏感文件依赖进行保留。
4. 在图压缩后执行异常检测和攻击路径搜索。

**技术效果：** 减少图存储和计算开销，同时保留关键攻击证据。

**权利要求骨架：** 一种溯源图压缩方法，包括：生成正常行为依赖模板；识别溯源图中的常规边和异常边；对常规边摘要化压缩；保留异常边用于攻击检测。

### P12. ATT&CK 约束的攻击阶段识别与 TTP 路径预测方法

**等级：B+。**  
**支撑论文：** [847] Zoomer，[109] KRYSTAL，[726] LLM-HGAN，[695] HADES。  

**二次创新点：** 把检测结果映射到 ATT&CK 技术阶段，并预测下一阶段可能行为，实现从“异常点”到“战术路径”的跃迁。

**技术问题：** 单点异常不等于攻击活动，安全运营更需要知道当前处于哪个攻击阶段以及下一步风险。

**技术手段：**

1. 将安全事件子图映射为 ATT&CK 技术候选。
2. 依据阶段顺序、前置条件和事件证据计算 TTP 置信度。
3. 在攻击阶段图上预测下一跳高风险行为。
4. 生成阶段化处置建议。

**技术效果：** 提升告警解释能力和提前防御能力。

**权利要求骨架：** 一种攻击阶段识别方法，包括：从安全事件图中抽取行为特征；映射到 ATT&CK 技术节点；基于阶段约束修正置信度；预测后续攻击阶段并输出处置策略。

### P13. 面向 APT 检测器验证的合成审计日志生成与回放平台

**等级：B+。**  
**支撑论文：** [795] SAGA，[528] RT-APT，[847] Zoomer。  

**二次创新点：** 不只生成样本，而是生成可回放、可注入背景噪声、可标注攻击阶段的审计日志序列，用于检测器压力测试。

**技术问题：** 真实 APT 数据稀缺、标注困难，检测器缺少可控验证集。

**技术手段：**

1. 定义攻击活动模板，包括进程、文件、网络、账号和权限事件。
2. 根据 ATT&CK 阶段生成事件序列。
3. 注入正常业务背景日志和时间扰动。
4. 将合成日志回放到检测系统并生成评测报告。

**技术效果：** 提升 APT 检测器测试覆盖度，降低真实攻击数据依赖。

**权利要求骨架：** 一种合成审计日志生成与回放方法，包括：根据攻击模板生成多源审计事件；加入正常行为噪声；按时间顺序回放事件；统计检测器对攻击阶段的识别效果。

## 6. 方向四：全流量特征识别

该方向最容易形成工程型专利，尤其是高速捕获、协议解析、特征预算、队列调度和硬件/软件协同。建议把“性能约束”写进方案，否则容易变成普通算法论文。

### P14. 高速全流量多粒度特征抽取与自适应预算调度方法

**等级：A。**  
**支撑论文：** [256] Marina，[619] BPF-DAG，[832] ADU length restoration，[835] UniNet，[503] NTLFlowLyzer。  

**二次创新点：** 建立从包、流、会话、协议字段到关系图的多粒度特征流水线，并按实时负载动态分配特征预算。

**技术问题：** Terabit 级链路无法对所有流量执行完整深度解析和图建模。

**技术手段：**

1. 在捕获端提取 L0/L1 轻量特征，包括包长、方向、时间间隔和基础五元组。
2. 在解析端按协议可见字段提取 L2 特征。
3. 在聚合端构建 L3 流关系图和会话行为摘要。
4. 根据链路速率、队列长度、风险初筛和资源使用率动态调整特征层级。
5. 对高风险流保留全量特征，对低风险流仅保留摘要。

**技术效果：** 在高吞吐场景下降低存储与计算开销，保障实时检测。

**权利要求骨架：** 一种高速全流量特征抽取方法，包括：按成本划分多粒度特征；监测系统资源和流量负载；根据风险和负载选择特征抽取路径；输出用于检测的特征摘要或全量特征。

### P15. 应用数据单元长度恢复的加密协议语义识别方法

**等级：A。**  
**支撑论文：** [832] Ultimate Encrypted Traffic Feature Engineering，[845] FlowSem-MAE，[836] QUIC pretraining。  

**二次创新点：** 针对 HTTPS/QUIC 等加密协议，利用可见包序列恢复应用数据单元长度和方向模式，形成协议语义级特征。

**技术问题：** 加密 payload 不可见，传统字节特征失效；但包边界和应用数据单元仍包含业务语义。

**技术手段：**

1. 从 TCP/TLS/QUIC 包序列中识别方向、长度和时间边界。
2. 基于分片、重传和握手状态恢复应用数据单元长度序列。
3. 将 ADU 长度序列与协议字段语义编码融合。
4. 使用该特征进行应用识别、恶意流量检测和未知类风险评估。

**技术效果：** 在不解密 payload 的前提下增强协议语义识别能力。

**权利要求骨架：** 一种加密流量应用数据单元特征提取方法，包括：解析加密会话的可见包序列；恢复应用数据单元长度和方向；生成协议语义特征；将协议语义特征输入检测模型。

### P16. 队列感知的流式 IDS 抗时序规避检测方法

**等级：A。**  
**支撑论文：** [766] NOS-Gate，[256] Marina，[615] hybrid data-control plane DDoS defense，[334] evolving volumetric attacks。  

**二次创新点：** 将流式检测队列状态纳入模型推理和采样决策，防御攻击者通过控制时序、包间隔和流量突发绕过检测。

**技术问题：** 攻击者可利用时序扰动和突发流量制造队列拥塞，使检测系统跳过高成本特征或延迟处置。

**技术手段：**

1. 实时监测检测队列长度、等待时间、丢包率和推理延迟。
2. 将队列状态作为检测上下文输入风险评分模块。
3. 对疑似时序规避流启用高优先级采样和快速路径。
4. 根据拥塞状态调整阈值和特征预算。

**技术效果：** 提升流式 IDS 在拥塞和时序规避攻击下的稳定性。

**权利要求骨架：** 一种队列感知流式入侵检测方法，包括：采集流量特征和队列状态；识别时序规避风险；根据队列状态调整采样和检测路径；输出风险结果和调度策略。

### P17. 字节-包-流动态属性图特征引擎

**等级：B+。**  
**支撑论文：** [619] BPF-DAG，[835] UniNet，[547] SnifferDog。  

**二次创新点：** 将字节、包、流三层特征构造成动态属性图，并在图上执行统一特征抽取。

**技术问题：** 多粒度特征通常分散处理，缺少统一结构表示，导致跨粒度关系难以利用。

**技术手段：**

1. 将字节片段、包、流、主机和会话定义为不同类型节点。
2. 建立包含顺序、包含、相似、共享目的地和时间邻近的多类型边。
3. 随流量到达增量更新动态图。
4. 输出面向分类、异常检测和开放集拒识的统一嵌入。

**技术效果：** 提升多粒度特征复用能力，减少重复建模。

**权利要求骨架：** 一种网络流量动态属性图特征提取方法，包括：将多粒度流量单元映射为异构节点；建立多类型关系边；随流量窗口增量更新图；基于图生成统一检测特征。

## 7. 方向五：AI驱动的网络流量检测分析系统

该方向适合做“系统平台型专利族”。重点应放在模型编排、漂移监测、LLM 解释、自动处置、边云协同，而不是单个分类器。

### P18. 流量大模型辅助的告警证据包生成与幻觉校验方法

**等级：A。**  
**支撑论文：** [567] TrafficLLM，[594] LLM for encrypted traffic analysis with MoE LoRA，[755] Multimodal Reasoning with LLM for Encrypted Traffic Interpretation，[848] ZTXPlainAI。  

**二次创新点：** 让 LLM 不直接替代检测模型，而是读取结构化证据、生成解释和处置建议，并通过证据约束防止幻觉。

**技术问题：** 现有流量检测输出通常只有标签和分数，分析员仍需人工查证；LLM 若直接解释流量又容易生成无依据结论。

**技术手段：**

1. 将检测结果、特征贡献、流关系图、威胁情报命中和历史相似事件组织成证据包。
2. LLM 只基于证据包生成告警摘要、攻击假设、处置步骤和复核问题。
3. 设置证据引用约束，所有结论必须绑定证据 ID。
4. 使用规则校验、检索校验和模型一致性校验过滤幻觉输出。

**技术效果：** 提升告警可读性和研判效率，降低 LLM 无依据解释风险。

**权利要求骨架：** 一种网络流量告警解释方法，包括：生成结构化证据包；基于证据包调用语言模型生成解释；校验解释中结论与证据的对应关系；输出可审计告警报告。

### P19. 漂移感知的网络流量检测模型编排与自动重训练方法

**等级：A。**  
**支撑论文：** [793] automated drift detection and adaptation，[637] DAIR-FedMoE，[538] self-supervised adaptation，[674] drift adaptation related papers。  

**二次创新点：** 将模型漂移监测、漂移类型识别、专家模型选择、重训练触发和回滚策略合并为运行时编排流程。

**技术问题：** 网络流量随业务、协议、时间和攻击手法变化而漂移，固定模型长期运行会性能衰退。

**技术手段：**

1. 持续监测输入分布漂移、特征漂移、图结构漂移和标签反馈漂移。
2. 根据漂移类型选择协议专家、场景专家或新类专家。
3. 对轻微漂移执行参数高效适配，对严重漂移触发重训练。
4. 对新模型进行影子评估，满足阈值后灰度上线。
5. 保留回滚版本和漂移解释。

**技术效果：** 提升检测系统长期运行稳定性，减少人工维护成本。

**权利要求骨架：** 一种漂移感知检测模型编排方法，包括：采集在线流量分布指标；识别漂移类型；选择适配策略和专家模型；执行影子评估和灰度切换；在性能下降时自动回滚。

### P20. 多智能体 SOC 分析闭环与规则更新方法

**等级：B+。**  
**支撑论文：** [604] Alert2Vec，[396] DeepDRAC，[567] TrafficLLM，[848] ZTXPlainAI。  

**二次创新点：** 将告警聚合、证据检索、攻击链推理、规则生成和人工反馈封装为多智能体协作流程。

**技术问题：** 检测系统输出与安全运营处置之间缺少闭环，人工经验难以回流模型和规则库。

**技术手段：**

1. 告警聚合智能体负责事件簇合并。
2. 证据检索智能体从知识图谱和流量库提取证据。
3. 攻击链智能体生成阶段化假设。
4. 规则智能体生成 Suricata/YARA/Sigma 等候选规则。
5. 人工确认后将规则、标签和证据回写系统。

**技术效果：** 缩短从告警发现到规则沉淀的周期，提高处置闭环效率。

**权利要求骨架：** 一种安全运营多智能体分析方法，包括：聚合告警事件；检索关联证据；推理攻击链；生成候选检测规则；根据人工反馈更新规则库和检测模型。

### P21. 联邦 MoE 边云协同的跨园区流量检测方法

**等级：B+。**  
**支撑论文：** [637] DAIR-FedMoE，[680] federated and quantized IDS，[449] client-sampled federated meta-learning，[805] federated machine unlearning。  

**二次创新点：** 使用专家路由解决跨园区复合漂移，同时利用量化、客户端采样和遗忘机制降低通信与隐私风险。

**技术问题：** 不同园区业务分布不同，集中训练受隐私和带宽限制，普通联邦平均难以适应复合漂移。

**技术手段：**

1. 每个边缘节点训练本地专家和漂移描述向量。
2. 云端聚合专家参数、原型和漂移统计。
3. 根据园区场景选择专家组合并下发路由策略。
4. 使用量化更新减少通信量。
5. 对被要求删除的数据执行联邦遗忘更新。

**技术效果：** 提升跨园区检测泛化能力，减少原始数据传输和通信开销。

**权利要求骨架：** 一种联邦专家混合流量检测方法，包括：在边缘节点训练本地专家；上传量化模型更新和漂移摘要；云端聚合专家并生成路由策略；下发路由策略用于本地检测。

### P22. DA-FDIDS 域自适应少样本动态入侵检测系统

**等级：B。**  
**支撑材料：** `方向分析/AI驱动的网络流量检测分析系统/DA-FDIDS论文综述部分.md`，以及动态图、少样本、域适应、LoRA 在线适配相关补充论文。  

**二次创新点：** 将 DA-FDIDS 从论文模型包装为“动态图少样本检测 + 跨域对齐 + LoRA 在线适配 + 缓存增强分类”的系统流程。

**技术问题：** 新场景、新攻击和低样本条件下，静态 IDS 模型难以快速迁移。

**技术手段：**

1. 用 TrafficEncoder 提取流量基础表征。
2. 用动态图模块捕获跨流关系。
3. 用少样本度量学习识别新类。
4. 用 GRL/MMD 对齐跨域分布。
5. 用 LoRA/Stable-LoRA 做在线轻量适配。
6. 用 Cache/RBF/MHA 做局部判别增强。

**技术效果：** 降低新场景适配成本，提升少样本入侵检测能力。

**权利要求骨架：** 一种域自适应少样本动态入侵检测方法，包括：提取网络流量表征；构建动态交互图；执行少样本类别判别；对源域和目标域表征进行对齐；通过参数高效模块在线更新检测模型。

## 8. 不建议优先专利化的内容

以下内容更适合写论文或作为技术秘密，不建议作为第一批专利主题：

1. 只把 CNN、Transformer、GNN、Mamba、LLM 换到流量分类上的模型结构。
2. 只提升某个公开数据集准确率，但没有在线部署、资源约束或安全处置流程。
3. 只构建数据集、基准或综述，缺少具体检测和处理流程。
4. 只做 attention 融合、多模态拼接或普通投票融合。
5. 只把 LLM 用于自然语言总结告警，但没有证据约束、校验和回写机制。
6. 直接复现某篇论文方法，未加入课题场景下的流程、设备、参数和闭环改造。

## 9. 建议的专利布局节奏

第一批建议申报 4 件核心专利：

1. 证据冲突感知的可信开放集加密恶意流量检测方法。
2. 端点溯源图、日志和网络流联合的 APT 攻击链重构方法。
3. 高速全流量多粒度特征抽取与自适应预算调度方法。
4. 流量大模型辅助的告警证据包生成与幻觉校验方法。

第二批建议申报 4 件支撑专利：

1. 混合噪声标签下未知加密恶意流量样本净化方法。
2. 资产-日志-行为-流量-情报知识图谱置信融合方法。
3. 漂移感知的网络流量检测模型编排与自动重训练方法。
4. 联邦 MoE 边云协同的跨园区流量检测方法。

第三批可作为储备：

1. 协议原生字段语义预训练与开放集迁移检测方法。
2. 队列感知的流式 IDS 抗时序规避检测方法。
3. APT 合成审计日志生成与回放平台。
4. DA-FDIDS 域自适应少样本动态入侵检测系统。

## 10. 下一步交底书材料清单

每个候选专利进入交底书前，建议补齐以下材料：

1. 现有技术痛点：至少列出 3 类现有方法的不足。
2. 系统流程图：数据输入、处理模块、输出结果和反馈闭环。
3. 关键步骤伪代码：尤其是阈值、队列、图更新、证据融合和模型更新步骤。
4. 技术效果指标：吞吐量、延迟、误报率、未知类召回率、图压缩率、通信量、人工复核量。
5. 可替代实施方式：不同模型、不同特征、不同部署位置，避免权利要求过窄。
6. 与论文的差异点：明确不是复现论文，而是在课题场景下形成系统流程、工程约束和闭环机制。
