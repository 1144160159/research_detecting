# 风险与阻塞项

| 项目 | 风险 | 处置 |
|---|---|---|
| SSH/网络 | 远端命令通道中断或超时会使状态未知 | 固定使用 CMD 直接 SSH 到 `10.0.5.103:25450`，禁用转发；超时后先用最小只读命令重验通道，不引入 VPN 或本地地址绑定 |
| Python 热路径 | 对象与字典开销无法满足高 Mpps | 先 profiling，再迁移结构数组/批处理/编译扩展 |
| 调度偏置 | 纯收益成本比可能饿死稀有关键流 | 增加保底队列、公平性和关键流覆盖门 |
| GPU 小批次 | 调度/拷贝开销抵消加速收益 | 自适应批大小、pinned buffer、异步 stream 与 CPU 回退 |
| 状态爆炸 | 高 churn 造成流表内存/回收压力 | 分片上限、时间轮、近似统计和显式驱逐指标 |
| 指标误读 | 合成烟测被当作生产吞吐 | 正式结论只来自真实回放、固定协议、至少三次复测 |
| 部署证据缺口 | 当前 GPU 容器只可见 veth 且无 CAP_NET_ADMIN，无法测物理 NIC drop 与真实端到端排队 | 将 Rust 数据面适配器部署到 `traffic-analysis-platform` 的真实采集节点，以 NIC/驱动计数器和同一流量发生器闭环验收 |
| 跨域泛化 | USTC→UNSW 的最差 macro-F1 仅 0.4157（fallback）/0.3265（normal） | 业务阈值冻结前不得宣称质量可接受；优先做域稳健归一化、校准与协议/数据集偏移诊断，再重跑相同冻结 manifest |
| 模式误判 | normal 与 fallback 被当成两个可独立发布的 Pareto 候选 | 将二者视为同一配置的运行模式；最终候选必须同时携带正常、降级和恢复证据 |
