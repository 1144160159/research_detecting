# 高速全流量多粒度特征抽取与自适应预算调度方法

工程代号：**HFT-MGBS**。

## 目录职责

- `00_总览`：总体目标、里程碑、完成度与验收门；
- `01_方案设计`：问题边界、架构、预算调度与优化路线；
- `02_工程设计`：基准、性能指标、压力与回归协议；
- `03_工程报告`：只记录已验证的性能与部署结论；
- `04_数据与运行`：远端环境、数据引用、运行手册和 manifest；
- `05_过程记录`：决策、风险、变更和实验迭代；
- `results`：本地仅保留索引，不保存大结果。

## 存储边界

本地只保留源码、配置、测试和文档。PCAP/PCAPNG、原始流量、特征矩阵、模型参数、检查点、日志、profiling 和运行结果全部留在 GPU 服务器。远端目录为 `/opt/data/private/wangwt/ParkAttackKE/HFT-MGBS`，公共数据集直接引用 `/opt/data/private/wangwt/ParkAttackKE/datasets`。

## 当前状态

已完成流式多粒度抽取、双向流语义、预算调度、执行期实测守卫、真实 PCAP 回放、同域分组质量、冻结输入哈希的 USTC→UNSW 独立留出，以及同候选 deep 故障—真实 PCAP 降级—探针恢复验证。物理 NIC 线上证据已建立机器审计合同；当前 83 项远端测试通过。

离线预选配置为 `batch=512、budget=5000us、execution safety=0.50`。性能、同域质量、独立留出和回退恢复四源证据已经能够联合硬门禁，但跨域 macro-F1 仍低；当前环境只可见容器 veth，不能验证物理 NIC 丢包、真实目标负载和线上端到端 P99/P999。因此仍不得把离线前沿表述为最终工程最优。

后续接入 `traffic-analysis-platform` 时，热路径保持其 Rust `PacketProcessor/FlowValue`，HFT-MGBS 的预算决策、关键流标记、降级原因和可选特征抽取应进入 Rust 数据面；Go 只承担配置、gRPC/Kafka 与可观测控制，Java/Flink 承担窗口聚合，Python 保留为离线训练与证据生成。无需把平台整体改写为 Python。
