# 候选组件统一验证矩阵

## 实验顺序

### E0：代码与环境门禁

- HFT-MGBS 本地禁入检查、Python 3.7/远端 3.9 语法、单测；
- 记录 GPU/CPU/NIC/NUMA/驱动/Conda、代码哈希和输入哈希；
- 禁止候选仓库自带 data/model 进入 HFT-MGBS 本地目录。

### E1：特征正确性

| 对照 | 输入 | 目标 |
|---|---|---|
| HFT-MGBS vs NTLFlowLyzer | 同一小型远端 PCAP | 双向包数/字节/IAT/flags/timeout 逐字段对齐 |
| HFT-MGBS vs BERT-ps Zeek 插件 | 同一流集合 | 带方向包长序列、截断/填充、乱序边界一致 |
| HFT-MGBS MFR adapter vs YaTC | 同一流集合 | multi-level matrix shape、归一化、掩码一致 |

E1 未通过时，后续精度和吞吐结果全部无效。

### E2：等预算识别基线

固定数据划分、前 K 包、可见字节、训练预算和 seeds，对比：

1. 统计特征 + 线性/树模型（最低成本基线）；
2. FastTraffic 机制适配；
3. BERT-ps 小模型/蒸馏模型；
4. YaTC 小型 MFR encoder；
5. ET-BERT 教师；
6. AutoML4ETC 搜索得到的参数量匹配子网。

报告 macro-F1、balanced accuracy、AUROC/AUPRC、ECE、参数量、FLOPs 代理、单批/单流 P50/P99、显存和吞吐。精度比较必须同时报告资源成本。

### E3：级联与调度消融

| 方案 | fast tier | deep tier | 调度 |
|---|---|---|---|
| S0 | 统计基线 | 无 | 无 |
| S1 | FastTraffic | 无 | 固定全量 |
| S2 | FastTraffic | YaTC | 固定置信阈值 |
| S3 | FastTraffic | YaTC | HFT-MGBS 成本/收益 |
| S4 | FastTraffic | YaTC | HFT-MGBS + 压力反馈 |
| S5 | FastTraffic | YaTC | RL/adaptive-monitoring 对照 |

必须测预算利用率、越界次数、各 tier 覆盖、关键流覆盖、公平性、准确率-延迟 Pareto 和降级恢复时间。

### E4：高速与过载实验

- 包长：64B、IMIX、真实分布；流型：mice/elephant/high-churn；
- 负载：25/50/75/100% + 突发 + 过载阶跃；
- 批次：多档 packet batch、GPU micro-batch、最大等待；
- 故障：GPU 超时/OOM、反馈中断、队列满、进程重启；
- 指标：Gbps/Mpps、首个丢包拐点、P50/P95/P99/P99.9、CPU/GPU/内存/PCIe、恢复时间。

### E5：热路径优化

按 E4 profiling 逐项验证结构数组/预分配、分片流表、批处理、compiled extension、pinned memory、异步 stream。每个优化只改变一个主变量，并执行 E1-E4 回归。

## 结果命名和完成门

远端运行使用 `HFT-MGBS/runs/<run_id>`，紧凑汇总使用 `results/<experiment>/summary.json`，每组必须有 manifest 和代码哈希。只有 `manifest.status=complete`、三次复测、无预算越界、无特征回归且原始日志存在，才能进入最终方案选择。
