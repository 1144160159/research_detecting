# PCAP指标链与候选证据门（2026-07-15）

## 已实现

- 经典 PCAP 流式读取，不把捕获一次性载入内存；
- Ethernet、双层 VLAN、IPv4、TCP、UDP、TCP flags 和可配置载荷截断；
- 非 IP、非 TCP/UDP、非首片分片、截断记录和畸形报文分别计数；
- 批次 P50/P95/P99/P99.9/max、吞吐、CPU 时间、RSS/内存、预算越界和关键流覆盖；
- 可选 `nvidia-smi` 后台采样，记录系统 GPU 利用率和显存占用及采样错误；
- deep 路径 circuit breaker：失败后回退、超时后 half-open 探测、连续成功后恢复；
- 最终候选证据门：不完整证据不得进入正式 Pareto 选择。

本地只使用内存构造的 PCAP 二进制做测试，没有在本地代码目录保存 PCAP、数据、模型或运行结果。

## 证据范围控制

`benchmark_pcap.py` 输出 `evidence_scope`，离线回放只能证明：

- 应用处理批次延迟；
- 调度预算是否越界；
- 关键流是否获得最低 tier；
- PCAP 中记录的解析接受/拒绝数量；
- 进程 CPU/内存以及可选的系统 GPU 采样。

它不能单独证明 NIC 丢包、线上端到端 P99、真实故障恢复时间或识别质量。最终候选必须通过 `validate_candidate_evidence.py`，同时具备以下 11 类证据：

1. live replay 吞吐；
2. NIC 前后计数器丢包；
3. 端到端 P99；
4. 端到端 P99.9；
5. CPU 资源；
6. GPU 资源；
7. 内存资源；
8. 预算越界；
9. 关键流覆盖；
10. 故障回退与恢复；
11. 固定质量协议。

此外要求 `manifest_status=complete`、至少三次正式复测、有效代码 SHA-256 和输入 SHA-256。缺少任一项即拒绝进入 Pareto 输入。

## 远端执行入口

单点运行：

```bash
PYTHONPATH=. /opt/data/private/wangwt/anaconda3/bin/conda run -n py3.9 \
  python scripts/benchmark_pcap.py /opt/data/private/wangwt/ParkAttackKE/datasets/<capture>.pcap \
  --batch-size 4096 --budget-us 25000 --gpu-index 0
```

矩阵运行：

```bash
PCAP_PATH=/opt/data/private/wangwt/ParkAttackKE/datasets/<capture>.pcap \
  bash scripts/run_remote_pcap_matrix.sh
```

矩阵包含 3 个 batch size、3 个预算和 normal/fallback 两种模式，共 18 个离线点；结果、环境、输入哈希、代码哈希和 manifest 只写远端。
