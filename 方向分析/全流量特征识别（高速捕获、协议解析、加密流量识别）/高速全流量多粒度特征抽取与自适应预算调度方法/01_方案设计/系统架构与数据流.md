# 系统架构与数据流

输入链路按 `采集适配 → 最小解析 → 流键规范化 → 全量基础特征 → 流/窗口状态 → 预算决策 → 选择性深层特征 → 下游识别接口` 执行。

## 关键原则

- 热路径只做固定成本、低分配操作；昂贵解析和载荷统计必须受预算控制。
- 流状态按分片所有权管理，避免跨核共享写；超时回收使用时间轮或分桶近似，不做全表扫描。
- 每种特征都带 `schema_version`、时间语义、来源层级和估算成本。
- 调度器输出必须可解释：优先级、估算成本、预算压力和最终 tier 可审计。
- 下游异常检测只消费稳定契约，不直接耦合采集/解析实现。

首版 Python 代码验证接口与调度逻辑；生产热路径后续可按 profiling 迁移到 C++/Rust/Cython/Numba 或专用数据面，不预先锁死技术栈。
