# 发布配置与进度文档当前状态修复

## 问题现象

ens8f0/ens8f1 恢复为 10GbE 后，发布配置和自动进度文档仍写着两个接口
无载波、被排除、硬件合格接口对为 0，并继续把 `af_packet_ts` 写成当前
主驱动。

## 根因

发布审计器把旧硬件故障状态写成固定期望；进度生成器也读取旧的
`kernel_receive_timestamp_ready` 字段，并包含“ens8 保持排除”的硬编码
文本。实验状态变化没有同步升级配置 schema 约束。

## 修改范围

- 更新发布配置为 ens8 双口硬件合格、`xdp-skb` 诊断优先、
  `af-packet-ts` 回退。
- 把 XDP 三轮稳定性、同场资源、eBPF 可复现构建和运行时抓包回退证据
  纳入 SHA-256 索引。
- 审计器改为验证 generic XDP 诊断资格、native XDP 未资格、生产门仍
  关闭，以及回退证据不能复用正常零丢包结论。
- 进度生成器更新硬门表、接口状态、证据索引和下一执行门。

## 验证证据

发布候选审计与进度生成器回归共 15 项通过；发布审计输出
`accepted=true`、算法候选 10、选择 A09、`final_pareto_eligible=false`。
生成的 `docs/ENGINEERING_PROGRESS.md` 明确记录 2 个硬件合格接口、1 对
硬件合格双口和 0 对生产完整预检接口。

远端制品审计随后暴露“无接口硬件阻塞”的两种表示不一致：发布配置使用
空对象，原始就绪汇总按接口保存 `ens8f0: []`、`ens8f1: []`。配置已改为
逐接口空列表，发布审计改为验证所有列表均为空，避免把表示差异误判为硬件
故障或放过非空阻塞。

## 性能影响与回退

该修复只改变配置、审计和文档生成，不进入数据面。若证据字段或 SHA 缺失，
审计失败关闭；可回退到上一份配置进行历史复现，但不得用旧配置描述当前
接口状态。

## 遗留风险

远端完整发布审计需要在全量代码同步后重新生成。生产阈值仍未冻结，因此
当前配置只证明诊断候选闭环，不证明最终生产 Pareto。
