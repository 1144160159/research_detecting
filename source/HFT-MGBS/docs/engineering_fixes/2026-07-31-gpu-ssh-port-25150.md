# GPU SSH 端口切换至 25150

## 问题现象

GPU 节点 `10.0.5.103` 已恢复启用，但 SSH 服务入口从 `25450` 变更为
`25150`。HFT-MGBS 的同步脚本和优化配置仍固定旧端口，会导致 GPU 代码同步、
远端校验与分离部署入口继续连接失效地址。

## 根因

这是部署端点的外部变更，不是 Python、Rust 或模型算法缺陷。旧端口同时存在于
两个 CMD 同步入口和优化配置中；分离部署 JSON 原先只记录主机，未显式记录 SSH
端口，容易再次产生配置漂移。

## 修改范围

- `sync_to_gpu.cmd`：`REMOTE_PORT` 改为 `25150`。
- `sync_split_deployment.cmd`：`GPU_PORT` 改为 `25150`。
- `configs/optimization_profile.yaml`：目标环境 SSH 端口改为 `25150`。
- `configs/split_deployment_rc1.json`：在 Python 推理面新增显式
  `ssh_port: 25150`。
- `tests/test_sync_contract.py`：增加两个 CMD 入口的端口契约断言。

未修改只读上游 `/home/wangwt/phase_2/code/traffic-analysis-platform/rust`，未移动
数据、模型、结果或运行日志。

## 验证证据

- TCP/SSH 握手已到达 `10.0.5.103:25150`，远端返回
  `OpenSSH_8.9p1 Ubuntu-3ubuntu0.7`。
- 新端口返回的 ED25519 指纹为
  `SHA256:ptg8SMNQvUQYHV0/hafU4hBlhZ/vb4wJUmM1XTVlROI`。
- 旧 `25450` 已固定指纹为
  `SHA256:qTTam8cM3VllUiId9B76j+bK/FhOqskpd10eXfRVcLU`；二者不同，因此按
  fail-closed 原则没有绕过 `StrictHostKeyChecking`，也没有执行认证、同步或远端
  测试。
- 本地契约测试必须在提交/同步前通过；主机密钥经管理员独立确认并固定后，才允许
  执行 GPU 只读预检与代码同步。

## 性能影响

端口变更不影响数据面吞吐、时延、算法精度或资源预算。本次没有新增 GPU 性能结果。

## 回退条件

只有部署管理员明确把 SSH 服务切回旧端口，且旧端点的主机密钥与服务状态重新通过
独立核验时，才可把上述四处端口配置统一回退。不得只回退单个脚本。

## 遗留风险

新旧指纹不同可能来自 SSH 主机密钥重建、端口映射到不同实例或合法的服务器迁移；
在得到可信渠道确认前无法区分。当前 GPU 服务“已恢复”的业务状态已记录，但
HFT-MGBS 的认证、项目目录、Conda 环境、GPU 清单和远端代码状态尚未在新端口确认。
